# ARC-T-0006 · Define events runs generated state split

## Outcome

Tusker stores current readable state in Markdown frontmatter, audit history in events, agent attempts in runs, and cache data in generated indexes.

## Acceptance contract

| AC | What must be true | Verification | Deliverables | Doc nodes |
|---:|---|---|---|---|
| 1 | Status remains canonical in task frontmatter. | schema/workflow tests | test output | tusker/model, tusker/daemon |
| 2 | Transitions and review/docs/verification events append to `_system/events/YYYY-MM.jsonl`. | event writer test | event fixture | tusker/model, tusker/daemon |
| 3 | Agent runtime details go under `_system/runs/<TASK-ID>/attempt-N.json`. | run record test | run fixture | tusker/model, tusker/daemon |
| 4 | Generated indexes can be deleted and rebuilt. | delete/reindex test | test output | tusker/model, tusker/daemon |

- Create event and run schemas.
- Update reindexer.
- Update status mutation to write frontmatter and append event.
- Warn on frontmatter status vs latest status event mismatch.

- Broad refactors not needed to satisfy the acceptance contract.

### Non-goals

## Constraints and stop conditions

The agent must preserve:

- Plain Markdown readability in Obsidian.
- Current task status in task frontmatter.
- Generated indexes as rebuildable cache.
- Runtime/audit data outside human-facing frontmatter.

The agent must not change:

- The v5 hierarchy: Epic → Task; docs as durable pages.
- The rule that Markdoc is optional and never canonical for task contracts.

Stop and ask for human input if:

- Existing repo behavior contradicts the v5 spec.
- Existing user data could be destructively migrated.
- A domain or doc_node is needed but not present in docs-map.

## Implementation notes

- Do not create per-task state mirrors.
- Do not derive current status solely from events.
- Do not put run IDs in task frontmatter by default.
