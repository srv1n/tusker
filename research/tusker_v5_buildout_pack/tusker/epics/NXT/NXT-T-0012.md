# NXT-T-0012 · Add greenfield + migration fixtures, smoke tests, and release checklist

## Intent

Prove that v5 works both as a new install and as a migration target, then capture the release sequence so this does not turn into one giant manual cutover gamble.

## Scope

In:
- greenfield fixture
- legacy migration fixture
- close-flow smoke
- docs export smoke
- release checklist

Out:
- infinite scenario coverage
- performance tuning beyond what the new flows need to pass

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | A greenfield fixture can initialize, create epic/task/doc notes, resolve docs impact, and close a task. | End-to-end smoke output. | reference/cli, reference/validator |
| 2 | A legacy fixture can migrate and then export docs successfully. | Migration + export smoke output. | spec/migration-v5, reference/validator |
| 3 | The smoke suite covers the new primary command path. | CI job or test suite output. | reference/cli |
| 4 | A release checklist exists for cutting the first v5 release. | Checklist doc or release note artifact. | spec/migration-v5 |

## Constraints

- Favor a small number of representative fixtures over dozens of shallow ones.
- The release checklist must describe the cutover order, not just assert that tests exist.

## Escalate if

- Greenfield and migrated flows require incompatible assumptions that cannot both be represented in the same release.
- The release checklist exposes a missing migration or export step that no current task owns.

## Deliverables

- greenfield fixture
- legacy migration fixture
