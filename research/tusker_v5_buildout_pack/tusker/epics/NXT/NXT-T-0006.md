# NXT-T-0006 · Ship validator phase 1 for the v5 contract

## Intent

Put teeth behind the smallest set of rules that actually prevent drift in the v5 model.

## Scope

In:
- phase-1 hard failures
- knowledge-delta shape validation
- risk-tier section checks as warnings or errors where appropriate
- clear validator messages

Out:
- a giant wall of phase-2 failures
- overfitting the validator before real failure data exists

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | `UNKNOWN_DOC_NODE` fails hard. | Validator test with a bad node fixture. | reference/validator, reference/docs-pipeline |
| 2 | `DOCS_IMPACT_UNRESOLVED` fails hard on close. | Close-flow validator test. | reference/validator, reference/docs-pipeline |
| 3 | `MISSING_KNOWLEDGE_DELTA` fails hard at `risk >= high`. | Validator test over empty/high-risk task. | reference/validator |
| 4 | Knowledge delta rows reject tautologies and require a real before→after or added/removed shape. | Delta-shape unit tests. | reference/validator, reference/templates |

## Constraints

- Validator messages must explain exactly what is missing and why it matters.
- Do not hard-fail every possible missing section on day one just because the schema can express it.

## Escalate if

- The close path bypasses validator logic in a way that makes `DOCS_IMPACT_UNRESOLVED` unenforceable.
- A useful knowledge delta shape is being rejected as invalid because the rule is too rigid.

## Deliverables

- phase-1 validator rules
- knowledge-delta shape checker
- clear user-facing error text

## Verification plan

- Run the validator over good and bad task fixtures for each phase-1 rule.
- Confirm the close path consumes the new docs-impact rule.
