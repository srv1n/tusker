# NXT-T-0011 · Realign daemon and runtime behavior with Markdown-first truth

## Intent

Keep the daemon useful without letting it become the source of current task truth.

## Scope

In:
- status as frontmatter truth
- events as audit only
- runs as attempt state only
- generated caches rebuildable from repo state
- daemon/recovery alignment

Out:
- designing a new distributed control plane
- forcing Obsidian to depend on daemon state

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | Task status remains canonical in Markdown and visible without the daemon. | Manual inspection plus runtime tests. | reference/runtime, reference/obsidian |
| 2 | Event files record audit history but do not have to be replayed to know the current state. | Runtime/audit tests. | reference/runtime |
| 3 | Run-state files are limited to attempt/runtime details. | Run-store tests. | reference/runtime |
| 4 | The daemon can restart and continue work without creating a second current-state mirror. | Recovery test. | reference/runtime |

## Constraints

- Do not require a reconciler for Obsidian to show the current state of a task.
- Avoid inventing per-task state mirrors.

## Escalate if

- A daemon workflow assumes event-derived current state in a way that cannot be removed without larger architecture changes.
- Run recovery depends on fields that the v5 model intentionally moved out of frontmatter.

## Deliverables

- runtime-state boundary changes
- restart/recovery coverage
- generated-index rebuild path

## Verification plan

- Open a task file directly and verify the current status is trustworthy without the daemon.
- Run daemon recovery tests with interrupted runs.
- Rebuild generated caches from the markdown source of truth.
