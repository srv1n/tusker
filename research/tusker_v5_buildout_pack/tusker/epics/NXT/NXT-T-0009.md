# NXT-T-0009 · Trim the CLI surface and add compatibility aliases

## Intent

Make the v5 CLI obvious enough that humans and agents stop bouncing between overlapping verbs.

## Scope

In:
- primary command set
- help text cleanup
- legacy alias forwarding or deprecation warnings
- example updates

Out:
- removing all old commands immediately
- changing deeper runtime behavior beyond the surface that the commands expose

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | Help output foregrounds the small v5 command set. | Help-text tests or snapshots. | reference/cli |
| 2 | Legacy commands still reach the right behavior or emit a clear deprecation warning. | Alias behavior tests. | reference/cli |
| 3 | New examples in docs and skill use the trimmed surface only. | Updated example snippets. | reference/cli, reference/skill |

## Constraints

- Compatibility aliases are a migration convenience, not the public mental model.
- Prefer one obvious command over three nearly synonymous ones.

## Escalate if

- A legacy alias would hide a real semantic break instead of guiding the operator through it.
- Help text becomes more verbose after the trim.

## Deliverables

- trimmed help output
- alias/deprecation behavior
- updated examples

## Verification plan

- Run help snapshots and alias tests.
- Check that README and SKILL examples no longer depend on legacy verbs.
