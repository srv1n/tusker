# ARC-T-0005 · Move durable docs out of epic folders while keeping type doc

## Outcome

Durable documentation pages live under `tusker/docs/` or configured repo docs paths, not as D-notes inside epic folders.

## Acceptance contract

| AC | What must be true | Verification | Deliverables | Doc nodes |
|---:|---|---|---|---|
| 1 | `type: doc` remains valid for durable pages, but docs no longer use task lifecycle fields. | doc schema fixture | fixture output | tusker/docs-system |
| 2 | Epic folders contain epics and tasks, not durable docs by default. | sample vault tree review | tree output | tusker/docs-system |
| 3 | docs-map maps every doc_node to a concrete doc path. | docs-map validator | validator output | tusker/docs-system |

## Constraints and stop conditions

The agent must preserve:

- Plain Markdown readability in Obsidian.
- Current task status in task frontmatter.
- Generated indexes as rebuildable cache.
- Runtime/audit data outside human-facing frontmatter.

The agent must not change:

- The v5 hierarchy: Epic → Task; docs as durable pages.
- The rule that Markdoc is optional and never canonical for task contracts.

Stop and ask for human input if:

- Existing repo behavior contradicts the v5 spec.
- Existing user data could be destructively migrated.
- A domain or doc_node is needed but not present in docs-map.

## Implementation notes

- Do not delete existing D-note content during migration.
- Do not make docs a work item lifecycle object.
- Doc update work uses task(kind: docs).
