# NXT-T-0008 · Keep docs export and publication alive under the new doc-page model

## Intent

Preserve the current docs publication value—navigation, content manifests, canon manifests, removed routes, and llms text—while moving the source model from epic D-notes to global docs pages.

## Scope

In:
- source discovery from `tusker/docs/`
- retained publish metadata on doc pages and/or docs-map nodes
- manifest/export compatibility
- redirect/removed-route handling

Out:
- building a brand-new docs site from scratch
- throwing away the current publication outputs because the source model changed

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | The docs exporter can read v5 doc pages under `tusker/docs/`. | Exporter integration test on v5 fixture. | reference/docs-pipeline |
| 2 | Navigation, content manifest, canon manifest, and llms outputs still build. | Fixture output diff or snapshots. | reference/docs-pipeline |
| 3 | Publish metadata required by legacy outputs is preserved after migration. | Migrated doc-page fixture with export pass. | spec/migration-v5, reference/docs-pipeline |
| 4 | Removed-route and redirect handling still works when paths change. | Routes-removed or redirect test. | reference/docs-pipeline |

## Constraints

- Do not break canon-manifest or llms generation while chasing a cleaner source model.
- Keep the source of truth repo-local and inspectable.

## Escalate if

- A required current output depends on metadata that cannot cleanly live on doc pages or node config.
- The exporter cannot support mixed legacy+v5 inputs during the transition window.

## Deliverables

- updated docs source discovery
- passing export/manifests
- route/redirect compatibility coverage

## Verification plan
