# NXT-T-0004 · Build the explicit legacy-to-v5 migration engine

## Intent

Provide a deterministic migration command that converts a real legacy Tusker repo into the v5 layout without silent loss of state, metadata, or navigability.

## Scope

In:
- dry-run and apply modes
- story -> task conversion
- bug -> task kind conversion
- epic path rename
- D-note -> docs page conversion
- ID collision handling
- wikilink and reference rewrites
- alias map and migration report generation

Out:
- supporting every arbitrary third-party customization without review
- hiding ambiguous migration cases from the operator

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | `tusker migrate v5 --dry-run` reports every planned file, ID, and field rewrite. | Dry-run report artifact over a legacy fixture. | spec/migration-v5 |
| 2 | `--apply` converts legacy stories and bugs into the task namespace with deterministic collision handling. | Post-migration fixture tree and alias map. | spec/migration-v5, reference/runtime |
| 3 | Legacy D-note publication metadata is preserved when docs pages move under `tusker/docs/`. | Migrated doc frontmatter plus docs-map synthesis output. | spec/migration-v5, reference/docs-pipeline |
| 4 | In-repo links and wikilinks are rewritten or aliased so navigation does not silently break. | Link-rewrite test over sample markdown set. | spec/migration-v5 |
| 5 | Running the migration twice is safe. | Idempotence test. | spec/migration-v5 |

## Constraints

- No silent data loss. If a mapping is ambiguous, fail and explain.
- Write a migration report and alias map before mutating the repo on apply.
- Preserve publish metadata needed by canon-manifest, llms text, and route export.

## Escalate if

- A legacy fixture exposes a publish metadata case that cannot be represented in the chosen v5 doc model.
- The link-rewrite strategy cannot preserve both raw Markdown readability and deterministic migration.

## Deliverables

- migration command
- dry-run report
- alias map
- legacy fixture and idempotence tests

## Verification plan

- Run dry-run on a representative legacy fixture and inspect the report.
- Run apply and diff the resulting tree.
- Run apply again and confirm no further changes.
- Run docs export on the migrated fixture and confirm outputs still build.

## Rollback

- Dry-run must write the exact apply plan before any mutation is allowed.
- Apply mode must write a migration snapshot/report so the operator can revert in git immediately if needed.
- Do not delete old files until rewritten files and alias map are written successfully.
