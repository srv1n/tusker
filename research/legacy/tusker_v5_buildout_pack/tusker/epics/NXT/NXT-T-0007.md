# NXT-T-0007 · Add the docs-impact hook, waiver flow, and close gate

## Intent

Turn documentation freshness from an aspiration into a close-time workflow with explicit dry-run, apply, and waiver behavior.

## Scope

In:
- docs check
- docs apply
- docs waive
- close-time gating
- no-op verification path

Out:
- full periodic sweeper automation
- background async orchestration outside the normal CLI flow

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | `tusker docs check <id>` can inspect a task and return a patch proposal, no-op verification, or waiver-required result. | Command output or fixture-based integration test. | reference/docs-pipeline, reference/cli |
| 2 | `tusker docs apply <id>` can persist the accepted docs outcome. | Apply-flow test. | reference/docs-pipeline |
| 3 | `tusker docs waive <id> <node>` records an explicit waiver with reason and actor. | Waiver fixture or event output. | reference/docs-pipeline, reference/runtime |
| 4 | `tusker close <id>` fails when docs impact remains unresolved. | Close integration test. | reference/docs-pipeline, reference/cli |

## Constraints

- Be honest that `docs check` is an agentic run, not a deterministic linter.
- A no-op docs result must still be recorded, not left implicit.

## Escalate if

- The close command cannot distinguish unresolved docs impact from waived/no-op state.
- The waiver model is becoming a silent bypass instead of an explicit decision.

## Deliverables

- docs check/apply/waive flow
- close gate integration
- waiver recording format

## Verification plan

- Run docs check on a task with doc nodes and confirm one of the three explicit outcomes occurs.
- Run docs waive and confirm the close command now succeeds for that node.
- Run close without resolving docs and confirm failure.
