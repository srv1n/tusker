# NXT-T-0005 · Add docs-map routing and controlled vocabulary support

## Intent

Replace freeform tags and ad hoc doc references with a controlled `domains + doc_nodes` routing model backed by `_config/docs-map.yaml`.

## Scope

In:
- load and validate docs-map
- controlled domain vocabulary
- exact node-to-page routing
- reindex/catalog support for node relationships

Out:
- running the docs impact hook itself
- rewriting publish manifests

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | Tasks can declare broad `domains` and exact `doc_nodes` from a repo-owned map. | Schema and reindex tests. | reference/docs-pipeline, reference/templates |
| 2 | Unknown domains or doc nodes fail validation. | Hard-fail validator tests. | reference/docs-pipeline, reference/validator |
| 3 | Docs pages and task references can be resolved through the same node catalog. | Catalog build or lookup test. | reference/docs-pipeline |
| 4 | The docs map is readable enough for humans to maintain directly in the repo. | Manual review of the example map plus fixture test. | reference/docs-pipeline, reference/obsidian |

## Constraints

- Do not reintroduce freeform tag soup as the automation mechanism.
- Keep the model to two layers. Do not invent a third taxonomy level unless the code proves it necessary.

## Escalate if

- A required current publication concept cannot be represented cleanly as a doc node or page mapping.
- The map format becomes so complex that humans stop editing it.

## Deliverables

- docs-map schema and loader
- controlled vocab validation
- node resolution tests

## Verification plan

- Load a valid docs-map fixture and resolve task references.
- Run validation with an unknown domain and unknown node fixture and confirm hard failure.
- Build a docs catalog/index entry from the map.
