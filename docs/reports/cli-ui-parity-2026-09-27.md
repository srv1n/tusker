# Serve UI and CLI action parity — 2026-09-27

This is a source-only audit. “CLI” means an executable command, not a command string displayed for copying. UI labels are grouped where several buttons use one endpoint. Route placeholders are IDs. A handler-only route may still call the same lower-level Go function as a CLI command. The browser obtains a configured Serve operator identity through `/api/capability`; it does not get to choose an arbitrary actor ([`internal/serve/ui/src/lib/api.ts:93`](../../internal/serve/ui/src/lib/api.ts), [`cmd/tusker/serve_actions.go:623`](../../cmd/tusker/serve_actions.go)).

## CLI actions without a UI action

Owner-relevant: `wave create/add/remove/outcome/brief/review` (authoring); `new task`, `task update` (full task contract, including pins); `run` (queue exact target); `work start/submit/review`, `finish`, `proof`, `proposal`, `closeout`, `verify`, `departure hold/resume` (lifecycle and acceptance); `projects add/list/enable/disable/rebind/remove/prune`; `models show/catalog/set/reset/profile-*`; `docs adopt`; and `list/search/show/doctor` for inspection. The UI covers selected start, status, route, gate, close, land, model, and project controls, but not the full authoring/review/acceptance flow ([`cli.go:973`](../../cmd/tusker/cli.go), [`cli.go:985`](../../cmd/tusker/cli.go), [`cli.go:1012`](../../cmd/tusker/cli.go), [`cli.go:1685`](../../cmd/tusker/cli.go)). A UI action for `projects enable/disable` exists; its exact distinction from visibility deserves a focused contract pass.

Internal or specialist plumbing: `runs claim/start/heartbeat/submit/fail/reclaim/release`, `worker`, `automation dispatch/collect-external/advance-external`, `mcp serve`, `acp`, migration/reindex/gc, setup/install/sync, and diagnostic demo tools. Exposing these as clickable owner controls is not required for action parity; they are runtime or maintenance mechanisms ([`cli.go:989`](../../cmd/tusker/cli.go), [`cli.go:1047`](../../cmd/tusker/cli.go)).

## Friction

- `wave start` requires `--mode background` and rejects every other value, though no other mode exists ([`direct_wave_authority.go:1174`](../../cmd/tusker/direct_wave_authority.go), [`cli.go:1178`](../../cmd/tusker/cli.go)). `run` already injects the value ([`direct_wave_authority.go:1208`](../../cmd/tusker/direct_wave_authority.go)).
- `wave list` and `runs list` are absent from command dispatch/help. The UI has both lists through `GET /api/waves?view=list` and `GET /api/runs`; CLI users must know `tusker list`, `wave show`, or `runs inspect` alternatives ([`cli.go:995`](../../cmd/tusker/cli.go), [`cli.go:1022`](../../cmd/tusker/cli.go), [`serve_command.go:466`](../../cmd/tusker/serve_command.go)).
- `task update --if-revision` requires a state hash the caller first retrieves; model set/profile writes require the model revision. The UI read supplies each hash before write ([`cli.go:293`](../../cmd/tusker/cli.go), [`model_levels.go:314`](../../cmd/tusker/model_levels.go), [`TaskScreens.tsx:117`](../../internal/serve/ui/src/features/product/TaskScreens.tsx)). Keep CAS but offer a CLI read/update workflow that does not force manual extraction.
- `models show` resolves a vault before reading global data, so it fails outside a repo even for global profile definitions ([`model_levels.go:246`](../../cmd/tusker/model_levels.go)).
- Serve project icon, docgraph save, and approvals have no equivalent CLI entry; project refresh and run recovery have similar-looking CLI commands with different semantics ([`serve_actions.go:1027`](../../cmd/tusker/serve_actions.go), [`serve_docgraph.go:362`](../../cmd/tusker/serve_docgraph.go), [`agent_access_approval.go:1103`](../../cmd/tusker/agent_access_approval.go)).
- UI currently exposes daemon Start; this is a resident-daemon control request, while CLI `daemon run` launches a process. Preserve that distinction ([`ProjectOps.tsx:344`](../../internal/serve/ui/src/features/ops/ProjectOps.tsx), [`serve_actions.go:1559`](../../cmd/tusker/serve_actions.go)).

## 10-line summary

1. Serve covers direct wave/task start and most delivery controls.
2. CLI owns much more authoring, review, and acceptance work than the UI.
3. Wave/task background starts accept `human:` in agent sessions.
4. Task updates reject that same impersonation through `resolveV7Actor`.
5. Serve operator actions reject configured human identities in agent sessions.
6. Icon upload, doc save, and access approval lack direct CLI verbs.
7. Execution UI writes use fixed `serve:operator` attribution.
8. `wave start --mode background` is a redundant required flag.
9. `wave list`, `runs list`, and global `models show` need CLI cleanup.
10. Serialize `cli.go` slices; preserve CAS and explicit human gates.
