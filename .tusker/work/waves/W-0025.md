# W-0025 · Replace delivery plans with direct task and wave authoring

## Intended result

Complete direct task and wave authoring with explicit work tiers, one-action Start, automatic wave progression, visible pause/resume and external architect routing; remove the delivery-plan implementation completely.

## Members

1. [FLW-T-0043](../tasks/FLW-T-0043.md) — Create complete tasks and atomic waves directly through the CLI
2. [FLW-T-0044](../tasks/FLW-T-0044.md) — Migrate plan identities and proof onto durable tasks and waves
3. [FLW-T-0045](../tasks/FLW-T-0045.md) — Make wave records the sole review and execution authority
4. [FLW-T-0046](../tasks/FLW-T-0046.md) — Replace plan discovery and Start screens with wave review
5. [FLW-T-0047](../tasks/FLW-T-0047.md) — Register external architects and route by actual connector capability
6. [FLW-T-0048](../tasks/FLW-T-0048.md) — Ship lean CLI authoring with complete technical worker packets
7. [FLW-T-0049](../tasks/FLW-T-0049.md) — Delete delivery-plan implementation and qualify migrated task-wave flow
8. [FLW-T-0050](../tasks/FLW-T-0050.md) — Continue authorized waves automatically with reliable pause and resume

## Ordered work

### Stage 1

- [FLW-T-0043](../tasks/FLW-T-0043.md) — Light, Standard and Demanding tasks with full body/checks can be created without spec, epic, priority, size, risk or factory/context metadata; invalid supplied references fail.
- [FLW-T-0047](../tasks/FLW-T-0047.md) — An external architect without a task attempt can register with exact provider/session/connection identity while unauthorized or cross-project attachment is rejected.
### Stage 2

- [FLW-T-0044](../tasks/FLW-T-0044.md) — Held/progressed/strict-proof/cross-wave fixtures preserve task IDs, relationships, gate owners and evidence meaning after conversion. (after authoring)
### Stage 3

- [FLW-T-0045](../tasks/FLW-T-0045.md) — Review/start reads wave/tasks only and succeeds for eligible configured fixture work without plan files. (after migration)
### Stage 4

- [FLW-T-0050](../tasks/FLW-T-0050.md) — Starting an authorized wave runs eligible tasks and subsequent dependency stages automatically; pause and restart preserve scope and ownership without another Play click. (after authority)
- [FLW-T-0048](../tasks/FLW-T-0048.md) — Fresh direct authoring needs no administrative fields and explicit work tier survives packet/capsule output. (after authority)
### Stage 5

- [FLW-T-0046](../tasks/FLW-T-0046.md) — Wave review has no plan picker/path entry and reads current wave/task facts through the published API. (after authority, autonomous)
### Stage 6

- [FLW-T-0049](../tasks/FLW-T-0049.md) — Deletion scan finds no active delivery-plan command, endpoint, parser or file dependency and no dormant backup; every old artifact has a verified disposition. (after experience, contacts, guidance)
