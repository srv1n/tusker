# W-0023 · Make ticket authoring and Play one complete product flow

## What this wave delivers

An architect writes complete tickets and classifies them as Tier 1/2/3 or named human responsibilities. Tusker resolves configured worker/reviewer profiles, records the real architect and executor, and shows exactly who will run before Play. Batches arrive as readable waves; standalone tickets remain supported. The final task proves the full product journey.

## Start with the audit, not a blank implementation

[Read the findings and implementation handoff](../../../docs/reports/task-authoring/audit-and-handoff.md). It maps ten observed gaps to existing source authorities and ticket owners. [Recovered partial patches](../../../docs/reports/task-authoring/handoff/README.md) preserve already-written routing, metadata and guidance work. Executors should inspect and continue that work; it is not accepted completion.

Dependencies follow this order because they share backend contracts. Review is Demanding; configured tier mappings select the actual harness/model, not prose recommendations.
