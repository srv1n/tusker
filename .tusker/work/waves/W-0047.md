# W-0047 · Docs integrity: touch, dead references, staleness, supersede, describes

## Intended result

Documentation drift is caught by standalone checks that do not depend on a task closing; stale and dangling docs are flagged; supersede is one command; generated and operator skills agree that docs/system is canon.

## Shared context

The doc graph lives in `internal/docgraph` (`docgraph.go`, `freshness.go`,
`resolver.go`, `docmap.go`). The CLI lives in `cmd/tusker/docs_cmd.go`
(subcommand table at the top, `docsStatusCmd`, `docsVerifyCmd`,
`v7DocTouchCheck`, `v7DocsTouchRule`), `cmd/tusker/docs_check_cmd.go`
(`docsCheckCmd`) and `cmd/tusker/v7_document_write.go` /
`v7_document_transaction.go` (document writes). Lifecycle values come from
`docgraph.LifecycleValues`; `code_conformance` accepts unverified, matches,
drift and not_applicable. `docs verify` already stamps
`last_verified: "YYYY-MM-DD @ <commit>"`; `DocsFreshness` already counts
commits touching `describes` after that commit.
Tasks that share a file are chained with hard dependencies so no two
members edit the same file concurrently. Each member updates
`docs/system/cli.md` or `docs/system/knowledge-and-feedback.md` only for
its own command or rule, in its own section.
