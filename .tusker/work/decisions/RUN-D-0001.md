# RUN-D-0001 · Sequential-first workspaces: keep worktrees, make merging trivial

## Decision

(Revised by owner, 2026-07-06.) Runs are sequential-first and execute **in
place at the repo root** by default: the runner's cwd is the repository
folder itself, so every session — daemon-dispatched or manually started —
lives in one folder and shows up together in local session browsers (the
Codex desktop app, `claude` resume lists). There is no merge stage at all in
this mode: the run commits on the current branch (or a task branch) and
sequential execution makes conflicts structurally impossible. Guard rail:
in-place dispatch requires a clean working tree; a dirty checkout blocks
dispatch with a legible error instead of interleaving agent and human edits.

Worktree isolation becomes the **opt-in** mode, engaged automatically only
when concurrency > 1 requires it (or a task explicitly demands isolation).
For those runs, landing is automatic when the result fast-forwards or
rebases cleanly onto HEAD; only a real textual conflict escalates to the
needs-me queue, never a silent overwrite.

## Context

Worktrees look like multi-agent machinery, and the obvious solo simplification
is to run agents directly in the main checkout. That is wrong for three
reasons. First, the operator's checkout is routinely dirty (uncommitted vault
edits, in-progress hand edits); an in-place agent run would interleave its
changes with the operator's and make attribution impossible. Second, a failed
or interrupted attempt in a worktree is discarded by deleting the worktree —
in-place it means untangling a half-finished diff from the working copy.
Third, merge pain is a function of temporal overlap, not of worktrees:
sequential runs branched from HEAD fast-forward back by construction. The
cost we actually avoid is concurrent-overlap conflict resolution, and we avoid
it with the concurrency cap and file-ownership partitioning of tasks, not by
giving up isolation.

## Consequences

- `workspace.strategy: in_place` is the default; runner cwd is the repo
  root, and one folder holds all threads (Tusker-dispatched and manual).
- In-place dispatch refuses on a dirty working tree; the operator commits or
  stashes first. This replaces worktree isolation as the protection against
  interleaved edits.
- Worktrees engage automatically when concurrent runs demand isolation;
  landing is ff/clean-rebase or escalate-on-conflict, with the two branch
  heads named in the needs-me queue.
- Parallelism stays bounded (max_active_runs 2) and tasks that share files
  are serialized at planning time; the merge step is expected to be a no-op.
- The serve UI shows landed/unlanded state per run so unmerged work is never
  invisible.
- RUN-T-0004 A5 implements the strategy switch and removes the hardcoded
  state-root workspace path.
