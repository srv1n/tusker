# ORC-T-0035 · Make DAG planning the canonical installed-skill default

## Intent

Canonical and generated agent guidance consistently turns multi-task requirements into held delivery DAGs and limits direct task creation to documented singleton exceptions.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The operator skill uses normative must-language for multi-task factory planning, final ID ownership, dry-run/import, inertness, review, and fingerprinted Start while preserving read-only and singleton routes. | See mapped verification. |
| A2 | Formal intake, quick mode, command references, resources, system documentation, and repository workflow snippets use one decision table and contain no competing manual multi-task creation path. | See mapped verification. |
| A3 | Guidance tells agents to ask only material product questions, derive factory mechanics from repository context, and never make the user choose task IDs, epic acronyms, dependency syntax, runners, workspaces, or proof modes. | See mapped verification. |
| A4 | Guidance handles missing tests, ambiguity, direct implementation, unattended requests, one-node DAGs, stable re-planning, stale authorization, and unrelated existing work without widening authority. | See mapped verification. |
| A5 | A guidance audit fails when canonical or generated instructions omit or contradict the factory-intake contract and reports the exact source file and repair. | See mapped verification. |
