# RUN-T-0044 · Dispatch: lease-guard the post-spawn/reconcile run-row writes (close the residual spawn->final-upsert stop-clobber window)

## Intent

Residual LOW finding from the adversarial review of RUN-T-0043 (dispatch atomic CAS). RUN-T-0043
closed the pre-dispatch stop-clobber window via `UpsertRunPreservingLease`, but the POST-spawn
final run-row persistence — `upsertRunWithStream(current, updated)` (`cmd/tusker/daemon.go` ~526 /
~626) and `reconcileRun`'s run write — remain plain, unguarded upserts. A stop (interrupt/park)
landing in the spawn→final-upsert window is clobbered back to `running`.

Impact is LOW: the process genuinely spawned, the daemon owns the lease, and the interrupt path +
next-poll `reconcileRun` tear it down; no double-dispatch (the row is `running`, which the claim
excludes). These writes cannot simply reuse the lease-preserving upsert, because after a successful
claim they must legitimately WRITE the new `claimed`/`running` lease (or a `scheduleRetry` result on
error) — so the fix requires branching on whether the lease is still held (write new lease) versus a
concurrent stop having taken it (back off / do not clobber).

Also fold in the exotic land-lane edge (review Finding 3, LOW): `v7DefaultBranchWorktree`
(`cmd/tusker/v7_land_cmd.go`) returns only the first worktree holding the default branch, so a
`git worktree add --force` second copy of the default branch keeps a stale HEAD/index after a land.
