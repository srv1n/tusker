# RUN-T-0030 · Kill clean-exit continuation churn: max_turns must reach the runner; mid-task exits must classify honestly

## Intent

Observed live during RUN-T-0017 trial run 2 on real multi-turn codex work (rows FBK-T-0005 and RUN-T-0002): attempts cycled roughly every 15 seconds with `runner exited cleanly while tracker state remained active; queued continuation retry`, even after `.tusker/WORKFLOW.md` set `codex.max_turns: 30` and `runners.codex_app_server.max_turns: 30`. Park-at-cap (RUN-T-0023) now bounds the damage — the loop terminates at the cap — but each churn cycle still burns a full attempt on ~15 seconds of no work, so real multi-turn tasks exhaust their cap without progressing.

This is an audit-then-fix task. Two questions, in order:

1. **Does `max_turns` actually reach the codex app-server session?** Trace the config value from WORKFLOW.md parse through runner dispatch to the JSON-RPC session parameters. A 15-second attempt on a task that needs many turns smells like the session is still running with an effective turn limit of 1, or with no task input at all.
2. **Why does a mid-task exit classify as a clean completion?** A runner that exits with the tracker state still active has NOT completed cleanly — it stopped early. Distinguish at minimum: (a) genuine completion (task moved to review/done), (b) declined dispatch (plan gate said no — expected, no retry), (c) early exit mid-work (turn limit, session error, model stop). Class (c) must not be labeled "exited cleanly" and must count differently from (a) in continuation decisions — it is the no-progress signal that park-at-cap exists for.

Semantics after the fix:

1. `max_turns` from WORKFLOW.md provably reaches the runner session (log the effective value at dispatch).
2. Continuation decisions use exit classification, not just process exit code. An early exit mid-work either continues with justification recorded or parks — never loops silently.
3. A real multi-turn codex task on this machine runs attempts measured in minutes of work, not 15-second cycles.
