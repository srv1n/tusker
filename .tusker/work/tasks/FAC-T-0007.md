# FAC-T-0007 · Write down how often we build and test at each stage

## Intent

We need one written page that says, in plain terms, how often we build and test
at each stage of the work: a light check on each change that touches only what
it touched, one combined build-and-test when a batch of work lands together, and
the full suite run overnight on the heavy machine. Today this rhythm lives in
people's heads and in scattered settings, so different workers follow different
rules and the cost creeps up.

This task writes the rhythm down as a durable reference page, so every worker
and reviewer follows the same rule and later work has one place to point at.

Done looks like: a canonical reference page exists that names the three stages,
says what each one runs and where it runs, and is linked from the pieces of work
that put it into practice.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A canonical reference page names the three stages and what each one runs. | Manual proof (page review) |
| A2 | The page says where each stage runs (local versus the heavy overnight machine) and describes the parallel-work pattern it assumes. | Manual proof (page review) |
| A3 | The page carries the standard "read when / skip when" heading and is linked from the work that enforces it. | Inline verification |

## Non-goals

- No code changes; this is a written reference only.
- No new numbers invented for disk floors or caps; those are measured in a separate piece of work.
- No versioned copies; the page is updated in place, per the spec's durable-artifact principle.
- No coverage of Xcode/Mac specifics beyond noting that they stay local.
