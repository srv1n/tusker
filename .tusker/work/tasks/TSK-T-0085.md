## Intent
processArchitectWaveReports reports "stalled" only when a question is pending (agent_coordination.go ~229), contradicting locked boundary 5 ("stalled-wave detection covers failed/blocked work and dependency deadlock even without a question"). It also finds the architect only from authored task fields, so a wave architect registered with `execution register --contact-role architect --wave` never receives reports. Fix detection and recipient resolution; deliver the report through the mailbox only.

Hard dependency on `ask-wait-delivery` only because both edit agent_coordination.go.

## Verified seams
- `processArchitectWaveReports` (~180-257): allDone => completed; stalled requires `len(pending) > 0`; report digest over member:state evidence => `RecordArchitectContinuation` + `PutAgentMessage` kind wave_result keyed by trigger.
- `waveArchitectAddress` (~259) — authored contacts only. `AgentContacts(project, waveID)` holds runtime wave contacts.
- `armed_wave.go buildArmedWaveSnapshot` member states: runnable, running, dependency-waiting, machine-parked, human-blocked, review, landed.
- RunStatus NextRetryAt / UpdatedAt for retry-pending and progress facts.
- `ApplyArchitectContinuation` is operator-invoked only; do not call it.

## Implementation contract
Locked:
- Stalled = wave armed, not all members done, no member running, runnable or in review, no member with a future NextRetryAt, at least one member machine-parked or human-blocked (directly or by hard-dependency closure), and no member run updated within the stall window. Pending questions are included when present but are not required.
- Stall window: reuse an existing configured value if one fits (search workflow/automation config); otherwise a single constant of 10 minutes with a `ponytail:` comment naming the upgrade path. Record which in the result.
- Report body adds blockers as `member:state:reason` in stable member order; digest covers outcome, member states/reasons, pending question IDs — never timestamps — so unchanged state creates no second report and a material change creates a new one.
- Architect = authored task contacts (existing) else the wave's registered architect contact (current generation); conflicting architects => no report and one daemon log line (existing behaviour for conflicts).
- Completed report unchanged in trigger semantics. Neither report creates, proposes or starts a wave.
Proposed: none beyond the window source.

## Failure and edge cases
- Four done, one machine-parked, zero questions, quiet past window => exactly one stalled report.
- Same state on the next 100 polls => no new message or continuation row.
- Parked member's reason changes => one new report.
- Member with retry scheduled in the future, or one member still running => no stall.
- Member waiting on a yield question (ask-wait-delivery parking) with nothing else runnable => stalled report that lists the pending question.
- Wave paused/disarmed => no stall report (authorization not armed).
- No architect anywhere => no report; forbidden: sending to the operator or inventing an address.
