# LIF-T-0012 · Add discard-task lifecycle and dependency-safe removal from active views

## Intent

Let an operator discard work they no longer intend to execute without deleting
the task record or silently weakening dependent task contracts. Discarded tasks
must leave active work surfaces, retire live execution, preserve audit history,
and give operators an explicit resolution path for downstream dependents.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | CLI and serve API expose an explicit discard operation that records a required reason, transitions the task to cancelled, retires runtime execution, and obsoletes its open gates. | Focused Go tests |
| A2 | Discard preflight reports downstream dependents and refuses the mutation until each is explicitly detached or cancelled; no dependency edge is removed silently. | Dependency-focused Go tests |
| A3 | The task UI confirms the blast radius, performs discard through the dedicated API, and active work views hide cancelled/superseded tasks by default while allowing an explicit discarded-history filter. | UI unit tests |
| A4 | Operator skill and lifecycle guidance define discard as cancellation/tombstoning, not physical deletion, including dependency and history rules. | Validation and skill doctor |

## Non-goals

- No routine physical deletion of task, attempt, evidence, event, or run history.
- No implicit cascade cancellation of downstream tasks.
- No reuse of discarded task IDs.
