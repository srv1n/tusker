# RUN-T-0013 · Runner wrapper: detach runners from daemon lifetime

## Intent

Binding design: `docs/design/prior-art-playbook.md` §3 item 8. Observed 2026-07-06: SIGTERM to the daemon took every `codex app-server` child with it, because the daemon owns the JSON-RPC stdio pipe — the D2 "runners survive daemon death" guarantee currently holds for shell runners only. Donors: opencode spawns its server `detached, stdio ignored, unref'd`; OpenHands routes runner output to log files explicitly "to avoid pipe-buffer deadlocks"; claude-squad gets the same property from tmux (rejected as a dependency — single-binary philosophy).

Build a thin runner-wrapper: a `tusker`-binary subcommand (no new executable) that (1) is spawned by the daemon detached — own process group/setsid, stdin from /dev/null, stdout/stderr to `.tusker/scratch/<TASK-ID>/` log files, no inherited daemon fds; (2) itself owns the runner child (codex app-server JSON-RPC over the wrapper's pipes, claude stream-json, shell); (3) writes all runner events durably to the runtime store/event sink and performs the RUN-T-0011 lease heartbeat (owner-scoped, generation-fenced) — so the wrapper, not the daemon, is the lease owner; (4) terminates itself when the heartbeat stop-signal fires or its lease is fenced. Daemon death then costs nothing: wrappers keep running, keep heartbeating the store directly, and the restarted daemon adopts them via RUN-T-0011's verified-alive adoption. Deliberate daemon shutdown gains a flag (`tusker daemon stop --drain` waits for wrappers to finish; default stop leaves them running to be adopted later).

## Non-goals

- No tmux/launchd involvement; the wrapper is plain process mechanics inside the existing binary.
- No change to runner protocols (codex JSON-RPC, claude stream-json semantics unchanged — only who owns the pipe).
- No remote runners.
