# TRC-T-0004 · Runtime journal spine for lease, supervisor, and gate transitions

## Intent

Implement the first step from TRC-D-0001: an append-only runtime journal spine
for run-control facts that currently disappear into mutable `daemon.db` rows or
per-attempt JSONL exhaust.

The journal must record lease transitions, attempt lifecycle edges, supervisor
decisions, runner approval/permission requests and decisions, durable
gate-suspension/resume points, terminal classifications, and projection
offsets. It should live under the daemon state root, scoped by project and
record, for example:

```text
<state-root>/runs/<project_key>/<record_id>/runtime.events.jsonl
```

The implementation may use a SQLite `runtime_events` table first if that is the
smallest safe append-only primitive, but the contract is log-primary ordering:
events are appended before/with projection updates, and projection rows must be
rebuildable from those events.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A versioned runtime event schema and append API exists for lease, attempt, supervisor-decision, approval/gate, and terminal-classification events; events have monotonic ordering per run and include project, record, work revision, lease generation, attempt id when known, producer, timestamp, type, and typed payload. | Inline verification |
| A2 | Dispatch/reconcile writes journal events for lease claim/running/heartbeat/retry/release or reclaim, attempt start/finish, supervisor decisions, and terminal classification before or atomically with the corresponding `daemon.db` projection update. | Inline verification |
| A3 | Runner approval and permission requests are represented as durable journal facts; a pending approval/gate suspension can be listed after daemon restart without the original runner process being alive. | Inline verification |
| A4 | Existing `runs inspect`, review packet, and serve/read APIs continue to read projections without user-facing format churn. | Inline verification |

## Non-goals

- No full `daemon.db` rebuild command yet; TRC-T-0005 owns that.
- No attempt boundary trace/replay schema changes; TRC-T-0001/TRC-T-0002 own that layer.
- No multi-daemon or distributed consensus design.
