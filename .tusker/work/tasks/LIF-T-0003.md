# LIF-T-0003 · Add atomic run claims and normalized execution lifecycle commands

## Intent

Create one atomic run-ownership service and CLI contract for daemon dispatch, Tusker CLI pickup, and external Codex/Claude sessions. A task remains durably ready/rework while a live claim projects it as in progress. All terminal paths produce a normalized outcome instead of relying on runner-specific logs.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A canonical CLI/API supports claim, start/session attach, heartbeat, submit-for-review, fail, interrupt, inspect, and reclaim using stable machine-readable JSON. | focused_test |
| A2 | Claim is transactional: concurrent claims for one task produce exactly one owner; losers receive the owning run id, actor, runner, workspace, and freshness without launching work. | focused_test |
| A3 | Claims validate task dispatchability, runner identity, registered project, workspace policy, and project concurrency through the same planning rules used by automation. | focused_test |
| A4 | Submit requires a normalized success outcome, required deliverable summary, and acceptance-mapped verification; process exit zero alone cannot request review. | focused_test |
| A5 | Fail and interrupt preserve attempt history, release live ownership according to retry policy, and do not mutate the durable task to a legacy `active` status. | focused_test |
| A6 | Existing run/lease consumers remain compatible or receive an explicit migration with schema tests. | broad_test |

## Non-goals

- Do not add a durable `active`, `claimed`, or `running` task status.
- Do not make runner transcript files the ownership source of truth.
- Do not add human approval gates.
