## Intent
Liveness decisions are wrong in both directions. (1) When the wrapper (group leader) dies but its child `codex`/`claude` is still running in the same process group, reconcile sees a leader identity mismatch and schedules a retry — a second worker then edits the same worktree. (2) `runProcessGroupAlive` treats any existing process group with the recorded PGID as ours; after a reboot or PID reuse an unrelated group keeps Stop refusing with manual_cleanup_required forever and `reconcilePersistedStopIntent` suppresses retries forever. (3) Two concurrent Stop clicks write the stop intent without compare-and-swap. (4) The start-fresh guard recognises a fresh request by a `LastError` string prefix, and a `LatestSession` fallback can revive the rejected native session.

## Verified seams
- `runProcessGroupAlive` (daemon.go ~624): `processIdentityMatches(run) || processGroupExists(run.ProcessPGID)`. `processGroupExists` (~616) is `kill(-pgid,0)`. `processIdentityMatches` (~6758) compares PID + recorded start time.
- Orphan path: daemon.go ~3142-3170 — when `run.ProcessPID > 0` and no status file, builds "runner process no longer matches recorded identity ..." and cancels/retries without checking the group.
- adaptive_reconcile.go ~376 `deadReservationRevision`: `processExists(pid) || processGroupExists(pgid)` treated as alive.
- `reconcilePersistedStopIntent` (daemon.go ~2055).
- Stop: `handleRunStopControl` (serve_actions.go ~245) → `saveRunSessionControlIntent` (run_session_controls.go ~64) with no expected-prior check.
- Start fresh guard: daemon.go ~5195-5245 checks `strings.HasPrefix(run.LastError, outcomeUnknownContextRecoveryReasonPrefix|runSessionControlFreshReasonPrefix)` then falls back to `d.store.LatestSession(...)`.

## Implementation contract
Locked:
- One liveness classifier used by reconcile, Stop preflight, stop-intent reconciliation and dead-reservation repair: `alive` (leader identity matches), `orphaned` (group exists, no process with pid==PGID, and host boot time is before the recorded process start), `gone` (group absent, or boot time is after the recorded start), `foreign` (a process with pid==PGID exists whose start identity does not match — POSIX never reuses a PID as a new process while a process group with that ID still exists, so a mismatched leader means the old group is gone).
- `orphaned` → never schedule a retry; kill the group under the existing Stop/containment rules only when a stop intent exists, otherwise surface Lost-with-live-children for the operator. `foreign`/`gone` → Stop settles without signalling anything; stop intent reconciles; retries are not suppressed forever.
- Stop intent writes are CAS on the prior intent revision; a concurrent second Stop returns the existing pending intent (idempotent), never a second write or error spam.
- Start fresh is recorded as a typed intent field (reuse `runSessionControlIntent`), not recognised from `LastError` text; when fresh/context recovery was requested, the `LatestSession` fallback is skipped.
- Keep run-controls-api's shared preflight functions as the single source of Stop/start-fresh availability; update them, do not fork them.
Proposed: boot time from `sysctl kern.boottime` on darwin and `/proc/stat btime` on linux, behind one helper; unknown boot time ⇒ treat as `orphaned` (conservative: no retry).

## Failure and edge cases
- Fixture: wrapper process killed, child `sleep` in the same group keeps running → reconcile does not create a new attempt; run shows the live-children state. Forbidden: `attempt_spawned` for a second attempt.
- Recorded PGID points at a group whose leader is a different, newer process → Stop settles, no signal sent to that group, retry not suppressed.
- Recorded start time before boot time → `gone`.
- Two Stop POSTs in parallel → exactly one intent row; both responses report the same pending intent.
- Start fresh after an outcome-unknown attempt whose LastError was later overwritten by another message → still no revival of the old session.
- Hand runs (hand-run-claims) keep their no-expiry-reclaim guarantee under the new classifier.
