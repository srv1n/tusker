## Intent
Wave review currently exposes member dependency IDs but not authoritative facts for dependencies outside the current wave. The UI is forced to label real Alpha/Beta tasks as Unknown. Extend the existing read projection; do not make the browser infer tracker truth.

## Verified seams
`buildDirectWaveReview` already loads the canonical v7 index, current wave, member tasks, frontiers, authorization, and runtime state. `directWaveReview` is the Serve/CLI wire response. `direct_wave_authority_test.go` covers cross-wave dependency contracts and review JSON.

## Producer contract
Add one top-level external-dependency fact per unique dependency referenced by a member but absent from the wave's member set. Each fact must carry enough display truth for the consumer: task ID, title, canonical task status/readiness, containing wave ID/title when present, and a classification of external, missing, or unavailable. Do not include full task bodies, proof receipts, hashes, or runtime internals.

Resolve within the same registered project and canonical tracker index. A colliding task ID in another project is never visible. A missing task is `missing`; an index/read failure is `unavailable`; neither is mislabeled as a valid external task. Stable ordering/JSON makes repeated reads deterministic.

The existing member waiting reason must select the first actually unfinished hard dependency, not a completed predecessor or stale next_ref. In the observed state it must say BET-T-0004, while the external facts report ALP-T-0004 done and BET-T-0004 unfinished.
