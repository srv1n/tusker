# RUN-T-0023 · Clean finish must release the run lease; continuation cap must park, not queue

## Intent

Found live during the RUN-T-0017 re-entry trial — the July 6 incident class survived RUN-T-0010/0011 on the claude-runner path. Observed sequence on CLN-T-0006 (all evidence in the run event log and `.tusker/scratch/CLN-T-0006/PLAN.md`):

1. Attempt 1 (claude runner) did the work correctly, recorded proof, moved the task to `review` — but its exit left the run lease active. Daemon logged the incident signature verbatim: `runner exited cleanly while tracker state remained active; queued continuation retry`.
2. Continuation attempts 2 and 3 each found durable state already correct, re-verified, exited cleanly — lease still not released. Each was a fresh session doing nothing but re-confirming (Ralph protocol held; the waste per attempt was bounded, not quadratic).
3. Attempt 4 self-diagnosed and ran `tusker finish --request-review`, which moved the attempt to handoff — the release the machine should have done at step 1.
4. `max_continuation_retries: 3` never parked the run: after attempt 4 the daemon queued yet another continuation (`lease_state: retry_queued`, attempt_count 4). RUN-T-0010's `parked_no_progress` terminal state never engaged on this path.
5. The invariant sentinel (RUN-T-0014) caught `attempt_count_within_caps` at 4 and opened the circuit — defense-in-depth stopped the loop at 4 attempts instead of 88. Working as designed, but it is the LAST line, not a substitute for the first two.

Three fixes, one seam:

1. **Release on clean finish:** when a runner attempt exits cleanly and the tracker state is non-dispatchable (review/done) or the attempt reported completion, the daemon/wrapper releases the lease and marks the attempt outcome — `tusker finish` semantics happen machine-side, not as runner etiquette. The reconciler (RUN-T-0011) must also release held/retry_queued leases for non-dispatchable tasks within one tick — audit why it did not here (task was in `review` across three ticks while continuations queued).
2. **Cap parks on every path:** continuation retries beyond `max_continuation_retries` transition the run to `parked_no_progress` (terminal for dispatch, redrivable) regardless of runner kind (codex app-server, codex exec, claude). Audit why the supervisor `continue_attempt` decision path bypassed RUN-T-0010's cap.
3. **Regression tests pinned to the claude lane:** RUN-T-0010's continuation-cap tests exercised a path that did not cover this; add the claude-runner (and generic supervisor-decision) equivalents so all runner lanes share one eligibility + parking implementation.
