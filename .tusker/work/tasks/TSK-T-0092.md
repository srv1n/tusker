## Intent
Answers to questions asked without waiting are marked stale and never reach Codex, Muse, Devin or any finished worker. For harnesses without soft delivery (Codex, Devin), the daemon hard-says an answer immediately, even while the worker's MCP ask is still waiting inline for the same answer, so the worker is interrupted and gets the answer twice. Wakeups for registered direct sessions stay held and are re-claimed on every poll forever. The yield-parking branch skips the session-state update and supervisor decision its sibling does. A wave whose member is parked on a question never reports stalled.

## Implementation contract
Locked:
- Every answer addressed to a task is delivered exactly once, in this order of preference: inline to a waiting MCP ask; soft (hook) to a live worker on a harness that supports it; hard say to a live worker only when the question was a yield question; otherwise held for the next continue, whose prompt includes it. Non-yield answers never interrupt a worker.
- While an MCP ask is waiting, mcp_serve.go refreshes a wait marker on the question (a timestamp column or transport field; proposed name `awaiting_until`). The daemon never hard-says an answer whose question has a fresh marker. After the marker expires, a 30 s grace applies before any hard say.
- Wakeups for registered direct sessions are marked `delivered` when the inbox hook delivers them and otherwise back off (next attempt at 1, 5, 15 minutes, then every 15 minutes); they are never re-claimed every poll.
- The yield-parking branch performs the same session-state update and supervisor decision as its sibling.
- `architectWaveStalled` treats a member parked with outcome waiting_for_human on an open yield question as stalled and lists the question in the report.

## Failure and edge cases
- Codex worker in `ask(wait_seconds=300)`; operator answers at 10 s → worker receives it inline; zero hard says; message consumed once.
- Codex worker asks with wait 0 and keeps working; operator answers → no interrupt; the answer is in the next continuation prompt, or in `check_messages` if the worker calls it first; delivered once.
- Muse worker asks via CLI with --yield and exits; operator answers → one continuation of the same session with the answer.
- Finished worker, non-yield answer → held; visible in the task's messages; no continuation created.
- Registered architect wakeup not picked up for an hour → at most 6 claims.
- Wave with one member yield-parked and no runnable frontier → one stalled report naming the question.
