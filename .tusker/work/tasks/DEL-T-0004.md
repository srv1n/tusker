# DEL-T-0004 · Replace risk-based human close with explicit authority gates and objective reviewer policy

## Intent

Remove the remaining policy contradiction that treats risk as human authority.
Independent reviewer agents should close objectively proven work at every risk
tier. Humans should enter only through explicit gates that name a capability,
external authority, unresolved product fact, or contractually subjective
acceptance.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Default and generated close policy allows an independent reviewer agent or human to close low, medium, high, and critical work after required objective proof and explicit gates pass. | Policy unit and fixture tests across all risk tiers. |
| A2 | High/critical risk selects stronger proof/reviewer/landing safeguards but does not synthesize a human acceptor; critical tasks no longer receive unconditional release and security gates. | Default/config migration tests and generated-workflow assertions. |
| A3 | Explicit auth, security, privacy, legal, billing, production-release, destructive-external-action, inaccessible-environment, unresolved-intent, and subjective-acceptance gates remain enforceable and survive restart. | Valid gate matrix. |
| A4 | Human gates for code review, basic test/log inspection, objective screenshots/recordings, benchmark interpretation, or implementation choices already settled by the spec are rejected with an actionable reviewer/rework alternative. | Invalid gate matrix covers CLI, proposals, validation, and imported plans. |
| A5 | Reviewer prompts, closeout, skills, templates, project canon, Serve actions, and validation describe the same authority boundary without `high/critical → human` residue. | Focused text/behavior assertions and repository search guard. |
| A6 | Existing repositories with legacy risk-based human close policy get an explicit diagnostic and idempotent migration; genuine explicit gates are preserved. | Cross-version workflow fixture tests. |

## Non-goals

- Reducing proof depth for high/critical changes.
- Allowing an implementation worker to self-review.
- Auto-performing production releases or other external authority actions.

## Operator artifact

A before/after close-policy matrix for every risk tier plus examples of valid
authority gates and rejected fake review/testing gates.
