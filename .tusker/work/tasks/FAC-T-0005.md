# FAC-T-0005 · Let a reviewer accept finished work in one step

## Intent

When a reviewer has looked at finished work whose proof is already green,
signing it off today takes several separate steps done in the right order. That
friction is pure overhead for the common, happy case.

This task gives the reviewer one move: for work whose proof already passes, a
single command records the acceptance, confirms the proof, and closes the work.
If any part of the proof is not actually green, the command refuses and leaves
the work open with a clear reason — it never rubber-stamps unproven work.

Done looks like: a reviewer runs one accept command and a ready, proven task
moves to closed with the reviewer recorded as the person who accepted it; a task
with a failing or missing proof is refused and stays open, saying why.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | One command accepts, confirms proof, and closes a task whose proof is already green. | Inline verification |
| A2 | The reviewer who accepted is recorded on the closed task. | Inline verification |
| A3 | A task with any non-green or missing proof is refused and stays open, with a named reason. | Inline verification |

## Non-goals

- No change to what makes proof green; this reads the existing proof result, it does not re-run or re-judge it.
- No bypass of acceptor rules — only an allowed reviewer/acceptor may accept.
- No batch/multi-task accept in one call; one task per accept.
- No new review findings flow here; returning work to the implementer on a finding is separate work.
