# RUN-T-0006 · Workspace lifecycle: setup scripts, files-to-copy, env vars, ports

## Intent

A fresh worktree contains tracked git files only: no `.env`, no installed dependencies, no build output, and any dev server it starts collides with the one already running at the repo root. This makes worktree-mode dispatch (RUN-T-0004 A5, RUN-T-0005) unusable on real projects. Close the gap with a workspace lifecycle, configured in `tusker.yaml` (design reference: docs/design/competitive-notes-conductor.md — Conductor's `scripts.setup/run/archive`, files-to-copy, and per-workspace port ranges, proven for a year in production):

1. Lifecycle scripts. `workspace.scripts.setup` runs once after workspace creation, from the workspace directory; a non-zero exit fails the dispatch with an agent-legible error naming the script and its output tail. `workspace.scripts.archive` runs before a workspace is removed; failure blocks removal the same way. Scripts are optional; absent scripts are a no-op.
2. Files to copy. `workspace.copy_files` is a list of gitignore-syntax globs (default `.env*`); files in the root checkout that are BOTH gitignored AND match a glob are copied into the new workspace. Tracked files are never copied (git handles those); patterns replace the default rather than merging with it.
3. Runner environment. Every dispatched runner and lifecycle script receives `TUSKER_TASK_ID`, `TUSKER_WORKSPACE_PATH`, `TUSKER_ROOT_PATH`, `TUSKER_DEFAULT_BRANCH`, and `TUSKER_PORT` — the first port of a reserved contiguous range (default 10) allocated per active workspace so concurrent dev servers and test harnesses never collide. Ranges are released when the run ends.
4. In-place runs skip the copy step and port isolation defaults (the operator's checkout already has its env); setup/archive scripts do not run for in_place workspaces.

## Non-goals

- No run-button style long-running script management (serve UI scope; the daemon runs verification commands, not dev servers).
- No cloud/remote workspaces.
- No secrets management beyond copying existing gitignored files.
