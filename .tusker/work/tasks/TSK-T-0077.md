## Intent
Devin runs through `devin acp`. Resume by `session/load` is implemented, but a lost Devin attempt is reported as abandoned with free-text reasons, ACP stop reasons and JSON-RPC errors map to outcomes without typed codes, and the fixture adapter cannot exercise session/load. This task makes Devin's Lost -> Continue path and its reasons match the contract.

## Verified seams
- `ACPRunner.Resume` and `startLiveACPForRunnerWithSession` (runner_acp.go) require negotiated `loadSession` and call `client.LoadSession`.
- `ACPRunner.Reconcile` returns released/abandoned with reason "ACP local transport cannot reconcile a lost fenced process; no automatic resume".
- `acpTerminalStatus` maps `acp.Outcome*` (internal/acp/client.go `outcomeForStopReason`: end_turn, max_tokens, max_turn_requests, refusal, cancelled) to AttemptOutcome with text reasons.
- `queueNativeSessionContinuation` already allows Devin (ResumeSession true for RunnerDevin).
- `cmd/tusker/testdata/fake_acp/main.go` handles `session/load` but advertises `loadSession: false`.

## Implementation contract
Locked:
- Keep Reconcile non-automatic (no daemon auto-resume of a lost ACP attempt), but it reports code process_lost and must not clear the persisted session ref, so run-state shows Lost and the operator's Continue resumes via session/load.
- `acpTerminalStatus` yields a typed code: max_tokens -> max_budget, max_turn_requests -> max_turns, refusal -> permission_denied, cancelled -> cancelled, delivery_unknown -> outcome_unknown, timed out/protocol/poisoned -> provider_error. JSON-RPC error responses to prompt: ACP auth_required (-32000) -> auth_expired; other errors -> provider_error with the bounded message. The code goes to the status file through typed-reasons' writer.
- Devin declares HardSay=true (cancel through the wrapper, then session/load with the message), ResumeAfterDeath=true, PreassignSessionID=false (identity comes from session/new and is persisted as today), SoftSay=false (ACP v1 has no mid-turn prompt; research).
- fake_acp gains `FAKE_ACP_LOAD_SESSION=1` to advertise loadSession and echo the loaded session id, and `FAKE_ACP_STOP_REASON` / `FAKE_ACP_PROMPT_ERROR` to emit chosen stop reasons or a JSON-RPC error. Defaults keep today's behaviour for existing tests.
Proposed: whether the JSON-RPC error code mapping lives in internal/acp or runner_acp.go; prefer runner_acp.go so internal/acp stays protocol-only.

## Failure and edge cases
- Wrapper killed mid-turn with a persisted session id: run shows lost with process_lost; `tusker runs continue` resumes through session/load with the same raw session id. Forbidden: session/new, or a cleared SessionRef.
- Adapter that does not advertise loadSession: Continue refuses with the existing "did not negotiate Devin session/load" reason; no new session is created silently.
- Stop reason refusal: permission_denied, blocked. Stop reason max_turn_requests: max_turns.
- JSON-RPC -32000 on prompt: auth_expired, blocked, not retried.
- Generic ACP runner (non-Devin): no capability changes; resume still refused.
