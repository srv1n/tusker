# KNW-T-0004 · Freshness stamps and docs status report

## Intent

- What this is: every reference document carries a "last checked against the
  code on <date>" stamp, and one report lists all documents sorted by how
  much the code they describe has moved since that stamp — plus which areas
  of the code no document covers at all.
- Why it matters: this is the one-screen answer to "which documents should I
  distrust?" It turns doc verification from a vague intention into a chore
  with an ordered work list, feeding wave-end and nightly verifier runs.
- What "done" looks like: an agent that confirms a document is accurate bumps
  its stamp with one command; the status report shows most-suspect documents
  first with a count of code changes since their stamp, and a gaps section
  for uncovered code.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A stamp command records date and current commit into a doc's header after verification. | Inline verification |
| A2 | The status report sorts docs by staleness: number of commits touching their declared code paths since their stamp; unstamped docs sort first as "never". | Inline verification |
| A3 | The report includes a coverage-gaps section listing top-level code areas claimed by no document. | Inline verification |
| A4 | The generated index page (from the map command) shows each doc's freshness from the same source. | Inline verification |

## Non-goals

- No automatic scheduling of verifier chores; the report is the input, the
  wave/nightly loop consumes it.

## Implementation notes

- File map (best guess): `internal/docgraph/freshness.go` (git log counting
  against `describes:` paths since `last_verified` commit),
  `cmd/tusker/docs_status_cmd.go` for `tusker docs status` and
  `tusker docs stamp <subject>`.
- Header field: `last_verified: "<YYYY-MM-DD> @ <short-sha>"` — parse and
  write via the KNW-T-0007 front-matter machinery, preserving the rest of
  the header byte-for-byte.
- Staleness metric: `git rev-list --count <sha>..HEAD -- <paths>`; treat a
  missing/unknown sha as "never". Keep it one git invocation per doc.
- Coverage gaps: top-level dirs of tracked `.go` code minus the union of all
  `describes:` paths; keep the granularity coarse (first path segment).
