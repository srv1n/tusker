# SRV-T-0022 · Register projects in the UI and configure daemon auto-dispatch per project

## Intent

Make project onboarding a first-class Serve UI flow. A user can select or enter a
local repository, register it with Tusker, and immediately see it in the project
list without opting it into daemon execution. Move daemon participation into
project settings as an explicit per-project choice so registration and automatic
task spawning/dispatch are independent operations.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The UI can register a valid local project and refresh/select the newly registered project without requiring CLI use. | focused_test |
| A2 | Registration validates inputs, reports duplicate/invalid-path failures in the UI, and does not implicitly enable daemon automation. | focused_test |
| A3 | Project settings expose the persisted per-project daemon automation choice; changing it updates daemon eligibility without deleting or re-registering the project. | focused_test |
| A4 | Existing registered-project, daemon, Serve API, and UI behavior remains green. | broad_test |

## Non-goals

- No automatic repository discovery or filesystem crawler.
- No daemon installation, launchd management, or global daemon start/stop control.
- No change to task eligibility rules once a project has opted into automation.
