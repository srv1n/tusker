# ACO-T-0008 · Wake the architect at wave boundaries and apply bounded corrections

## Intent

The frontier architect should perform material judgment when a wave completes or needs intervention. Its answer, correction or next-wave proposal must return through persistent contacts and current delivery authority, without turning every task completion into another premium review.

## Implementation notes
Mandatory spec section: .tusker/specs/agent-coordination.md#locked-boundaries-for-the-follow-up. The installed delivery schema inherits spec_refs at plan level; this anchor limits the required section read.

Recommended implementation: GPT-5.6 Sol / medium. Independent review: GPT-5.6 Sol / medium. These are deliberate task choices, not a reason to silently change model/effort or permissions.

Consume the report from waves and the safe conversation/worker-resume seams from clarification. An ordinary task completion updates the wave projection; do not wake the architect for each task or unchanged progress. Material scope/spec/interface questions wake promptly; peer-only questions remain peer-local. A completed or actionable stalled wave produces one decision turn per changed material.

Use existing validated answer/proposal/repair/needs-user/objective-complete forms. A correction references the reviewed patch and task/work revision, named acceptance gaps and desired result. Return it to the legitimate worker context and request rework through existing lifecycle authority. Closed/accepted/stopped or changed work cannot silently reopen; preserve the feedback and surface the required repair/new-task decision. Claim application before side effects, check revision and stop immediately before application, and preserve idempotency across duplicate feedback and restart.

Reuse existing limits/counters for bounded correction attempts. The first pilot requests two accepted correction rounds; duplicates/transport retries do not consume or reset the count. Exhaustion escalates once. Do not add a second acceptance verdict or let the supervisor waive proof, independent review or landing. A valid next-wave proposal passes current delivery validation/import/start controls and inherits only the correct objective contacts. A stopped/paused objective retains proposals without launching. Provide UI and accounting with deterministic decision cause, target, revision and application facts.
