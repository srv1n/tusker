# TRC-T-0003 · Spike: append-only run event log as source of truth, runtime DB as projection

## Intent

Analysis spike, output is a decision record — no production code. Two independent sources in docs/design/aie2026-mining/durability-loops.md argue the same inversion: the append-only event log should be the source of truth for runtime state, with the SQLite runtime store reduced to a rebuildable materialized projection (Amnara [6:50:30]/[6:51:05]; Restate [5:22:08]). Today Tusker is the opposite: daemon.db rows are authoritative, JSONL events are exhaust. The costs of the current shape showed up twice on 2026-07-06: a SQLITE_BUSY crash killed the daemon with no recoverable narrative of what was in flight, and lease/capacity bugs (RUN-T-0007) had to be diagnosed from side effects rather than replaying the decision sequence.

Evaluate the inversion honestly against Tusker's actual scale (single host, one daemon, tens of runs/day):

1. What breaks today: enumerate runtime-state losses on daemon crash/restart, including whether human-gate and approval state survives (durability-loops nuggets: a permission prompt that vanishes on crash-resume [6:54:12]; durable-promise suspension as the fix [5:13:24]).
2. Migration shape: which daemon.db tables (runs, leases, attempts, supervisor_decisions, turns) could become projections of an event log; where the log lives; rebuild cost; how `state_rev` CAS interacts with log ordering.
3. Cost: write amplification, poll-loop latency, complexity added to a codebase maintained by agents.
4. Recommendation: adopt / adopt-partially (e.g. supervisor decisions and gate state only) / reject — as a TRC decision record with the reasoning, so the choice is durable either way.
