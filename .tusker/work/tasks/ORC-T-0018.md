# ORC-T-0018 · Run opt-in timetables, holds, and misfire policy in the daemon

## Intent

The resident daemon evaluates only opted-in projects at the nearest due window and produces one idempotent departure decision.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Opted-out projects add no departure wakeups, polling work, Git access, records, or dispatch capacity consumption. | See mapped verification. |
| A2 | Daily windows and timezone behavior share one scheduling primitive with existing batch gates rather than creating a second clock implementation. | See mapped verification. |
| A3 | Global, project, and release-only holds are durable, attributable, instantly effective for future actions, and expose the exact resume action. | See mapped verification. |
| A4 | Staging windows default to skip-on-misfire and full promotion coalesces at most one ungated missed window; no policy replays every missed departure. | See mapped verification. |
| A5 | Concurrent triggers and restarts converge on the unique departure record without launching duplicate work. | See mapped verification. |
