# FBK-T-0001 · Bring multi-repo agent feedback into structured Tusker review

## Intent

Build the first-class path from multi-repo agent feedback notes to structured Tusker review, promotion, and visible fanout. This parent task owns the pipeline work surfaced by the 2026-07-05 intake digest and sub-agent analysis.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Feedback commands can resolve explicit repo lists and registered projects, while reporting stale or unhealthy vault roots without losing healthy targets. | Focused tests cover explicit repos, registry-backed targets, and stale `kurpod`-style vault root handling. |
| A2 | A structured ingest path imports feedback notes from multiple repos into the output vault with stable source refs, source project keys, repo roots, vault roots, import run IDs, and dedupe keys. | Focused tests cover multi-repo ingest, basename collisions, duplicate notes, and output-vault placement. |
| A3 | Feedback-note-derived signals participate in review alongside task/event-derived signals without being hidden behind markdown-only digests. | Focused tests prove note-derived signals appear in JSON review output with stable finding IDs and source note citations. |
| A4 | Promotion can select a specific feedback finding and create a parent-linked task or proposal while preserving source refs and without auto-dispatch unless fanout is explicitly enabled. | Focused tests cover selected finding promotion, dry-run mode, duplicate existing-work detection, and fanout-disabled behavior. |
| A5 | Operator docs explain the intake -> review -> promote -> fanout workflow and distinguish explicit feedback notes from mechanical task/event signals. | Documentation diff plus focused doc/help assertions. |

## Non-goals

- Implement the Xcode cleanup doctor itself.
- Implement the Tusker/ChatGPT onboarding doctor itself.
- Clean up local task hygiene in source repos that merely produced derived signals.
