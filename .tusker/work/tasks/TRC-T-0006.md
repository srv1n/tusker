# TRC-T-0006 · Serialize CAS and atomically replace canonical Markdown writes

## Intent

`saveV7DocumentCAS` currently reads and checks `state_rev`, then writes with a
plain truncating `os.WriteFile`. Two writers can both pass the check and lose one
update, while interruption or disk exhaustion can truncate canonical Markdown.
Serialize each document's complete CAS transaction with a cross-process lock:
acquire, reread, validate the base revision, serialize, write a same-directory
temporary file, sync, atomically rename, then release. Lock artifacts must be
owner-only runtime state and must never appear in the canonical vault or Git.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Two concurrent writers using the same base revision cannot both commit: exactly one succeeds, the other receives `CAS_CONFLICT`, and the resulting document parses with a matching `state_rev`. | focused_test |
| A2 | A write, sync, or rename failure leaves the original document byte-for-byte intact and removes temporary files; successful replacement preserves the intended file mode. | focused_test |
| A3 | The lock spans reread through rename across processes, is owner-only runtime state, and cannot leak into `.tusker` source or deadlock after a writer process exits. | focused_test |
| A4 | Existing V7 status, proof, gate, wave, land, and reconcile mutation tests remain green. | broad_test |

## Non-goals

- No multi-file transaction across separate task/gate documents.
- No CRDT or remote multi-user editing.
- No runtime event-log rewrite; TRC-T-0007 owns that path.
