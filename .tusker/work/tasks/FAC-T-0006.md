# FAC-T-0006 · Send a reviewer's findings straight back to the person who did the work

## Intent

After an independent reviewer looks at a piece of work and finds a problem, that
problem should land straight back with whoever did the work — with the
reviewer's note attached — so they can fix it. The work must not slip closed
while a finding is still open.

Today an independent review can run, but a finding doesn't automatically bounce
the work back with the note in hand, so findings get lost or the work closes
around them. This task makes a reviewer's finding return the work to its author
with the note pasted in, and holds the work open until the finding is settled.

Done looks like: when a reviewer records a problem, the work returns to the
person who did it showing the reviewer's note, and it cannot close until that
finding has been dealt with.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A recorded reviewer finding returns the work to the person who did it. | Inline verification |
| A2 | The reviewer's note is pasted into the work the author sees. | Inline verification |
| A3 | The work cannot close while a finding is still unsettled. | Inline verification |

## Non-goals

- No change to who the reviewer is or how the reviewer is chosen; the review lane already exists.
- No auto-fixing of the finding; it only routes the note back to the author.
- No email/chat notification; the return happens inside the work record.
- No cap redesign; the existing limit on review cycles stays as-is.
