# LIF-T-0008 · Replace production settings fixtures with live runtime projections

## Intent

Delete production-facing hardcoded worktree/run rows and wire project Settings to authoritative daemon/runtime APIs. Labels such as active, held, running, stale, and interrupted must be liveness-derived. Persisted controls must round-trip through the backend and affect subsequent planning/dispatch.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The Settings worktree/run panel contains no imported static active rows; an empty runtime produces an explicit empty state and cannot display AGX-T-0003, CLN-T-0007, or any other fixture as live. | focused_test |
| A2 | Active counts and rows come from canonical run/session APIs and distinguish shared repository sessions from opted-in worktrees. Running requires a fresh lease; stale and terminal rows are labeled accurately. | focused_test |
| A3 | Workspace mode, modifying-run concurrency, and auto-spawn controls load provenance, persist through backend actions, refresh from server state, and influence automation planning. | focused_test |
| A4 | UI tests fail if production Settings imports mock runtime state or computes liveness from hardcoded elapsed strings. Development fixture mode remains isolated and visibly identified if retained. | focused_test |
| A5 | Production bundle and backend regression suites pass with zero, one, stale, interrupted, and multiple historical runs. | broad_test |

## Non-goals

- Do not delete useful test fixtures; prevent them from entering production projections.
- Do not infer active state from task status, attempt existence, or a historical held value.
- Do not silently turn on auto-spawn during registration or settings migration.
