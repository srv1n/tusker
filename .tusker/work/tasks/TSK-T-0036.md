## Problem and intended result

Current ReadinessContract already separates contract, interactive, automation, authorization and runtime dimensions, but human remedies are strings and wave/runtime projections can disagree. Extend the existing representation with a versioned diagnostic envelope and typed, non-executable recovery descriptors. This task owns the shared read-only interface; downstream admission, doctor, repair and UI consume it. Add only the fields needed by this proposal, without a registry framework or parallel state store.

## Verified seams and integration ownership

Verified: ReadinessContract, ReadinessBlocker, ReadinessProvenance and ReadinessLegacyAdapter in cmd/tusker/readiness_contract.go; existing tests in readiness_contract_test.go. Proposed execution_diagnostics.go/test.go house the bounded envelope if keeping it in the readiness file obscures the existing contract. Preserve existing consumers and serialization compatibility; bump schema explicitly only if a breaking change is unavoidable.

## Failure cases and boundaries

Distinguish healthy/complete/normal_wait from recoverable_fault/human_decision/product_defect/unavailable. Findings include stable code, project+record+wave scope, source revision and observed_at, causal/affected IDs, next_actor, retry_after only when meaningful, action ID with typed argv/preconditions/authority/expected effect, and verifiable postcondition. Do not embed shell snippets as an executable protocol. Diagnose inputs read-only; unavailable state cannot be coerced to ready. Deterministic root-cause precedence must not suppress independent actionable blockers. The source evidence is bounded and excludes environment secrets/raw prompts.
