# SRV-T-0012 · SSE reconcile: live-update idle blocks, protect the block you are editing

## Intent

Operator decision (2026-07-06): with ambient autosave (SRV-T-0011) over multi-writer files, the last piece that makes "it's just live" safe is reconciliation — turning a concurrent runner write from a data-loss event into a smooth merge. Ride the SSE stream (SRV-T-0008): it pushes small invalidation hints when the daemon changes a task on disk. Behavior splits on whether the human is editing the affected block:
1. If you are **not** editing that block, the render live-updates — you watch the runner's change appear (the existing SSE → TanStack Query invalidation path).
2. If you **are** editing that block, do not touch the edit buffer — show a quiet "changed underneath you" indicator and reconcile on the next idle/blur/save.

Block- or field-level granularity keeps a runner's front-matter write (e.g. `status`) from ever colliding with your prose edit. On an autosave 409 (SRV-T-0011 rejects the stale write), this is where the conflict resolves: fetch the new base, rebase the local buffer automatically when the edits do not overlap, or surface a compact resolve affordance when the same block changed on both sides — never silently drop either side's work.

Dependencies: SRV-T-0008 (the SSE event stream) supplies the push signal; SRV-T-0011 (the autosave loop) supplies the 409/in-flight state this reconciles against. Scope is deliberately block/field-granular reconcile, not full collaborative editing.

## Acceptance

| A1 | An external change to a task the user is viewing but not editing live-updates the render within one event, with no manual refresh (SSE → query invalidation). | Inline verification |

| A3 | On an autosave 409, the client fetches the new base and rebases non-overlapping local edits automatically; a same-block conflict surfaces a compact resolve affordance. Neither the runner's write nor the human's edit is silently lost. | Inline verification |
| A4 | Front-matter writes and prose edits reconcile independently — a runner status change never disturbs an in-progress prose edit, and vice versa. | Inline verification |

## Non-goals

- No CRDT/OT full collaborative editing — block/field-granular reconcile only.
- No change to the SSE wire format (SRV-T-0008 owns it) or the write endpoint (SRV-T-0004).
- No offline or queued-edit support.
