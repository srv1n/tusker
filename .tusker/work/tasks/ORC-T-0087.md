# ORC-T-0087 · Ship lockstep compatibility and a compact progressive-disclosure skill

## Intent

Tusker publishes one machine-readable compatibility contract and installs a small trigger-complete router whose plan, work, operate, and rare specialized guidance loads only when selected.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Capabilities expose one versioned compatibility fingerprint covering binary command/schema support, workflow range, factory contracts, canonical skill source, and generated install provenance without relying on prose frontmatter metadata. | See mapped verification. |
| A2 | Skill sync, copy, bundle, setup doctor, and rollout doctor distinguish current, stale, missing, incompatible, and locally modified installs and provide one deterministic repair without changing project knowledge or authority. | See mapped verification. |
| A3 | SKILL.md frontmatter contains only name and a trigger-complete description, and its body is at most 900 words and 140 lines while retaining capability check, mode routing, universal authority boundaries, hard stop, and one compact loop. | See mapped verification. |
| A4 | PLAN.md owns planning, review, import, and Start guidance; WORK.md owns interactive and dispatched implementation, proof, and human-wait guidance; OPERATE.md owns daemon, wave, review, integration, and recovery guidance; rare topics remain direct one-hop routes. | See mapped verification. |
| A5 | Every normative rule has one owning file, removed legacy references leave no broken links, primary mode guides do not require recursive reference loading, and generated installs exactly match canonical source. | See mapped verification. |
| A6 | Representative planning, interactive, dispatched-worker, dispatched-reviewer, human-wait, onboarding, and Xcode prompts select only the required guides and stay within recorded word and loaded-context budgets without losing safety behavior. | See mapped verification. |
