# ACO-T-0004 · Wake the right agent and resume blocked work from its answer

## Intent

A blocked worker can ask its architect or a relevant peer, safely yield and continue when its answer arrives while other work progresses. The same behavior survives restarts without repeated model calls. Done is a runnable five-task scenario and wakeup ledger. Scope is targeted clarification and waiting; later-wave planning belongs to the next task.

## Implementation notes
Read .tusker/specs/agent-coordination.md and its September 10 decision log. Implement the customer journeys using existing execution, runtime, packet, delivery and UI machinery. Preserve the dirty baseline and other owners. Use the supported interactive work-session protocol; do not launch a daemon or nested worker from an interactive session. The current automation pause is a rollout setting, not a reason to omit the mechanism. Keep configuration unchanged during implementation. Task ownership and real dependency edges govern integration. Proposed new filenames below are recommendations; trace actual callers before editing, resolve routine choices locally, and record the final contract in the named artifact. No model turn for routing, polling, summaries of unchanged state or relay. Use configured work/review levels, keep checks focused, and leave integrated builds/live qualification to the qualification task. Do not claim provider documentation or offline fixtures as a live harness pass. Independent review remains required; no new human code-review gate.

Add deterministic mailbox consumption to the resident daemon, preserving existing ownership and generation fencing. At most one active turn per conversation; deliver into an active turn only when transport conformance permits, otherwise queue. Coalesce available questions without delaying blocking clarification; notices wait for relevant turns. Workers produce a durable wait/yield receipt or invoke the claimed CLI surface, then settle before releasing the model slot. Preserve workspace/progress, avoid false task completion, and resume the legitimate current attempt only after question and revision validation. Handle reply-before-yield, stop-during-send, late answer, endpoint replacement, retry and delivery-unknown. Reserve eligibility for architect clarification so parked workers cannot exhaust its capacity; detect required-reply wait cycles without an LLM. Reuse existing settings to preserve paused/enabled mode while implementing both paths. Put compact contact/question and command guidance into the actual packet; do not require an additional operating skill.

Artifact: docs/reports/agent-coordination/clarification.md. Required named check prefix: TestAgentClarification. Run the verification after implementation settles; the named cases must exist and be executed. Capture actual results in the artifact. A command that matches no tests is incomplete.
