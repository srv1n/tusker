# MAC-T-0007 · Project switcher for menu-bar triage

## Intent

The menu-bar panel is the fastest Tusker surface, but its triage sections are
currently locked to the all-project aggregate. Operators managing several
registered repositories cannot focus the panel on one project or tell which
project's work they are looking at without opening the full app.

Add a compact project switcher to the `/panel` header. It must retain an
explicit **All projects** view, expose every registered project with enough
status context to distinguish idle, active, and unhealthy projects, and scope
the panel's human actions, attention, review, running, and failure sections to
the selected project. Switching must reuse the existing project-keyed query
cache and live refresh paths so it feels immediate and never mixes rows from
the previous selection.

| A6 | At exactly 420×640 in shell mode, the header and open switcher fit without horizontal scroll, project names truncate cleanly, the selected project remains obvious, and all controls are usable with keyboard and VoiceOver labels. | manual_check |
| A7 | UI typecheck/tests/build and the signed Mac bundle build pass. | broad_test |

## Non-goals

- Registering, enabling, disabling, or removing projects from the panel.
- Replacing the full app's sidebar project navigation.
- Changing daemon projection/cache semantics owned by `SRV-T-0025`.
- Adding a native AppKit project model; the web panel remains the source of UI state.
