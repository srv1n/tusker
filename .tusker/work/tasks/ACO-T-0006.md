# ACO-T-0006 · Show supervisory context and truthful delivery in the task inspector

## Intent

An operator should see who can answer, what decision the architect received and whether feedback reached the worker, without interpreting a queued row as a delivered or accepted result.

## Implementation notes
Mandatory spec section: .tusker/specs/agent-coordination.md#operator-and-agent-experience. The installed delivery schema inherits spec_refs at plan level; this anchor limits the required section read.

Recommended implementation: GPT-5.6 Luna / xhigh. Independent review: GPT-5.6 Terra / high. These are deliberate task choices, not a reason to silently change model/effort or permissions.

Reuse the existing inspector, message conversation and recipient/reply controls. Consume packet/report/continuation projections; do not infer lifecycle state in the browser. Show effective architect/origin/peer contacts, pending decisions, compact report/evidence links, correction round/limit, and delivery/consumption/application uncertainty separately. Render supervisor feedback as feedback, not acceptance. Preserve drafts/correlation across refresh and make unsupported contacts actionable.

Add keyboard/focus labels and a narrow-viewport check around existing controls. Do not add a chat product or edit source authority. UI fixtures can be authored as soon as mailbox/report contracts exist; final integration waits for supervision. Backend additions must stay in the existing Serve projection seam with the runtime owner, not duplicate scheduling in an endpoint.
