# FAC-T-0008 · Only build and test the parts a change actually touched

## Intent

When a change touches only a couple of parts of the project, the light per-change
check should build and test just those parts — not the whole thing. Today that
check runs the project's entire command set no matter how small the change,
which burns long build cycles on parts nobody touched.

This task makes the per-change check look at what a change actually touched and
run its check, style, and focused tests scoped to just those parts. The
combined build-and-test that runs when a whole batch lands still covers
everything — this narrowing applies only to the light per-change stage.

Done looks like: a check on a change that touched one area runs only that area's
build, style, and tests and skips the untouched areas, while the batch-landing
check still runs the full set.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A per-change check runs build, style, and focused tests only for the areas the change touched. | Inline verification |
| A2 | Areas the change did not touch are skipped by the per-change check. | Inline verification |
| A3 | The batch-landing check still runs the full set, unchanged. | Inline verification |

## Non-goals

- No change to the one-pass, all-defects harvest behaviour within the chosen scope.
- No new test runner or per-language knowledge baked into the tool; scope selection stays project-configured.
- No narrowing of the overnight full suite.
- No cross-change dependency analysis beyond the files a change touched.

## Implementation notes

Best-guess file map — verify before editing:

- `runGateTier` in `cmd/tusker/gate_tier.go` runs `policy.HarvestCommands`
  wholesale. Add a per-change mode that derives the touched paths (diff against
  the base branch — `workspaceTreeStateHash` and `gitFactOutput` helpers exist
  in the tree) and selects the matching subset of commands/packages.
- Keep the harvest (one pass, every defect) within the selected scope.
- Distinguish the per-change mode from the wave-end collective run so the latter
  stays full. Reference the tiers named in the FAC-T-0007 reference page.
