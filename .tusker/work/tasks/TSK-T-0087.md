## Intent
Daemon runs give Muse the bounded raw log, so `monitorBoundedRunnerCommand` runs, and it maps typed failure codes only for Codex. Muse typed reasons (TSK-T-0076) exist only in the unbounded monitor, so in real runs usage limits are guessed from text and retried. Muse classification also runs only on exit 0 and treats any "limit" as usage_limit. A status file with an unknown code fails the whole read. Codex rotation cuts at a byte boundary, so one JSON line can split across segments, and `extractMessageRef` reads only the current segment.

## Verified seams
- runner_raw_log_limit.go `monitorBoundedRunnerCommand` (~308); Codex-only mapping `if runner == RunnerCodexExec && exitCode != 0 ...` (~355). daemon.go ~4619 selects the bounded log for Muse (read-only here).
- runner_exec.go Muse classification in the unbounded monitor (~371-383, exit-0 only); status read failing on unknown code (~343); `extractMessageRef` (~477).
- runner_muse.go keyword mapping `strings.Contains(lower, "usage"), strings.Contains(lower, "limit")` (~190).

## Implementation contract
Locked:
- One classification function per driver, called by both monitors: Codex and Muse typed codes apply in bounded and unbounded runs, on any exit code, from the tail of the raw log.
- Muse usage_limit requires a rate/usage-limit phrase ("rate limit", "usage limit", "quota", or the provider's typed code). "context limit", "turn limit" and "max turns" never map to usage_limit.
- An unknown code in a status file degrades to reason `unknown` with the raw code kept in the diagnostic; the rest of the status loads.
- Rotation cuts only at a newline boundary. A single line larger than the segment is written whole into its own segment with a `[oversized line N bytes]` marker. `extractMessageRef` scans the current segment, then earlier segments, newest first, until found.

## Failure and edge cases
- Fake muse under the bounded log exits 1 after `{"type":"run.terminal.failed","error":"rate limit exceeded"}` → Blocked usage_limit, no retry queued. Forbidden: retry_queued lease.
- Fake muse exits 1 with "context limit reached" → Failed with a non-usage code.
- Codex log crossing the rotation size mid-line → both segments parse line by line with no partial JSON; the message ref from a line in segment 1 is still found after rotation.
- Status with `"reason_code":"future_code"` → state loads, reason unknown.
