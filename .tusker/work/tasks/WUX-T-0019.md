# WUX-T-0019 · Ship selectable project visibility

## Intent

People who initialize a folder see it in Tusker automatically and can choose whether it stays on the main screen. Every registered folder remains recoverable in All Projects, and changing that check box never changes automation. Done means the choice survives restart, broken folders cannot crash the service, and the desktop keeps the current page during service recovery.

## Implementation notes
Persist one visibility bit in the existing machine project registry and migrate old rows to visible. Reuse the existing project summary, mutation, settings, and navigation-filter paths. Apply a logical project's choice to its grouped checkouts. Register from init by default with an explicit no-register escape hatch. Keep visibility independent from the existing automation-enabled field. Quarantine unreadable project work during reconciliation and avoid reloading committed WebKit content after runtime recovery. Rebuild the existing embedded web assets; add no dependency or secondary preference store.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Running init registers the folder for app discovery, shows it by default, and leaves automation disabled. | See mapped verification. |
| A2 | Global Settings lists every registration and its error state; checking or unchecking one logical project changes only main-screen membership for all grouped checkouts. | See mapped verification. |
| A3 | Existing registrations migrate without disappearing, and hidden registrations remain stored and recoverable. | See mapped verification. |
| A4 | A missing project cannot terminate reconciliation, and runtime recovery does not reload a committed main window or panel. | See mapped verification. |
