# AAC-T-0006 · Show access and one-time approval where work happens

## Intent

An operator sees the selected access level before work starts and can resolve an exceptional action in the task they already use. Done is a complete request-state walkthrough with screenshots and keyboard verification. There is no separate permissions inbox or recurring approval ritual.

## Implementation notes
Read .tusker/specs/agent-access.md and its decision log. This is future implementation work; the planning session has not built or dispatched it. Preserve the shared dirty baseline and reconcile current ownership before editing. Reuse existing profile, runner, runtime and UI authorities. Do not launch a daemon or nested worker from an interactive session, change automation, invent provider fallback or add an OS sandbox. Proposed new filenames are recommendations; trace the common launch, test and resume callers before choosing the smallest complete implementation. Keep native coverage explicit. Run named checks after implementation settles; zero matching cases is failure. Use disposable fixture files for negative cases. Paid/live provider runs require explicit authorization and separate evidence. Record outcomes, exact route/version and limits in the artifact. Independent review uses existing workflow, not a new human code-review gate.

Use the existing profile selector/route preview, task detail and HumanActionCard. Display short effective access with a details link and profile repair action. Render exact bounded/redacted immutable arguments, working folder, route and consequences; expand long commands without hiding meaningful flags. Offer Block action and Allow once only for a demonstrably live supported request. No Enter/dismiss auto-approval, Allow all or session-wide grant. Display duplicate deliveries once; show pending/allowed/denied/expired states. Dismiss leaves pending; Block sends deny. Dead process requests are informational, with existing Retry creating a new attempt/request. Bind mutation to expected revision and show conflicts without replay. Use contract/runtime APIs rather than a second browser state authority. Required tests: AgentAccessApprovalUI in agent-access-approval.test.ts; browser scenarios include a second agent and a no-callback route.
