# AGX-T-0002 · Composite commands: single-roundtrip verify-and-finish

## Intent

Closing a task honestly currently takes four to six CLI roundtrips (`status` → `verify add` per acceptance row → `proof status` → `finish` → `closeout`), and each roundtrip costs an agent a full tool call plus re-reading state. Add composite commands for the two hottest paths: (1) `tusker done <ID> --covers A1 --check "<cmd>" --result pass [repeatable] [--request-review]` performing verify-add for each row, proof recompute, and finish in one invocation; (2) `tusker start <ID>` performing claim plus packet emission. Additionally, every mutating command's `--json` output must include the resulting `status`/`readiness`/`proof_status` and a `next` hint, so agents never need a follow-up state query.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | One `tusker done` invocation with multiple `--covers` rows produces an end-state identical to the equivalent manual command sequence (asserted by test on resulting frontmatter and proof status). | Inline verification |
| A2 | `tusker start <ID>` claims and emits the agent packet in one call. | Inline verification |
| A3 | All mutating commands return resulting state plus a `next` hint in `--json` output. | Inline verification |
| A4 | `skill/references/COMMANDS.md` teaches the composite path as the default loop. | Inline verification |

## Non-goals

- No removal of the granular commands; composites wrap them.
- No auto-close semantics changes (close policy untouched).
