## Intent
Claude runs are not detached: `ClaudeRunner.Start` calls `startLiveClaude`, which spawns `claude` with `exec.CommandContext` and stdin/stdout/stderr pipes inside the daemon process. Restarting or crashing the daemon ends or blinds every Claude run. Native resume is also dead: `ClaudeRunner.Capabilities` reports `ResumeSession:false`, and `ClaudeRunner.Resume` substitutes a non-empty default command (plan mode, Read/Glob/Grep only) so `startLiveClaude` never appends `--resume`. A single stdout line over 4 MiB kills the run via `failCriticalRunnerIO`. The contract (run-session-continuity "Harness routes") requires detached Claude with a Tusker-assigned `--session-id` persisted early and `claude -p --resume <id>` for continue.

## Verified seams
- runner_claude.go: `Capabilities` (~12, ResumeSession false), `Start` (~16), `Resume` (~32 default command; `{{session_ref}}` opt-in check).
- runner_claude_live.go: `startLiveClaude` (~64) builds the default command, appends `--resume {{session_ref}}` only when `req.Command` is empty and resume is set; `cmd := exec.CommandContext(...)`, `StdinPipe/StdoutPipe/StderrPipe`; `readStdout`/`readStderr` (~358/375) use `scanner.Buffer(buf, 4*1024*1024)` and call `failCriticalRunnerIO` on scan error; `handleStdoutLine` extracts session/message refs.
- runner_wrapper.go: `startDetachedRunnerWrapper` (~28) returns a `StartResult` without `SessionRef`; `runnerWrapperStartChild` (~189) switches on CodexAppServer, CodexExec, Muse, ACP/Devin, CodexACP — no Claude case (falls to "runner wrapper does not support runner").
- runner.go: `StartRequest` (~85) has no session-identity field.
- daemon.go dispatch (~5005-5020) copies `start.SessionRef` into run and attempt immediately after Start returns — that is the "persist before first prompt completes" point once the wrapper returns the pre-assigned id.
- Muse reference pattern: runner_muse.go `Start`/`Resume` via `startDetachedRunnerWrapper`, `museCLIResumeArgv`.
- Existing fake-claude tests: runner_live_test.go (~907, ~1108, ~1182, ~1271) write temporary fake-claude.py scripts.

## Implementation contract
Locked:
- `ClaudeRunner.Start` and `Resume` launch through `startDetachedRunnerWrapper(ctx, RunnerClaude, ...)`; `runnerWrapperStartChild` gains a `RunnerClaude` case that runs the existing `startLiveClaude` inside the wrapper (the wrapper owns stdio and writes events/raw log to disk). The daemon process never holds Claude pipes.
- Fresh start: Tusker generates a UUIDv4, adds `--session-id <uuid>` to the argv (unless the profile argv already carries one — then refuse with config error rather than silently use a different id), and returns it as `StartResult.SessionRef` from `startDetachedRunnerWrapper` so dispatch persists it before the prompt completes. Proposed field: `StartRequest.NativeSessionID` (runner.go) carried through the wrapper request.
- Resume: argv is the original start argv (same `--mcp-config`, `--settings`, permission, tools, model flags) with `--session-id <x>` removed and `--resume <session_ref>` added. Never add `--bare`. Refuse `bypassPermissions` exactly as today. `Resume` no longer substitutes the plan-mode read-only default for execute-lane runs; the resumed command must match the lane's policy command.
- `ClaudeRunner.Capabilities().ResumeSession = true` only after the above lands (run-controls-api's `nativeResumeRunnerCapabilities` reads this value; it adds the Claude case itself).
- Oversized stdout/stderr line: truncate to a bounded prefix in the raw log with a `[truncated N bytes]` marker, skip parsing it, record a `stdout_line_oversized` diagnostic event, and continue. Scanner errors other than oversize remain critical.
Proposed: `--resume-session-at {{message_ref}}` stays an opt-in profile template only.

## Failure and edge cases
- Daemon killed (SIGKILL) mid-run with a fake claude still streaming → the fake keeps running, events continue landing in the event sink, the wrapper publishes terminal status; after daemon restart the run reconciles as the same attempt. Forbidden: a second attempt spawned; fake receiving SIGPIPE/EOF on stdout.
- Start result is persisted with SessionRef equal to the `--session-id` value in the child argv; the id is present before the fake emits its first `result` record.
- Resume → child argv contains `--resume <id>`, carries identical `--mcp-config`/`--settings` values as the start argv, contains no `--session-id` and no `--bare`.
- Profile argv already containing `--session-id` → config error, no launch.
- Wrapper launch failure → existing `runnerWrapperPublishStatusIfAbsent` failed status; no orphan claude.
- 6 MiB single stdout line, then a normal `result` line → run completes normally; raw log shows the truncation marker.
- Claude extension bridge requested → existing `extension_bridge_unsupported` refusal unchanged.
