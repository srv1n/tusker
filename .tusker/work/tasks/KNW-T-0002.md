# KNW-T-0002 · Generated map and index with structural checks

## Intent

- What this is: a command that reads every documentation header and draws the
  whole knowledge tree automatically — a diagram in the overview page, an
  index page listing every document with its one-line description, and a
  machine-readable graph for the web view. Nobody ever draws or edits these
  by hand.
- Why it matters: a hand-maintained map is just another document that rots.
  Generating it forces the structure: a document with a broken or missing
  connection cannot appear on the map, and the generator says exactly what
  is wrong. The map is guaranteed current at every commit.
- What "done" looks like: running the command refreshes the diagram and
  index; repository validation fails if someone adds a document and forgets
  to refresh; a document with a missing parent, a duplicate subject, or a
  circular connection makes generation fail with the specific defect named.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | One command regenerates: a mermaid diagram inside a fenced generated region of the overview doc, a generated index page (subject, file, description, freshness), and a JSON graph artifact. | Inline verification |
| A2 | Generation refuses malformed graphs — orphan doc (no parent), dangling edge, cycle — naming the file and defect. | Inline verification |
| A3 | Validation regenerates in memory and goes red when committed artifacts are stale, with a "run the map command" hint. | Inline verification |
| A4 | The real corpus in this repository generates clean and the artifacts are committed. | Inline verification |

## Non-goals

- No serve-UI rendering of the JSON graph (deferred; the artifact just exists).
- No content linting beyond structure (readable-shape lint is separate work).

## Implementation notes

- File map (best guess): `internal/docgraph/graphmap.go` (build graph from
  KNW-T-0007 nodes, detect orphans/cycles/dangling edges),
  `internal/docgraph/render.go` (mermaid + index + JSON emit),
  `cmd/tusker/docs_map_cmd.go` for `tusker docs map`.
- Generated region markers: `<!-- generated: docs map (do not edit) -->` ...
  `<!-- end generated -->` inside `docs/system/00-overview.md`; whole-file
  generated outputs: `docs/system/INDEX.md`, `docs/system/graph.json`.
- Validate hook: same in-memory build, byte-diff against committed files
  (gofmt pattern). Deterministic output ordering (sort by subject) so diffs
  are stable.
- Freshness column reads `last_verified` if present, "never" otherwise
  (KNW-T-0004 populates it; render must not depend on that task).
