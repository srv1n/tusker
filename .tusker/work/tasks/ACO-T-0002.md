# ACO-T-0002 · Store and exchange questions and replies durably

## Intent

An agent or person can address a question, receive a durable receipt and answer it without copying between conversations. The question and answer remain inspectable after a restart. Done is a request-and-response example set plus a failure matrix. Scope is durable messaging and public operations; this task does not launch recipient models.

## Implementation notes
Read .tusker/specs/agent-coordination.md and its September 10 decision log. Implement the customer journeys using existing execution, runtime, packet, delivery and UI machinery. Preserve the dirty baseline and other owners. Use the supported interactive work-session protocol; do not launch a daemon or nested worker from an interactive session. The current automation pause is a rollout setting, not a reason to omit the mechanism. Keep configuration unchanged during implementation. Task ownership and real dependency edges govern integration. Proposed new filenames below are recommendations; trace actual callers before editing, resolve routine choices locally, and record the final contract in the named artifact. No model turn for routing, polling, summaries of unchanged state or relay. Use configured work/review levels, keep checks focused, and leave integrated builds/live qualification to the qualification task. Do not claim provider documentation or offline fixtures as a live harness pass. Independent review remains required; no new human code-review gate.

Use runtime SQLite transactions and existing authenticated CLI/Serve conventions. Implement send/ask/list/show/reply and recipient resolution through the contacts registration hook, plus a compact read projection for packets. Store immutable IDs, idempotency key, origin/project/revision, typed destination, correlation, reply-required/yield intent and bounded content/artifact refs. Persist before acknowledgment. Record transport acceptance, consumption, answer and application separately. Provide transaction-safe claim/settle and incoming-reply APIs to the scheduler. Handle duplicate enqueue, orphan or forged replies, concurrent receive/stop, expired questions, missing recipients, sender spoofing, unsafe paths and unknown delivery without claiming exactly-once provider execution. Add no daemon loop or independent service.

Artifact: docs/reports/agent-coordination/mailbox.md. Required named check prefix: TestAgentMessages. Run the verification after implementation settles; the named cases must exist and be executed. Capture actual results in the artifact. A command that matches no tests is incomplete.
