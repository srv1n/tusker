## Intent
Activity is lossy and can kill runs. ACP: the client's update queue holds 256 updates and poisons the session on overflow, while `observeUpdates` does one fsynced event write per non-message update (including per-token `agent_thought_chunk`), so a thought burst overflows the queue and ends a long Devin run. `tool_call_update` replaces the start event and loses the title/command; `plan` and `usage_update` are dropped into generic diagnostics. CLI: Claude `tool_result` replaces `tool_use` (command lost); Codex `turn.failed`/`error` records and Claude error results without text are dropped, so failed runs show no reason; the 1 MiB tail returns nothing when the newest line exceeds 1 MiB; redaction misses `AWS_SECRET_ACCESS_KEY=...`, URL userinfo credentials, PEM blocks and JWTs.

## Verified seams
- internal/acp/client.go: `Limits.MaxUpdates` default 256 (~111); `enqueueUpdate` (~2024) poisons with "session update queue limit exceeded".
- runner_acp.go `observeUpdates` (~519): coalesces only `agent_message_chunk`; every other update → `appendACPEvent` → `EventLog.Append` (event_log.go syncs); tool events use `message_id = "acp:tool:<id>"` with text `title|id, status, content`.
- run_activity.go: `appendRunActivity` (~103) deletes the earlier same-ID event and appends the new one; `cliRunActivity` (~119) handles item.* (agent_message, command_execution, file_change, mcp_tool_call), assistant/user blocks, and `result` only when text non-empty; `runActivityTail` (~68) reads the last 1 MiB and returns nil if no newline in it.
- config.go `hookSecretPattern` (~22) uses `\b(token|secret|...)` which does not match `AWS_SECRET_ACCESS_KEY` (underscore is a word char); `redactHookOutput` is shared with hooks.
- run_activity_test.go ~25 locks the lossy tool output `"test-1\ncompleted\n2 passed"`.

## Implementation contract
Locked:
- Never persist `agent_thought_chunk` (hidden reasoning is excluded by spec). Drop it before any write.
- The ACP reader never blocks on disk per token: coalesce non-message updates too (tool updates per tool-call id, plan, usage) and flush on the existing 1 s ticker/turn end; the queue must not overflow under a burst of 10k thought chunks plus 1k tool updates. Raise `MaxUpdates` only if coalescing alone is insufficient; overflow must still fail closed for genuine protocol floods.
- Tool activity merges per id: first title/command kept, status updated, output appended (bounded by `runActivityTextLimit`). Applies to ACP (`acp:tool:<id>`) and Claude (`tool_use` + `tool_result` by `tool_use_id`) — implement the merge in `appendRunActivity` or at write time, but the displayed event carries command AND result.
- ACP `plan` → `plan` activity event with a checklist text (`[x]`/`[ ]` per entry, status-aware); `usage_update` → non-activity `usage` event.
- Codex `turn.failed`, `error`, error items and Claude `result` with `is_error`/`subtype` error and no text → `Level:"error"` activity events with the provider message or subtype.
- `runActivityTail` reads backwards in chunks until it has N complete records (proposed N=200) or a bounded budget (proposed 8 MiB); an oversized single record is represented by a truncated placeholder record, never by an empty result.
- Redaction adds: env-style `*_SECRET*`, `*_TOKEN*`, `*_KEY*`, `*PASSWORD*` assignments; `scheme://user:pass@` userinfo; `-----BEGIN ... PRIVATE KEY-----` blocks; JWT-shaped `eyJ...\.eyJ...\.` tokens. Keep the existing patterns.
- Do not change the signatures of `cliRunActivity`, `runActivityTail`, `appendRunActivity` or `serveRunEventFromPayload` callers in serve_runs.go (owned by run-controls-api); new kinds render through the existing kind/text/level/activity fields.

## Failure and edge cases
- Fake ACP agent emits 10k `agent_thought_chunk` then a tool call and a final message → session completes; no thought text in the event log; queue never poisons.
- `tool_call` (title "Run tests", command) then `tool_call_update` (status completed, content "2 passed") → one displayed event containing "Run tests", the command, "completed" and "2 passed". Update run_activity_test.go ~25 expectation accordingly.
- Codex raw log whose last records are `turn.failed {error:{message:"usage limit"}}` → an error-level activity event with that message.
- Newest raw-log line 3 MiB → tail returns earlier records plus a truncated placeholder.
- `AWS_SECRET_ACCESS_KEY=abc123`, `https://u:p@host/x`, a PEM private key, a JWT → all `[REDACTED]`; ordinary words like "tokenizer" untouched.
