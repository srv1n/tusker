# ORC-T-0056 · Register, name, and bind work started outside the daemon

## Intent

An operator can register or attach a direct Codex, Codex Cloud, or Claude invocation, recognize it by a human name, find unbound work in one inbox, and bind it later without retroactively granting authority.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Pre-launch registration returns an immutable Tusker execution ID, and post-launch attach idempotently correlates a local session or cloud task ID while keeping operator name, provider label, agent type, and ticket identity separate. | See mapped verification. |
| A2 | Unbound direct executions appear in a queryable inbox and cannot contribute proof, request review, land, close, arm a wave, release, spend, or otherwise mutate delivery authority. | See mapped verification. |
| A3 | Rename, attach, detach, and rebind are audited and conflict checked; task and wave must agree, a conflicting live owner refuses, and every successful binding creates a generation and time boundary that leaves earlier observations proof-ineligible. | See mapped verification. |
| A4 | Direct launch helpers report source and process facts where available but refuse inside dispatched workers or forbidden nested model sessions and never start a daemon, arm a wave, or mint a task claim. | See mapped verification. |
