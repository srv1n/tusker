# ORC-T-0016 · Build the deterministic shadow planner and CLI

## Intent

Operators can inspect an immutable, model-free departure decision with typed reasons before authorizing staging or promotion.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The planner snapshots task state revisions, source SHAs, wave authorization, integration and default refs, proof fingerprints, gate intent, resource needs, and release eligibility. | See mapped verification. |
| A2 | Disabled mode returns a clear disabled decision without Git fetch, mutation, model invocation, or a durable departure run. | See mapped verification. |
| A3 | Shadow mode may refresh configured remote refs under a bounded timeout but cannot mutate Git refs, task or wave records, gates, external systems, or launch paid work. | See mapped verification. |
| A4 | Offline or failed fetch is indeterminate or blocked, never reported as empty cargo. | See mapped verification. |
| A5 | Check, status, and bounded history commands emit stable JSON and concise product-language terminal output. | See mapped verification. |
