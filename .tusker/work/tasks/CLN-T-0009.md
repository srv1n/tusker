# CLN-T-0009 · Verification-row grammar: documented markers, self-explaining errors, compliant templates

## Intent

Contract-authoring agents keep tripping the verification "exactness" check blind (see feedback note `2026-07-10-sarav-verification-exactness-grammar-undiscoverable.md`; concrete instance: SRV-T-0023 blocked at dispatch, six MAC/SRV tasks warned, all with real commands in their rows). Root cause: `v7VerificationCheckLooksExact` (`cmd/tusker/v7_validation.go`) accepts marker strings (`command:` / `proof:` / `manual proof`) OR a hardcoded tool-prefix allowlist that has already rotted against this repo's own stack — `bun` and `swift` are absent, and compound `cd x && ...` checks can never match a prefix. The rule appears in no doc, the create-time placeholder row doesn't model a passing value, and the error names the failure without stating the accepted grammar.

Make the grammar the contract, discoverable at every point an agent touches it:

- **Canonical grammar**: a check cell is exact iff it starts with `command: <exact shell command>` or `manual proof: <exact human steps>` (case-insensitive, optional surrounding backticks around the command). Keep the legacy tool-prefix allowlist as a compatibility fallback so existing vault tasks don't regress, but the grammar is what gets documented and templated everywhere. Do not extend the allowlist further — that path rots (bun/swift proved it).
- **Compliant templates**: `tusker new task` (and gate creation) emit placeholder verification rows already in the grammar, e.g. `command: <exact command that proves A1>` / `manual proof: <exact steps a human runs>`, so filling in the placeholder cannot leave the grammar. The placeholder text itself must still be detected as placeholder (not dispatchable) until edited — reuse the existing dispatchability check.
- **Self-explaining diagnostics**: everywhere the rule fires — the `VERIFICATION_PROOF_MISSING` / `VERIFICATION_MISSING` / `GATE_VERIFICATION_PROOF_VAGUE` validate issues and the dispatch blocker in `cmd/tusker/commands_v7.go` ("verification missing exact command or manual proof") — the message/hint must state the grammar and show one passing example row, and name the offending row when identifiable. An agent reading only the error must be able to fix the row without reading Go source.
- **Docs**: add the grammar with one passing and one failing example to the canonical operator skill command reference (skill source in this repo; sync flows to installs) and to `.tusker/WORKFLOW.md` if it discusses verification.
- **Author-time check**: ensure `tusker validate` output (or a `--task <ID>` scoped invocation if cheap to add) lets an author lint a single task's rows before promoting it to ready; document that flow in the skill as the authoring loop's last step.
