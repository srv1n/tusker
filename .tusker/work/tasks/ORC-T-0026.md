# ORC-T-0026 · Notify only on red promotion, failed release, or spending hold

## Intent

Operators receive one actionable deep-linked notification for the three exceptional outcomes and silence for routine departures.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Only promotion red, release failed, and spending or paid-launch hold events are eligible for scheduled-promotion push delivery. | See mapped verification. |
| A2 | Notifications are deduplicated by durable outcome, identify project and revision, state one bounded cause, and deep-link to the morning brief. | See mapped verification. |
| A3 | Green, empty, shadow, ordinary staging, operator-held, retrying, and repeated unchanged outcomes remain silent. | See mapped verification. |
| A4 | Notification preferences persist through the settings API, default to the documented safe values, and cannot enable scheduled promotion, model triage, or release. | See mapped verification. |
| A5 | Delivery failure is recorded for retry or inspection without changing the underlying promotion, release, or hold truth. | See mapped verification. |
