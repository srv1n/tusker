# FAC-T-0014 · Guards auto-do: auto-open attempts and auto-propose branch state changes

## Intent

- What this is: two tracker guards currently stop an agent with an error and
  make it type the remedy by hand — requesting review with no work session
  open, and changing task state while on an implementation branch. Neither
  remedy involves a choice, so this task makes the tool apply the remedy
  itself and say so in one line instead of refusing.
- Why it matters: every dispatched worker and interactive session pays these
  refusals in extra round-trips and tokens, on every task, forever. The
  decision log locked the principle that guards with no-decision remedies
  auto-do; this is that principle landed in the tool.
- What "done" looks like: requesting review on a task with no open work
  session just works, with a one-line notice that a session was opened; a
  status change attempted from an implementation branch just works, recorded
  as a proposal with a one-line notice; nothing about what the guards protect
  (proof attribution, single-writer state on the control branch) is weakened.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Requesting review with no open attempt auto-opens one, attributes proof to it, and prints a single-line notice naming the attempt; the old refusal is gone. | Inline verification |
| A2 | A durable status change attempted on an implementation branch is recorded as a proposal automatically with a single-line notice; the change applies when it reaches the control branch; a direct write still never happens on the branch. | Inline verification |
| A3 | Explicit `attempt start` / proposal commands keep working unchanged for callers that want the explicit flow. | Inline verification |
| A4 | The protections themselves hold: proof rows still attribute to the current attempt, and protected-field validation still flags raw hand-edits on non-control branches. | Inline verification |

## Non-goals

- No change to what fields are protected or which branches count as control
  branches.
- No change to review-bounce semantics or attempt numbering.
- No removal of the attempt or proposal records themselves — this changes who
  writes them, not whether they exist.

## Implementation notes

Builder appendix — verify the paths before editing.

- Attempt auto-open: `latestV7AttemptID` (`cmd/tusker/commands_v7.go`) is the
  refusal point; the finish/request-review path should call the same creation
  path as `tusker attempt start` when no attempt exists, then proceed. Keep
  the hint (`v7_proof_test.go` pins "attempts are runtime/session state") for
  callers that hit the error through other paths, if any remain.
- Branch auto-propose: `v7ProtectedImplementationFlowHint` and the
  protected-branch refusal around it; route to the existing proposal
  mechanism (`propose status`) instead of returning the hint. The
  `PROTECTED_FIELD_CHANGED` validation in `cmd/tusker/v7_validation.go` stays
  untouched — it polices raw hand-edits, which remain refusable.
- Notices: one line each, e.g. "opened attempt <id>" / "on branch <x> →
  recorded as proposal".
