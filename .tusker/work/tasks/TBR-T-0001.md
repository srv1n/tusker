# TBR-T-0001 · Start Serve when only disabled projects are loadable

## Intent

The menu bar app could fail to open the local web app when every registered
project was disabled. The projects were still valid read targets, but the
selection code ignored them. Let the app open a disabled project for
inspection without enabling background work.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Serve selects a loadable disabled project when no enabled project is available. | Focused Go test |
| A2 | Disabled projects remain ineligible for daemon dispatch. | Existing selection test |
| A3 | TuskerBar starts and reports the live bundled runtime. | Swift test and manual installed-app check |

## Non-goals

- Enable automation for a disabled project.
- Prove that a local app bundle is a public release.

## Implementation notes

Builder appendix:

- Serve target selection: `cmd/tusker/daemon_serve.go`.
- macOS runtime reporting: `apps/mac/TuskerBar/Sources/TuskerBar/RuntimeSupervisor.swift`.
- Current deep links and Spotlight routes: `DeepLinks.swift` and `Spotlight.swift`.
