# ORC-T-0084 · Separate delivery review, held import, and Start readiness

## Intent

A valid plan can be reviewed and imported held without unattended infrastructure, while Start remains the only transaction that requires operational readiness and exact human-confirmed authority.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Delivery review returns a successful read-only projection for a semantically valid plan and reports planValid, importReady, and startReady separately even when the project is disabled, the daemon is off, the runner is unavailable, the wave is disarmed, or the integration lane is dirty. | See mapped verification. |
| A2 | Dry-run and held import validate only contract, bounded context, stable scope, existing held lineage, and atomic write safety, and they create or reconcile held disarmed records without requiring automation or daemon readiness. | See mapped verification. |
| A3 | Invalid plans and unsafe import material still fail with typed contract or import blockers, while operational Start blockers never masquerade as review or import failure. | See mapped verification. |
| A4 | Start revalidates the exact plan and context fingerprints and retains project, daemon, runner, approval, workspace, integration, and authorization preflight with transactional refusal and replay behavior. | See mapped verification. |
| A5 | CLI JSON and Serve consume the same phase projection and no review or import path enables, arms, starts, dispatches, calls a provider, moves a ref, releases, or spends. | See mapped verification. |
