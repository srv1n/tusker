# SRV-T-0006 · Serve API polish: empty collections marshal as [], never null

## Intent

Live smoke of the wave-1 serve backend (2026-07-06, real vault on `127.0.0.1:7420`) found one contract violation: `GET /api/needs` returns literal `null` when the needs list is empty — the classic Go nil-slice marshaling trap. The wire contract (`internal/serve/ui/src/types/domain.ts`) types every collection endpoint as an array; the UI must never need `?? []` guards against the backend. Audit every serve endpoint that returns a collection (`/api/needs`, `/api/tasks`, `/api/runs`, `/api/epics`, `/api/docs`, `/api/projects`, and every array-typed field nested inside detail objects — gates, blockers, verification rows, roster edges) and guarantee empty marshals as `[]`. The honesty rule is unchanged: a field whose *value* is genuinely unknown stays explicit `null`; this task is only about empty *collections*.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Every collection endpoint and every nested array field returns `[]` when empty, across the full read surface. | Inline verification |
| A2 | A regression test asserts `/api/needs` returns `[]` (not `null`) against a vault state with zero needs-me signals. | Inline verification |

## Non-goals

- No new endpoints, no field additions, no UI changes.
- No changes outside `cmd/tusker/serve_*.go` and `internal/serve/**`.
