# DEL-T-0002 · Add atomic wave preflight and unattended arm, pause, and disarm authorization

## Intent

Make unattended execution an explicit, durable, batch-scoped authorization.
Preflight explains the entire wave once; arm records consent for the exact spec
revision and task set. No worker should rediscover permission at each task
boundary, and arming must not silently authorize unrelated ready work.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `wave preflight` is read-only and reports spec/DAG validity, exact task proof, artifact contracts, dependency frontiers, project/daemon health, runner/skill compatibility, approval policy, workspace isolation, genuine human gates, concurrency, and landing policy. | Focused fixture matrix covers a green wave and every blocker class. |
| A2 | `wave arm` atomically fingerprints the spec revision and exact member set, records actor/time, promotes only valid held members, and leaves unrelated tasks untouched. | Atomic state tests include concurrent arm attempts and write-failure rollback. |
| A3 | A material spec, task, dependency, gate, or member-set change marks authorization stale and prevents new dispatch until re-preflighted and re-armed. Proof/evidence progress that does not change intent preserves authorization. | Fingerprint transition tests. |
| A4 | `pause`, `resume`, and `disarm` are idempotent, audited, and stop future claims without forging terminal results for live workers. | Lifecycle and restart tests. |
| A5 | CLI, JSON, Serve, and Mac projections distinguish derived wave completion from execution authorization and show the exact action needed. | API/UI contract tests and golden output. |
| A6 | Interactive direct work remains outside wave/daemon authorization: an explicit user request may execute held/backlog tasks after checking live ownership, without attempting a daemon claim. | Skill and execution-mode assertions. |

## Non-goals

- Starting a foreground daemon or spawning ad hoc nested model workers.
- Weakening task acceptance/proof requirements to make preflight green.
- Treating task creation or `automation plan` as execution authorization.

## Operator artifact

Side-by-side green and blocked preflight reports showing the authorized task
fingerprint, DAG frontier, runner/service health, and exact remediation.
