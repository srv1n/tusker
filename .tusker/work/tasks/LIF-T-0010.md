# LIF-T-0010 · Add run inspector with resume, deliverable, and authorization details

## Intent

Turn Run Detail into the operator's single trustworthy explanation of who authorized work, where it ran, how to resume it, what it changed, what was verified, and why it ended. Use normalized runtime data; do not scrape raw logs or imply that process activity equals delivery.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Run Detail displays task/project, authorization source and actor, runner/profile, registered repository, physical workspace/mode, session id, lifecycle timestamps, heartbeat freshness, and normalized outcome. | focused_test |
| A2 | Supported sessions provide a working runner-specific resume action and copyable command; unavailable resume explains whether the session, process, or workspace is missing. | focused_test |
| A3 | Delivery is a separate section showing changed-file/diff summary or artifact, acceptance-mapped verification, proof status, and explicit `no deliverable` when none exists. | focused_test |
| A4 | Failure/interruption displays a bounded reason and retry/reclaim eligibility without dumping transcripts or cumulative token noise. | focused_test |
| A5 | Interrupt and redrive actions refresh canonical state, obey ownership/concurrency policy, and cannot operate on the wrong attempt. | focused_test |
| A6 | Responsive UI tests cover shared/worktree, live/stale/terminal, resumable/unavailable, delivered/empty combinations. | broad_test |

## Non-goals

- Do not expose raw runner transcripts or secret-bearing environment/commands.
- Do not claim a session is resumable without a stable harness session id and existing workspace.
- Do not show aggregate token totals in this view.
