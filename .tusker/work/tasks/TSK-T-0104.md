## Intent
Superseding a doc today takes three manual edits: write the new doc,
set the old doc's `status: superseded`, and add `superseded_by`. A
missed edit leaves two "current" docs. Add
`tusker docs new <subject> --kind <kind> --supersedes <old-subject>`
that does all of it in one transaction.

## Verified seams
- `docs new` is implemented in `cmd/tusker/docs_cmd.go` (front matter
  template near line 500).
- Use the existing document write transaction in
  `cmd/tusker/v7_document_transaction.go` / `v7_document_write.go`, so
  both files are written or neither is.
- `superseded_by` is already validated by `docgraph` (successor must
  exist) and resolved by `resolver.go`.

## Writes
- New doc: `supersedes: <old-subject>` in front matter, plus a body
  line linking the old doc.
- Old doc: `status: superseded`, `superseded_by: <new-subject>`. Leave
  its body unchanged.

## Edge and failure cases
- Old subject does not exist: refuse, write nothing.
- Old doc already superseded: refuse and name its current successor.
- Old doc kind differs from `--kind`: refuse unless both are in the
  same family (decision to decision, doc to doc, proposal to proposal).
- Old doc has uncommitted changes: refuse, as other document writes do.
- `--print` previews both writes without writing.
