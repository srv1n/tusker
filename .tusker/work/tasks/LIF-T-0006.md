# LIF-T-0006 · Teach Codex and Claude skills the claimed-run protocol

## Intent

Update the canonical Tusker operator skill and generated Codex/Claude installations so manually initiated agents participate in the same run lifecycle as daemon runners. The protocol must be terse, executable, and impossible to confuse with a durable `active` task status.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Canonical skill instructions require task resolution and successful claim/preflight before implementation edits, then submit or fail on every normal terminal path. | focused_test |
| A2 | Codex and Claude installed skills are produced through `tusker skill sync`; generated copies are not hand-maintained and both expose the same lifecycle semantics and exact commands. | focused_test |
| A3 | Claim refusal tells the agent to stop duplicate implementation and reports the owning run/session/workspace or an exact resume path. | focused_test |
| A4 | The protocol explains that durable task status remains ready/rework while live execution is represented by the run lease; agents never write `active` or `in_progress` into task frontmatter. | focused_test |
| A5 | Skill fixtures/tests cover manual pickup, successful submission, explicit failure, and abrupt termination handled later by heartbeat expiry. | broad_test |

## Non-goals

- Do not duplicate project-specific canon into the generic operator skill.
- Do not directly patch generated `.agents/skills` or `.claude/skills` copies.
- Do not require human gates or manual status bookkeeping for routine execution.
