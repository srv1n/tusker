# SRV-T-0002 · Implement read-only tusker serve MVP

## Intent

Implement `tusker serve` per the approved spec (SRV-T-0001 / `docs/specs/10-tusker-serve.md`): a React + Vite + TanStack Router/Query + Tailwind SPA, built to static assets and embedded in the Go binary via go:embed, backed by a read-only JSON API over the SQLite runtime store and vault markdown. MVP views: needs-me queue (human gates, `waiting_on_human`, failed runs), active runs with attempt status and token totals, task/epic browser with rendered contracts, and evidence per task. Default bind `127.0.0.1`; no runtime CDN fetches; `make check` must not require node — the built assets are committed or built via a separate make target per the spec.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `tusker serve` starts against this repo's vault and runtime store and serves the four MVP views from the embedded SPA. | Inline verification |
| A2 | The needs-me queue lists `waiting_on_human` tasks, blocking gates, and failed runs, most-urgent first. | Inline verification |
| A3 | The JSON API has zero mutating endpoints; bind address defaults to localhost; the page loads with no external network requests. | Inline verification |
| A4 | Frontend builds reproducibly via pnpm + Vite and embeds via go:embed; single-binary distribution is preserved. | Inline verification |
| A5 | New Go and TS code respects the 1,000-line file guideline and the full suite is green. | Inline verification |

## Non-goals

- No editing surface (SRV-T-0003), no auth, no remote binding.
- No parity with Obsidian views; authoring stays in markdown.
