# SRV-T-0002 · Implement read-only tusker serve MVP

## Intent

Operator decision (2026-07-06): this task no longer waits for the SRV-T-0001 spec. The operator wants real data flowing now — no further mock-fixture work anywhere. For the read-only API scope, `internal/serve/ui/BACKEND-GAPS.md` plus `docs/design/serve-ui-supplement.md` are the binding interim contract; the SRV-T-0001 spec proceeds in parallel and any divergence it identifies is reconciled at review. The owner-approval gate that used to sit before this task now gates the write surface (SRV-T-0003/SRV-T-0004) instead.

Implement the `tusker serve` backend. Scope shift (2026-07-06): the SPA already exists — built front-end-first at `internal/serve/ui` (React + Vite + TanStack Router/Query + Tailwind, Bun tooling) against a typed in-browser mock. This task is therefore the truth side, not the pixels: a read-only JSON API over the SQLite runtime store and vault markdown, go:embed of the built assets, and flipping the UI's `src/lib/api.ts` seam from mock to real per endpoint. The API contract is already written down and must be honored, not reinvented: `internal/serve/ui/BACKEND-GAPS.md` (endpoint table §4, missing-fields list §3) with `src/types/domain.ts` as the wire shapes, both aligned with `docs/design/serve-ui-supplement.md`. Default bind `127.0.0.1`; no runtime CDN fetches; `make check` must not require Bun/node — built assets are committed or built via a separate make target per the spec. Polling refresh is acceptable for the MVP; SSE is a follow-up unless the spec says otherwise.
