## Intent
The run detail endpoint never sends `controls.capabilities`, so the UI (`SessionRecoveryControls.capabilityFor`) falls back to client guesses: Continue is enabled whenever `resume.supported` although `queueNativeSessionContinuation` refuses for live owners, review lane, succeeded attempts, fingerprint mismatch or stale wave authorization; Recover ignores `run.Terminal`; pending Stop is invisible after reload. The UI also reads activity freshness fields the server never sends, and merged events are not ordered. The spec requires allowed actions computed by the same preflight the action endpoint uses.

## Verified seams
- `handleRun` (serve_command.go ~1650) builds `serveRunDetail` (serve_types.go ~520) with `Resume: resumeCapability(&run, session)` and `Events: serveRunEvents(...)`; no controls.
- `resumeCapability` (run_runtime_commands.go ~69) returns Supported for codex_exec/muse/devin with a display command `codex exec resume '<id>'` (wrong order; see codex-exec-durability) and no Claude case.
- Action endpoint: `handleRunSessionControl` (serve_actions.go ~164) → `handleRunStopControl` (~245), `handleRunFreshControl` (~323); continue → `queueNativeSessionContinuation` (work_recovery.go ~144); recover_context → `queueOutcomeUnknownContextRecovery` (work_recovery.go ~18). `nativeResumeRunnerCapabilities` (work_recovery.go ~277) lacks Claude.
- Pending intent: `loadRunSessionControlIntent` (run_session_controls.go ~49), read-only here.
- `serveRunEvents` (serve_runs.go ~354) appends event-log activity then CLI raw-log activity with no ordering; CLI events often have empty TS.
- UI contract already declared in internal/serve/ui/src/types/domain.ts: `RunControlProjection {capabilities, pending, readback, checkpoint}`, `RunActionCapability {action, available, reason}`, `RunActivityFreshness`, plus `lastMessageAt`, `messageAgeSec`, `activityCaptureState`, `heartbeatAgeSec` on RunSummary.

## Implementation contract
Locked:
- Extract a pure preflight per action — `continue`, `recover_context`, `stop`, `start_fresh`, `reconnect`, `pause` — returning `(available bool, reason string)`, and call the SAME function from both the action handler and `handleRun`. The mutating paths keep their CAS/idempotency; only the refusal decision is shared. No second copy of the rules.
- `handleRun` returns `controls: {capabilities: [...all six actions...], pending: <current stop/fresh intent if unresolved>}` using the domain.ts field names. `pause` is always unavailable with the reason that no harness acknowledges durable pause.
- Add activity freshness to run summary/detail: `activity {captureState, heartbeatAt, messageAt, toolAt, *AgeSec}` and the flat aliases the UI reads. Silence is reported, never inferred as hung. Timestamps come from recorded events; never invented.
- `serveRunEvents`: stable-sort the merged list by TS; events with empty TS keep capture order relative to their source and sort after the last timestamped event that preceded them in that source (proposed: inherit predecessor TS for ordering only; the wire TS stays empty).
- `resumeCapability`: codex display command becomes `codex exec <flags> resume <id> -` shape (or omit the command when the flags are not known); add `RunnerClaude` driven by `(&ClaudeRunner{}).Capabilities().ResumeSession`; `nativeResumeRunnerCapabilities` adds the same Claude case, so Claude Continue turns on automatically when claude-detached-session lands and stays refused before.
- Keep `resume` in the payload for older clients.

## Failure and edge cases
- Live owner (process identity matches) + resume supported → continue.available=false with the exact handler refusal text; forbidden: available=true.
- Review-lane run, succeeded attempt, missing session ref, stale wave authorization, fingerprint mismatch → each maps to the same reason string the POST returns (table-driven test: GET capability reason == POST refusal reason).
- Terminal run with outcome-unknown → recover_context available; terminal succeeded → not available.
- Stop POSTed, then GET → `controls.pending.action == "stop"` until settled; after daemon settlement pending disappears.
- Race: capability computed available, state changes, POST → POST refuses (handler re-runs preflight); GET afterwards reflects the refusal.
- Events: event-log item at 10:00:05 and a CLI item without TS captured after a 10:00:03 CLI item → order 10:00:03, (empty), 10:00:05 stable across repeated reads.
