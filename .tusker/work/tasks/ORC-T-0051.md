# ORC-T-0051 · Discover harness capabilities and bootstrap semantic profiles

## Intent

Tusker exposes a provider-neutral local capability catalog and can preview or write deterministic semantic runner profiles without overwriting explicit policy or enabling automation.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Catalog JSON isolates per-harness success/failure and records model, effort, known service tiers, default/hidden state, source, confidence, CLI version, and observation time; inspection performs no authentication, configuration write, or model launch. | See mapped verification. |
| A2 | Codex parses the installed CLI live catalog and explicitly labels bundled fallback; Claude returns only declared aliases and supported efforts with lower confidence because no machine-readable model-list endpoint exists. | See mapped verification. |
| A3 | Fresh init writes a balanced semantic role set when capabilities permit, and explicit profile bootstrap supports dry-run/write while preserving existing explicit profiles, routing, and `automation.enabled: false`. | See mapped verification. |
| A4 | Profile validation accepts low, medium, high, xhigh, max, and ultra where configured, rejects unknown effort strings, and task complexity accepts only routine, standard, complex, or frontier. | See mapped verification. |
