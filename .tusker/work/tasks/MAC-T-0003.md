# MAC-T-0003 · SSE client + UNUserNotificationCenter notifications + status item badge

## Intent

The payoff feature: the daemon does work in the background; the human gets a native, clickable notification when something needs them, and the status item shows how much is waiting. Builds on the panel (MAC-T-0001) and codes strictly against the event contract from SRV-T-0024 (read its contract doc first; do not reverse-engineer payloads from Go source).

- **SSE client**: consume `<baseURL>/api/stream` with `URLSession.bytes(for:)` and an incremental SSE parser (handle `data:`/`event:`/`id:` lines, multi-line data, comments/keep-alives). Reconnect forever with jittered exponential backoff (cap ~30s); on reconnect use the monotonic event `id` to drop replays per the contract doc. Connection state surfaces as a subtle status-item indicator change (e.g. dimmed icon when disconnected).
- **Notifications** via `UNUserNotificationCenter` (remember: only works from the signed `.app` bundle):
  - Request authorization on first bundle launch; if denied, degrade silently to badge-only and say so in Settings.
  - Notify on contract kinds with urgency `attention` and `critical` by default (task waiting on human, review batch ready, run failed). `info` events are badge-only by default.
  - Per-kind toggles in a "Notifications" section of the Settings window from MAC-T-0002.
  - `threadIdentifier = task_id` so repeated events for one task group; set `interruptionLevel` `.timeSensitive` for `critical`, `.active` otherwise.
  - A notification category with a default click action and an explicit "Open" button: activating either summons the panel (via `PanelController.show(path:)`) navigated to the event's `deep_link_path`. Do not open the browser.
  - De-dup: never post two visible notifications for the same (task_id, kind) while an earlier one is undelivered/uncleared; update instead (stable notification identifier).
- **Badge**: fetch `<baseURL>/api/summary` on connect and after every relevant stream event (debounced, e.g. 500ms); render `attention + review` as a count next to the status item icon (`NSStatusItem.button` attributed title). Zero renders as no text. If the Dock icon is enabled (MAC-T-0002), mirror the count via `NSApp.dockTile.badgeLabel`.

Keep the SSE parser and event→notification mapping as pure, unit-testable Swift types (no AppKit imports) so `swift test` can cover them.

## Non-goals

- No `tusker://` scheme or JS bridge (MAC-T-0004) — notification activation calls the panel controller directly.
- No approve/reject action buttons on notifications (write actions come later, if ever, behind the review-batch flow).
- No polling fallback beyond `/api/summary` refresh; SSE is the transport.
