# RUN-T-0039 · Close ceremony leaves live runtime rows: terminal tasks trip the invariant circuit and freeze fleet dispatch

## Intent

Found in today's land-wave close ceremony (2026-07-08). After RUN-T-0034, OPS-T-0002, and SRV-T-0008 were closed via `tusker close`, the daemon.db runs table still held non-terminal rows for 13 tasks whose canonical status was already done/cancelled/backlog: CLN-T-0001, SRV-T-0007, RUN-T-0010/0011/0012/0013/0017/0026/0027/0034/0035/0036/0037, plus backlog rows SRV-T-0001 and CLN-T-0002. The daemon opened the invariant circuit — `invariant_violation: held lease task is not dispatch-eligible; repair stale terminal records with tusker runs retire` — and froze ALL fleet dispatch until an operator manually retired 15 rows and ran `daemon resume`. RUN-T-0037 built canonical-terminal retirement, but only on the RUNNER-observation path; operator `tusker close` and the reconcile tick never sweep runtime rows, so a clean operator close strands live leases behind terminal tasks and the circuit becomes routine hand-repair.

Semantics:

1. **Close authority.** Closing or cancelling a task retires its non-terminal runtime rows in the same operation — OR the daemon's reconcile tick sweeps any runtime row whose canonical task is terminal (done/cancelled/backlog). Pick one authority and make it the sole owner of the sweep; do not split it across both.
2. **Auditability.** Each retirement records who and why (e.g. `retired by close ceremony: canonical status done`), so a post-mortem can tell an operator-close retirement from a runner-observed one.
3. **Circuit stays last-resort.** The invariant circuit remains containment of last resort for any row the chosen authority somehow misses; it is not the mechanism operators must hand-repair on every close.
