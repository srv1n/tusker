# ORC-T-0031 · Produce a bounded deterministic planning-context packet

## Intent

An agent can ground a delivery DAG in current repository facts through one read-only packet instead of broad source or tracker excavation.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The context packet binds project identity, governing spec fingerprints, relevant epic and duplicate clues, routed knowledge, test and gate commands, runners, workspace and landing policy, protected refs, and known shared resources. | See mapped verification. |
| A2 | Context selection is bounded to cited specs and routed domains and excludes secrets, environment values, raw logs, transcripts, unrelated tasks, and broad source contents. | See mapped verification. |
| A3 | Missing test, runner, knowledge, or project facts remain typed unknowns with actionable discovery or gate remedies and are never converted to invented verification. | See mapped verification. |
| A4 | Human-readable and stable JSON outputs explain provenance for every resolved fact and remain entirely read-only when project automation or the daemon is enabled. | See mapped verification. |
| A5 | Repeated context generation on unchanged inputs is stable and a material spec, configuration, test-command, or relevant knowledge change produces a new context fingerprint. | See mapped verification. |
