## Intent
A chapter or decision can claim to be current or accepted without
saying which code it governs, so no drift check can see it. Today only
`code_conformance: matches` requires `describes` (`checkConformance` in
`internal/docgraph/docgraph.go`).

## Rule
In `validateHeader` (or next to `checkConformance`), raise
`DOC_DESCRIBES_REQUIRED` when `describes` is empty and the document is:
a chapter with lifecycle `current` or legacy `canonical`; a decision or
proposal with lifecycle `accepted`; or any doc with
`code_conformance: matches` (keep the existing message for that case).
Proposed: `code_conformance: not_applicable` exempts the doc, for
chapters that describe no code (vision, glossary, index).

## Repo backfill
A scan on 2026-10-05 found three accepted/current docs with no
`describes`: `docs/system/proposals/task-states.md`,
`docs/system/proposals/00-index.md`,
`docs/system/proposals/kill-switch-and-access.md`. The 16 `canonical`
chapters must also be checked. Add real `describes` paths, or set
`code_conformance: not_applicable` for docs that describe no code.
