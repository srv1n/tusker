## Intent
`YieldSender` is stored and never read. When an answer arrives for a live worker, processAgentWakeups only knows Codex app-server steering; for a finished worker it queues continuation, but nothing stops the normal retry path from treating "ended turn while waiting" as a failure. Make one deterministic route from answer to the waiting worker. Also stop the daemon from overwriting a hook-delivered message as 'unsupported'.

Cross-wave: depends on wave B `say-cli` (B3, hard say = interrupt + resume same native thread) and `run-state` ("Waiting on you" derivation). This task calls them; it does not reimplement either.

## Verified seams
- `agent_coordination.go processAgentWakeups` (task branch -> QueueAgentContinuation; execution branch -> codexLiveHandle only; execution without AttemptID -> transport 'unsupported'); `QueueAgentContinuation`; `SetAgentWakeupClaimState`.
- `agent_messages.go putAgentAnswer` queues the wakeup for the original sender.
- `workerSoftDelivery` (message-inbox); MCP ask semantics and YieldSender = wait requested (mcp-server).
- daemon.go: locate the retry/settlement seam that schedules the next attempt after an attempt settles (verify by name; `PollOnce` ~708 calls processAgentWakeups then pollOnce).

## Implementation contract
Locked routing for an `answer` wakeup to task:<item> whose parent question is unanswered-before-now:
1. Parent question already consumed its answer via the MCP wait (answer consumed_at set) => wakeup 'delivered', nothing else.
2. Live owner and workerSoftDelivery(harness) supported => wakeup 'held'; the PostToolUse hook or check_messages delivers. If the answer is still undelivered after a 120s grace, escalate to 3.
3. Live owner, soft unsupported (or grace expired) => call B3 hard say with the answer text addressed to that attempt; success => 'delivered' and message transport 'delivered'; B3 refusal => 'held' with its reason; uncertain => 'uncertain' (no blind resend).
4. No live owner => existing QueueAgentContinuation (same-session continue, TSK-T-0051) => 'scheduled'.
- A settled attempt whose task has an open question it sent with YieldSender=true and no answer is parked as waiting (no retry, no failure count, no budget spend); B run-state shows "Waiting on you" from that open question. The answer then takes route 4. Deduplicate by the existing one-wakeup-per-message key; a repeated answer notification adds no delivery.
- Execution recipients that are registered interactive sessions (Source direct_claude|direct_codex, no AttemptID): wakeup 'held' with reason "delivered by session inbox hook"; never overwrite a message whose transport_state is already 'delivered' or which is consumed. direct_devin stays 'unsupported'.
- Codex app-server steering branch is left as an optional driver, unchanged.
Proposed: where the grace timestamp is read from (message CreatedAt is sufficient; no new column).

## Failure and edge cases
- Reply before yield: answer exists when the worker's ask returns => worker gets it inline; wakeup marks delivered; no say, no continuation.
- Answer arrives while the worker is mid-tool on Claude: soft path; forbidden: hard interrupt within the grace.
- Answer for superseded work (WorkRevision/lease generation changed): existing stale handling; forbidden: delivering into the new attempt as if applicable.
- Worker process ends between route decision and say: B3 refuses => held; next poll takes route 4.
- Daemon restart after say succeeded but before the wakeup update: wakeup reclaimed after the 1-minute claim expiry; say idempotency (B3) prevents a second interrupt; if B3 cannot prove it, state 'uncertain'.
- Two answers to one question: first applies; second is visible, not delivered twice.
- Operator stop: stopped runs are never continued by an answer.
