# RUN-T-0001 · Bring the Claude Code runner to parity with codex_app_server

## Intent

Codex app-server is the first-class runner today; Claude Code should be a co-equal citizen so both harnesses can co-live and tasks can route to either. The Claude runner (`runner_claude_live.go`) already drives `claude -p` stream-json but has known gaps versus `codex_app_server`: the native extension bridge is marked not implemented, reconcile continuity is "best-effort", and session resume, interrupt, approval handling, and usage metrics are weaker. Close the gap to a shared capability bar: Start/Resume/Reconcile/Interrupt/Collect all functional, structured events with machine-readable final status, per-attempt token usage captured, and resume surviving a daemon restart. Prove it by running the same fixture task end-to-end (execute lane through review lane) on both runners.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A capability matrix (recorded as evidence) shows claude-code matching codex_app_server on every capability the daemon uses: start, resume, reconcile, interrupt, collect, structured final status, token usage. | Evidence card |
| A2 | The same fixture task completes end-to-end on the claude-code runner: dispatch, worktree, attempt events, review-lane promotion. | Inline verification |
| A3 | Session resume works across a daemon restart on the claude-code runner; interrupt cleanly abandons an attempt. | Inline verification |
| A4 | Per-attempt token usage from Claude stream-json is recorded in the runtime store and appears in the review packet. | Inline verification |

## Non-goals

- No new harnesses beyond Claude Code (RUN-T-0003 documents the seam).
- No profile/model selection work (RUN-T-0002).
