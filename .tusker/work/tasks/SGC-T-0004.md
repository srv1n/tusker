# SGC-T-0004 · Refuse terminal task transitions while a verified-live runner holds the task

## Intent

- What this is: closing or discarding a task must not quietly abandon a runner
  that is still running for it. Today the terminal transition retires the run
  record and wipes the stored process identity without stopping the process,
  and the scratch cleanup that follows can delete files that process is still
  writing.
- Why it matters: the operator is left with an orphaned process nobody can stop
  (its process identity has been erased) that is writing into files that no
  longer exist. This predates scratch cleanup, but cleanup makes it destructive
  instead of merely untidy.
- What "done" looks like: closing or discarding a task with a live runner either
  stops that runner first and confirms it exited, or refuses with a clear
  instruction to interrupt the run. Process identity is never cleared before
  termination is confirmed.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Closing or discarding a task whose runner is verified live either stops the runner and confirms exit, or refuses with an actionable message. | See mapped verification. |
| A2 | Stored process identity is never cleared while the process is still alive. | See mapped verification. |
| A3 | Retiring a queued or already-dead run is unaffected. | See mapped verification. |

## Non-goals

- Scratch cleanup policy itself (already shipped in SGC-T-0001).
- Coordinating the age-based sweep with the daemon (SGC-T-0005).

## Implementation notes

Builder appendix. Raised as a HIGH finding by an external review of the SGC
epic on 2026-08-05; verified against the code before filing.

- The standalone path `retireCanonicalRuntimeRows` (`cmd/tusker/runtime_terminal_retirement.go`)
  calls `retireRuntimeRun(..., true)` directly. The daemon equivalent
  `Daemon.retireCanonicalRuntimeRun` calls `stopRunExecution` first. The
  standalone path is the gap.
- `retireRuntimeRun` marks the run terminal and clears `ProcessPID` /
  `ProcessPGID` without killing anything.
- Callers to fix: `cmd/tusker/v7_control_cmd.go` (manual close) and
  `cmd/tusker/v7_discard_cmd.go` (discard), both via
  `retireCanonicalRuntimeRowsForTask`. The check must happen BEFORE the terminal
  projection is committed, not after.
- Reuse the existing process-identity verification and the `tusker runs interrupt`
  remedy rather than inventing a new one.
- Name new tests with the substring `LiveRunnerRetirement`.

## Knowledge delta

Terminal task transitions and runner liveness are coupled: retiring a run record
clears the only stored process identity, so anything that retires a live run
destroys the ability to stop it afterwards. Record the rule that liveness is
checked before the terminal projection commits, not after.
