# RUN-T-0042 · Runner review-flip is worktree-local: completion classifier reads canonical, misfires early_exit, finished work churns to park

## Intent

Found in the 2026-07-08 dogfood: five freshly-dispatched tasks (RUN-T-0038/0039/0040/0041, SRV-T-0014) each did complete, on-contract work in their worktrees — 8–13 changed files, focused tests green — then **parked at the continuation cap** with `runner early exit while tracker still active`. None reached canonical review; all had to be snapshotted and hand-landed. Root cause is the write-side mirror of the bug RUN-T-0037 fixed on the read side.

The seam: a runner finishes, runs `tusker finish --request-review`, which flips the tracker to `review` and records verification rows — but those writes land in the **worktree-local** `.tusker/` copy, which is attempt-local scratch until merged (RUN-T-0037 canon). The daemon's completion classifier then consults the **canonical** vault to decide whether the attempt completed; canonical is still `ready` (the flip is unlanded), so the clean exit is scored `early_exit`, a continuation is queued, the re-dispatched runner finds its own worktree already done and exits again, and the row churns to the park guard. The completion signal never crosses from worktree to daemon. Land being broken (OPS-T-0006) means canonical never catches up on its own, so the churn is deterministic, not a race.

Semantics — the runner's review-request must produce a **run-level completion signal the daemon sees without waiting for the flip to reach canonical**:

1. When a runner exits cleanly after requesting review (worktree tracker now `review`/`done`, proof satisfied), the attempt outcome is a terminal completion (`succeeded` / `waiting_for_review`) — not `early_exit`. The classifier's "is this done?" test must read a signal the runner controls at exit (wrapper-reported request-review marker, or the worktree tracker state it just wrote), not solely canonical state it cannot yet write.
2. A task whose worktree holds a pending (unlanded) review flip is **not re-dispatched**. Either the completion in (1) releases the lease terminally so no continuation is queued, or the dispatch gate treats worktree-review as do-not-dispatch until the work lands. Pick one authority consistent with RUN-T-0037.
3. The blocker/outcome text distinguishes a genuine no-progress early exit (real churn) from a review-complete exit (finished, awaiting land) so the UI and post-mortems never again read "parked" as "failed" when the work is done.
4. **Design decision required from the owner (see Non-goals / linked conflict):** this seam overlaps the invariant-circuit timing that RUN-T-0033 and RUN-T-0039 disagreed on. RUN-T-0039 (landed) opens the circuit immediately when a held lease sits on a not-dispatch-eligible recently-updated review task; RUN-T-0033 (reverted at cf82a1e) suppressed that for a ~2-poll convergence grace window after `updated_at`. The completion signal in (1)+(2) may make the grace window unnecessary, or the grace window may be the chosen mechanism. The implementer must resolve which one owns the "fresh review flip" moment, and the fix here must stay consistent with whichever the owner picks — it cannot silently re-break RUN-T-0039's `TestCloseRetirementKeepsInvariantCircuitOpen`.
