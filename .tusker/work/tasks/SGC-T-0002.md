# SGC-T-0002 · Add scratch garbage collection command

## Intent

- What this is: a cleanup command that sweeps a project's scratch area,
  deleting any top-level entry whose newest content is older than a
  configurable age — fourteen days by default. It previews what it would
  delete by default and only acts when explicitly confirmed.
- Why it matters: closing tasks only cleans task-owned folders. The real disk
  audit showed the biggest offenders were hand-named working folders that no
  task close would ever touch — hundreds of megabytes of week-old rejected
  audio renders.
- What "done" looks like: running the cleanup shows a list of stale scratch
  entries with sizes and ages, deletes nothing until confirmed, and after
  confirmation the listed entries are gone and everything newer is untouched.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The default run lists stale scratch entries with size and age and deletes nothing. | See mapped verification. |
| A2 | A confirmed run deletes exactly the listed entries — anything newer than the age limit survives, task-keyed or not. | See mapped verification. |
| A3 | The age limit is configurable and defaults to fourteen days. | See mapped verification. |

## Non-goals

- Scheduling the sweep from the daemon (deferred in the spec).
- Doctor integration (SGC-T-0003).

## Implementation notes

Builder appendix — verify paths before editing; line numbers are from a
2026-08-04 read and may have drifted.

- New `tusker gc` command (or `tusker scratch gc`; keep the surface small).
  Dry-run by default, `--yes` applies, `--ttl` overrides the 14-day default.
  Staleness of a top-level entry = newest mtime within it.
- Reuse the deletion engine from SGC-T-0001 (spec decision 6). The dry-run
  action-list shape in `cmd/tusker/purge.go:67` (`planTuskerPurge` /
  `applyTuskerPurge`, `tuskerPurgeAction{Kind, Path, Reason}`) is the shape
  precedent — follow it, don't necessarily share code.
- Wire the command in `cmd/tusker/cli.go` next to the other maintenance
  commands (best guess; check how `purge` registers).
- Name new tests with the substring `ScratchGC` (e.g.
  `TestScratchGCDryRunListsStaleEntries`, `TestScratchGCAppliesWithYes`,
  `TestScratchGCSparesFreshEntries`).
