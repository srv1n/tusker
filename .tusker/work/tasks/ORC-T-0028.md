# ORC-T-0028 · Prove default-off safety, shadow parity, recovery, and cutover

## Intent

Failure-injection and migration proof demonstrate that Tusker can replace an existing conductor without a cadence gap or unauthorized side effect.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A repository with absent or disabled configuration experiences zero departure wakeups, Git fetches, records, branch movement, model launches, release attempts, notifications, or misleading UI pending state. | See mapped verification. |
| A2 | Shadow comparison covers empty cargo, eligible cargo, holds, offline fetch, ungated main, restart, duplicate trigger, red gate, and green promotion with exact decision diffs. | See mapped verification. |
| A3 | Crash injection at evaluating, staging, gating, promoting, releasing, and terminal persistence converges without duplicate main movement, release, notification, or repair task. | See mapped verification. |
| A4 | A standalone task completes the zero-ceremony path from finish through review, staging, scheduled full gate, main promotion, and morning brief. | See mapped verification. |
| A5 | Two projects contending for one heavy resource serialize correctly while independent light work continues. | See mapped verification. |
| A6 | The cutover runbook keeps the legacy conductor authoritative until representative parity passes, disables it only after Tusker becomes authoritative, and preserves one rollback window. | See mapped verification. |
