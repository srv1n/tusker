## Intent
Run detail showed `Attempt 1 succeeded` and `Attempt 2 running` while the product was simply moving from implementation to independent review. It looked like an unexplained retry and offered weak navigation back to the wave.

## Implementation contract
Present the ordinary lifecycle as named stages: Implementation, Verification, Independent review and Completed. Attempt numbering is secondary and scoped to a lane, e.g. `Implementation · try 2`, only when a stage genuinely retried. A successful implementation followed by a running reviewer must never appear as two generic attempts.

The current stage, elapsed/liveness and applicable action remain prominent. Collapse raw event names, session IDs and workspace paths under Technical. Explain a real retry with its recorded reason; never infer failure merely from count. Interrupt and Redrive appear only when valid and explain consequence/refusal in plain language.

`Back to wave` returns to the originating wave's Dependencies/DAG view with the previously selected task/viewport when that navigation context exists. A direct task URL falls back to the task overview. Do not add a second history store; use current route state/query parameters.
