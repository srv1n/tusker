# RUN-T-0015 · Daemon under launchd: self-healing resident process with watchdog

## Intent

Binding design: `docs/design/prior-art-playbook.md` §2 (daemon self-supervision row) and §4 gap 5. The daemon died silently on 2026-07-06 morning and nobody noticed for hours ("who supervises the supervisor"). systemd answered this decades ago; on macOS the equivalent is launchd. The daemon must be a managed service: crashes restart it (bounded, never hot-looping), hangs are detected (a watchdog fed by the reconcile tick, so "alive" means "reconciling", not "process exists"), and a crash-loop ends in a loud failed state instead of thrash.

Scope:

1. `tusker daemon install` / `tusker daemon uninstall`: writes/removes a per-user launchd agent plist (`~/Library/LaunchAgents/`) with `KeepAlive` on abnormal exit, `ThrottleInterval` ≥ 10s, stdout/stderr to the daemon log path. Idempotent; `install` on an already-installed daemon updates in place.
2. Watchdog: the RUN-T-0011 reconcile tick already emits a beat; add a self-check — if the beat is older than 3 ticks, the daemon exits abnormally (deadlocked loop → launchd restarts it; the RUN-T-0011 boot adoption + sweep makes restart safe by construction).
3. Crash-loop breaker: track restart timestamps in the daemon state root; more than 5 abnormal starts in 10 minutes ⇒ the daemon starts in circuit-open mode (no dispatch, reads only, red banner with reason `crash_loop`) instead of thrashing — the launchd analog of systemd `StartLimitBurst`, implemented daemon-side since launchd's own limiter is weaker.
4. `tusker daemon status` distinguishes: managed-by-launchd vs manually-run, last restart cause, crash-loop state.
5. Uninstalled/manual mode keeps working exactly as today (tests and dev loops must not require launchd).
