## Intent
The run detail shows lease and a fresh/stale/dead liveness dot, with no typed reason and no way to message the agent. Operators need the same six-state model the CLI now has, the reason and guidance, and a Say box whose delivery note is honest per driver. The UI must not guess: state, allowed actions and delivery route come from the server.

## Verified seams
- `serveRunSummary` (serve_types.go) and `runSummaryChecked`, `serveRunLiveness` (serve_runs.go). Wave A (A:run-controls-backend) adds server-projected allowed actions and freshness fields to this summary first.
- Action routing: serve_actions.go `case len(parts) == 4 && parts[1] == "runs" ...` (redrive, recover, control, pause/stop/start-fresh); interrupt route `serveRunInterruptTaskID` (serve_command.go). Operator identity: `s.serveOperatorActor`.
- UI: `RunDetail.tsx`, `detail/RunHeader.tsx` (renders `LivenessIndicator`), `lib/api.ts` (`interrupt`), `types/domain.ts`. Wave A's UI task edits RunDetail.tsx and SessionRecoveryControls.tsx first.
- Backend functions from this wave: `deriveRunOperatorState` (run_state.go), say/continue functions in run_say.go.

## Implementation contract
Locked:
- Summary adds `operatorState` (same object as the CLI `operator_state`) and `sayRoute` computed from runner capabilities: `soft` (note "Delivered between tool calls"), `hard` (note "Interrupts the agent, then resumes the same conversation with your message"), or `none` with the declared reason. The allowed-action list from wave A is aligned so Say appears only in working/quiet, Answer only in waiting_on_you, Continue only in blocked/failed/lost, exactly as the spec table; the same preflight function backs the endpoint and the projection.
- `POST /api/runs/:taskId/say?project=` body `{message, idempotencyKey}` and `POST /api/runs/:taskId/continue?project=` body `{message?}` delegate to the run_say.go functions and return canonical readback (delivery, route, operatorState). The existing `recover` action `continue` keeps working and shares the same function.
- `serveRunLiveness` no longer returns `dead` from silence alone; silence maps to the quiet state. The liveness dot, if kept, reads from operatorState.
- UI: RunHeader shows a state badge (text plus icon, not color alone); Blocked/Failed/Lost show the reason guidance sentence and the raw code only in a secondary detail; RunSayBox shows the server-provided note, disables send while a request is in flight, reuses the idempotency key on retry of the same text, and shows accepted/uncertain/refused from readback.
- Quiet never renders hang language.

## Failure and edge cases
- Double-click Send: one delivery (same idempotency key); the second response shows duplicate, not an error.
- Server returns refused (state changed to failed): the box shows the refusal reason and the Continue action from the fresh allowed-actions list.
- Run with sayRoute none: box hidden, reason shown.
- Response lost, page reloaded: readback shows the stored delivery; no resend.
- Stale snapshot (run advanced to a new attempt): endpoint refuses by fence; UI refreshes.
