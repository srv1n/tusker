# KNW-T-0003 · Doc-touch drift warning at task close

## Intent

- What this is: when a task finishes, Tusker checks whether the code the task
  changed is code that a reference document claims to describe. If so, the
  task must either have updated that document in the same change or carry a
  one-line note saying "document unchanged because <honest reason>". For
  now a missing answer produces a loud warning; a configuration switch will
  later turn it into a hard stop.
- Why it matters: documentation rots at exactly one moment — when code
  changes and the description doesn't. Catching it inside the task, while
  the author still has full context, makes the fix a two-minute edit instead
  of a later archaeology project.
- What "done" looks like: closing a task whose changes touch described code
  without a doc edit or waiver prints a precise warning naming the document
  and the touched area; flipping the switch makes the same close refuse; an
  honest one-line waiver always satisfies the check.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The task diff is intersected with every canonical doc's declared code paths; implicated docs are computed correctly for files, directories, and nested paths. | Inline verification |
| A2 | An implicated doc with neither an edit in the diff nor a waiver verification row produces a warning at close naming doc and touched path (warning mode = default). | Inline verification |
| A3 | With the enforcement switch on, the same close is refused with the same named message; a doc edit or a waiver row satisfies it in both modes. | Inline verification |
| A4 | Code paths claimed by no document trigger nothing at close but are listed as coverage gaps by the docs status report (stub acceptable until KNW-T-0004). | Inline verification |

## Non-goals

- No judgment of whether a doc edit is truthful or a waiver honest — that is
  the reviewer lane's checklist line, added to the reviewer prompt here but
  not machine-checked.
- The blocker flip itself is a config change later; this task ships it off.
