## Intent
Doc-touch drift is only checked at task close (`v7DocTouchCheck` in
`cmd/tusker/docs_cmd.go`), and only when the task has a resolvable
source/base commit. A repo without a closing Tusker task gets no check.
Add `tusker docs touch --since <ref> [--json]` that runs the same check
against `git diff --name-only <ref>...HEAD` plus uncommitted changes, so
a pre-merge hook can call it.

## Verified seams
- `docgraph.CheckDocTouch(corpus, changedPaths, waivers)` already returns
  `DocTouchReport.Missing`. Reuse it; do not reimplement path matching.
- `v7DocsTouchRule(vaultPath)` already resolves `docs.touch_rule`
  (warn | block | off, default warn). Reuse it as the per-repo block
  switch.
- Register the subcommand in the table at the top of `docs_cmd.go` and
  add it to the `tusker docs --help` usage list.

## Decisions
Locked: no Tusker task is required; the command takes no task ID.
Locked: exit code is 0 under `warn` (drift printed to stderr) and
nonzero with code `DOC_TOUCH_DRIFT` under `block`; `off` prints nothing
and exits 0.
Proposed: waivers for the standalone command come from repeatable
`--waive <subject>` flags, since there is no task Verification table.

## Edge and failure cases
- `<ref>` does not resolve: fail with a clear error, never treat as "no
  changes".
- Not a git repo: fail with a clear error.
- No document has `describes`: exit 0 silently, matching
  `v7DocTouchCheck`.
- A changed doc itself counts as touched (the doc edit satisfies it).
- Deleted and renamed paths count as changed.
