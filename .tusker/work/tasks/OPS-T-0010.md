# OPS-T-0010 · Make tusker update atomic and refuse self-referential installs

## Intent

`tusker update` assumes the running executable came from a source checkout. For
a release-installed binary, source discovery can resolve to the destination
binary itself. The current installer removes that destination and then creates
a symlink back to the now-missing path, destroying the installed command.
Harden the update/install path so source and destination identity is checked
before mutation and replacement happens atomically. A refused update must leave
the existing executable byte-for-byte intact and explain how to update a
release install.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | When the resolved source executable and destination are the same file/path, update refuses before mutation with an actionable release-install message and the installed executable remains intact. | focused_test |
| A2 | A normal checkout-backed update replaces the destination atomically with the intended executable/symlink and never exposes a missing or self-referential destination. | focused_test |
| A3 | Existing install/update behavior and the full suite remain green. | broad_test |

## Non-goals

- No network downloader or auto-update implementation.
- No release signing or version-policy changes.
- No changes outside the binary install/update path and its tests.
