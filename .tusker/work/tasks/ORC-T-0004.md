# ORC-T-0004 · Schedule the batch gate tier and spawn repair tasks on red

## Intent

Doctrine (`skills/tusker/references/INTEGRATION_MERGE.md`) says full suites are
an unattended batch tier that never blocks a lane. Today that tier exists only
as ad-hoc overnight prompts: on 2026-07-20 a lane babysat a fail-fast full
workspace gate from 02:55 to 05:11, chasing failures one rerun at a time. Make
the batch tier a first-class daemon job: per-project configuration of the gate
command set and canonical feature profile, scheduled once per period, run
unattended. On red, parse the first actionable failures and auto-create repair
task(s) carrying the error excerpt and a link to the gate run; on green, record
the result in the gate ledger (seam: ORC-T-0005). The batch tier never blocks,
reverts, or gates a merge.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A project can configure a batch gate (commands + feature profile + period); the daemon runs it unattended at most once per period and records the outcome. | Inline verification |
| A2 | A red batch run auto-creates a repair task containing the first actionable error excerpt, the failing command, and a reference to the gate run; repeated reds update rather than duplicate the open repair task. | Inline verification |
| A3 | A green batch run is recorded with tree state and profile so an unchanged tree is not re-gated (consumes ORC-T-0005 when available; a local record is acceptable until then). | Inline verification |

## Non-goals

- No external CI-service integration; the resident daemon is the scheduler.
- No merge blocking or auto-revert semantics of any kind.
