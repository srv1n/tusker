# RUN-T-0018 · Repair wrapper-survival seam: daemon death must not read as stop-signal

## Intent

Central-gate failure found at the seam between RUN-T-0011 (owner-scoped heartbeat as stop-signal) and RUN-T-0013 (detached runner wrapper that survives daemon death). Exact evidence from `go test ./e2e/crashrecovery -run TestDaemonKillNineAdoptsSurvivingWrapper`:

- Daemon is killed with SIGKILL while the wrapper's runner child is mid-run.
- Expected (RUN-T-0013 A-criteria): wrapper survives, heartbeats the store **directly** under its lease owner+generation, and the restarted daemon adopts it after verifying pid+start_time.
- Actual: wrapper log ends `runner wrapper stopping: lease heartbeat stopped`; status file records `exit_code: 130`; run record shows `lease_state: released`, `attempt_outcome: failed`, `last_error: "runner exited with code 130"`, `process_pid: 0`. The attempt is dead before the restarted daemon can adopt it.

Diagnosis to confirm: the wrapper is treating *absence of daemon heartbeat renewal* as the stop-signal. That inverts ownership — per the binding design (`docs/design/prior-art-playbook.md` §2 semantics, §3 items 1–2: Beads owner-scoped heartbeat, OpenHands generation fencing), the **wrapper** owns lease heartbeating for its attempt. The stop-signal the wrapper must obey is explicit: its lease row's fence/generation advanced past its own, lease reassigned to another owner, or an operator stop/drain marker — never mere staleness caused by the daemon being gone.

Semantics after the fix:

1. Wrapper renews its own lease heartbeat directly against the runtime store on the RUN-T-0011 cadence, regardless of daemon liveness.
2. Wrapper self-terminates only on: (a) generation fence advanced beyond its own, (b) lease owner changed away from it, (c) explicit stop/drain signal, (d) its runner child exiting. Daemon death is none of these.
3. Restarted daemon adopts the surviving wrapper via verified liveness (pid + start_time) per RUN-T-0011; adoption must not bump the fence in a way that kills the legitimate survivor.
4. The drain path (`tusker daemon stop --drain`) and explicit stop-signal path from RUN-T-0013 must keep working unchanged — no regression trading one failure for the other.
