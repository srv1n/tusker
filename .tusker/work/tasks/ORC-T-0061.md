# ORC-T-0061 · Make execution history converge with authoritative cursors

## Intent

A client can reconnect to an execution root or wave, prove it reached the committed tail, and recover from event loss or replacement without relying on best-effort notifications.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Every durable source timeline has an epoch and monotonic sequence; tail, before, and after fetches return opaque cursors plus committed tail, has-older, and has-newer facts with deterministic bounds. | See mapped verification. |
| A2 | Retention, source replacement, stale cursors, missing ranges, subscriber eviction, and restart return explicit reset, gap, or stale-cursor facts and a bounded recovery action rather than an empty or silently incomplete page. | See mapped verification. |
| A3 | Root and wave projections merge multiple sources deterministically while each row retains source execution, source epoch, source sequence, provider event identity, and authoritative versus provisional provenance. | See mapped verification. |
| A4 | Streams only notify clients to fetch; a client advances checkpoints only from authoritative fetch results and keeps fetching until it can prove the committed tail, including after late and duplicate events. | See mapped verification. |
