## Intent
Devin CLI sessions cannot bind an interactive work claim and have no trustworthy session identity. `agentSessionKind()` recognizes only Codex and Claude markers, so a Devin-hosted agent is invisible to the session guards (human-actor refusal, daemon-spawn rejection, docs-adopt approval). Recognize the Devin session marker for *classification* so those guards cover Devin identically — while refusing to treat it as a conversation identity until Devin exports an immutable per-process session identifier.

## Verified seams and ownership
Session detection is `agentSessionKind()` in `cmd/tusker/execution_mode.go`; host provenance is `TaskAuthoringContextFromEnvironment` and `nativeConversationKnown` in `cmd/tusker/task_authoring_provenance.go`; the claim-time source gate and inference live in `workSessionStartCmd` in `cmd/tusker/work_session_cmd.go`. Reuse these. Do not add a parallel session registry, a new actor kind, a config flag, or any identity derived from the host's session database.

## Implementation contract
The Devin CLI exports `CHISEL_SESSION_DB` (path to its session SQLite database) into the environment of shell/tool invocations inside a session. Detect it in `agentSessionKind()` and report an `interactive Devin session` kind, keeping the `TUSKER_ATTEMPT_ID` dispatched-worker check first. The existing `interactive ` prefix convention must keep working: human-actor refusal, daemon-spawn rejection, and docs-adopt user-session approval gain Devin coverage for free.

`TaskAuthoringContextFromEnvironment` returns `source=devin` with an **empty conversation id**, unconditionally. Do not open, query, or infer identity from `CHISEL_SESSION_DB` contents — cwd matching and activity recency are not identity boundaries: two Devin sessions sharing a working directory can be misresolved, and a misresolution can wrongly pass `SameAuthoringConversation` (same-session self-review) as well as wrongly refuse a genuinely independent review. Fail closed instead.

`devin` remains a valid `work start --source` value and is inferred for `--current-workspace` the same as codex/claude, so the refusal lands on the truthful gate: `nativeConversationKnown` can never be satisfied for Devin while no immutable per-process session id exists, and `--current-workspace` refuses with the existing native-conversation error. Keep `devin` in the `nativeConversationKnown` source set so a future `DEVIN_SESSION_ID`-class marker activates the fence without a structural change — the env reader is the single point that would populate it.

This classification is not authentication and matches the existing posture for `CODEX_SESSION_ID`/`CLAUDE_CODE_SESSION_ID`: presence of the marker classifies the session; it does not verify a caller.

## Failure and edge cases
- Any `CHISEL_SESSION_DB` value — absent, missing file, foreign schema, populated rows — produces identical provenance: `source=devin`, empty conversation id. Nothing reads the file.
- A Devin `--current-workspace` claim always refuses with the native-conversation error; a Devin session can therefore never record a `self_implementation;source=devin;conversation=…` trigger.
- Review-session independence is fail-closed in both directions: a self_implementation claim (any source) cannot be reviewed by a Devin session because the reviewer context never satisfies `nativeConversationKnown`; a fabricated devin conversation inside a stored trigger cannot produce an independent pass either.
- `agentSessionKind` ordering stays: dispatched worker > codex > claude > devin; marker collisions report the first trusted kind.
- Unblock condition (upstream): a Devin-exported immutable per-process session id (e.g. `DEVIN_SESSION_ID`). When that lands, `TaskAuthoringContextFromEnvironment` populates `conversation_id` from it and the existing fence activates.
