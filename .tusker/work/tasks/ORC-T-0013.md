# ORC-T-0013 · Env-tunable or condition-based budgets for timing-bound e2e tests

## Intent

Two e2e tests carry fixed wall-clock budgets that fail under host I/O
pressure regardless of code health:

- `TestArmedWaveCrashRestartConverges` (`crashRunWait` 60s; observed 70-72s
  under load).
- `TestSpecToWaveDelivery` (3-minute budget; observed 146-195s; also failed
  once during ORC-T-0011's broad gate on 2026-07-21 and passed on isolated
  rerun).

Make the budgets env-tunable (e.g. a `TUSKER_E2E_BUDGET_SCALE` multiplier or
per-test env overrides) or, preferably, replace fixed sleeps with
condition-based waits that poll for the converged state and only fail on a
generous hard ceiling. A loaded laptop running the suite must not produce
red gates for healthy code.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The two named tests no longer depend on a fixed wall-clock budget: either budgets scale via a documented env variable, or waits are condition-based with a generous ceiling. | Inline verification |
| A2 | Default (env unset) behavior on an unloaded host is unchanged or faster; the suite still fails promptly on genuinely non-converging runs. | Inline verification |

## Non-goals

- No rewrite of the e2e harness beyond the timing/wait mechanics of these
  two tests.
- No relaxation that would mask real convergence failures.
