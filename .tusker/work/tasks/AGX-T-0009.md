# AGX-T-0009 · Conform the Tusker operator skill to Agent Skills progressive disclosure

## Intent

Make the canonical Tusker operator package a strict, portable Agent Skills
package with a small activation surface and deliberate progressive disclosure.
The installed package must teach agents to treat the CLI as the mutation
boundary, route only the context needed for the current job, and keep generic
operator mechanics separate from repository knowledge.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The canonical package conforms to the current Agent Skills `SKILL.md` schema: package/name identity, required metadata, string-valued optional metadata, license reference, and focused description triggers. | Package validation tests. |
| A2 | Progressive disclosure is explicit and bounded: the main skill stays below 500 lines, directly routes focused one-hop references, and does not require broad reference or vault reads. | Structural tests plus manual package inspection. |
| A3 | Operator mechanics, repo project knowledge, generated agent installs, and portable bundles have one unambiguous source-of-truth boundary; Codex, Claude, and generic Agent installs resolve the same canonical package. | Install/sync tests. |
| A4 | The skill accurately describes CLI-first mutations, targeted daemon notification, adaptive safety reconciliation, interactive-versus-daemon execution, objective review, and genuine human gates. | Contract assertions and documentation review. |
| A5 | Tusker provides a package-aware doctor path that validates an operator skill as an Agent Skills package without misclassifying bundled templates as live V7 tracker records. | Focused doctor tests. |
| A6 | Skill, install, routing, and broad repository tests pass without introducing new validation findings. | Focused and broad commands below. |

## Non-goals

- Rewriting project-specific domain canon into the reusable operator skill.
- Publishing or deploying binaries.
