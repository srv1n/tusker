# ORC-T-0020 · Stage continuously and promote only an exact full-green candidate

## Intent

Reviewed work integrates into delivery branches while the default branch moves only through a deterministic, full-gated, compare-and-swap promotion.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Stage mode may land eligible reviewed tasks into their delivery branch but cannot move the configured default branch. | See mapped verification. |
| A2 | Promote mode reuses the serialized landing engine, staging worktree, batch bisection, gate ledger, and landing audit instead of implementing parallel merge machinery. | See mapped verification. |
| A3 | The full promotion gate binds the exact frozen candidate, command, profile, and toolchain, and focused staging proof cannot satisfy it. | See mapped verification. |
| A4 | Candidate, task, authorization, integration, gate, or default-ref drift before update produces a named recompute or refusal and never an optimistic push. | See mapped verification. |
| A5 | Successful promotion records the exact last successfully gated and promoted SHA only after the ref update and remains idempotent on replay. | See mapped verification. |
| A6 | Existing repositories without the opt-in policy retain the current reviewer and wave landing behavior. | See mapped verification. |
