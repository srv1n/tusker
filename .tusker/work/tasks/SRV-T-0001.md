# SRV-T-0001 · Read and navigate documentation in the serve UI

## Intent

- What this is: a Docs section inside each project in the web app. It lists
  every document by subject, shows the generated map of how documents connect,
  and renders any document as a readable page. Links between documents
  (the double-bracket references) are clickable, and each page shows which
  documents point back at it, so a reader can walk the graph in either
  direction without knowing file paths.
- Why it matters: the documentation system exists, but today the only way to
  read it is opening files in an editor. The web app is where the operator
  reviews work; the documentation has to live where the reviewing happens.
- What "done" looks like: open a project, click Docs, see the document list
  and the map, click any document, read it rendered cleanly, click a
  reference inside it and land on the referenced document, and see a
  "referenced by" list at the bottom of every page.

## Acceptance

| A3 | Double-bracket references render as links that navigate to the referenced document; unresolvable references are visibly marked, not silent. | Inline verification |
| A4 | Each document page lists the documents that reference it (backlinks), and each entry navigates on click. | Inline verification |

## Non-goals

- No editing from the UI (SRV-T-0002).
- No semantic search; the list plus the existing find semantics are enough.
- No redesign of other sections (SRV-T-0003 handles navigation cleanup).

## Implementation notes

Builder appendix — verify paths before editing.

- Backend: add read-only endpoints in `internal/serve/` (grep for existing
  handlers like `/api/epics` in `internal/serve/*.go`) — e.g. `GET
  /api/docs?project=<id>` (list from the docgraph corpus), `GET
  /api/docs/<subject>?project=<id>` (body + resolved links + backlinks), and
  serve `docs/system/graph.json`. Reuse `internal/docgraph` for parsing;
  compute backlinks by scanning corpus bodies for `[[subject]]` references.
- Frontend: `internal/serve/ui/` (React + TanStack Router + Tailwind v4,
  Bun-only — use `bun install` / `bun run build`, never npm). Follow the
  existing route/page pattern (see ProjectWork / Library pages) for a new
  Docs route with list, reader, and map views. Markdown rendering: check
  what the UI already uses before adding a dependency.
- Map view: render from graph.json; a simple tiered/grouped layout is fine —
  do not hand-draw structure that fights the generated artifact.
- Sidebar entry: add Docs under the project (SRV-T-0003 may regroup later;
  land it as its own item for now).
