# TRC-T-0001 · Boundary trace schema and per-attempt recorder

## Intent

Today a failed run is diagnosable only by reading raw runner JSONL logs — no stable identity for "what the model saw and returned at each boundary," no way to re-examine a decision after the fact, and no substrate for replay. This task lays the foundation of the trace & replay workstream (docs/design/aie2026-adoption-plan.md, workstream 2): every crossing of a nondeterministic boundary (model call, tool call, retrieval) is recorded as a typed trace record, per attempt, in an append-only file.

Define the trace record as a versioned Go struct + JSON schema with these fields (from the adoption plan's schema, trimmed only if a field is genuinely inapplicable): `trace_id`, `work_item_id` (task id), `node_id`, `node_type` (model|tool|retrieval), `input` (JSON), `output` (JSON), `error` (JSON, nullable), `model_provider`, `model_name`, `model_params`, `prompt_version`, `skill_versions`, `code_sha`, `tool_schema_version`, `permission_scope`, `retrieved_chunk_ids`, `created_at`. Records append to `.tusker/_generated/traces/<TASK-ID>/<attempt-id>.jsonl` (generated artifact, gitignored per existing ignore policy).

The recorder hooks the daemon's runner-supervision path where attempt events are already observed — it must not require runner cooperation beyond what the existing event stream provides; fields the stream cannot yet supply are recorded as explicit nulls, not omitted, so schema gaps are visible. Reading traces gets a minimal CLI: `tusker trace list <TASK-ID>` (attempt → record count → boundary types) and `tusker trace show <trace-id>` (one record, pretty-printed). Replay itself is a later TRC task; this task only guarantees faithful capture.

## Non-goals

- No replay execution, replay modes, or `replay:<trace-id>` verification rows (subsequent TRC tasks).
- No trace UI in `tusker serve` (SRV epic consumes this later).
- No retention/pruning policy beyond living under `_generated` (follow-up once volumes are real).
- No instrumentation inside runners themselves; capture is at the supervision boundary only.
