# SRV-T-0026 · Human-action contract and review card for task gates

## Intent

Make a human-owned gate an executable, plain-language review action rather than
a tracker badge. The V7 vault already records the action, completion condition,
agent boundary, and acceptance rows covered by a gate; Serve currently either
throws those fields away in task detail or collapses raw `verification` gates
to the misleading UI label `clarify`.

Ship one vertical slice through the live Go Serve API and the task-detail UI.
For a task such as `MAC-T-0001` / `MAC-G-0002`, an owner must be able to see
what to do, why it needs a person, the relevant checks, and the one correct
completion action without reading tracker internals.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `GET /api/tasks/:id` exposes a typed, server-derived human-action contract for an open human gate: semantic action kind, title, exact action, why the agent cannot do it, completion condition, gate id, and the acceptance rows named by the gate's `covers` field. The existing V7 task/gate frontmatter remains the source of truth; no duplicate human-action record is introduced. | focused_test |
| A2 | Raw V7 kinds are presented truthfully: `verification` becomes a manual-verification action, `decision`, `signoff`, `release`, and provisioning-style gates retain distinct semantics, and an unknown kind renders a safe generic human action rather than being mislabeled `Clarify`. | focused_test |
| A3 | A task with an open human action renders a prominent `Your action` card before the task prose. It states the action, why the owner is needed, done-when condition, and only the covered acceptance checks in plain language. Tracker ids, evidence-kind selectors, actor inputs, and waive/obsolete controls are absent from the normal path. | focused_test |
| A4 | The card has one contextual completion action that records gate evidence, plus an explicit return-to-rework path. On mutation readback the card and task state refresh; a successful completion disappears and a refused mutation remains visible with its reason. | focused_test |
| A5 | A task whose machine work is complete and which awaits human review is represented as `review` / `Needs your review`, never as a misleading actionable backlog item. The state transition or projection responsible for the contradictory backlog view is covered by regression tests. | focused_test |
| A6 | The compact `/panel?shell=1` route uses the same live human-action contract and retains a readable, actionable presentation at 420×640; it does not fork or re-derive gate semantics in the client. | focused_test |

## Non-goals

- Do not change the V7 vault schema or migrate existing gates; `action`,
  `verification`, `why_agent_cannot`, and `covers` are already canonical.
- Do not redesign unrelated task editing, evidence storage, or the global
  inbox beyond consuming the shared served human-action contract.
- Do not add a generic LLM summary of a task. The content must be deterministic
  and traceable to the gate and task contract.
