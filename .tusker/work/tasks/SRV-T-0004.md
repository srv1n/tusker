# SRV-T-0004 · Docs tree explorer for quick corpus navigation

## Intent

- What this is: a persistent file-explorer rail inside the Docs section,
  like an IDE sidebar. The documentation corpus is, on disk, a small folder
  tree (docs/system, .tusker/specs, .tusker/specs/decisions); the explorer
  shows exactly that tree, with folders that collapse, the currently open
  document highlighted, and a filter box for jumping by name. It stays
  visible across the Docs views (list, reader, graph) so moving between
  documents is one click, never a trip back to a list page.
- Why it matters: the reader today navigates by wiki-links, backlinks, and
  the graph — great for following meaning, slow for "open that other file I
  know exists." An operator reading five docs in a review session needs the
  IDE reflex: glance left, click, keep reading.
- What "done" looks like: open any document; the tree shows where it lives;
  clicking any other document opens it without losing the tree state;
  typing in the filter narrows the tree to matching docs instantly.

## Non-goals

- No file operations from the tree (create, rename, delete stay with the
  CLI and tombstone workflows).
- No drag-and-drop reorganization.
- No second data source: the tree derives entirely from the existing
  docgraph list payload (paths already included); no new endpoints.

## Implementation notes

Builder appendix — verify paths before editing.

- Frontend only: `internal/serve/ui/src/features/knowledge/`. Build the
  tree by splitting each doc's `path` on `/` and rendering the real
  directory hierarchy as-is (docs/system, .tusker/specs,
  .tusker/specs/decisions and any nested folders), folder icons on
  directories, note entries inside — the operator asked for the most
  obvious possible mirror of the file system, not curated groups.
- The explorer is a layout concern of the knowledge routes: a shared shell
  component wrapping the three views, so the rail does not remount (and
  lose state) when switching between them. Collapse state in a small
  module-level store or context; no new dependencies.
- Follow existing UI primitives (SectionLabel, Chip, cn) and the app's
  compact type scale; kind dot per entry mirrors the graph legend colors.
- Filter matches title, subject, and filename, case-insensitive; matching
  folders stay visible with their matching children.
