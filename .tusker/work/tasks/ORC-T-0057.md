# ORC-T-0057 · Admit provider observations through one bounded event contract

## Intent

Local hooks, structured model output, and cloud polling enter Tusker through one replay-safe envelope that can report execution facts but cannot acquire ownership or delivery authority.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A versioned envelope carries provider, source event ID or sequence, source cursor, parent provider session, child handle, agent type, optional label, status, timestamp, capabilities, and bounded provider-specific metadata with deterministic validation. | See mapped verification. |
| A2 | Duplicate, replayed, late, and out-of-order events converge idempotently; persisted source checkpoints survive restart; malformed, oversized, unknown, and unsupported input produces a typed refusal or degraded observation without dropping already committed history. | See mapped verification. |
| A3 | Provider input cannot claim work, bind an execution, grant proof, finalize an outcome, arm or mutate a wave, move a ref, release, spend, overwrite a parent resume identity, or forge a local process fact. | See mapped verification. |
| A4 | Provider-child correlation is unique within its parent and provider, capability facts retain their provenance and freshness, and unsupported independent control remains explicitly false or unknown. | See mapped verification. |
