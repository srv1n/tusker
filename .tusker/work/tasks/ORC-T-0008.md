# ORC-T-0008 · Model the integrator lane as a typed work kind

## Intent

Integration is the highest-leverage lane in multi-lane work — it owns merges,
shared namespaces, and the central gate — yet Tusker cannot represent it. The
2026-07-20 recovery (slice a dirty tree, renumber migrations, merge, gate) ran
from a hand-written prose brief. Model the integrator as a typed work kind:
its claim owns the shared-namespace paths (lockfiles, migrations, generated
files) so implementation claims intersecting them are refused (ORC-T-0001);
its packet (`tusker packet --for integrator`) composes the merge brief
mechanically from worker end-state reports (ORC-T-0003) — branches, HEAD SHAs,
worktrees, and the overlap set between them — instead of a human reciting git
facts into a prompt.

Depends on ORC-T-0001 (path-claim refusal) and ORC-T-0003 (end-state reports).

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A task can be typed as integrator work; its claim owns the vault-configured shared-namespace paths, and a non-integrator claim intersecting them is refused via the ORC-T-0001 mechanism. | Inline verification |
| A2 | `tusker packet --for integrator` composes worker end-state records into a merge brief: per-lane branch + HEAD SHA + worktree + clean/dirty, and the file-overlap set between the lanes' diffs. | Inline verification |
| A3 | The integrator packet's required reads include the integration doctrine reference (`references/INTEGRATION_MERGE.md` from the installed skill). | Inline verification |

## Non-goals

- No automatic merging or conflict resolution; the packet informs an agent, it
  does not act.
- At most one integrator lane per vault is assumed, not enforced beyond the
  path-claim mechanism.
