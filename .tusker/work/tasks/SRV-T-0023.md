# SRV-T-0023 · Compact /panel triage route in serve UI for the Mac shell

## Intent

The Mac shell (epic MAC) opens a floating panel of roughly 420×640 points hosting a WKWebView. It needs a purpose-built compact route in the serve UI (`internal/serve/ui`, React + TanStack + Tailwind v4, Bun-only tooling) that answers "what needs me right now?" in ten seconds. The existing full-page views are too wide and navigation-heavy for a dropdown panel.

Add a `/panel` route:

- Dense single-column triage layout designed for 420×640 (must remain usable from ~360×480 up to ~500×800; no horizontal scroll).
- Sections, in priority order, each with a count header: **Needs attention** (human actions/gates, from the data behind `/api/needs` and `/api/gates`), **Review queue** (from `/api/review/batch`), **Running now** (active runs from `/api/runs` with status/lane), **Recent failures** (recent failed runs).
- Rows are one line each: task id, truncated title, age/status chip. Clicking a row opens the corresponding full view — same-origin router navigation in a browser; when running inside the shell (see detection below) it should call `window.tuskerShell?.openFull(path)` if present and fall back to normal navigation (the bridge itself lands in MAC-T-0004; guard every call with optional chaining).
- Shell detection: treat the presence of `?shell=1` on the URL (persist in a module, survive client-side routing) or a `TuskerShell/` substring in `navigator.userAgent` as "embedded" mode; in embedded mode hide the global nav/chrome and outer padding.
- Live updates: subscribe to the same `/api/stream` invalidation mechanism the rest of the UI uses so counts and rows refresh without reload.
- Empty state: a single calm "Nothing needs you" view when all sections are empty.
- Reuse existing query hooks/components wherever they exist; do not fork data-fetching logic for the panel.

- No write actions beyond what existing UI components already expose.
- No Swift/shell work (epic MAC) and no implementation of `window.tuskerShell` itself.
