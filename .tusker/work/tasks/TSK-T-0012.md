## Intent
A terminal implementation with missing command proof was shown as a broken wave definition and left the user with no supported action. Establish the retained cause, then make lifecycle projection and recovery truthful.

## Verified seams and ownership
The existing recovery path is in `cmd/tusker/serve_runs.go` and `serve_actions.go`; wave controls/blockers and frontier admission are projected from `direct_wave_authority.go`; daemon/completion reconciliation owns automatic continuation. Reuse these. Do not create a second retry service or reset attempt counters.

## Implementation contract
Reconstruct BET-T-0003's screenshot transition from retained history or a faithful fixture without mutating the retained project. Classify at least: implementation failed before submission, implementation submitted but check missing/failed/stale, reviewer failed, reviewer rejected, capacity wait, dependency wait and configuration failure. Only the last category may say setup is broken.

For a recoverable implementation failure expose the existing supported retry/redrive action as `Retry task`, with exact eligibility/refusal reason. A successful submission with noncurrent checks uses `Rerun checks`; a failed reviewer uses `Retry review`. Never rerun implementation for reviewer-only failure. An exhausted budget requires an explicit new bounded window and shows attempt consumption; no automatic reset. Active owner, paused wave, changed material and duplicate click must refuse or replay idempotently.

Ensure pause/resume and reconciliation preserve the lane and do not strand an authorized ready member after its project-capacity slot becomes free. A configured limit of one is valid. The next eligible sibling must be admitted automatically after the occupying execute/review lifecycle releases the slot. Do not increase concurrency silently. Do not emit a synthetic attempt zero as a real attempt.

Producer contract to UI: existing wave/task projections must provide a specific state, responsible machine/human actor, effective recovery action and disabled/refusal reason. Add the smallest field only if existing `phase`, `waitingReason`, `proofInvalidation`, controls and recovery response cannot express it.

## Failure and edge cases
- Resume while material drifted refuses; it does not silently reauthorize changed scope.
- Concurrent poll, retry click and daemon reconciliation admit at most one lane attempt.
- A normal dependency or capacity wait never becomes a warning/error blocker.
- Completed canonical state wins over stale runtime history, but historical failure remains inspectable.
- Project and record identity fence all recovery; a colliding task ID in another project is untouched.
