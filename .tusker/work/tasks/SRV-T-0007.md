# SRV-T-0007 · Daemon hosts the serve UI: one resident process, minimum footprint

## Intent

Operator decision (2026-07-06): the steady state is exactly ONE resident tusker process. Today `tusker daemon` (poll/dispatch loop) and `tusker serve` (read-only UI/API, SRV-T-0002) are separate processes reading the same SQLite store and vault — double footprint, two things to babysit, and cross-process store contention that the busy-retry work (RUN-T-0008 A3) exists to absorb. Consolidate: `tusker daemon run` starts the serve HTTP server in-process (goroutine) on a configured address, default `127.0.0.1:7420`, serving the embedded SPA and JSON API from the same process that owns the poll loop — sharing the daemon's store handle so UI reads never open a second SQLite connection.

Design constraints:

1. **Crash isolation inside the process**: every HTTP handler is panic-recovered; a UI/API panic must never take down the dispatch loop, and a dispatch-loop failure must follow existing daemon semantics regardless of the HTTP server. The two share a process, not a fate.
2. **`tusker serve` stays, as the daemon-down fallback**: when a live incumbent daemon is detected (via the RUN-T-0008 instance guard), `tusker serve` does not bind a duplicate server — it prints the incumbent's serve URL and exits 0. When no daemon is alive, it runs standalone read-only exactly as today (inspection mode over a cold vault/store).
3. **Config**: `serve.enabled` (default true) and `serve.addr` (default `127.0.0.1:7420`) under the daemon/runtime config; localhost-only binding enforced as in SRV-T-0002 A3.
4. **Single-instance guard covers the port**: the D6 flock guard already guarantees one daemon; the serve port therefore has one owner. A bind failure on startup is a loud, agent-legible error naming the holder, not a silent skip.
5. Read-only remains read-only: consolidation adds no mutating endpoints (the write surface stays gated behind SRV-T-0003/SRV-T-0004).

## Non-goals

- No mutating endpoints, no auth, no remote bind (unchanged from SRV-T-0002).
- No SSE migration in this task (polling refresh stays; SSE is its own follow-up).
- No launchd/auto-restart packaging (separate decision).
