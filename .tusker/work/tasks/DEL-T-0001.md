# DEL-T-0001 · Import an approved spec as a validated delivery DAG and wave

## Intent

Create the safe bridge from an approved canonical spec to Tusker-owned work
records. A planning model may propose the decomposition, dependency graph,
acceptance, proof, artifacts, and concurrency, but Tusker validates the proposal
and writes the real task IDs, revisions, relations, and wave atomically.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A versioned delivery-plan schema represents governing spec/decision refs, task outcomes, exact verification, hard/soft dependencies, artifact contracts, owned paths, runner/concurrency hints, and knowledge nodes without embedding final Tusker IDs or state revisions. | Focused schema and round-trip tests. |
| A2 | `delivery plan/import` supports dry-run and atomically creates or updates one wave plus held task contracts with real IDs, stable source keys, bidirectional spec traceability, and deterministic dedupe. | Fixture tests cover a new import, repeated import, changed plan, and rollback after a forced write failure. |
| A3 | Import rejects cycles, dangling references, placeholder acceptance/proof, invalid artifact contracts, duplicate source keys, and a spec outside the repository without leaving partial records. | Negative fixture matrix asserts the exact blocker and unchanged vault state. |
| A4 | CLI and JSON output expose the resulting DAG, topological frontiers, task/spec mapping, expected concurrency, and every issue that must be fixed before preflight. | Golden CLI/JSON tests. |
| A5 | Operator and skill docs explain that models propose plans while Tusker owns final records; planning and import remain inert and never dispatch work. | Focused help/doc assertions plus skill validation. |

## Non-goals

- Selecting or running an implementation model.
- Arming, dispatching, reviewing, or landing the imported wave.
- Importing arbitrary free-form transcripts as tracker truth.

## Operator artifact

A golden delivery-plan fixture and rendered DAG showing the proposed task
frontiers, acceptance/proof summary, artifact contracts, and final Tusker IDs.
