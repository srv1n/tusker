# ORC-T-0015 · Persist restart-safe departure runs

## Intent

The runtime store owns first-class idempotent departure records instead of representing scheduled system work as fake task attempts.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A departure record captures project, policy, scheduled window, state, candidate fingerprints, gate, promotion, release, skip or block reason, and model invocation count. | See mapped verification. |
| A2 | A uniqueness constraint prevents duplicate departure creation for the same project, policy, and scheduled window across concurrent triggers and daemon restarts. | See mapped verification. |
| A3 | State transitions use compare-and-swap semantics and reject stale writers without losing the winning terminal result. | See mapped verification. |
| A4 | Startup reconciliation classifies incomplete states as safely resumable or explicitly blocked and never repeats an already committed ref or release action. | See mapped verification. |
