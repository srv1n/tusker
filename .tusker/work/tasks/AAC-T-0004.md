# AAC-T-0004 · Keep exceptional approvals tied to the exact live action

## Intent

An operator can allow or block one exceptional action without accidentally approving another attempt, changed command or expired process. Done is a decision and recovery matrix with durable request examples. Ordinary allowed work continues without manual review.

## Implementation notes
Read .tusker/specs/agent-access.md and its decision log. This is future implementation work; the planning session has not built or dispatched it. Preserve the shared dirty baseline and reconcile current ownership before editing. Reuse existing profile, runner, runtime and UI authorities. Do not launch a daemon or nested worker from an interactive session, change automation, invent provider fallback or add an OS sandbox. Proposed new filenames are recommendations; trace the common launch, test and resume callers before choosing the smallest complete implementation. Keep native coverage explicit. Run named checks after implementation settles; zero matching cases is failure. Use disposable fixture files for negative cases. Paid/live provider runs require explicit authorization and separate evidence. Record outcomes, exact route/version and limits in the artifact. Independent review uses existing workflow, not a new human code-review gate.

Use the contract DTOs, runtime SQLite store, normalized EventPermissionRequest, acp_permission.go and existing human-action records. Bind request identity, execution/attempt/session, native option ID, command payload, working directory, targets, policy fingerprint, revision and liveness. Validate and settle atomically; duplicate delivery/response is idempotent and conflicting/stale response fails. Reuse exact supported native callback mechanisms for CLI hooks and ACP, documenting whether the agent delegates all relevant operations. Preserve secret redaction while retaining a secure immutable response binding. Reconcile restart with actual native request liveness; expire dead requests and never replay a stored shell command. Resume/new attempt recomputes access; running attempt snapshots do not silently change. Unsupported/headless callback denies through native mechanisms and surfaces needs attention, with no synthetic stdin approval or permission downgrade. Worker identity cannot self-approve. Extend existing authenticated serve action operations and CLI projection; no new service or generic approval queue. Required tests: TestAgentAccessApproval and TestAgentAccessApprovalRecovery.

Planned contract: one approval belongs to one immutable live native request. The implementation report must document expiry, restart and unsupported callback behavior.
