# WUX-T-0016 · Replace the project sidebar with a scrolling strip

## Intent

People can scroll directly to any project, select it once, and use Work or Documents without repeated navigation branches. Global utilities and project settings use recognizable icons. Done is the actual application shell with before/after images and exercised interactions. Preserve current destinations and project identity; avoid redesigning page content.

## Implementation notes
Read .tusker/specs/work-area-redesign.md section 4 and its September 10 decision entry before editing. This replaces the old sidebar contract; other Work redesign tasks are not prerequisites. Inspect the current dirty checkout and all callers of changed helpers. Reuse existing code and preserve concurrent work. This task is inert planning until assigned; implement interactively through the supported Tusker claim protocol, without starting a daemon, nested worker or automation. Use configured Standard work and review levels. Keep tests focused and defer build until the final qualification task. Review acceptance against actual changed material; retain lifecycle/independent-review requirements without adding a human code-review gate. Do not mutate tracker records by hand.

Consume project-state. Trace routes/__root.tsx and active WorkExperience before removing the desktop Sidebar. Reuse registration, refresh, search, project grouping/checkout selection, attention and existing menus. Proposed new ProjectStrip.tsx and ProjectStrip.css are file hints, not required abstractions. Keep all projects in one native horizontal scroller, nonwrapping, with overflow-only mouse arrows and focus reveal; no All projects menu or top-N cutoff. Remove visible Search/settings text and repeated project labels while preserving accessible names/tooltips. Wire one selected-project navigation row and its secondary actions; preserve global-scope and shell=1 behavior. Clean obsolete navigator/collapse paths and update their direct preview/test callers after checking usage, retaining Add project and recovery. Capture before-desktop.png before this task changes the shell. Add project strip shell focused tests and test/project-strip.browser.mjs against the real routed app, using existing Playwright loading patterns and the planned URL/env in spec section 4. Browser script must name cases project strip desktop, overflow, keyboard, persistence, scope, and regression; save the specified after screenshots and shell.md with fixture provenance. Tests must verify behavior and layout, not grep source strings. Independent review examines rendered evidence and route/state behavior; no screenshot score replaces acceptance.

The browser entry also provides --live using TUSKER_PROJECT_STRIP_LIVE_URL: no intercepted/fabricated API responses, no task execution or persisted settings changes, and explicit refusal if a real base URL is absent. Exercise read-only project switching, Work/Documents, both settings scopes, attention and back/forward; record actual routes. Isolate the browser context from the user's session.
