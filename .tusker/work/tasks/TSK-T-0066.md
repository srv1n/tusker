## Intent
With run-controls-api serving `controls.capabilities`, the UI must stop guessing. Today `capabilityFor` falls back to client heuristics, `RunDetail` can leave an action spinner forever after a refused/unknown result, Stop pending disappears on reload, the task inspector's "Open run logs" is a raw `<a>` (full page reload) inside the collapsed Activity section, persisted "run" queries render stale run state as current after reload, and `identity.repo_root` never matches the Go field `registered_repo_path`.

## Verified seams
- SessionRecoveryControls.tsx `capabilityFor` (~94-138): advertised capability first, then client fallbacks for reconnect/continue/stop/pause/recover_context/start_fresh.
- RunDetail.tsx (~55-115): `pendingAction`, `settleAction`, `onSessionAction`, and a `useEffect` clearing pending only on specific readbacks; no timeout; refusal (`result.refused`) does not clear it.
- TaskInspector.tsx ~459: `<a data-testid="inspector-open-run" href=...>` inside `<Section title="Activity">`. This file has UNCOMMITTED operator edits — preserve them.
- queryPersistence.ts `STARTUP_QUERY_ROOTS` (~13) includes "run" and "runs".
- domain.ts `RunDetail.identity.repo_root` (~836) vs Go `RunIdentityMetadata.RepoRoot json:"registered_repo_path"` (runtime_store.go ~363). Fix the TS side; Go tag is canonical.
- Existing tests: tests/run-session-controls.test.ts, tests/query-persistence.test.ts, tests/runs-detail.test.ts.

## Implementation contract
Locked:
- `capabilityFor` uses only `run.controls.capabilities` (then the legacy `run.capabilities` alias). Missing capability ⇒ action disabled with "This server did not declare this action." No client-side eligibility rules remain.
- Pending: cleared on refused result, on error response, on canonical readback showing no pending intent, or after a bounded timeout (proposed 60 s) with a visible "Result unknown — refresh" note; never cleared optimistically on success alone. After reload, `controls.pending` renders the pending Stop state.
- "Open run logs" becomes a TanStack `<Link to="/p/$projectId/runs/$taskId">` rendered outside the collapsed section (always visible when a run exists).
- Persisted run data: either remove "run" from `STARTUP_QUERY_ROOTS` or render a visible "cached — refreshing" marker and disable every action until a fresh fetch succeeds. Proposed: remove "run" (detail); keep "runs" list with the marker.
- domain.ts: `identity.registered_repo_path`; keep reading `repo_root` as a fallback for older servers.

## Failure and edge cases
- Server declares continue unavailable while `resume.supported=true` → Continue disabled with the server reason. Forbidden: enabled Continue.
- Server omits capabilities (older server) → all mutation actions disabled; Reconnect (observe-only) still allowed only if declared.
- POST returns `{refused:true}` → spinner clears immediately, refusal reason shown.
- POST hangs / network error → pending stays with "result unknown" and clears at timeout; a second click is blocked while pending.
- Reload during pending Stop → pending Stop visible from `controls.pending`.
- App start with persisted run cache and server down → no action enabled; cached marker visible.
