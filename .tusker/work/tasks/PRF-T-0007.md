# PRF-T-0007 · Manual refresh and attention-based sweep cadence in serve UI

## Intent

Third tier of PRF-D-0001's freshness model (Sarav, 2026-07-11): the background sweep can be slow because the human can always force freshness, and the daemon should spend attention where the human is looking.

1. **Manual refresh:** a per-project "Refresh now" button (and optionally global) in the serve UI. `POST /api/projects/<id>/refresh` marks the project dirty through the same targeted-reconcile path as PRF-T-0006 (reuse it — do not build a parallel path), rebuilds that project's snapshot, and the scoped stream event refreshes the view. Rate-limit server-side (e.g. one in-flight refresh per project, min 2s between) so a stuck spinner can't be hammered into a CPU spike.
2. **Attention-based cadence:** while a client has a project view open/expanded, that project's safety-net sweep runs at an attention cadence (e.g. 15–30s) instead of the 2–5 min background cadence; reverts when attention ends. Attention signal options: scope the SSE subscription by project (stream connect carries `?project=<id>`; daemon boosts while ≥1 scoped subscriber exists) or a lightweight attention heartbeat from the SPA. Prefer the SSE-scope approach — the connection lifecycle gives expiry for free (client disconnect/navigate = attention gone). Boost is per-project only; other projects stay on background cadence.

Depends on PRF-T-0006 (targeted reconcile path to reuse) and pairs with PRF-T-0004 (scoped invalidations so the refresh only refetches that project's queries).

## Acceptance

## Non-goals

- The notify transport itself (PRF-T-0006) and sweep stagger math (PRF-T-0001).
- Any global always-fast polling — attention boost is strictly per-project and presence-bound.
