# RUN-T-0016 · Soft dependency edges: review-with-proof unblocks dispatch, close-order stays enforced

## Intent

Operator friction (2026-07-06 night, feedback note `2026-07-06-sarav-soft-dependencies-allow-a-dependency-edge-to-unb.md`): the RUN-T-0010→0011 chain stalled overnight because dependency satisfaction requires the dependency to reach `done`, and `done` for high-risk tasks requires a human acceptor — so human review latency became **dispatch** latency for the whole chain, even though 0010 was machine-complete and gate-green hours earlier. Principle: **review gates closing, never flowing.**

Semantics:

1. Dependency edges gain a hardness: `hard` (today's behavior: dep must be `done`) and `soft` (dep must be in `review` with `proof_status: satisfied`, or `done`). Frontmatter form: `dependencies:` entries stay plain strings (default hardness applies) or become `"<TASK-ID>:soft"` / `"<TASK-ID>:hard"` — keep the parser backward-compatible with every existing task file.
2. Default hardness by the **dependency's** risk: deps on high/critical tasks default `hard`; deps on low/medium default `soft`. An explicit suffix always wins.
3. **Close-order is inviolable regardless of hardness**: a task cannot reach `done` while any dependency is not `done`. `tusker close` enforces this; the close error names the unfinished dependency.
4. Rework cascade: if a soft-unblocked dependency is rejected at review (moved to `rework`), every dependent that dispatched on the soft edge is flagged — running work gets the RUN-T-0011 heartbeat stop-signal path (its eligibility evaporates), non-started dependents flip back to `blocked_by_dependency`, and the review packet for the reworked task lists affected dependents so the human sees the blast radius.
5. `tusker automation plan` and the readiness reconciler both understand hardness; the daemon's shared eligibility function (RUN-T-0011) consumes readiness as today — no second eligibility site.

This task touches tracker/vault semantics (readiness, reconcile, close policy, plan), not the daemon dispatch core — safe to run in parallel with RUN-T-0011 by a second runner. If both land in the same wave, integration is via readiness fields only.
