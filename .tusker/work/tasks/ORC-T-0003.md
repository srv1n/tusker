# ORC-T-0003 · Enforce normalized end-state reports at run submit

## Intent

On 2026-07-20 an overnight lane ended a seven-task delivery with a one-line
answer: no branch, no SHA, no gate verdicts, no report. On 2026-07-11 a
background lane's wrapped "exit 0" masked a real failure. Reports are prose
today, so they can be absent or wrong. Runner results are already normalized
at submit; extend that contract with a required end-state record — branch,
HEAD SHA, worktree path, clean/dirty, and per-acceptance gate verdicts — and
refuse submission without it. The git facts (branch, SHA, dirty state) are
captured by the harness from the workspace itself, never trusted from the
model's text.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A run submit without a complete end-state record is refused with an actionable error naming the missing fields. | Inline verification |
| A2 | The harness captures branch, HEAD SHA, and clean/dirty from the workspace at submit time; a model-claimed SHA that contradicts the workspace is recorded as a discrepancy, with the harness value authoritative. | Inline verification |
| A3 | The end-state record renders into the attempt record and the stream board (ORC-T-0002) so "what did this lane leave behind" is answerable without reading the transcript. | Inline verification |

## Non-goals

- No retroactive backfill of historical attempts.
- No change to the product-level review/close flow; this is submit-shape only.
