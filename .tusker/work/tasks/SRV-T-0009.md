# SRV-T-0009 · Front-matter fields edit as typed inline controls, never text

## Intent

Operator friction (2026-07-06): front matter (status, priority, readiness, risk, dates, assignee) renders beautifully in the read view as typed chips — `PropertyPanel.tsx` pills, and the TaskContract right rail's `FactRow` + `StatusChip`/`ReadinessChip`/`PriorityChip`/`RiskChip` (`TaskContract.tsx:172-191`) — but there is no way to edit any of it inline. The `PropertyPanel` free-field button is a dead stub (`PropertyPanel.tsx:31-34`, `// TODO(api): free-field editor (title/priority) via structured control.`), and the only click target that *does* swap to an editor — the Intent prose — drops to a raw monospace `<textarea>`, the visual opposite of the surrounding chips. Front matter is deliberately structured data, not YAML text (`domain.ts:242-243` `frontmatter: Array<{ key; value; locked }>`; fixtures note persistence is "through explicit action endpoints (no raw YAML writes)"). So the fix is typed inline controls, one per field kind: click a chip, edit that value with the right control, commit through a structured action — never expose YAML or a textarea.

Design:
- Click a free (unlocked) front-matter chip → an inline popover with a control matched to the field kind: enum fields (status, priority, readiness, risk) → a select over the schema-allowed values; date fields → a date control; free text (title) → a single-line input. Commit on select/Enter; Escape cancels.
- Locked fields stay read-only, keep the lock icon (`PropertyPanel.tsx:22-29`), and on click explain *why* they are locked instead of dead-clicking.
- Persistence routes through the structured action endpoints owned by SRV-T-0004. Until that lands, wire the mutation to the existing mock action layer so the control is fully exercised; the swap to the real endpoint is a one-line change of the mutation target, not a rewrite. No hard dependency — the UI is buildable and testable now.
- Keep both render sites in sync: `PropertyPanel` (used by DocReader and TaskContract) and the TaskContract right-rail chips read the same source, so one edit reflects in both.

## Non-goals

- No raw YAML editing and no front-matter textarea, ever.
- No new backend endpoint here — persistence rides SRV-T-0004's action API; wire to the mock now.
- No prose or body editing (SRV-T-0010 owns that surface).
