## Intent
`tusker docs check` passes a current doc whose `describes` paths or
backtick code paths no longer exist. Add a dead-reference rule so the
doc fails.

## Verified seams
- `ValidateCorpus` / `ValidateRepository` in `internal/docgraph/docgraph.go`
  produce `[]Issue`; add the new rule in a new file
  `internal/docgraph/deadrefs.go` and call it from there.
- `docsCheckCmd` in `cmd/tusker/docs_check_cmd.go` maps issue codes to
  hints (see the `superseded_by` hint near line 119); add a hint for the
  new code.

## Rule
Applies only to documents whose lifecycle is current (or legacy
canonical) and to accepted decisions. Proposals and superseded docs are
exempt because they name planned or historical paths.
- `describes` entry: a literal path must exist; a glob must match at
  least one file. Issue code `DOC_DESCRIBES_DEAD`.
- Inline backtick span outside fenced code blocks: treat as a path only
  when it contains `/`, has no spaces, is not a URL, and does not start
  with `-` or `$`. Strip a trailing `:line` or `#anchor`. It must exist
  relative to the repo root. Issue code `DOC_CODE_PATH_DEAD`.

## Edge and failure cases
- Backtick text like `a/b` that is prose, not a path, will false-fire.
  Proposed: honor an HTML comment `<!-- docs-check: ignore-path <path> -->`
  in the doc as the escape hatch. Do not add a config file.
- Paths with globs inside backticks (`cmd/tusker/*.go`) use glob matching.
- Paths under `.tusker/` and `docs/` count like any other path.
