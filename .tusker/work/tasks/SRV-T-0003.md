# SRV-T-0003 · Consolidate the project sidebar and add failed-run acknowledge

## Intent

- What this is: a slimmer sidebar and a way to dismiss dead alerts. Each
  project currently shows seven navigation items; this folds the attention
  list and the run history into the project's Overview page, and folds the
  Library (generic vault file browser) into the Docs section as a Files tab,
  leaving four items: Overview, Work, Docs, Ops. On the Overview page, every
  failed-run alert gets an acknowledge action that clears it after the
  operator has decided it needs no further action.
- Why it matters: five projects times six items is a wall of navigation, and
  most items answer the same question — "what needs me and what happened?"
  Meanwhile a failed run today sits in the attention list forever unless the
  operator finds an obscure command-line incantation; an attention surface
  you cannot clear stops being trusted.
- What "done" looks like: the sidebar shows four items per project; Overview
  opens with attention items on top and recent runs below; clicking
  acknowledge on a failed run removes it from attention everywhere and it
  stays gone after a refresh.

## Non-goals

- No visual redesign beyond regrouping; keep the existing look.
- No change to how runs are recorded or what counts as needing attention.
- No removal of any data view — everything remains reachable via Overview.

## Implementation notes

Builder appendix — verify paths before editing.

- Frontend: `internal/serve/ui/` (React + TanStack Router + Tailwind v4,
  Bun-only). Sidebar component and project routes — grep for the route
  definitions of Needs me / Runs (ProjectNeeds, ProjectRuns pages) and fold
  their components into ProjectOverview as sections; add route redirects for
  the removed paths.
- Acknowledge: backend endpoint in `internal/serve/` wrapping the same path
  as `tusker runs retire <record> --reason <text>` (see cmd/tusker runs
  wiring); reason can default to "acknowledged from serve UI". Refuse for
  runs that are still active.
- Ordering with SRV-T-0001: this task depends on it only so the two do not
  fight over the sidebar and route files; the Docs item lands there.
