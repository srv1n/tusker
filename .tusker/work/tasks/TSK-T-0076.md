## Intent
Muse is one of the four first harnesses, but its native identity is known only after the process exits, its terminal reasons are free text, and its exec records never reach the run activity feed. A Muse run lost mid-way can therefore neither be shown truthfully nor continued. This task makes Muse satisfy the same contract as the others.

## Verified seams
- `MuseRunner.Start` / `Resume` / `Reconcile` / `Interrupt` (no-op) / `Capabilities`, `museCLIArgv`, `museCLIResumeArgv`, `classifyMuseCLIOutput`, `museSessionID` (runner_muse.go).
- `monitorRunnerCommand` (runner_exec.go) calls `classifyMuseCLIOutput` after exit and emits `muse_session_started` only then. typed-reasons owns runner_exec.go; this task changes only functions in runner_muse.go, keeping the call shape `monitorRunnerCommand` expects as extended by typed-reasons, or asks before touching runner_exec.go.
- Operator interrupt already reaches Muse through `interruptRunProcess` (process group SIGINT, SIGTERM, SIGKILL).
- `cliRunActivity` (run_activity.go) parses Codex exec and Claude records only; Muse records are ignored. Known Muse record fields: `payload_type`/`record_type`, `payload.text|output|message` (`musePayloadText`, worker_provider_muse.go), terminal payload types run.terminal.completed|failed|cancelled with `reason`.

## Implementation contract
Locked:
- Start pre-assigns a UUID and passes `--session-id <uuid>` (unless the command already has one) and returns it as `StartResult.SessionRef`, so the run row carries the native identity before the first turn completes. Resume keeps `museCLIResumeArgv`.
- `MuseRunner.Interrupt` stays a no-op in the Runner interface because the shared process-group path is the interrupt; add a test proving a Muse run is interrupted, settles as cancelled/resumable, and can be continued with the same session id. Do not add a second signalling path.
- Muse declares HardSay=true, PreassignSessionID=true, ResumeAfterDeath=true, SoftSay=false. `muse session-message send` is not a verified soft path for a running exec process; soft Say for Muse needs separate qualification (existing `tusker worker qualify muse`), not this task.
- `classifyMuseCLIOutput` also yields a typed code: run.terminal.cancelled -> cancelled; run.terminal.failed with reason text mapped by one Muse-owned function (usage/limit -> usage_limit, auth/login -> auth_expired, permission/approval -> permission_denied, else provider_error); missing terminal record -> outcome_unknown.
- `cliRunActivity` gains Muse records: terminal records and records carrying `musePayloadText` become agent_message events; unknown payload types are ignored (they remain in raw diagnostics). Do not invent tool-call mapping for payload types not present in a fixture you can cite; list any gap in the task notes.

## Failure and edge cases
- Muse process killed after the first record: run row already has the pre-assigned session id; state lost; Continue resumes with the same `--session-id`. Forbidden: empty SessionRef.
- Command template already contains `--session-id X`: X is used and returned; no second flag.
- run.terminal.failed with reason "rate limit exceeded": usage_limit, blocked, no automatic retry.
- Output with no terminal record and exit 0: outcome_unknown (lost). Forbidden: succeeded.
- Unknown payload types and non-JSON lines: ignored without failing the run.
