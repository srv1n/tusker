# ACO-T-0005 · Produce decision-ready completed and stalled wave reports

## Intent

A frontier architect should decide from accepted evidence and actionable blockers, not reconstruct a wave from task-ID:state strings. Extend the existing report producer and stall predicate, including failures without outstanding questions.

## Implementation notes
Mandatory spec section: .tusker/specs/agent-coordination.md#architect-continuation-and-autonomy. The installed delivery schema inherits spec_refs at plan level; this anchor limits the required section read.

Recommended implementation: GPT-5.6 Terra / high. Independent review: GPT-5.6 Sol / low. These are deliberate task choices, not a reason to silently change model/effort or permissions.

Verify the current ArchitectReport/processArchitectWaveReports behavior identified by the review. Extend that producer, not a new report subsystem. Populate accepted results from authoritative proof/review/landing state; include outcome, task/spec/work revision, patch/base identity, acceptance-to-check mapping, failed/waiting tasks, actual questions, unresolved requirements/risks and detailed evidence pointers. A completed worker attempt is not necessarily an accepted/landed task. Preserve source-of-truth references and mark stale/missing facts explicitly.

Define no-runnable-work using actual scheduler eligibility. Failed/blocked tasks and wait-cycle deadlock can require a report with zero questions. A future eligible retry, active worker, resource contention and operator pause have distinct reasons and must not generate false stall alarms or forbidden wakeups. Hash decision-relevant material including changed evidence/questions/revisions, not only task states or timestamps. Bound reports, preserve blocker/question visibility and omission counts, and avoid model summarization. Expose a pure projection usable by UI/supervision and test it without a live daemon.
