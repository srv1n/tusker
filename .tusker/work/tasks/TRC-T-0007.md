# TRC-T-0007 · Append-safe runtime event logs with monotone sequence numbers

## Intent

The runtime event logger reads and rewrites the entire JSONL file for every
append, logger instances restart sequence numbers, and some operational appends
ignore failures. Replace it with an append-safe, cross-process serialized path.
Under one owner-only lock, read the current tail/sequence, reject or quarantine a
malformed trailing record, append exactly one complete JSON line with the next
monotone sequence, sync, and surface errors to the caller. Event files and locks
must be owner-only and appending must not rewrite prior bytes.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Concurrent logger instances/processes append without lost records and produce unique, strictly increasing sequence numbers. | focused_test |
| A2 | Appending preserves all prior bytes, writes one valid JSONL record, uses owner-only permissions, and reports lock/write/sync failures. | focused_test |
| A3 | A malformed or partial trailing line is detected and handled loudly without silently rewriting valid history. | focused_test |
| A4 | Runner/wrapper lifecycle paths no longer discard critical event append errors, and runtime/replay suites remain green. | broad_test |

## Non-goals

- No retention or compaction policy.
- No remote event transport.
- No canonical Markdown mutation changes.
