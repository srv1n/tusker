# ORC-T-0009 · Run gate-tier proof in harvest mode behind preflight refusal

## Intent

On 2026-07-20 an integration lane burned roughly five hours discovering six
defects one at a time: the project's gate ran fail-fast, so each fix forced
another full compile/link cycle over ~199 test binaries. The project already
had a no-fail-fast runner profile; nothing selected it. Separately the same run
died at minute ~35 on a full disk, and the recovery deleted the build cache the
next run needed.

Make gate-tier execution structurally cheap: run gates through a Tusker-invoked
path that (1) performs cheap preflight checks and refuses early with a named
cause, (2) executes in harvest mode so one pass yields the COMPLETE failure
set, and (3) emits a structured defect list an agent can fix as one batch.
Preflight order per `skills/tusker/references/INTEGRATION_MERGE.md`: gate-ledger
hit, disk headroom, build-slot free, profile parity, tree frozen.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A gate invoked through Tusker runs in the project's configured harvest (no-fail-fast) mode and returns every failure from one pass, not the first. | Inline verification |
| A2 | Preflight refuses before any expensive work when disk headroom is below the configured floor, the build slot is held, the profile does not match the canonical gate profile, or the tree is dirty — each refusal naming the cause and the remedy. | Inline verification |
| A3 | The run emits a structured defect list (per failure: command, target/test, first actionable diagnostic excerpt) consumable by a repair batch and by ORC-T-0004's repair-task creation. | Inline verification |
| A4 | A gate whose tree state already has a passing ledger entry (ORC-T-0005) short-circuits with a hit instead of re-running. | Inline verification |

## Non-goals

- No new test runner and no per-language runner logic beyond configuration:
  projects declare their harvest-mode command and preflight thresholds.
- No automatic fixing of defects; this task produces the list, not the patch.
