# KNW-T-0007 · Front-matter schema and docs index core

## Intent

- What this is: the foundation of the documentation system. Tusker learns to
  read the header block at the top of every documentation file, understand
  what kind of document it is, what subject it covers, how it connects to
  other documents, and complain precisely when a header is wrong, missing,
  or claims a subject another document already owns.
- Why it matters: every later piece — search, the generated map, drift
  warnings, adoption of old repos — reads documents through this one lens.
  If duplicate subjects or version-suffixed copies can sneak in here, the
  whole system routes readers to the wrong document.
- What "done" looks like: running the repository's validation over the
  existing documentation set passes clean; planting a duplicate-subject file
  or a file named like a second version makes validation fail with a message
  naming the offending file and the exact problem.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Documentation headers across system docs, specs, and decision logs parse into one shared in-memory model with subjects, keywords, and connection fields. | Inline verification |
| A2 | Validation fails with a named-file, named-defect message on: duplicate subject, missing required header fields, and version-suffixed filenames (v2, _new, -final, "(1)"). | Inline verification |
| A3 | A superseded document (tombstone) is recognized: it must name its successor, and validation fails if the successor does not exist. | Inline verification |
| A4 | The existing docs/specs corpus in this repository validates clean after any needed header additions (subject, keywords, part_of). | Inline verification |

## Non-goals

- No search command, no map generation, no drift rule — later tasks.
- No changes to task/epic schema; this touches documentation files only.

## Implementation notes

Builder appendix — paths are best guesses; verify before editing.

- File map: new package `internal/docgraph/` (model + parser + lint:
  `doc_node.go`, `frontmatter.go`, `lint.go`); wiring into validate lives in
  the existing validate path (locate via `grep -rn "func.*runValidate\|validate" cmd/tusker/commands_v7.go cmd/tusker/cli.go`).
- Corpus roots: `docs/system/*.md`, `.tusker/specs/*.md`,
  `.tusker/specs/decisions/*.md`. Node types by root. Required fields:
  `subject` (unique across corpus), `status`; canonical docs also `part_of`
  (except the root overview) and `describes`; specs may carry `updates`;
  decision logs `decides_for`. `keywords` optional everywhere.
- Tombstone: `status: superseded` + `superseded_by: <subject>`.
- Update the real corpus front-matter in the same diff (add `subject`,
  `keywords`, `part_of` to the seven docs/system files and existing specs).
- Plain identifiers per house rules (e.g. `DocNode`, `SubjectIndex`,
  `CheckHeaders` — no jargon).
