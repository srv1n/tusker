# FBK-T-0002 · Add Xcode build-state doctor and safe cleanup recipe

## Intent

Promoted from the Cinta agent feedback note. Add a Tusker-supported Xcode build-state doctor and safe cleanup recipe so agents can distinguish generated Xcode infrastructure corruption from code failures and unblock honest build-green proof.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The doctor detects stale `build.db` locks, Xcode build database I/O/internal inconsistency, and `supplementaryOutputs` map corruption from recent logs or result bundles. | Fixture-backed focused tests for each failure signature. |
| A2 | Dry-run output lists exact generated paths it would inspect or remove and classifies the failure as likely infrastructure, likely code, or unknown. | Focused CLI tests assert dry-run output and classification. |
| A3 | Cleanup mode removes only generated DerivedData/XCBuildData paths scoped to the project or workspace and refuses broad or ambiguous destructive paths. | Focused tests cover safe path selection, refusal cases, and dry-run parity. |
| A4 | The recipe documents how an agent should use the doctor in proof without claiming code validation when Xcode infrastructure remains broken. | Docs/help assertions plus updated operator guidance. |

## Non-goals

- Fix Xcode itself.
- Make Xcode builds pass for every project.
- Delete user source files, package caches, or unrelated global developer state.
