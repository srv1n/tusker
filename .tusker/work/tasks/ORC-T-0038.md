# ORC-T-0038 · Detect and repair stale factory-intake skill installs

## Intent

Symlink, copied, bundled, and generated Tusker skill installs expose verifiable planning-contract provenance and cannot silently retain the pre-DAG intake behavior.

| ID | Outcome | Proof |
|---|---|---|
| A1 | Canonical skill metadata names the factory-intake contract schema and source fingerprint used by planning and wave preflight. | See mapped verification. |
| A2 | Symlink installs resolve the canonical contract immediately while copied and bundled installs record their materialized source fingerprint and contract version. | See mapped verification. |
| A3 | Setup and rollout doctor distinguish current, stale, missing, incompatible, and locally modified installs and provide the exact safe skill-sync or source repair. | See mapped verification. |
| A4 | A wave planned under the factory contract cannot preflight with an installed skill that predates or contradicts that contract. | See mapped verification. |
| A5 | Sync refreshes generated installs without overwriting project knowledge, unrelated instructions, secrets, or user-authored plugin and skill content. | See mapped verification. |
