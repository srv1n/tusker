## Intent
Checking an armed wave must be cheap and must not repeat itself. Today each
check reloads every task file several times, fingerprints the wave three
times and rebuilds the same projection of the integration branch on every
pass, even when nothing changed. Make the wave check reuse what it already
knows until the wave, its tasks, its specs or its branch actually change.

## Failure and edge cases
- Editing a wave member, a spec it cites, or the wave itself after arming
  must still be caught before more work starts or lands.
- A new commit on the integration branch must invalidate the cached
  projection.

## Acceptance
| ID | Outcome | Proof |
| --- | --- | --- |
| A1 | Two wave checks with nothing changed in between load the vault and fingerprint the wave at most once in total. | Verification A1 |
| A2 | Changing a member task, a cited spec, or the branch tip between checks is detected on the next check. | Verification A2 |
