# PRF-T-0006 · CLI write-notify triggers targeted per-project reconcile

## Intent

Core of PRF-D-0001. All agent/runner task mechanics flow through the `tusker` CLI, so the CLI is the natural change-notification source: when a CLI command mutates vault state (status, proof, evidence, gate, new task/epic, reconcile-triggering writes), it should tell the daemon *which project* is dirty so the daemon reconciles that one project immediately — instead of every project rediscovering changes via a timed full scan.

Design surface:
- **Transport:** the daemon control socket (`cmd/tusker/daemon_control.go:45` accept loop) already exists; alternatively a monotonic `dirty_seq` per project in the shared SQLite runtime store (`~/Library/Application Support/tusker/daemon.db`) that the daemon checks cheaply. Pick one; socket ping with store fallback is acceptable.
- **Sender:** a small post-mutation hook in the CLI write path (wherever task/gate/evidence/status writes land) — fire-and-forget, must never block or fail the CLI command when the daemon is down.
- **Receiver:** daemon maps notify(project) → immediate reconcile of that project only, debounced (e.g. 250–500ms) so a burst of CLI writes from one agent turn coalesces into one reconcile.
- **Serve:** the resulting stream event should carry the project key so the UI refetches only that project's queries (ties into PRF-T-0004).
- With this landed, the timed poll becomes the staggered safety-net sweep (PRF-T-0001 sets its cadence; PRF-T-0003 makes it cheap). Out-of-band writers (Obsidian, git, humans) are the sweep's job, not this task's.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A CLI mutation (e.g. `tusker status <id> ready`) is reflected in daemon state and the serve stream within ~1s, without waiting for the sweep. | Inline verification |
| A2 | Notify reconciles only the affected project (no full-registry scan on the notify path). | Inline verification |
| A3 | A burst of CLI writes coalesces into a single reconcile (debounce). | Inline verification |
| A4 | CLI commands succeed unchanged when the daemon is not running (notify is fire-and-forget). | Inline verification |

## Non-goals

- Safety-net sweep cadence/stagger (PRF-T-0001) and incremental scan cost (PRF-T-0003).
- Detecting non-CLI writers (Obsidian/git/manual edits) — the sweep covers those.
