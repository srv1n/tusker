## Intent
Dogfooding Tusker on the rzn backend on 2026-10-24 (dogfood bug list entries
8 to 20) cost hours. Every check of a task shared one 10-minute budget, so a
cold 13-minute Rust build lost its result. Checks silently dropped the
build-routing variables. The repo's mandatory test wrapper never counted as a
test, and nothing said why. A failed check kept only a digest of its output. Make the checks fit
a repo with slow builds and wrapped test runners, and make every refusal name
its cause.

## Failure and edge cases
- Checks still get a minimal environment unless the repo names more; a
  wildcard for every variable is refused, so the shell's secrets never reach a
  check by accident.
- Receipts recorded before this change stay valid.
- Raw check output is never written to the task.
- When a task is refused while recording a batch, its dependents are skipped
  before they run any check.

## Implementation notes
The rzn wrapper is `make cargo-any CARGO_ARGS='test …'`; its pattern goes in
WORKFLOW.md `verification.test_commands`. A bare `*` in `verification.env` is
refused. Report: rzn/backend/tusker-dogfood-bugs.md entries 8 to 20.

Not done here, needing a decision: dropping `test` and `[` from the test-runner
list (so `[ -f x ]` stops counting as a focused test), a real definition of
`broad_test`, running checks from a frozen snapshot of the task's commit, and
letting a dependency in review satisfy `tusker start`.
