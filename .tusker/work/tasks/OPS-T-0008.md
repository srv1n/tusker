# OPS-T-0008 · tusker land: guard main update-ref against a checked-out default branch (avoid wedged/stale main worktree)

## Intent

From the GPT-5.5 Pro Extended pre-push review (handoff `cgpt_mrc05ks3_5fcda4b9`), HIGH finding on the merge lane. `landV7WaveToMain` (`cmd/tusker/v7_land_cmd.go:694`) advances the default branch with `git update-ref refs/heads/<defaultBranch>` even when that branch is **checked out in a worktree** (the operator's main working tree, or another linked worktree).

Consequence: the branch ref moves forward but the checked-out worktree's index/working tree stays at the old tree. The operator is left on a stale, dirty-looking `main` after a *successful* land — a state where an accidental commit or `git checkout -- .` / reset can silently revert the just-landed changes. This is a data-loss-adjacent footgun on the primary merge path.

Fix: before `update-ref`, detect whether the default branch is checked out in any worktree (`git worktree list --porcelain`, or `git rev-parse --symbolic-full-name HEAD` per worktree). Then either (a) perform the main update through the clean checked-out worktree and fast-forward/reset its index safely when the tree is clean, or (b) refuse the land with an actionable error when the default branch is checked out and dirty, instructing the operator how to proceed. Never leave a checked-out worktree desynced from its advanced branch ref.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | When the default branch is checked out and clean, a successful wave land leaves that worktree's HEAD/index synced to the advanced ref (no stale/dirty main). | focused_test |

| A3 | When the default branch is not checked out anywhere, current `update-ref` fast path behavior is unchanged. | focused_test |
| A4 | No regression to the serialized wave/land lane or OPS-T-0006 landing summary. | broad_test |

- No move away from the low-level `commit-tree`/`update-ref` integration approach; this task only makes the final main advance safe w.r.t. checked-out worktrees.
