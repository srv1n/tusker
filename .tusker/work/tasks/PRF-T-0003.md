# PRF-T-0003 · Incremental mtime-based vault index with frontmatter-only loads

## Intent

The dominant CPU cost. `listAllNotes` (`cmd/tusker/notes.go:15`) walks the vault (`notes.go:72-140`), reads **every** `.md` in full (`helpers.go:294` bare `os.ReadFile`) and re-parses all YAML frontmatter with yaml.v3 (`frontmatter.go:40`) on every call, 8-way concurrent (`notes.go:27`). There is no mtime/size/hash cache anywhere in the load path. Live daemon sample 2026-07-11 (PID 64141, 99.5% CPU, 125 CPU-min in 97 wall-min): hot frames are `listAllNotes.func1`, `parseFrontmatter`, `walkDirEntries`, and GC/malloc — allocation churn from re-reading ~2,750 files every 5s tick.

Compounding waste, all confirmed by investigation:
- **Full body always retained** (`Note.Body`, `schema.go:11-16`) even for frontmatter-only consumers like `pollOnce` and `loadV7Index`. `MetadataOnly` skips notes entirely; there is no frontmatter-only mode.
- **~9 independent full-scan entry points**; `loadV7Index` alone has 78 non-test call sites, none sharing results.
- **`reconcileV7` rebuilds the full index up to ~6× in one invocation** (`commands_v7.go:1563, 1577, 1587, 1622, 1705, 1712`); `reconcileV7ControlProjections` similar (`commands_v7.go:1645-1712`).
- **`parseFrontmatterMustRead` (45 non-test sites, `helpers.go:346`) re-reads files already loaded moments earlier** inside reconcile loops (`commands_v7.go:1594, 1678`).
- **Dead cache**: `_generated/indexes/*.json` are written by reindex (`commands_index.go:326-348`) and dashboards (`v7_state_runtime.go:43-58`) but never read back by anything.
- Config YAML is also re-resolved hot (`configRawMap`, `resolveTuskerConfigForRepo` in the live sample).

Deliverables: a per-vault note cache keyed by `(path, mtime, size)` reused across poll ticks (stat-only pass when unchanged); a frontmatter-only load mode that does not retain bodies; one shared index per `pollOnce` tick and per CLI invocation (kill the intra-invocation rebuilds and `parseFrontmatterMustRead` double-reads on those paths); decide whether `_generated/indexes` JSONs get wired as a persistent cache or deleted.
