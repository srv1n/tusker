# AAC-T-0003 · Run Muse directly without changing existing profiles

## Intent

People can deliberately choose the installed native Muse client while their existing Muse profiles keep working through their current agent route. Done is a route comparison and execution-protocol evidence, including unsupported controls. This story adds direct command-line execution only.

## Implementation notes
Read .tusker/specs/agent-access.md and its decision log. This is future implementation work; the planning session has not built or dispatched it. Preserve the shared dirty baseline and reconcile current ownership before editing. Reuse existing profile, runner, runtime and UI authorities. Do not launch a daemon or nested worker from an interactive session, change automation, invent provider fallback or add an OS sandbox. Proposed new filenames are recommendations; trace the common launch, test and resume callers before choosing the smallest complete implementation. Keep native coverage explicit. Run named checks after implementation settles; zero matching cases is failure. Use disposable fixture files for negative cases. Paid/live provider runs require explicit authorization and separate evidence. Record outcomes, exact route/version and limits in the artifact. Independent review uses existing workflow, not a new human code-review gate.

Add distinct harness ID muse_cli and a native Muse CLI dialect using existing installed-executable runner abstractions. Preserve muse as the current Codex-profile route and label it Muse via Codex where needed. Reuse current Muse model discovery, but do not treat discovery as execution readiness. Inspect the exact installed CLI help/schema and qualify flags for workspace, approval mode, permission profile, sandbox network and non-shell write scope; do not assume --disable-sandbox, --disable-approval and --disable-write mean the same thing. Parse structured progress, final/session receipts, cancellation and errors using the existing event contract. Record whether direct CLI supports a live callback or only denial/termination; never fake an interactive approve action. Test absent executable/auth failure/unsupported fields and exact legacy arguments. MSP serve is not ACP and is out of this execution story. Required tests: TestAgentAccessMuse and TestMuseNativeRoute.
