# MAC-T-0004 · tusker:// deep links + WKWebView JS bridge (window.tuskerShell)

## Intent

Wire the two directions of shell↔web integration so anything on the system can deep-link into the panel and the web UI can talk back to its native host. Builds on the panel (MAC-T-0001) and the `/panel` route conventions (SRV-T-0023).

**`tusker://` URL scheme** (system → shell):
- Register via `CFBundleURLTypes` in the bundle Info.plist; handle in the app delegate (`application(_:open:)`).
- Routes: `tusker://open?path=<url-encoded serve-UI path>` summons the panel navigated to that path; `tusker://task/<TASK-ID>` is sugar for the task's deep-link path (use the same path convention as SRV-T-0024's `deep_link_path`). Unknown/malformed URLs are ignored with a log line, never a crash.
- This gives the daemon, CLI, scripts, and Raycast a one-line way in: `open "tusker://task/RUN-T-0043"`.

**JS bridge** (web → shell), the `window.tuskerShell` API that SRV-T-0023 already guards for:
- A `WKScriptMessageHandler` named `tuskerShell` plus a `WKUserScript` (documentStart, main frame only) that defines `window.tuskerShell` with: `openFull(path)` (open `<baseURL><path>` in the default browser), `closePanel()`, `notify({title, body, path})` (post a local notification via the MAC-T-0003 pipeline when present; no-op silently otherwise), `setBadge(count)` (advisory; `/api/summary` remains authoritative and wins on next refresh), and a readonly `version` string.
- Inject only when loading the configured base URL origin — never for arbitrary origins the webview might get navigated to.
- Shell → web: implement `PanelController.show(path:)` navigation as an in-page router push when the bridge page is loaded (`evaluateJavaScript` calling a `window.tuskerShell.onNavigate?.(path)` hook the web side may register), falling back to a full URL load. This keeps deep links from reloading the SPA.
- Document the full JS API surface and URL scheme in `apps/mac/TuskerBar/README.md`; if the serve UI needs a hook registration tweak in `internal/serve/ui`, keep it to a minimal, optional-chained addition consistent with SRV-T-0023's conventions.

## Non-goals

- No two-way RPC framework; the five bridge methods above are the whole surface.
- No changes to notification mapping (MAC-T-0003) beyond routing `notify` through it.
- No `x-callback-url` or return-value callbacks.
