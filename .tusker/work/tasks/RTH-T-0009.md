## Intent
The rzn PIX wave (W-0034, 2026-10-25) and the remaining dogfood bug list
entries (7, 13, 14, 16, 18, 21) showed Tusker blocking normal shared-workbench
work. Only one task could be claimed per checkout. Backlog tasks could not be
started, or even created, without owned paths. Wave tasks could not join an
epic. `[ -f x ]` counted as a test. A concurrent commit turned a check into a
plain fail. Generated vault files filled every `git status`. Make those paths
work, and make each refusal say what to do next.

## Failure and edge cases
- Two claims in one checkout are still refused when either task declares no
  owned paths, or when their paths overlap. The refusal names the other task.
- `--dependencies` replaces the whole list, so the remedy for a hard
  dependency in review restates every dependency.
- A failing check that edits tracked files itself is reported as a tree
  change rather than a fail.
- Already-tracked generated files are only listed, with an untrack command
  that leaves tracked attempt notes alone. Land still stages them in older
  repos that track `_generated/`.
- spec_refs still resolve only under docs/system (and legacy .tusker/specs).
  A file elsewhere is refused with a hint saying where to move it.
