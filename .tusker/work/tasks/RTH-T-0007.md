## Intent
With the Tusker UI open, the resident daemon used about two cores without pause.
Every request for task detail or run history rereads each run's event log and
scrubs secrets from every event with eight case-insensitive patterns, again on
every refresh. One pattern tries a long match at the start of every word. Scrub
each piece of text once and skip patterns that cannot match, so an open UI costs
little.

## Failure and edge cases
- Every secret the scrubber hides today stays hidden; no output may change.
- New events appended to a log are still scrubbed.
- Memory used for remembered results stays bounded.

## Implementation notes
Verified 2026-10-19 by sampling the daemon (pid 69954, ~208% CPU with TuskerBar's web UI open):
hot path is serveServer.handleAPI -> taskDetailFor / runSummary -> serveRunHistory ->
serveRunEventsFromTails -> runActivityText -> redactHookOutput (cmd/tusker/config.go:26),
called from cmd/tusker/run_activity.go:15. Samples are dominated by regexp machine
steps, unicode.SimpleFold and GC. Worst pattern: hookEnvSecretPattern (config.go:20),
`(?i)\b([A-Z][A-Z0-9_]*(?:SECRET|TOKEN|KEY|PASSWORD)...` — under (?i) the class matches
every word and backtracks. Best guess: a cheap lowercase keyword prefilter per pattern
(e.g. skip the env/secret/query patterns unless the text contains secret/token/key/
password/authorization/capability), and a small bounded memo of redacted text keyed by
the input (or by run log path + size) in run_activity.go. Do not change pattern
semantics. Do not edit serve_*.go.
