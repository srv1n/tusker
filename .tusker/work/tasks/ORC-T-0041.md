# ORC-T-0041 · Add one universal claimed work-session protocol

## Intent

Every modifying interactive or automated agent has one shared runtime owner, revision, workspace, branch, and terminal handoff without requiring project automation to be enabled.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Work start atomically resolves readiness, ownership, task and source revision, workspace, branch, lease, attempt intent, and authorization source through the existing run-ownership service and returns a bounded packet and exact next action. | See mapped verification. |
| A2 | Interactive start works while project automation is disabled but cannot start a daemon, enable automation, arm a wave, launch a worker, or authorize any other task. | See mapped verification. |
| A3 | Healthy owners, owned-path conflicts, unsafe workspace state, unsatisfied dependencies, terminal tasks, and human gates refuse with stable causes, while only provably dead expired holders are reclaimable. | See mapped verification. |
| A4 | Status, heartbeat, submit, fail, and release enforce owner and revision compare-and-swap semantics and every terminal path releases or retires the live lease exactly once. | See mapped verification. |
| A5 | Legacy claim, attempt, and runs commands delegate or name the canonical replacement without creating contradictory active-work state, and guarded agent finish or review mutations require a live work session unless a human uses an explicit attributable break-glass path. | See mapped verification. |
| A6 | Canonical work-session mutations notify the resident daemon of the exact changed task but never cause an interactive session to dispatch or spawn a nested model. | See mapped verification. |
