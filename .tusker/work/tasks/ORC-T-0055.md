# ORC-T-0055 · Establish the durable execution identity and lineage ledger

## Intent

One normalized execution ledger gives every direct invocation and wave authorization generation an immutable root, records every managed or provider-owned strand separately, and preserves existing attempt history without becoming a second ownership system.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Tusker generates immutable execution and root IDs; a new direct invocation receives one root and a new wave authorization generation receives one logical root whose member attempts are independently leased managed children. | See mapped verification. |
| A2 | Display name, normalized search label, task, wave, attempt, session, provider session or task, reusable agent type, provider child handle, node kind, creator, and timestamps remain separate typed fields. | See mapped verification. |
| A3 | Retry, resume, fork, managed-child, and provider-child edges enforce their distinct ownership semantics; provider-child upsert is idempotent and managed-child creation requires independently admitted ready or rework work. | See mapped verification. |
| A4 | Existing attempt relationship rows backfill idempotently, remain readable during compatibility rollout, survive interrupted migration and restart, and cannot weaken work-session, lease generation, or process-identity fences. | See mapped verification. |
