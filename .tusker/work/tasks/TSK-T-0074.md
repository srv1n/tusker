## Intent
An operator cannot tell a running agent anything, and Continue exists only as a Serve action without a message or failure summary. Decision D3 locks hard Say as interrupt, settle, then resume the same native thread with the message as the prompt, and Continue as the same path with a typed failure summary. This task adds `tusker runs say` and `tusker runs continue`, keeps `tusker runs interrupt`, and makes the whole path durable, fenced and idempotent. Soft Say for Claude is added later by claude-soft-say on top of this pipeline.

## Verified seams
- Interrupt: `interruptRuntimeRunScoped` (run_runtime_commands.go) -> daemon control or `interruptRunProcess` (daemon.go), ending in interrupted/cancelled with resumable=true. This is the only interrupt path; reuse it.
- Continue: `queueNativeSessionContinuation` (work_recovery.go) with its fences (live-owner refusal, session compatibility, context fingerprint, wave authorization, UpsertRunIfSnapshot, QueueRunDirective); today reachable only from Serve `handleRunRecovery` (serve_command.go). TSK-T-0051 (W-0039, held) scoped this; extend its implementation, do not fork it.
- Resume prompt: `renderAttemptPromptForResume` (daemon.go) builds the delta prompt passed to `runner.Resume` in daemon dispatch.
- Durable fenced delivery: `WorkerDelivery`, `PutWorkerDelivery`, `transitionWorkerDelivery`, `markWorkerDeliveryState` (worker_coordination.go), keyed by `WorkerAttemptIdentity` plus idempotency key.
- Capability lookup: `nativeResumeRunnerCapabilities` (work_recovery.go) duplicates `runnerForName` (daemon.go); replace the name switch with `runnerForName(...).Capabilities()` so capabilities come from the driver.
- CLI dispatch and help: cli.go `case "runs interrupt"` block and `printRunsHelp`. `tusker run <ID>` is taken by `directRunCmd`, so the verbs go under `tusker runs`.
- Codex exec driver: `CodexExecRunner.Capabilities` (runner_codex.go).

## Implementation contract
Locked:
- Commands: `tusker runs say <TASK-ID> (--message <text> | --message-file <path|->) --by <actor> [--key <idempotency-key>] [--json]` and `tusker runs continue <TASK-ID> [--message ... | --message-file ...] --by <actor> [--json]`. `tusker runs interrupt` is unchanged except its JSON also returns the resulting `operator_state`.
- Durable record: every Say and every Continue message is one `WorkerDelivery` of kind `instruction` bound to the current attempt identity (attempt id, attempt generation, work revision, native session id). Default idempotency key when `--key` is absent: `say:` + sha256(actor, body, attempt id, generation). Repeating the same command returns the same delivery and performs no second interrupt or continuation.
- Say preflight uses run-state: allowed in `working` and `quiet`; in `waiting_on_you` refuse and point to `tusker message reply`; in `blocked`, `failed`, `lost` refuse and point to `tusker runs continue --message`; runs with no native session refuse. Route selection reads capabilities only: the `SoftSay` route is added by claude-soft-say; this task implements the `HardSay` route and refuses with the declared reason when a driver declares neither.
- Hard route: store delivery -> interrupt through the shared path -> wait for settlement (`runSessionControlSettled`) -> `queueNativeSessionContinuation` with an options value carrying the delivery ids and an optional typed failure summary -> the daemon's resumed attempt renders pending deliveries verbatim under an "Operator message" heading in `renderAttemptPromptForResume` and marks them accepted with the child attempt id as receipt, in the same claim that creates the child attempt.
- Pending-delivery rule (makes restart safe): every stored, not-yet-accepted instruction delivery bound to the parent attempt identity is included, in stored order, in the next native continuation of that run, whichever command queued it. A CLI crash after interrupt therefore loses nothing: a later `runs continue` (or the same `runs say` retried) delivers it.
- Continue: wraps `queueNativeSessionContinuation`; the resumed prompt includes the typed failure summary (code, guidance, last error, last event) from typed-reasons plus any message. Start fresh stays explicit and separate.
- Codex exec declares HardSay=true, ResumeAfterDeath=true, PreassignSessionID=false, SoftSay=false (research: no verified mid-turn injection in exec mode).
- No "deliver when the current turn ends" route: all four drivers support hard Say, so a deferred route would have no user (add it when a driver declares neither).
Proposed: exact new delivery state names between stored and accepted (for example `awaiting_settle`); delivery result JSON shape `{delivery, route, operator_state, continuation}`.

## Failure and edge cases
- Two terminals run `runs say` with different messages while Working: one interrupt, one queued continuation, both messages in the resumed prompt in stored order. Forbidden: two child attempts or two live processes.
- Same `runs say` repeated after a lost response: same delivery id, `duplicate: true`, no second interrupt.
- CLI killed after interrupt, before queueing: delivery stays stored; `tusker runs continue` later includes it. Forbidden: message silently dropped.
- Run completes successfully between Say preflight and interrupt: delivery marked undelivered with reason "run completed before delivery"; command exits non-zero with that reason. Forbidden: continuing a succeeded attempt.
- Attempt changed between read and interrupt (new generation): delivery marked stale via markWorkerDeliveryState; no signal sent to the new attempt.
- Runner declares HardSay=false: refused with the declared reason; no interrupt.
- Continue on a `working` run: refused by the existing live-owner check.
- Continue on `blocked` usage_limit: queued; the prompt contains the usage_limit guidance line.
- Daemon restart between queueing and claim: the directive and pending deliveries survive; exactly one child attempt consumes them.
