## Intent
Landing gates and closeout checks are started today with no process group, no
time limit and no record. If the daemon dies, they keep running and nobody knows.

Add a process inventory and route every check through one way of starting
processes:
- Each check runs in its own process group and gets an inventory row: owner,
  kind (check), PID, process group, start time, starting daemon instance,
  started time and last sign of life (last output).
- The check's whole group is stopped when the check finishes or is cancelled,
  or when its starter asks all of its checks to stop.
- A check silent for longer than the project's check silence limit (default 10
  minutes) is stopped. The outcome is recorded as stuck and stopped, which must
  read differently from a failed check.
- Agent wrapper spawns also write an inventory row of kind agent session (they
  already record PID, process group and start time on the run row).
- Expose an operation that stops every check started by a given daemon instance,
  for the watchdog and shutdown task to call.

## Failure and edge cases
- A check that keeps printing output for 30 minutes is not stopped.
- A reused PID with a different start time is never treated as the same process.
- The isolated sandbox gate path must also cancel and stop its group; today it
  runs with a background context that is never cancelled.
- An inventory write failure must not let a check run unrecorded: refuse to
  start it and report why.
