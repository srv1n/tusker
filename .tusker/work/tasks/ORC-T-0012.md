# ORC-T-0012 · Evidence-by-risk-class defaults in the shipped template

## Intent

Every repo re-declares proof policy by hand. A fresh vault's WORKFLOW.md is
generated by `defaultWorkflow()` (`cmd/tusker/daemon.go`), and `config.go`'s
`mergeConfig` merges only the poll interval and the definition-of-done flags
(`RequireCodeComplete`, `RequireUserVerifiedForUI`) — there is no single
declarative evidence-by-risk-class default that projects inherit. So each task
re-declares `proof_mode` / `evidence_budget` individually, and the
`orchestration.gate` stanza is added ad hoc (this repo has it; a fresh
`tusker init` elsewhere does not).

Make the shipped template land good defaults so a fresh `tusker init` starts
correct:
- `proof_mode: inline` with `evidence_budget: 0` as the default;
- evidence files required only for the evidence-bearing proof modes — `card`,
  `artifact`, `audit` — with everything else inline;
- an `orchestration.gate` stanza present with placeholder `profile` and floor
  values and a comment per field explaining it. The `min_free_disk_gb` comment
  MUST state the value has to be MEASURED against the project's real peak build
  footprint, and cite that an unmeasured guess of 15 GB authorized a doomed run
  on 2026-07-20 (the run died on a full disk mid-gate and its recovery deleted
  the build cache the next run needed).

Existing repos are unaffected until they re-seed.

File map for the implementer: the seeded `.tusker/WORKFLOW.md` orchestration/
proof content originates in `defaultWorkflow()` (`cmd/tusker/daemon.go`); the
repo-contract helper docs ship from the embedded tree
`skills/tusker/assets/repo-contract/` (written by
`writeEmbeddedTree("repo-contract", ...)` in `cmd/tusker/install.go`); and
`skills/tusker/references/WORKFLOW.md` is the skill's lifecycle reference. The
default proof/gate stanza and its explanatory comments belong in the template
source that a fresh init seeds.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A fresh `tusker init` on a scratch directory produces a WORKFLOW that declares the default proof policy: `proof_mode: inline`, `evidence_budget: 0`, and evidence files required only for the `card`, `artifact`, and `audit` proof modes. | Inline verification |
| A2 | The same fresh WORKFLOW contains an `orchestration.gate` stanza with placeholder `profile` and floor values and a comment per field; the `min_free_disk_gb` comment states the value MUST be measured and cites the 2026-07-20 unmeasured-15 GB doomed run. | Inline verification |
| A3 | Existing repos are unaffected until re-seeded: re-running `init`/sync without an explicit force/overwrite flag does not rewrite a repo's existing WORKFLOW proof/gate declarations. | Inline verification |

## Non-goals

- No change to the proof engine or to how `config.go` resolves proof mode at
  runtime; this task changes the DEFAULTS a fresh init lands, not resolution
  semantics.
- No migration of existing repos; re-seed is opt-in.
- No hand-editing of generated install copies under `.agents/**` or
  `.claude/**`; only canonical template source is changed.
