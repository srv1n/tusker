# TRC-T-0002 · Replay modes and replay-backed verification rows

## Intent

With boundary traces recorded (TRC-T-0001), make them executable again. Design sources: docs/design/aie2026-adoption-plan.md workstream 2; docs/design/aie2026-mining/durability-loops.md and factories-leftovers.md.

Replay runs a recorded attempt's decision path against current code with recorded boundary outputs substituted for live calls. Two modes ship first: `mock` (every model/tool boundary returns the recorded output — fully deterministic, zero model calls, suitable for CI) and `live-tools` (model outputs replayed, tool calls re-executed — detects environment drift). Comparison is state-transition equality, not text match: a replay passes when the sequence of typed state transitions (lease changes, verify-row writes, file-touch sets) matches the recording, not when byte-identical text is produced.

This powers a new verification-row check type: `replay:<trace-id>`. A task's verification table can pin a recorded failure or a golden run; re-running verification replays the trace in `mock` mode and fails on transition divergence. Regressions become replayable artifacts instead of prose bug reports.

Integrity rule (from the Cursor mining, [8:19:43]/[8:20:14] — models mine git history and forks for expected answers): replay-graded environments must be stripped — the replay worktree excludes `.git` history and runs with network access off in `mock` mode, so a runner under evaluation cannot look up the recorded answer.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `tusker trace replay <trace-id> --mode mock` re-executes a recorded attempt with all boundary outputs substituted, makes zero network/model calls, and reports pass/fail by state-transition equality (regression test on a fixture trace). | Inline verification |
| A2 | `--mode live-tools` re-executes tool boundaries live while substituting model outputs, and reports which boundaries diverged from the recording. | Inline verification |
| A3 | A verification row of the form `replay:<trace-id>` executes mode `mock` replay during proof evaluation; a deliberately divergent fixture fails the row with the first divergent transition named. | Inline verification |
| A4 | Mock-mode replay environments are stripped: no `.git` history in the replay worktree and network off; a test asserts both properties. | Inline verification |

## Non-goals

- No `record`-mode re-capture during replay and no trace diffing UI (later TRC work).
- No serve-UI replay surface (SRV epic consumes this).
- No flakiness scoring or replay-based evals (needs a corpus first).
