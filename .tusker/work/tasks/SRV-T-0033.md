# SRV-T-0033 · Prevent and reconcile duplicate project registrations

## Intent

Make project registration idempotent across CLI, install, and serve entry points, and reconcile legacy duplicate discovery rows without deleting historical runtime evidence.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Re-registering the same canonical repository or vault path returns the existing project instead of creating another registry row. | Automated tests cover CLI and storage-level registration. |
| A2 | Existing duplicate discovery rows are automatically consolidated deterministically, preserving one authoritative project while retaining historical runtime rows under their original identities. | Automated reconciliation tests cover enabled/healthy preference, startup cleanup, and history retention. |
| A3 | Equivalent paths, including cleaned and symlink-resolved forms where available, cannot bypass duplicate protection. | Focused canonical-path tests. |

## Non-goals

- Do not delete repository files, vault content, task documents, or Git worktrees.
- Do not merge different repositories merely because their folder names match.
