# SRV-T-0025 · Instant multi-project Serve projections and seamless project switching

## Intent

Serve currently exposes all registered projects in navigation but builds every
read endpoint from one launch-time vault. Requests for any other project waste
roughly a second rebuilding the wrong snapshot and then return an empty array.
Even the primary project reparses Markdown and recomputes the automation queue
on every endpoint request, while the overview adds a projects-first request
waterfall and replaces the whole view with skeletons.

Make Serve a genuine multi-project projection service. Registered projects get
independent, eagerly warmed snapshots keyed by project ID. Reads reuse the
materialized projection; mutations and daemon events invalidate the owning
project so the next read refreshes it without cross-project contamination.
Project switching must render cached data immediately and refresh in place.

| A2 | Snapshot builds are cached per project and concurrent reads share one build; repeated unchanged reads do not rewalk/reparse the vault or recompute its queue. | focused_test |
| A3 | Project registration, task/gate/evidence mutations, and daemon state events invalidate only the affected projection; no stale mutation result or cross-project data leak is served. | focused_test |
| A4 | The daemon eagerly warms enabled registered projects, and endpoint latency after warmup is bounded to an in-memory projection read. | focused_test |
| A5 | Project overview does not wait for a projects metadata request before mounting project queries, and existing cached content remains visible during background refresh. | focused_test |
| A6 | Full Go Serve tests, race checks, UI typecheck/tests/build, signed Mac bundle build, and a live three-project smoke test pass. | broad_test |

## Non-goals

- No SQLite search/index migration; the current vault sizes fit comfortably in memory.
- No filesystem watcher dependency. Daemon poll events and mutations own invalidation.
- No changes to project task schemas or migration of registered repositories.
