# AAC-T-0001 · Define shared access settings and preserve existing profiles

## Intent

People can describe project access once and get the same answer in settings and execution. Existing profiles retain their permissions and selected agent when upgraded or edited. Done is a contract example set, migration matrix and capability report examples. This story defines and resolves policy; native execution and interface changes follow in dependent stories.

## Implementation notes
Read .tusker/specs/agent-access.md and its decision log. This is future implementation work; the planning session has not built or dispatched it. Preserve the shared dirty baseline and reconcile current ownership before editing. Reuse existing profile, runner, runtime and UI authorities. Do not launch a daemon or nested worker from an interactive session, change automation, invent provider fallback or add an OS sandbox. Proposed new filenames are recommendations; trace the common launch, test and resume callers before choosing the smallest complete implementation. Keep native coverage explicit. Run named checks after implementation settles; zero matching cases is failure. Use disposable fixture files for negative cases. Paid/live provider runs require explicit authorization and separate evidence. Record outcomes, exact route/version and limits in the artifact. Independent review uses existing workflow, not a new human code-review gate.

Extend RunnerProfileDefinition, existing settings persistence and revision handling, runner catalog DTOs, PreparedLaunch and EffectivePolicy. Publish exact read/save/catalog/preview response examples, issue codes and approval DTOs for dependent stories in contracts.md. Use an optional versioned access object mutually exclusive with active legacy permission_preset; no parallel policy store. Add shared private-folder settings and profile additions. Apply defaults only on new profile creation, never missing-field legacy reads. Preserve tiers, overrides, disabled profiles, expected revisions and existing full-access admission. Resolve workspace from execution context, narrow temporary directory, native support roots and explicit references. Validate absolute paths, symlink-aware overlaps, private precedence and workspace conflicts; deny unsupported required controls, including read-only reference mapped to write. Keep provenance keyed by exact executable/transport/version/config and reuse conformance invalidation. Add types/API seams for resolveAccess and normalized requests in the existing authorities, not a one-provider interface hierarchy. Update CONTEXT.md only with the concise agreed domain terms, preserving its dirty contents. Required tests: TestAgentAccessContract and TestAgentAccessMigration.
