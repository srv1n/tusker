# ORC-T-0046 · Ship one outcome-first factory operations surface

## Intent

A user can see what delivered, what is working, what is in review or rework, what is blocked, what needs a decision, and what runs next without opening logs or task frontmatter.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | CLI, stable JSON API, Serve, and desktop consume one versioned projection with ordered Delivered, Working now, In review or rework, Blocked, Needs your decision, and Next frontier sections. | See mapped verification. |
| A2 | Rows use product outcomes, bounded causes, affected dependency closure, automatic next action, accepted artifacts, and integration or default revisions while raw logs, prompts, transcripts, YAML, heartbeats, and token totals stay in diagnostics. | See mapped verification. |
| A3 | The surface shows automation enabled state, configured and effective dispatch scope, armed wave fingerprint health, integration and promotion mode, capacity, resource holds, and exact pause, resume, disarm, or repair action. | See mapped verification. |

| A5 | Disabled, disarmed, stale, idle, running, review, rework, parked, human-gated, integrated, and promoted fixtures remain understandable and accessible at desktop and narrow widths. | See mapped verification. |
