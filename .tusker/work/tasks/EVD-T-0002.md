## Intent
Whether passing checks still match the code should be decided with git, at
the moment the proof is used: review, landing and closeout. Today the daemon
reads and hashes every file in each wave member's workspace up to four times
on every pass, including one hash that is immediately repeated with nothing
in between, and hashes review workspaces before knowing whether anything
needs them. The proof rule stays: proof only counts for the exact code it
ran on.

## Failure and edge cases
- A commit or an uncommitted edit in the task's files after the checks ran
  must make the proof stale.
- Generated files that git ignores still need a content check, because git
  cannot see them.
- A review task with no pending close event must not touch its workspace.
