# MAC-T-0010 · Recover Mac shell from stale startup state

## Intent

Make the native Mac window and panel recover when their last observed runtime
state is stale. A healthy Serve endpoint must win over a missed or out-of-order
runtime notification; the loading overlay must never remain above a live UI.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The visible main window and panel continue probing `/api/summary` while runtime state is idle, checking, starting, or failed, and load immediately when it is healthy. | Focused Swift tests and source inspection |
| A2 | Late health callbacks cannot overwrite a newer probe result, and loading a healthy page hides the stale startup overlay immediately. | Focused Swift tests |
| A3 | Cold daemon startup gets a bounded 15-second readiness window, while the steady-state monitor retains a three-second health timeout. | Focused Swift tests |
| A4 | The signed release app bundles the current Go runtime and Serve assets successfully. | Release app build |

## Non-goals

- Installing or restarting the user's currently running TuskerBar app.
- Changing project reconciliation or automation policy.
