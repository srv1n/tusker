# PRF-T-0008 · Adaptive event-driven reconciliation with idle project backoff

## Intent

Make the resident daemon event-driven for ordinary operation and cheap when
repositories are idle. Canonical CLI writes and UI attention should reconcile
one project immediately. Timed reconciliation remains a bounded safety net for
raw file edits and recovery, but runs only for projects whose adaptive cadence
is due and uses the frontmatter cache so unchanged projects do almost no work.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Every successful canonical vault mutation flows through one shared post-commit notification boundary; adding a new mutating command cannot silently omit targeted daemon reconciliation. | Mutation classification/notification tests. |
| A2 | CLI writes and UI refresh/attention reconcile only the affected project promptly; bursts coalesce and reset that project's activity age. | Control-socket and scheduler tests. |
| A3 | Each enabled project independently backs off through hot, warm, cool, and cold safety cadences: 60 seconds, 5 minutes, 10 minutes, then 30 minutes; activity immediately returns it to hot. | Deterministic clock/scheduler tests. |
| A4 | Actively viewed projects reconcile at the 20-second attention cadence, while unrelated projects keep their own idle cadence and are not loaded on another project's tick. | Multi-project attention tests. |
| A5 | Projects with live/retry-sensitive runtime state or armed runnable work never enter an unsafe cold cadence; crash recovery, lease retirement, review, and genuine human-gate projections remain timely. | Runtime-state cadence tests and crash-recovery suite. |
| A6 | An unchanged due project performs frontmatter/cache validation without full Markdown reads or YAML reparses; a changed file invalidates only its cached note and produces the correct state. | Instrumented note-cache tests. |
| A7 | Raw external edits remain discoverable within the project's current bounded safety cadence, and daemon restart safely begins hot rather than trusting stale in-memory activity. | External-edit and restart tests. |
| A8 | Status/stream projections expose the effective cadence, last activity, and next due time so idle behavior is observable rather than magical. | API/status tests. |
| A9 | Focused daemon/serve tests, broad Go/e2e tests, UI checks, and race-sensitive reconciliation tests pass. | Commands below. |

## Non-goals

- Filesystem watchers as a correctness dependency.
- Disabling safety reconciliation forever for registered projects.
- Enabling project automation by default.
