# ORC-T-0058 · Track Codex local, app, cloud, and native child executions

## Intent

Codex top-level threads, cloud tasks, and native subagents appear under the correct Tusker root with their real provider identities and truthful control limits.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Local CLI and app event paths capture the top-level thread, provider child ID, reusable agent type, spawn label when available, parentage, lifecycle event, and source sequence without confusing nested IDs with the resumable parent thread. | See mapped verification. |
| A2 | Codex Cloud records the durable cloud task, environment, status, provider timestamps, and discoverable children without inventing a local PID, wrapper heartbeat, or operating-system settlement. | See mapped verification. |
| A3 | Replay, polling overlap, missing optional fields, malformed hook payloads, lost hook delivery, and provider status regression converge or report degraded visibility with an actionable reason. | See mapped verification. |
| A4 | Adapter capability facts distinguish parent interrupt, independent child control, resume, enumeration, and replay support; unavailable capabilities never become controls or fake ownership. | See mapped verification. |
