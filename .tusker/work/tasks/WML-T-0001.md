## Intent
Make the two workspace modes real. Shared mode works in the project's own checkout with no worktrees and no branches, commits each task's owned files directly, runs tasks in parallel only when their owned files do not overlap, and fixes rejected work forward. Worktree mode merges each task into main as soon as it passes review and its landing check, with no wave branch; if main moved, the task is brought onto current main and its checks rerun, and only a real conflict returns it as rework. Re-approval is needed only when a task's promise changes and then applies to the next attempt; commits to main never require it.

## Acceptance
| ID | Outcome | Proof |
| --- | --- | --- |
| A1 | In shared mode a task runs and lands in the project checkout with no worktree, task branch or wave branch, committing only its owned files. | Verification A1 |
| A2 | In worktree mode a passing task merges into main immediately, including after main moved, with no wave branch. | Verification A2 |
| A3 | A commit to main does not require re-approval; a changed task promise does, and applies to the next attempt instead of being refused while one runs. | Verification A3 |
