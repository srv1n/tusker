# OPS-T-0011 · Fail closed when release checksums cannot be verified

## Intent

The public installer currently continues when no checksum tool is available or
when `checksums.txt` has no entry for the selected archive. That turns integrity
verification into best effort. Fail closed before extraction or destination
mutation unless a supported checksum tool exists, exactly one non-empty entry
matches the asset, and the computed SHA-256 matches. Error messages must identify
the missing capability/entry/mismatch without deleting an existing binary.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Missing checksum tools or a missing/duplicate/empty asset entry refuses installation before extraction or destination mutation. | focused_test |
| A2 | A checksum mismatch refuses with expected/actual values and preserves an existing installed binary; a valid checksum installs normally. | focused_test |
| A3 | Installer tests cover macOS and Linux command variants and the release artifact checksum format. | focused_test |
| A4 | Existing install/update and full release-candidate gates remain green. | broad_test |

## Non-goals

- No artifact signing or notarization.
- No network retry policy.
- No updater changes owned by OPS-T-0010.
