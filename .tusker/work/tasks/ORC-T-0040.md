# ORC-T-0040 · Make daemon dispatch authority explicit and wave-scoped by default

## Intent

A repository can enable the resident daemon without authorizing arbitrary ready tasks, while existing explicitly broad automation remains compatible and visible.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Fresh setup writes automation disabled with effective dispatch scope armed_waves, and absent setup never produces a background claim. | See mapped verification. |
| A2 | An enabled armed_waves project dispatches only ready or rework members of an armed, non-stale exact wave fingerprint and refuses unrelated eligible tasks with a stable reason. | See mapped verification. |
| A3 | The all_eligible scope is an explicit advanced mode, while existing enabled projects with no scope preserve prior behavior through a visible legacy-effective projection and doctor warning rather than silent authority drift. | See mapped verification. |
| A4 | Workflow inspection, automation planning, wave preflight, daemon status, and Serve expose configured and effective scope plus provenance and one exact repair. | See mapped verification. |
| A5 | Changing dispatch scope never enables automation, arms a wave, starts a daemon, satisfies a gate, changes runner permission, moves a Git ref, or authorizes release or paid work. | See mapped verification. |
