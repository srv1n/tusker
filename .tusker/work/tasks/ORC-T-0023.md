# ORC-T-0023 · Bind optional releases to named authorized profiles

## Intent

A separately opted-in release runner deploys only the exact green promoted revision without exposing credentials or arbitrary shell authority to models.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Promotion never implies release; absent, disabled, held, or unauthorized release configuration produces no external action. | See mapped verification. |
| A2 | Release configuration names a validated profile rather than embedding an arbitrary deploy shell command in the departure policy. | See mapped verification. |
| A3 | The release binds the promoted SHA, environment, credential provider, deterministic runner, idempotency key, rollback reference, and authorization provenance. | See mapped verification. |
| A4 | Secrets resolve only inside the release runner and are absent from prompts, records, task Markdown, logs, notifications, JSON APIs, and command previews. | See mapped verification. |
| A5 | Release hold, retry, duplicate trigger, partial failure, and rollback record one truthful durable outcome without repeating a successful release. | See mapped verification. |
