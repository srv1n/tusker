# LIF-T-0005 · Route daemon dispatch and manual pickup through one ownership path

## Intent

Route every execution entry point through the same claim and project-capacity transaction before starting a process. Eliminate the race where manual Codex work leaves a task ready and the daemon independently dispatches Claude for the same contract. Record the authorization source for audit and operator display.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Daemon polling claims through the canonical ownership service and starts a runner only after ownership commits; claim refusal is a normal no-dispatch outcome. | focused_test |
| A2 | Manual Tusker CLI, Codex, and Claude pickup use the same service and block daemon pickup immediately without requiring a durable task-status edit. | focused_test |
| A3 | Every run records authorization source (`daemon_auto`, `tusker_cli`, `codex`, or `claude`), actor, trigger, and project automation state at claim time. | focused_test |
| A4 | Disabling project auto-spawn prevents new daemon claims but does not interrupt, delete, or hide existing runs; manual claims remain available. | focused_test |
| A5 | Project concurrency and task exclusivity are enforced atomically under concurrent daemon/manual attempts, including two different tasks in shared mode. | focused_test |
| A6 | Retry/redrive paths create a new attempt under the same task only after prior ownership is terminal or reclaimable. | broad_test |

## Non-goals

- Do not infer authorization from runner name alone.
- Do not make project registration automatically enable daemon dispatch.
- Do not interrupt active work merely because auto-spawn is switched off.
