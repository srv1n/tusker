# FBK-T-0004 · Add Tusker and ChatGPT handoff onboarding doctor

## Intent

Promoted from three duplicated RZN feedback notes. Make Tusker and ChatGPT handoff onboarding reproducible enough that agents do not need to manually purge stale vault state, repair skill symlinks, rebuild binaries, or debug browser workflow drift by hand.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Tusker setup doctor checks stale vault symlinks, generated-vs-source skill sync state, binary/version mismatch, and missing or mismatched `WORKFLOW.md` paths. | Focused fixture tests include the stale `kurpod` `tusker` vs `.tusker` vault-root case. |
| A2 | `tusker skill sync` or its replacement is source-aware and reports whether it is syncing from canonical source, generated install output, or an invalid source. | Focused tests cover canonical, generated, and invalid source paths. |
| A3 | Handoff setup diagnostics cover ChatGPT handoff profile/routing checks, zip attachment pattern validation or auto-detection, and browser workflow version drift with actionable remediation. | Focused tests or provider-probe fixtures assert each diagnostic without requiring live browser credentials. |
| A4 | The repair path is idempotent and separates dry-run diagnostics from write actions. | Fixture tests run doctor/repair twice and verify stable output. |

## Non-goals

- Require live ChatGPT credentials for ordinary tests.
- Make browser-backed ChatGPT durable Tusker state.
- Hide setup failures by silently rewriting user-owned config.
