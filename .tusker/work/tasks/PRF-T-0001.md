# PRF-T-0001 · Raise reconcile poll default and add interval override

## Intent

The daemon reconciles every 5 seconds because the workflow default stamps `runtime.poll_interval_ms = 5000` into every project (`cmd/tusker/workflow.go:148`). `nextPollInterval` (`cmd/tusker/daemon.go:203-228`) takes the **minimum** interval across all loadable registered projects, so one 5s project drags the whole daemon to 5s; the 30s fallback only applies when no project is loadable. There is no flag or env override — the legacy `poll.interval_seconds` config key (`cmd/tusker/config.go:54`) is display-only and dead.

Change the default to 30000ms (or 60000ms), add a global override (`TUSKER_POLL_INTERVAL_MS` env or daemon flag) with a sane floor (e.g. clamp ≥ 5000), and consider whether min-across-projects is even the right aggregation. Keep the watchdog consistent: stale threshold is `3 × pollInterval` (`cmd/tusker/daemon.go:46-50, 174-228`) — verify no false self-kill (`os.Exit(70)`) at longer intervals.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | With no project setting `poll_interval_ms`, the effective poll interval is ≥ 30s. | Inline verification |
| A2 | A global override (env or flag) beats per-project workflow values and is clamped to a floor. | Inline verification |
| A3 | Watchdog does not false-trigger at the longer default (staleness math tracks the effective interval). | Inline verification |
