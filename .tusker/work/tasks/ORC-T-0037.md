# ORC-T-0037 · Migrate repository onboarding to the delivery-plan language

## Intent

Onboarding produces conservative knowledge proposals and optional requirements-traceable executable DAGs instead of a parallel task-list format with weaker validation.

| ID | Outcome | Proof |
|---|---|---|
| A1 | The onboarding prompt emits project observations, assumptions, questions, proposed epic contracts, source-keyed gates, and V2 delivery plans for executable work without assigning final Tusker identities. | See mapped verification. |

| A5 | Existing onboarding packets remain readable and migration reports every field that cannot be converted without human intent. | See mapped verification. |
