# PRF-T-0004 · Serve snapshot dedup and redundant walk elimination

## Intent

The daemon and the serve UI feed each other work every tick even when nothing changed. Confirmed chain:

1. `pollOnce` ends with an **unconditional** `poll_tick` broadcast (`cmd/tusker/daemon.go:941` → `daemon_stream.go:47-49`, keys `daemon`+`projects`), no did-anything-change guard.
2. The SSE broker has no coalescing/debounce (`serve_stream.go:63-90`); the SPA invalidates per message with none either (`internal/serve/ui/src/lib/stream.ts:126-130`), so every tick refetches `/api/daemon` and `/api/projects` on every connected client.
3. `/api/daemon` → `daemonStatusFromSnapshot` reloads all registered projects **including workflow files** (`serve_command.go:690`) and calls `hasOpenP0Escalation` — a **full uncached vault walk via `loadV7Index` on every request** (`serve_command.go:721` → `v7_escalation_digest_cmd.go:806-817`).
4. `/api/projects` → `handleProjects` reloads metadata + `ListRuns` + a per-project snapshot loop (`serve_command.go:744-775`).
5. Even warm snapshot-cache hits pay `projectForSnapshot` → `loadRegisteredProjects` + `resolveV7ProjectID` per request (`serve_command.go:433, 391, 406`).
6. Snapshot rebuilds (30s TTL, `serve_command.go:381,453`) call `serveDocList`, which walks the **entire repo root** frontmatter-parsing every `.md` (`serve_docs.go:62-100`) — pathological for large repos and vendored trees.
7. `projection_refreshed` fires after any rebuild with no content comparison (`serve_command.go:495-500`), invalidating ~13 query families even for byte-identical snapshots. `serveSnapshotEntry` has no hash field (`serve_types.go:24-34`).

Deliverables: gate or content-hash the per-tick invalidations (identical snapshot → no broadcast); move escalation state into the cached snapshot; drop the pre-cache metadata reload on warm hits; scope the docs walk (vault + configured docs dirs, skip `.git`/`node_modules`/vendor at minimum); add client-side debounce; keep the single-flight cache semantics covered by `serve_multi_project_cache_test.go`.
