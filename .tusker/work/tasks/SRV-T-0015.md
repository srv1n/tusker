# SRV-T-0015 · Runs list is unreadable: NaN event timestamps, unlabeled columns, terminal churn rows masquerading as live runners

## Intent

Observed today (2026-07-08) across the runs list and event tails (TRC-T-0002 and AGX-T-0005 pages). Three defects on the honest-runs surface:

- Every event-tail row renders `NaN:NaN:NaN` for its timestamp — a field-name/format mismatch between the runs API (reworked in the "honest runs API" wave) and the UI's timestamp parser.
- The runs list shows bare, unlabeled columns — e.g. `2.4`, `13:43.74`, `15`, `259` (apparently tokens-M, duration, attempts, events) — with no header row and no lease/outcome column.
- Dozens of pre-RUN-T-0036/0037 churn-era historical rows (14–15 attempts each) render visually identical to live runs, which is exactly why the operator read them as "numerous fake runners still running".

Semantics:

1. **Valid timestamps.** The event tail parses the timestamp field the runs API actually emits (matched name and format) and renders real clock times; no NaN.
2. **Labeled columns.** The runs list has a header row naming every column and surfaces lease_state and outcome per row.
3. **Terminal vs live distinct.** Terminal/historical rows are visually distinguished from live runs (styling/badge/section), so a settled 15-attempt churn row can never be mistaken for a running fleet member.
