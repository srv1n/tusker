# ORC-T-0048 · Make claimed DAG execution the canonical installed-skill contract

## Intent

Every installed Tusker agent plans multi-task work as an inert DAG, claims modifying work through the shared session protocol, and leaves routine review, landing, and successor scheduling to the opted-in daemon.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The operator skill uses normative must-language for multi-task delivery-plan DAGs, inert import, epic versus wave authority, project opt-in, armed-wave dispatch scope, and one fingerprint-bound Start action. | See mapped verification. |
| A2 | Interactive guidance requires work start and direct implementation without starting a daemon or nested runner, while dispatched-worker guidance verifies the injected claim and never claims again. | See mapped verification. |
| A3 | Implementation guidance submits proof, reviewer guidance submits only a typed verdict, and all guidance assigns clean merge, close, integration, and successor scheduling to deterministic Tusker handlers. | See mapped verification. |
| A4 | Guidance asks users for requirements, acceptance, important tests, constraints, and genuine decisions and never makes them operate task IDs, dependency syntax, workspaces, runners, retries, review cycles, or frontiers. | See mapped verification. |
| A5 | Setup and rollout doctor distinguish current, stale, missing, incompatible, and locally modified canonical, symlinked, copied, and bundled installs and provide one safe sync or policy repair. | See mapped verification. |
| A6 | Guidance tests fail on any path that implies automatic project enablement, whole-epic execution, arbitrary lifecycle scripts, reviewer Git choreography, release authority, paid work, or unclaimed modifying work. | See mapped verification. |
