## Intent
The daemon should only work on a project when something changed or the
operator is using it. Today any live run puts its project on a full pass
every five seconds, every project is fully reread at least every five
minutes, and registered projects nobody is working on still get timed
passes. A project is active only while it has a live or retry-queued run,
an armed wave with members left, or the operator interacted with it in the
last ten minutes. Active projects with live runs get a cheap heartbeat;
everything else waits for an event.

## Failure and edge cases
- A CLI command, a runner report, a process exit or a scheduled wake-up
  (retry backoff, budget) still triggers work immediately.
- Hand edits to an active project's task files are noticed by a stat-only
  check on the heartbeat; hand edits to an idle project are picked up when
  the operator next interacts with it.
- Opening or clicking a project in the UI triggers one rescan of that
  project, debounced, not one per request.
- At startup only projects with live work are rescanned; adoption of
  running agents and the process janitor still run.
- Wave frontiers advance on wave, task or spec change, on a run finishing
  or landing, and on a rescan; never on a timer.
