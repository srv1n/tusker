# DEL-T-0006 · Dogfood and roll out spec-to-wave unattended delivery across registered projects

## Intent

Prove the complete operator workflow in a disposable project and then roll the
compatible skill/workflow/runner configuration across registered repositories.
This is the acceptance task: no production claim is credible until a canonical
spec becomes an armed DAG, survives failure and daemon restart, drains serial
and parallel branches, lands objective work, and emits the artifact-first brief
without inline human babysitting.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A disposable fixture starts from an approved spec and imports a six-plus-task DAG with one serial root, two parallel frontiers, soft and hard dependencies, exact proof, and mixed artifact contracts. | End-to-end fixture and imported graph artifact. |
| A2 | One preflight and arm action causes the managed daemon to execute the complete eligible graph through isolated workspaces, reviewer close, integration landing, and documentation updates without further approval prompts. | Recorded lifecycle timeline and final wave state. |
| A3 | Injected worker failure, daemon SIGKILL/restart, stale authorization, and one credential gate each produce the specified containment/recovery behavior while unrelated branches continue. | Failure-injection matrix and replay artifacts. |
| A4 | The final brief leads with acceptance-linked screenshots/video, benchmark delta, trace/matrix, and security/reliability summary where applicable; it distinguishes landed, parked, and genuine human action precisely. | Promoted delivery-brief artifact. |
| A5 | Setup doctor identifies and idempotently repairs stale Tusker skills/workflows/binaries, legacy runner harnesses, routine approval prompts, dead/unmanaged daemon services, and invalid close-policy defaults across registered fixture projects. | Cross-project diagnostic/repair matrix. |
| A6 | Rollout never rewrites project knowledge, task contracts, secrets, or unrelated repo instructions; incompatible projects remain quarantined with one actionable report. | Preservation and quarantine tests. |
| A7 | Go, e2e, Serve UI, skill doctor, knowledge validation, and macOS shell checks pass under the serialized validation policy. | Broad automated suites. |

## Non-goals

- Enabling automation for real external projects without explicit operator authorization.
- Claiming production readiness from unit tests without the disposable managed-daemon dogfood run.
- Treating quarantined or credential-blocked projects as rollout failures for healthy projects.

## Operator artifact

The artifact-first brief from the disposable wave, including the DAG timeline,
visual/benchmark/trace evidence, daemon restart, isolated parked closure, landed
tasks, documentation delta, and exact cross-project rollout report.
