## Intent
TSK-T-0064's three regression tests fail on HEAD with "Claude worker MCP requires a prepared direct argv launch": cd908c56 made `startLiveClaude` and the Codex exec start refuse any request without `CommandArgv`, and the tests still pass a command string. Production dispatch always prepares argv, so live launches work, but restart survival, session-id persistence and `--resume` argv are now unproven. Separately, any successful Claude run whose result record lists `permission_denials` is stored as Blocked (permission_denied), which is common under `--permission-prompts none`.

## Verified seams
- runner_claude_live.go `startLiveClaude` (~120): refusal at ~121; dead string-command branch ~139-160 (`command == ""` default, `shellLikeFields`, appending `--replay-user-messages`); prepared-argv branch ~187-205 (`claudeSessionArgv`, `projectWorkerMCP(..., 900, true)`, `appendClaudeMCP`, unconditional `append(argv, "--replay-user-messages")` ~202, absolute-path and `completionVerifyExecutableIdentity` checks).
- runner_claude_live.go `claudeFailureCode` (~590): checks `payload["permission_denials"]` (~594) before the result subtype. runner_exit_classification.go `classifyRunnerProcessExit` (~18) lets a reason code override an exit-0 success.
- runner_claude.go `Start`/`Resume` validate session flags (`validateClaudeSessionFlags`, `validateClaudeResumeFlags`).
- runner_codex.go start/resume refusals (~83, ~92) and `appendCodexMCP` (~103).
- Tests: runner_claude_detached_test.go (~139, ~197, ~262) and fake-claude scripts in runner_live_test.go.

## Implementation contract
Locked:
- Keep the prepared-argv requirement. Delete the unreachable string-command branches in `startLiveClaude` and the Codex exec start/resume so one launch path remains. The refusal message names the fix ("dispatch must supply a prepared argv; command-string launches are no longer supported").
- Update every Claude/Codex runner test that used `Command` to build a prepared argv: absolute path to the fake script, executable fingerprint and search path computed with the same helpers dispatch uses. No production shortcut or test-only flag.
- Append `--replay-user-messages` only when absent from argv.
- `claudeFailureCode` returns permission_denied only when the result is not a success (`subtype != "success"` or `is_error == true`). A successful result with denials stays succeeded and records the denials as a diagnostic event `claude_permission_denials` (count and tool names only).
- Add an argv-level test: start argv contains `--session-id <uuid>`, `--mcp-config` and `--settings`; resume argv contains `--resume <same id>` with byte-identical `--mcp-config`/`--settings` values, no `--session-id`, no `--bare`.
Proposed: helper name for building prepared test argv.

## Failure and edge cases
- Fake claude exits 0 with `{"type":"result","subtype":"success","permission_denials":[{"tool_name":"Bash"}]}` → outcome succeeded, one `claude_permission_denials` event. Forbidden: Blocked state or permission_denied reason.
- Fake claude exits 1 with `subtype:"error_during_execution"` and denials → Blocked permission_denied.
- Profile argv already containing `--replay-user-messages` → appears exactly once.
- Request without CommandArgv → config error, no process spawned, no raw log created.
