# AAC-T-0002 · Apply project access through Codex and Claude controls

## Intent

Routine coding runs proceed automatically while the selected agent applies the requested restrictions and reports gaps honestly. Done is a native-control support matrix backed by disposable boundary probes. This story compiles and enforces policy through existing adapters; it does not build an operating-system sandbox or a general command interpreter.

## Implementation notes
Read .tusker/specs/agent-access.md and its decision log. This is future implementation work; the planning session has not built or dispatched it. Preserve the shared dirty baseline and reconcile current ownership before editing. Reuse existing profile, runner, runtime and UI authorities. Do not launch a daemon or nested worker from an interactive session, change automation, invent provider fallback or add an OS sandbox. Proposed new filenames are recommendations; trace the common launch, test and resume callers before choosing the smallest complete implementation. Keep native coverage explicit. Run named checks after implementation settles; zero matching cases is failure. Use disposable fixture files for negative cases. Paid/live provider runs require explicit authorization and separate evidence. Record outcomes, exact route/version and limits in the artifact. Independent review uses existing workflow, not a new human code-review gate.

Reuse internal/runner prepare/policy execution paths and runner_claude_live.go hooks; trace runner_codex_live.go, runner.go and daemon admission so UI, CLI, test and resume share the resolver. Add the minimum native setting/hook mappings for installed Codex and Claude versions. Do not mix Codex legacy sandbox and newer permission profiles, or use bypassPermissions to implement bounded Claude access. Connect usable existing deny rules rather than claiming declarations are enforced. Classify supported recognized destructive actions, deny catastrophic/private/out-of-scope targets and emit an immutable normalized request for eligible in-scope exceptions. Unsupported required controls make the route unavailable; distinguish direct-file-tool coverage from shell/script coverage. Review-only and Internet off cannot rely on a prompt alone. Allocate and safely clean only attempt-owned temporary directories. Fingerprint actual native config and hook identity. Update runner qualification output with exact tool coverage and test evidence. Required tests: TestAgentAccessNative and TestAgentAccessDestructive. Callback persistence belongs to approval-lifecycle; until available use deterministic native denial, never auto-approve.
