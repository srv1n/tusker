# AGX-T-0006 · Spec and decision traceability: canonical docs linked to work

## Intent

Design happens in interactive sessions with a planning agent; the durable output is canonical markdown — specs under docs/specs/ and docs/design/, decisions under .tusker/work/decisions/ — human-readable, with mermaid diagrams where structure helps. What is missing is the *linkage*: standing in a spec you cannot see its work streams, and standing in a task you cannot see its governing design. Make traceability first-class:

1. Tasks and epics support a `spec_refs` frontmatter list naming their governing specs/decisions (repo-relative paths or decision ids). The planning agent writes these at authoring time.
2. Specs and decisions carry a Work streams section linking the epics/tasks that implement them.
3. `tusker validate` warns on dangling refs in both directions (spec_refs pointing at missing files; Work streams naming unknown task ids).
4. Capsules (`tusker show --capsule`) and agent packets surface spec_refs so an executing agent reads the governing design before touching code — this is the "read next" hop that keeps implementation aligned with intent.
5. The convention (including mermaid-in-specs) is documented in the skill references so every future planning session produces linked, diagrammed canon by default.

Rendering (mermaid, wikilink hops in a browser) is SRV scope; this task is the vault convention, validator, and packet plumbing.
