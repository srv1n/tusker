# RUN-T-0025 · Restart must adopt surviving wrappers, not fence-and-replace them

## Intent

Found live during the RUN-T-0017 re-entry trial, step 2. After SIGKILL of the daemon with two runs mid-attempt:

- **Survival worked** (RUN-T-0013/0018 proven live): both wrappers stayed alive (reparented to pid 1), and both rows' heartbeats kept advancing (~30s cadence) with no daemon — the wrappers heartbeat the store directly.
- **Adoption did not**: the restarted daemon bumped both lease generations (observed 2 and 6), which the wrappers correctly obeyed as a fence-advance stop signal and exited; the daemon then dispatched fresh attempts (attempt_count 1 → 2 on both). Fence-and-replace, not adoption.

The e2e fixture (`TestDaemonKillNineAdoptsSurvivingWrapper`) passes while the live machine replaces — so the fixture models something the real path doesn't do. Likely suspects to audit: the row's `process_pid` had been overwritten with a child pid different from the wrapper pid (observed 42702 vs wrapper 26154 on one row), so verified-liveness (pid + start_time) failed and the daemon reclaimed; or adoption ran before the first wrapper heartbeat refreshed the row.

Fence-and-replace is safe (no duplicate leases, no loop, work restarted cleanly in the same worktree) but wasteful: it discards in-flight attempt progress and re-spends tokens on every daemon restart — under launchd (RUN-T-0015) that cost recurs on every crash/update cycle.

Semantics (per RUN-T-0011 A-criteria, unchanged — this is a repair, not a redesign):

1. On restart, for each held lease with a fresh heartbeat, the daemon verifies liveness against the **wrapper** process identity (pid + start_time recorded at wrapper spawn, not the runner child's), and adopts: keeps the lease generation, does not spawn a new attempt, resumes watchdog supervision.
2. Only when verification fails (dead pid, recycled pid, stale heartbeat past reclaim grace) does the daemon fence and re-dispatch.
3. The e2e adoption fixture is extended to reproduce the live divergence (whatever the audit finds: pid overwrite, heartbeat timing) so fixture-green implies live-green.
