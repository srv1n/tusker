## Intent
The task drawer mixes status, routing, raw receipts, provenance, workspace internals and completion evidence into one scroll. A human cannot find the ticket, current action or whether completion is trustworthy.

## Information architecture
Keep status and the single applicable action fixed at the top. Below it use five sections/tabs in this order:
1. `Overview`: what the ticket is, authored intent/contract summary, current stage and blockers.
2. `Activity`: implementation, verification and independent-review timeline plus a clear Open logs action.
3. `Routing`: tier, worker and reviewer in plain language.
4. `Completion`: acceptance, required checks and independent review as pass/pending/fail/stale badges with concise evidence summaries.
5. `Technical`: raw IDs, hashes, receipt wire data, workspace/branch binding and provenance.

Default to Overview on each newly selected task. Preserve selected tab during polling for the same task. Switching task resets to Overview. Use current components and CSS; do not add a tab library or a parallel task-detail model.

## Content rules
`Unbound provenance` becomes `No architect thread linked` or `No origin thread linked` in Technical; it is not shown as an error. Hide self-claim commands for daemon-owned work. For a configured worker/reviewer, show role and model once, not repeated identity strings. Tier stays editable where currently authorized.

Completion must answer: what was required, latest result, which machine stage produced it, and whether it applies to current material. Collapse history behind `Previous results`. Raw receipt hashes remain Technical. Never show `Completed` together with `accepted proof is unavailable`; either current completion proof is satisfied or the task is not represented as completed. Historical failed/noncurrent proof stays visible without overriding current accepted proof.

The fixed action follows lifecycle recovery semantics: Retry task, Rerun checks, Retry review, View decision, or no action needed. Disabled actions show the exact reason. No terminal command relay, confirmation modal or instruction for a human to perform an agent review.
