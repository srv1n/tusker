## Intent
When the daemon restarts, it must find what the previous instance started and
clean it up, instead of starting the same work again. On 2026-10-18 the watchdog
killed the daemon every three minutes and each restart reran the landing gate.

Deliver:
- A janitor pass at daemon startup and on every poll. It compares inventory rows
  with live owners. When the owner is gone and identity (PID, process group,
  start time) matches, it stops the group and records a durable event with
  reason and rule. When identity cannot be confirmed, it reports and does not stop.
- Agent sessions whose owner record still exists are adopted and left alone,
  however long they have run.
- A landing gate in progress is owned by a daemon instance. A new instance stops
  a dead instance's gate before running it again, so at most one copy runs.
- One global landing-gate slot by default.
- Before the watchdog exits, it stops the checks its daemon started.
- Every abnormal restart counts toward the crash-loop breaker, including while
  landing a passed review. When the breaker opens, automation pauses and the
  reason is visible.
- An agent session with no sign of life past the agent silence limit (default 20
  minutes) emits a silent signal. It is never stopped by this task.

## Failure and edge cases
- A runner launched by the previous daemon and still working must survive a
  daemon restart untouched.
- Never stop a process that carries no Tusker owner identity.
- A janitor pass must be cheap: one process listing per pass, not per row.
- The breaker must not trip on a single clean upgrade restart.
