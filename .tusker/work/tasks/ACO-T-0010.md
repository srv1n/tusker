# ACO-T-0010 · Attribute architect, worker and correction cost from existing run facts

## Intent

Token efficiency must be measured over accepted work, not guessed from worker token prices or inferred from a zero-cost mailbox operation. Join existing message, run and usage facts into a compact per-trial receipt and comparison.

## Implementation notes
Mandatory spec section: .tusker/specs/agent-coordination.md#locked-boundaries-for-the-follow-up. The installed delivery schema inherits spec_refs at plan level; this anchor limits the required section read.

Recommended implementation: GPT-5.6 Terra / high. Independent review: GPT-5.6 Sol / low. These are deliberate task choices, not a reason to silently change model/effort or permissions.

Use the execution/run usage ledger and supervision cause IDs; add only missing correlation fields at their current authority. Record objective/wave/task/material, trigger/message/decision, exact native conversation/turn, model/effort/profile/transport, fresh/resumed context, available input/output/cached/reasoning usage, elapsed time and outcome. Separate initial architect setup, planning, material clarification, worker execution, correction, independent review and bookkeeping. Do not double-count provider events/turns across retries or reattachment; duplicate bookkeeping events remain attributable without charging a new model turn.

Keep unavailable usage unknown. Report raw totals first. If explicit rate data is provided, label cost estimates with rate source/time and account for cached input/output semantics; do not equate API list-price estimates with actual subscription charges. A comparison includes failed/abandoned attempts and any frontier correction/review work. Quality/acceptance mismatch, missing coverage or unknown usage must prevent a blanket savings percentage.

Provide a small stdlib analyzer at the proposed scripts/test-agent-coordination-cost.py path with --receipts/--output and --self-test, using existing receipt files rather than a new telemetry backend or model-powered evaluator. Receipt schema/fixture design can proceed after contacts; hook final decision attribution after supervision. Qualification owns the actual model trials and test budget.
