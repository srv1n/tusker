# ORC-T-0085 · Isolate interactive work admission from daemon dispatch authority

## Intent

The universal work-session protocol admits user-directed work using interactive safety facts only and returns typed dependency, gate, ownership, terminal, and workspace refusals.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Interactive work start ignores registry polling state, automation enablement, daemon liveness, wave authorization, and automated critical-risk dispatch policy while still requiring ready or rework task state and a safe exact workspace. | See mapped verification. |
| A2 | Unsatisfied dependencies, genuine open human gates, terminal state, healthy owners, owned-path conflicts, stale revisions, and unsafe workspaces each return their exact typed cause, affected IDs, and remedy. | See mapped verification. |
| A3 | A dependency message that contains the words gate or human remains a dependency blocker, and no blocker code depends on prose ordering or substring matching. | See mapped verification. |
| A4 | Opening or refusing an interactive session cannot enable automation, arm a wave, start a daemon, launch a worker, authorize another task, move a ref, release, call a provider, or spend. | See mapped verification. |
| A5 | Existing work-session owner, revision, lease, identity, heartbeat, submit, fail, release, and dead-holder reclaim semantics remain unchanged. | See mapped verification. |
