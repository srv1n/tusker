## Intent
HEAD is red: `TestWorkSessionStartRefusalMatrix/unsafe_workspace` (work_session_cmd_test.go ~489-506) expects `WORK_SESSION_UNSAFE_WORKSPACE` when a shared-strategy checkout has a dirty tracked file, but `FSWorkspaceManager.Prepare` (workspace_manager.go ~101-114) now snapshots dirty tracked paths (`inPlaceDirtyPaths` → `startingDirtyPaths`) and proceeds, so start returns nil. Verified 2026-09-23: `go test ./cmd/tusker -run TestWorkSessionStartRefusalMatrix` fails with "workspace refusal = <nil>". Which contract is intended is an operator decision (gated below).

## Verified seams
- workspace_manager.go `Prepare`: shared strategy records `startingDirtyPaths` for new sessions, reuses them for a continuing session.
- work_session_cmd.go: `--current-workspace` handling (~138-160, requires a trusted interactive Codex/Claude/Devin session with a native conversation id); `workSessionStartBlocker` maps `ReadinessBlockerWorkspaceUnsafe` → `WORK_SESSION_UNSAFE_WORKSPACE` (~626); `workSessionUnsafeWorkspaceBlocker` (work_session_readiness.go ~184, read-only here).
- The failing test calls `workSessionStartCmd` without `--current-workspace`.

## Implementation contract
Blocked on human gate `workspace-dirty-contract`. Recommended contract (implement this unless the operator decides otherwise, and record the decision in the task log):
- Background/daemon runs and interactive starts WITHOUT `--current-workspace` on a shared checkout with dirty tracked files → refuse with `WORK_SESSION_UNSAFE_WORKSPACE`, naming up to 3 dirty paths.
- Explicit `--current-workspace` interactive claims → allowed; dirty tracked paths are snapshotted as `startingDirtyPaths` (today's behavior) so proof excludes pre-existing edits.
- Keep the refusal decision in work_session_cmd.go (caller knows the mode); `Prepare` keeps snapshotting and gains no mode flag unless needed.
If the operator chooses "always snapshot", instead update the test to assert the snapshot and remove the refusal case, with the decision cited in the test comment.

## Failure and edge cases
- Dirty tracked file, no `--current-workspace` → refused; forbidden: run lease created.
- Same with `--current-workspace` from a trusted interactive source → claim succeeds; `startingDirtyPaths` contains the file.
- Only untracked files dirty → existing behavior unchanged (state which in the test).
- Continuing session (same project/record metadata) → no new refusal.
