## Intent
An interactive claim (`tusker task start --mode interactive` / `tusker work start`, `run.HandRun=true`) gets a 60 s lease. An agent session that does not call `tusker work heartbeat` every minute loses its claim: the claiming CLI process exits immediately, so its recorded process identity is "dead", the lease expires, and three daemon paths reclaim or release it. A second worker can then be dispatched into the same task/workspace while the human-driven agent is still editing. This contradicts the comment in work_session_cmd.go (~266-271): "Never let an expired timestamp alone steal a live interactive workspace."

## Verified seams
- `defaultRunLeaseTTL = 60s` (runtime_store.go ~827); `ClaimRunLease(..., handRun bool, ...)` (~3390) records `hand_run`.
- `activeInteractiveBacklogClaim` (work_session_readiness.go ~10) protects only when `runFreshness == "fresh"` and task status is backlog.
- Reclaim paths ignoring `HandRun`:
  1. `reconcileExecuteRunWithPlan` (daemon.go ~2344) → when not fresh, `closeNonDispatchable` → `releaseIneligibleRun` (~2616).
  2. `reclaimExpiredDispatchCapacity` (daemon.go ~1742) → `autoRepairDeadReservation` (adaptive_reconcile.go ~480) → `store.reclaimExpiredRunLeaseIfSnapshot`.
  3. `reclaimDeadOwnedPathHolders` (run_ownership.go ~171) → `store.ReclaimExpiredRunLease` (runtime_store.go ~3971).
- Explicit release exists: `runsReleaseCmd` with `--break-glass --by human:<name> --reason` (run_runtime_commands.go ~895) records `break_glass actor=...`; `tusker work` finish/release paths in work_session_cmd.go.

## Implementation contract
Locked:
- A non-terminal hand run is never reclaimed, released or taken over by lease expiry, dead-process probe, dead-reservation repair or owned-path takeover. The only ways it ends: the claiming session finishes/releases it, the operator runs `tusker runs release` (with `--break-glass` when the claimant is not the actor), or the task is closed by a human transition.
- Put the guard at the shared store primitive (`reclaimExpiredRunLeaseIfSnapshot`, which `ReclaimExpiredRunLease` and `autoRepairDeadReservation` route through) so every current and future caller is covered, plus an explicit HandRun check before `releaseIneligibleRun` in `reconcileExecuteRunWithPlan`. The explicit release/break-glass path must still work (it must not route through the guarded primitive, or it passes an explicit override).
- Stale hand runs stay visible: expose them as "Quiet — held by interactive session <owner>" through existing readiness/diagnosis (a `ReadinessBlockerInteractiveOwner`-style blocker naming the break-glass command), never as silently reclaimable.
- Dispatch still refuses to start another worker on a task with a live or quiet hand run (the claim occupies its owned paths).
Proposed: none of the TTL values change.

## Failure and edge cases
- Hand run, no heartbeat for 10 minutes, dead claimant PID → after several daemon polls the run is still leased to the same owner/generation; no new attempt; task not re-queued. Forbidden: `lease_state` released/reclaimed, a new `attempt_spawned`, an owned-path takeover event.
- Another task overlapping owned paths becomes ready → it stays blocked on the hand run's owned paths; takeover never happens.
- Operator `tusker runs release --break-glass --by human:sarav --reason x` → released with attribution; daemon may then dispatch normally.
- Claimant `work finish` → normal completion unchanged.
- Non-hand daemon run with expired lease and dead process → existing reclaim behavior unchanged (regression guard).
- Pre-migration rows with NULL `hand_run` (`HandRunStamped=false`) keep today's behavior; document the choice in the test.
