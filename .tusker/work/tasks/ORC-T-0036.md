# ORC-T-0036 · Ship delivery review and Start in Serve

## Intent

The factory intake is usable as a product surface where a user reviews outcomes, proof, flow, and genuine decisions and starts the exact delivery without opening a terminal or YAML.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Serve renders the same versioned five-section review projection as the CLI and deep-links requirements, tests, artifacts, gates, and the eventual wave without recomputing planning truth. | See mapped verification. |
| A2 | The Start delivery control displays the exact fingerprint and permitted effect, requires explicit confirmation, and calls the same import, preflight, and arm transaction as the CLI. | See mapped verification. |
| A3 | Invalid, changed, disabled, daemon-off, runner-blocked, shared-workspace, gated, importing, armed, running, parked, and completed states have accessible labels and one truthful next action. | See mapped verification. |
| A4 | Starting delivery cannot enable project automation, install the daemon, change runner permissions, satisfy a gate, authorize release or spend, or absorb unrelated tasks. | See mapped verification. |
| A5 | Desktop and narrow-width fixtures keep requirements, proof, decisions, and Start hierarchy understandable without exposing raw orchestration records. | See mapped verification. |
