# ORC-T-0045 · Make review-to-integration-to-done one deterministic transaction

## Intent

A valid review result is converted into an idempotent staged merge, objective gate, integrated task closure, and exactly-once successor unlock without asking a model to operate Git or lifecycle state.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A passing result freezes source, review, proof, gate, and integration revisions, merges the exact task branch in a detached staging worktree, materializes review verification and task close there, runs the merged-state gate, and compare-and-swap updates the integration ref. | See mapped verification. |
| A2 | A changes-requested result idempotently records bounded findings, returns the task to rework, preserves its branch and workspace, releases review ownership, includes complete context in the next packet, and relocks affected soft dependents. | See mapped verification. |
| A3 | Merge conflict, red gate, stale source, stale review, proof or gate drift, and integration-base drift cannot close the task and instead produce one contextual rework or parked result with reproduction and stable defect identity. | See mapped verification. |
| A4 | A projected integrated done task immediately recomputes its affected hard and soft successor closure, dispatches only the newly eligible authorized frontier within capacity, and allows independent branches to continue. | See mapped verification. |
| A5 | Task completion moves only the wave integration ref and delegates default-branch movement to the configured immediate or scheduled promotion policy without widening release or paid-triage authority. | See mapped verification. |
| A6 | Crash and replay at result persistence, staging, merge, gate, close materialization, integration CAS, audit persistence, and successor wake converge without duplicate review, merge, close, terminal rewind, successor claim, or default-ref movement. | See mapped verification. |
