# Reconcile completed work without requiring an implementation-session claim

## Intent

Tusker currently requires an implementation claim before it can accept, verify, review, or close work already present in the registered checkout. That makes a missing provider conversation ID—currently Devin's case—a hard completion blocker even when the current task material exists and its exact checks can be rerun.

Add one supported recovery action, **Reconcile completed work**, to the existing work-recovery flow. It adopts the current declared task material without claiming to know who implemented it, runs the current verification contract, and either closes the task or queues only the review explicitly required by the task's proof contract.

This is not a bypass for authorization, proof, dependencies, gates, or independent review. It removes provider/session identity as a prerequisite for accepting objectively verified work.

## Locked product decisions

- Reuse the existing `work recover`, verification-receipt, closeout, and review-queue machinery. Do not add a parallel tracker, proof store, or lifecycle state machine.
- The action is `adopt_completed` and is presented to users as **Reconcile completed work**.
- Implementation identity is provenance only. Missing identity is stored truthfully as `external/unknown`; no Codex, Claude, Devin, conversation, execution, event, duration, or original attempt is fabricated.
- Adoption requires either a current durable task/wave authorization whose material still matches, or an explicit `human:<name>` or `operator:<name>` invocation. An unprivileged agent cannot adopt inert, unauthorized work.
- The registered repository, task's declared material scope, current task contract, dependencies, owned-path conflicts, gates, and source/material fingerprints remain fail-closed.
- Existing command verification rows are rerun against the current registered checkout. Only fresh authenticated receipts bound to the current task contract/work/source/material count.
- Review policy comes from the task's authored proof requirements:
  - Without `independent_review`, satisfied objective proof and gates close the task automatically.
  - With `independent_review`, adoption queues the configured review lane and does not close.
  - Security, privacy, release, destructive-action, provider, physical-device, subjective, and human gates remain untouched.
- Unknown implementation provenance can never be presented as proven independence. Review of adopted unknown work requires a known native/dispatched reviewer identity and records that implementation provenance was unavailable.
- Do not infer review requirements from provider, work level, or legacy risk labels. The authored proof contract is authoritative.
- The action is idempotent and CAS-protected. Repeating it against unchanged material creates no duplicate attempts, receipts, reviews, or close events.

## Verified seams

- `cmd/tusker/work_recovery.go`: shared CLI/Serve recovery transition and current verification execution.
- `cmd/tusker/real_work_lifecycle.go`: registered-workspace material binding and read-only reconciliation.

- `cmd/tusker/v7_verification_execution.go` and `cmd/tusker/v7_proof_cmd.go`: authenticated receipts and authored proof authority.
- `cmd/tusker/direct_wave_authority.go` and `cmd/tusker/serve_command.go`: existing recovery projection and Serve action boundary.
- `cmd/tusker/cli.go`: existing `work recover` routing/help.
- `internal/serve/ui/src/features/workbench/`: expose one applicable **Reconcile completed work** action; keep technical identity details subordinate.

## Required cases

1. **Devin bootstrap:** `CHISEL_SESSION_DB` exists but no immutable Devin conversation ID does. Authorized current material is reconciled without `--current-workspace`; the source remains `external/unknown`.
2. **Objective close:** a task requiring only command proof closes after fresh checks pass.
3. **Required review:** a task explicitly requiring `independent_review` moves to review and is not closed. A known independent reviewer can review it; an unknown/untrusted reviewer cannot claim independence.
4. **Changed material:** contract, source, scope, dependency, gate, or workspace drift between preflight and commit refuses atomically.
5. **Unauthorized work:** an inert task with no matching authorization refuses an agent invocation.
6. **Unsafe workspace:** wrong repository, missing/escaping declared scope, conflicting live owner, or unreadable material refuses before checks.
7. **Failed checks:** failure is recorded truthfully and the task stays recoverable; it is not closed or sent to review.
8. **Idempotency:** repeating the action after success is a no-op with the existing outcome.
9. **Ordinary lifecycle:** normal claimed Codex/Claude/daemon work and same-conversation review fencing remain unchanged.

## Non-goals

- Do not derive Devin identity from `CHISEL_SESSION_DB`, cwd, recency, or database rows.
- Do not weaken destructive, release, security, privacy, billing, provider, physical-device, subjective, or human gates.
- Do not rewrite historical attempts or receipts.
- Do not require independent review unless the authored proof contract requires it.
- Do not redesign the complete task/wave state model.

## Bootstrap handoff

This task repairs the boundary that currently prevents Devin current-workspace claims. A Devin implementer must not fabricate a native identity or mutate tracker records to simulate a claim. Implement under the user's direct authority in the shared checkout, preserve existing dirty work, and use the new action itself for truthful post-change reconciliation. Final review must be performed by a known Codex/Claude or dispatched reviewer identity.
