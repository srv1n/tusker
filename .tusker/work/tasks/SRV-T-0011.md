# SRV-T-0011 · Ambient autosave: optimistic, debounced, CAS-guarded doc writes with no edit mode

## Intent

Operator decision (2026-07-06): editing should have no modes — the task view is always live, like Notion/Linear. Once the prose surface is unified (SRV-T-0010), replace the explicit save trigger in `useDocEditor` (`editor.ts:87-109`) with ambient autosave: the local buffer updates optimistically on every keystroke; a debounced write (~600ms idle, flushed on blur) persists in the background; there is no Edit button, no Cancel, no Save, no "unsaved" mode.

Because Tusker `.md` files are multi-writer — runners write the same file on disk while the human types — two things are non-negotiable, not polish:
1. Every autosave carries the base rev and the server enforces CAS. No blind writes: a write against a stale rev must 409, never clobber newer on-disk content.
2. In-flight saves coalesce so rapid edits do not race — last edit wins locally, each PUT is CAS-guarded and ordered.

Two model shifts fall out of removing explicit save:
- Removing save removes discard, so undo (TipTap history, ⌘Z) becomes the safety net and must be reliable.
- Validation moves from a hard gate to advisory — you cannot block someone mid-sentence, so an invalid edit still persists (as the working copy) and surfaces issues inline as non-blocking diagnostics. Front-matter schema stays constrained at the source by SRV-T-0009's typed controls; prose is freeform.

Dependency: the real CAS-guarded doc-body write endpoint — `PUT /api/docs/*path` carrying base rev → 200 with new rev / 409 conflict payload / 422 validation (contract sketched at `editor.ts:6-9`). That endpoint is backend work; the nearest owner is SRV-T-0004 (action/persistence API with provenance). If doc-body write falls outside 0004's final scope it needs a thin backend task — flagged for the planner. The client loop here can be built and unit-tested against the existing mock CAS in `editor.ts` (`conflictArmed`/`reconcile`), so most work proceeds now; only end-to-end persistence (A4) is gated on the real endpoint. Conflict *reconciliation* on a 409 while typing is SRV-T-0012, not here.

## Non-goals

- No conflict *reconciliation* UI — SRV-T-0012 owns 409-while-editing behavior; here a stale write is rejected and surfaced, not merged.
- No front-matter autosave semantics (SRV-T-0009 commits via typed controls).
- No new editor surface (SRV-T-0010 delivers it).
