# ACO-T-0003 · Reach supported agent conversations without a relay model

## Intent

Tusker can deliver a message directly through a supported installed harness and accurately explain unsupported controls. Expensive models are never started just to relay a message. Done is a provider capability matrix with source, protocol and installed evidence marked separately. Scope is transport and endpoint control; scheduling decisions belong to the clarification task.

## Implementation notes
Read .tusker/specs/agent-coordination.md and its September 10 decision log. Implement the customer journeys using existing execution, runtime, packet, delivery and UI machinery. Preserve the dirty baseline and other owners. Use the supported interactive work-session protocol; do not launch a daemon or nested worker from an interactive session. The current automation pause is a rollout setting, not a reason to omit the mechanism. Keep configuration unchanged during implementation. Task ownership and real dependency edges govern integration. Proposed new filenames below are recommendations; trace actual callers before editing, resolve routine choices locally, and record the final contract in the named artifact. No model turn for routing, polling, summaries of unchanged state or relay. Use configured work/review levels, keep checks focused, and leave integrated builds/live qualification to the qualification task. Do not claim provider documentation or offline fixtures as a live harness pass. Independent review remains required; no new human code-review gate.

Qualify the exact installed Codex, configured Muse, Claude and ACP routes using the primary sources in the spec and read-only version/protocol probes. Define operations for attach, idle resume/send, safe active delivery, turn observation, reply capture and uncertain-delivery reconciliation. Record capability state and freshness by version/profile/host/endpoint. Reuse existing argument compilers, structured events, admission and process supervision. Never infer external application access from an ID or infer a Tusker-callable API from an in-model SendMessage tool. Implement deterministic direct adapters for supported routes with fixture-backed protocol tests; preserve unsupported/unknown for other operations. Active injection remains optional per route, with queue-until-idle supplied by the scheduler. Preserve exact model/profile and provider permissions during resume. No private socket scraping, silent CLI-to-app-server fallback, new runtime installer or model-powered courier. Live paid canaries are performed by the final qualification task against this same surface.

Artifact: docs/reports/agent-coordination/transports.md. Required named check prefix: TestAgentTransport. Run the verification after implementation settles; the named cases must exist and be executed. Capture actual results in the artifact. A command that matches no tests is incomplete.
