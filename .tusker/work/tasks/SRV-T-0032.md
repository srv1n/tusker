# SRV-T-0032 · Make human gates first-class across search, Work, and Needs

## Intent

Make open human gates visible and actionable wherever a human reviews work. Tasks remain the primary lifecycle object, while gates retain their own identity, status, blocked-task relationships, and completion actions.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Global search returns tasks and gates across registered projects, labels their type and project, and opens gate results at an actionable blocked-task detail (or the project gate surface when no single task is available). | Focused UI tests |
| A2 | Work board and table keep task lifecycle columns but expose every open human gate by G ID, title/action, and blocked task relationship on the affected task. | Focused API and UI tests |
| A3 | Needs me and the compact panel present gate-backed needs as gate actions rather than task-only cards, and multiple gates on one task remain separately visible. | Focused API and UI tests |
| A4 | Existing satisfy, waive, obsolete, accept, and rework actions remain reachable; no gated task status is introduced. | Typecheck and regression suite |

## Non-goals

- Replacing typed task/gate detail and mutation endpoints with one ambiguous CRUD API.
- Turning gate readiness into a durable task lifecycle status.
- Promoting evidence, attempts, runs, or feedback into the primary Work board.
