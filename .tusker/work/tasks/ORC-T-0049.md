# ORC-T-0049 · Dogfood and cut over the factory control loop without a cadence gap

## Intent

Tusker can enable the new reactor for one low-risk project and then roll it out safely while legacy execution remains authoritative until parity, rollback, and operator visibility are proven.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A read-only doctor checks managed daemon health, project registration, automation and dispatch scope, wave authorization, runner approval, workspace isolation, integration cleanliness, skill version, review-result support, and completion-reactor feature state. | See mapped verification. |
| A2 | Shadow mode compares frontier, ownership, review reaction, integration decision, and successor wake without claiming, reviewing, mutating tasks, merging, closing, moving refs, or consuming model capacity. | See mapped verification. |
| A3 | One low-risk armed wave completes through the new control loop with its operations surface and reliability artifact reviewed before the reactor becomes authoritative for another project. | See mapped verification. |
| A4 | The cutover keeps current authoritative execution available until representative parity passes and prevents both control loops from owning the same task or integration transaction. | See mapped verification. |
| A5 | Rollback stops fresh new-reactor actions while preserving live leases, task and review history, integration refs, audit facts, and one documented recovery path. | See mapped verification. |
| A6 | Rollout never automatically enables another repository, arms another wave, broadens all_eligible scope, starts a daemon from an agent session, disables a legacy conductor, promotes main, releases, or authorizes spending without its separate explicit boundary. | See mapped verification. |
