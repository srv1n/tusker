# SRV-T-0021 · Wire Run interrupt and show queued work waiting for the daemon

## Intent

Run Detail presents an Interrupt button that only logs to the browser console,
while Redrive is real and refuses correctly when a process is still live. Wire a
guarded `POST /api/runs/<task>/interrupt` endpoint through the same command/store
path as `tusker runs interrupt`. The UI must confirm the action, disable while
pending, surface refusal/error text, and refresh until canonical process/lease
state proves interruption.

Also make `retry_queued` honest when the daemon is down: show "Waiting for
daemon" with the daemon-down reason instead of a live elapsed timer or "lease
held", and prevent duplicate redrive while already queued.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Interrupt from Run Detail calls a localhost-guarded endpoint sharing CLI interrupt semantics; success/refusal is visible and the control cannot double-fire. | focused_test |
| A2 | After interrupt, readback shows the canonical terminal/interrupted lease and process state before offering Redrive. | focused_test |
| A3 | `retry_queued` plus daemon-down renders as waiting for the daemon, freezes misleading live timing, and disables duplicate Redrive with an actionable explanation. | focused_test |
| A4 | Existing run, redrive, stream, and full UI/Go gates remain green. | broad_test |

## Non-goals

- No daemon auto-start implementation.
- No runner process model changes.
- No redesign of the Run Detail page.
