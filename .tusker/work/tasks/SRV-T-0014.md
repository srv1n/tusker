# SRV-T-0014 · Run detail header renders false live state: completed runs show Running with frozen elapsed and zero tokens

## Intent

Observed today (2026-07-08) on the TRC-T-0002 run detail page. The codex runner had FINISHED — worktree suite green, task flipped to review, the DB run row read lease_state=unclaimed, the attempt released — yet the detail header showed "Running · lease held" with a green 6s pulse, ELAPSED frozen at 14m46s across multiple hard refreshes, and INPUT 0 / OUTPUT 0 tokens despite a full implementation turn. Meanwhile the attempt list on the same screen correctly read "Attempt 1 · Released". Three contradictory sources on one page: a live header, a frozen clock, zero tokens, and a released attempt. SRV-T-0008 (SSE live updates) had just landed, so the header is either not subscribed to the run-row store or maps stale fields.

Semantics:

1. **Single source.** The header's live/terminal state derives from the same run-row store that feeds the attempt list — one store, one truth. A released/unclaimed run row renders as terminal in the header, never as "Running · lease held".
2. **Elapsed stops at release.** ELAPSED counts up only while the lease is held; on release it freezes at release-minus-start, not at whatever value it held when the SSE stream stopped.
3. **Tokens from recorded turns.** INPUT/OUTPUT totals come from the recorded turn data on the run (TRC-T-0002 had real usage), not a live counter that reads 0 once the stream ends.
4. **Refresh-stable.** A completed run looks completed after a hard refresh — terminal state does not depend on an in-flight SSE connection to be revealed.
