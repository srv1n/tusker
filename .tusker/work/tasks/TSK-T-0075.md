## Intent
Decision D3 allows Claude's open stdin stream-json channel as the soft Say path: a message reaches the running agent between tool calls with no interrupt. `claudeLiveHandle` already writes user messages and control requests to stdin, but once A:claude-detached moves Claude under the detached wrapper, the daemon and CLI no longer hold that handle. This task gives the wrapper a local control channel so Say and Interrupt reach the Claude process it owns, and maps Claude's native result signals to typed reason codes. Work level is demanding because a local socket that writes into an agent's stdin is a command-injection surface; permissions, peer checks and fencing need careful review.

## Verified seams

- Wrapper lifecycle: `runRunnerWrapperWithChildStarter`, `runnerWrapperStartChild`, `runnerWrapperWait`, `runnerWrapperInterrupt`, `runnerWrapperStopSignal` (runner_wrapper.go). The Claude case in `runnerWrapperStartChild` is added by A:claude-detached.

## Implementation contract
Locked:
- The wrapper opens a unix domain socket in the attempt's private runtime directory, socket mode 0600 inside a 0700 directory, path recorded in the attempt record (not in logs or UI). It accepts only same-uid peers (check peer credentials) and one newline-delimited JSON request per connection: `{attempt_id, lease_generation, delivery_id, op: "say"|"interrupt", body}`. Requests whose attempt id or generation do not match the wrapper's current fence are refused.
- `say`: the wrapper writes one stream-json user message to Claude's stdin and acknowledges only after Claude echoes it (launch Claude with `--replay-user-messages`); the ack carries the echoed message uuid, stored as the delivery receipt, and the delivery moves to accepted. No echo within a bounded timeout -> delivery `uncertain`, never re-sent automatically (a second write could duplicate the instruction).
- `interrupt`: the wrapper sends the Claude interrupt control_request; the existing process-group escalation remains the fallback when the child does not settle.
- Claude declares SoftSay=true, HardSay=true, PreassignSessionID=true, ResumeAfterDeath=true. In run_say.go the SoftSay route is chosen when the run is `working` or `quiet` and the socket is reachable; if the socket is missing or refuses, the same delivery falls back to the hard route (the delivery records which route delivered it).
- Claude reason mapping: result subtype error_max_turns -> max_turns; error_max_budget_usd -> max_budget; error_during_execution -> provider_error unless its text matches the Claude driver's own usage-limit/auth patterns (usage_limit, auth_expired); non-empty `permission_denials` or `system/permission_denied` with no success -> permission_denied. The code is written to the status file via typed-reasons' writer.
Proposed: socket file name, ack timeout (suggest 10s), and whether one long-lived accept loop or per-request goroutine.

## Failure and edge cases
- Request from a different uid, or with a stale lease generation: refused, nothing written to stdin.
- Socket path already exists from a crashed wrapper: removed only if it is a socket owned by this uid inside the attempt directory; otherwise the wrapper refuses to start the channel and Say falls back to hard.
- Say while Claude is mid-tool: message is written; echo arrives when Claude reads it between tool calls; delivery accepted then. Forbidden: marking accepted on write alone.
- Claude exits while a say is pending: delivery uncertain and visible; no automatic duplicate on Continue.
- Two says concurrently: serialized writes, two echoes, two receipts, order preserved.
- Body with newlines and a JSON-looking payload: encoded as one JSON string; cannot inject a control_request.
- Wrapper restarted (new generation): old socket gone; requests with the old generation refused.
