# OPS-T-0002 · Merge lane: integration branch per wave, optimistic batch + bisect, one landing to main

## Intent

Binding design: `docs/design/prior-art-playbook.md` §5 decision 2 (donors: bors "Not Rocket Science Rule", Gas Town Refinery + integration branches — `docs/design/research/research-operating-models.md` §1.3, §3.2). Today, runner worktree branches are merged to main by hand; with 3–5 parallel runners this is where swarm output either lands safely or rots. Two hazards the lane kills: **semantic merge conflicts** (two individually-green branches that break combined — only testing the *merged* state catches this) and **ordering breakage** (sibling B landing against a main that sibling C's assumptions predate).

Semantics:

1. **Integration branch per wave** (`integration/W-####`, cut from main at wave create). Runner worktrees for wave members branch **from the integration branch**, so siblings start with already-landed sibling work present.
2. **`tusker land <TASK-ID>`** (runner-invoked at finish, or daemon-invoked on review-pass): queues the task branch for the lane. The lane is **serialized** (one landing at a time per repo).
3. **Optimistic batch + bisect:** the lane merges all queued branches onto the integration branch in a staging ref, runs the gate formula (from repo config; default `go build ./... && go vet ./... && go test ./... -count=1`, UI build when touched), and on green lands the whole batch. On red it bisects: good halves land, the isolated bad branch is kicked back — its task goes to `rework` with the failing gate output attached — and the batch is never wholly blocked.
4. **Wave landing:** when all wave members are done and the integration branch is green, the lane lands `integration/W-####` to main as **one merge commit** titled by the wave, then deletes the integration branch. Idempotent: rerunning after a crash detects the ancestor state and skips to cleanup.
5. **Guards (three layers):** runner prompts forbid pushing/merging to main (contract text); a repo pre-push hook blocks direct default-branch pushes unless the land command's env guard is set; the land command is the only authorized path and is idempotent.
6. Solo-repo simplification kept deliberately: no PRs required — branches land locally; the audit trail is the wave record + merge commits (every landing appends who/what/when to the wave record — the observability lesson from the donor's "6 PRs merged and I had no idea when").
