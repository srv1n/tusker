# ORC-T-0042 · Reconcile changed DAG closures without reparsing whole projects

## Intent

Canonical task, proof, gate, dependency, wave, and runtime mutations wake only the affected project and graph closure while adaptive scans preserve correctness for raw edits and restart.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The daemon control notification carries project, changed object IDs and kinds, resulting revisions, cause, and affected eligibility classes with backward-compatible handling of existing project-only notifications. | See mapped verification. |
| A2 | One in-memory per-project projection maintains parsed operational records, forward and reverse hard or soft edges, wave authorization, eligibility, and frontier generation without becoming durable source of truth. | See mapped verification. |
| A3 | A warm one-task CLI mutation in a 10000-task fixture reads and parses only changed records plus its bounded reverse dependency or wave closure and performs no note reads or parses in unrelated registered projects. | See mapped verification. |
| A4 | Raw edits, missed notifications, registry changes, restart, and cache mismatch fall back to adaptive reconciliation, and unchanged fallback scans remain stat-only with zero Markdown reads and YAML parses. | See mapped verification. |
| A5 | Incremental update, cold rebuild, and a clean full reconcile produce identical task eligibility, blockers, and ordered frontiers for hard, soft, gated, stale-wave, and terminal transitions. | See mapped verification. |
| A6 | Performance counters and benchmark output report records stated, read, parsed, graph nodes recomputed, projects woken, and elapsed time without writing per-poll history or logs into task records. | See mapped verification. |
