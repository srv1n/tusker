# FAC-T-0001 · Mark interactive work when a session claims a task

## Intent

When someone opens a coding session directly and picks up a piece of tracked
work by hand, the record should remember that a person did this outside the
automated line. Today a claim looks the same whether the daemon handed the work
out or a human grabbed it in a live session, so no later view can tell hand-run
work from automated work — and that blind spot is what forced people to
orchestrate by hand.

This task makes a claim carry that distinction. Picking up work in a live,
hands-on session stamps it as "done outside the daemon," and that stamp rides
along with the work so any later view can be honest about how it happened. Work
the automated line hands out carries no such stamp.

Done looks like: after a person claims a task in a live session, the work's
record clearly shows it was picked up by hand; work the daemon dispatched still
reads as automated; and the stamp stays put as the work moves along until it
closes.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Claiming a task in a hands-on session records a durable marker that the work was picked up by hand, outside the automated line. | Inline verification |
| A2 | Work the automated line hands out carries no such marker, so the two are always distinguishable. | Inline verification |
| A3 | The marker stays on the work's record through later status changes, until the work closes, so later views can read it. | Inline verification |

## Non-goals

- No new board columns or web-view changes here; surfacing the marker to readers is a separate piece of work.
- No change to who may claim, or to the claim's other effects (lease, branch capture) — only the added hand-run marker.
- No attempt to guess intent after the fact; only a claim made in an interactive session is marked, and only at claim time.
- No per-vendor or per-tool labelling; the marker is simply "picked up by hand vs handed out by the daemon."

## Implementation notes

Best-guess file map — verify before editing:

- `claimCmd` in `cmd/tusker/commands_pickup.go` writes the lease via
  `writeV7Lease` and emits a `claimed` event with the current branch. Set the
  hand-run marker here when the claim did not originate from an automation
  dispatch. Prefer a plain field name (e.g. `outside_daemon` or `hand_run`).
- `emitNextSelection` in the same file also claims on `tusker next --claim`; the
  same marker applies to that path.
- The daemon's dispatch path (`automationDispatchCmd` in
  `cmd/tusker/automation_commands.go` and the dispatch code in `daemon.go`) must
  NOT set the marker, so the two origins stay distinguishable.
- The lease/run record is `RunStatus` (see fields used in `cmd/tusker/streams.go`);
  plumb the flag onto the durable record so it survives status changes.

Constraint: keep the identifier a simple human word, per the spec's plain-naming
rule.
