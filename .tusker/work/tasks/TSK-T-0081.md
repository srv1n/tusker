## Intent
Claude workers launch with `--strict-mcp-config` and no `--mcp-config`, Codex with `--ignore-user-config`, ACP with `mcpServers: []`, so no worker can see the Tusker tools. Project one per-attempt MCP configuration (and, where soft delivery is supported, the worker hook) into every launch AND every resume of the same attempt.

This task hard-depends on wave A `claude-detached` (owner of the Claude launch/resume argv) and `codex-resume` (owner of Codex exec resume argv); rebase onto their final argv builders rather than the lines named below.

## Implementation contract
Locked:
- One helper in worker_mcp_launch.go builds the per-attempt projection from (harness, attempt identity, state dir, absolute tusker path from os.Executable). Files go in the attempt's private state directory (the directory of StatusPath/RawLogPath), mode 0600 — never in the worktree, never in ~/.claude, ~/.codex or Muse settings.
- Server entry name `tusker`, command = absolute tusker executable, args `mcp serve --max-wait <N>`, env = the five identity vars plus TUSKER_EVENT_SINK passed explicitly (Codex MCP servers do not inherit the full environment).
- Claude: `--mcp-config <attempt>/mcp.json` (keep `--strict-mcp-config`) and `--settings <attempt>/settings.json` containing `permissions.allow: ["mcp__tusker"]` and, because workerSoftDelivery(claude) is supported, a PostToolUse hook running `<tusker> message inbox --project <p> --run <attempt> --format hook`. --max-wait 900.
- Codex exec: `-c mcp_servers.tusker.command=...`, `args=[...]`, env forwarding, `tool_timeout_sec=960`, and the per-tool approval setting that prevents approval stops under `approval_policy="never"` (verify exact keys in Codex primary docs and record them; label anything unverified). No hooks while workerSoftDelivery(codex) is unsupported. --max-wait 900.
- Devin ACP: pass the stdio server in `mcpServers` on session/new AND session/load/resume (new acp.Config field; nil keeps today's empty list). --max-wait 50 (tool timeout unverified).
- Muse: probe-first. Use a per-invocation mechanism only if Muse 1.3.0 help/docs verify one that does not write the user's settings (candidates: `--agents <JSON>` overlay; a workspace settings file is forbidden because it lands in the worktree and needs `--trust-workspace`). If none is verified, compile no MCP entry, record `ask route: cli` for Muse, and the worker packet/prompt tells Muse workers to use `tusker message ask` (already bound to TUSKER_ATTEMPT_ID). --max-wait 50 if injected.
- Resume uses byte-identical projection flags to start for the same attempt (same files, regenerated if missing). A new attempt gets new files.
Proposed: exact file names; whether the helper lives in internal/runner or cmd/tusker (keep hasForbiddenPolicyArg semantics either way).

## Failure and edge cases
- Operator runner profile already contains `--mcp-config`/`--settings`/`-c`: existing policy_conflict admission refusal unchanged; forbidden: merging operator values into the Tusker projection.
- os.Executable unresolvable or state dir unwritable: launch refused with a typed admission error; forbidden: launching without the tools while claiming Ask is available.
- Resume after the state dir was cleaned: files regenerated identically; forbidden: resume without --mcp-config.
- Codex resume argv (`exec resume <id> -`) keeps every -c mcp_servers flag before `resume` per D2 ordering.
- Attempt identity values containing quotes/spaces: passed as argv/JSON values, never shell-interpolated (the `sh -lc` legacy path quotes them or is refused).
- ACP agent whose initialize reports no MCP stdio capability: launch proceeds with an explicit capability note; forbidden: silent drop.
