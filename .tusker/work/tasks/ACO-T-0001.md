# ACO-T-0001 · Keep architect and peer contacts attached to work

## Intent

Every task can retain its architect, planning origin and useful peer contacts after a worker finishes or restarts. People can inspect whom to ask without finding a conversation by hand. Done includes concrete contract examples and a behavior matrix. Scope is identity, endpoint binding and packet projection; message delivery and model execution belong to later tasks.

## Implementation notes
Read .tusker/specs/agent-coordination.md and its September 10 decision log. Implement the customer journeys using existing execution, runtime, packet, delivery and UI machinery. Preserve the dirty baseline and other owners. Use the supported interactive work-session protocol; do not launch a daemon or nested worker from an interactive session. The current automation pause is a rollout setting, not a reason to omit the mechanism. Keep configuration unchanged during implementation. Task ownership and real dependency edges govern integration. Proposed new filenames below are recommendations; trace actual callers before editing, resolve routine choices locally, and record the final contract in the named artifact. No model turn for routing, polling, summaries of unchanged state or relay. Use configured work/review levels, keep checks focused, and leave integrated builds/live qualification to the qualification task. Do not claim provider documentation or offline fixtures as a live harness pass. Independent review remains required; no new human code-review gate.

Extend the existing execution ledger and attachment model, not a second agent registry. Use typed execution-root and task-owner addresses. Add optional authored coordination fields to schema and delivery import with visible wave inheritance, strict identity/project validation and backwards compatibility. Update the actual task packet emitter in commands_v7.go after tracing it. Store profile/host/native ID and capability evidence in replaceable endpoint bindings with generation and lineage; never weaken same-task resume checks. Define the typed mailbox/wakeup API, response shapes and stable verification case names for the other streams in contracts.md. Add a registration hook sufficient for independently implemented message CLI/Serve commands without duplicating the command router. Task recipient resolution must preserve a pending task address when no owner is running. Clarify exact-execution addressing for completed workers, unique owner resolution, unsupported native children and external-attachment admission.

Artifact: docs/reports/agent-coordination/contracts.md. Required named check prefix: TestAgentContacts. Run the verification after implementation settles; the named cases must exist and be executed. Capture actual results in the artifact. A command that matches no tests is incomplete.
