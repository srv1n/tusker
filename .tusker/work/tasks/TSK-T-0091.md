## Intent
Several W-0043 surfaces fail quietly. One message rendering over ~16 KiB makes the hook inbox `break` with nothing selected, so that message and everything behind it are never delivered. The MCP server exits on a line over 1 MiB instead of answering -32700, treats `"id":null` as a request, ignores answer-consume errors and returns messages from earlier work revisions. Questions addressed to an architect whose binding is `inbox` show up as operator needs, inviting double answers, with one contacts query per question. The worker MCP projection omits `TUSKER_STATE_ROOT`, so with a non-default state root every tool refuses and every hook is silent.

## Verified seams
- agent_message_inbox.go selection loop `break` (~117), omitted count (~144).
- mcp_serve.go `scanner.Buffer(make([]byte, 4096), 1<<20)` (~109), request loop (~183), answer consume (~332), `check_messages` (~290).
- serve_human_action.go binding checks `binding.State == "bound"` (~45, ~56) inside a per-question loop (~37-58).
- worker_mcp_launch.go `projectWorkerMCP` (~22); runner_preflight.go strips `TUSKER_STATE_ROOT` from worker env (~40, read-only here: keep the strip for the worker process itself).

## Implementation contract
Locked:
- Inbox rendering truncates any single message body to fit the 16 KiB bound with a pointer line `full text: tusker message show --project <p> <id>`, and never lets one message block later ones. The omitted count covers only messages actually left pending.
- MCP server: a line over the buffer limit gets a -32700 error and the server keeps serving; `"id":null` requests get -32600; a failed answer consume returns isError and leaves the answer unconsumed; `check_messages` returns only messages for the current work revision.
- Needs list excludes questions whose resolved architect binding is `bound` or `inbox`, fetched once per snapshot.
- `projectWorkerMCP` puts `TUSKER_STATE_ROOT` into the MCP server env and the hook command only when the daemon's state root differs from `DefaultStateRoot()`. The worker process env stays stripped.
- docs/system/orchestration.md: hook snippets use the absolute tusker path, say the hook needs the same state root as the daemon, and say that a new Claude session id (for example after /clear) needs `tusker execution register` again. Fix the Codex hooks doc link or remove it.

## Failure and edge cases
- Pending: 30 KiB message, then two small ones → one hook call delivers all three, the first truncated with a pointer.
- 2 MiB request line → -32700, next valid request answered.
- Architect bound with state inbox → question not in operator needs; unbound architect → question in operator needs marked undeliverable.
- Daemon with TUSKER_STATE_ROOT=/tmp/x → Claude --mcp-config env and hook command carry it; worker env does not.
