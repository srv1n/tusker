## Intent
Two defects end long Codex runs. (1) Native Continue for `codex_exec` builds `codex exec resume <exec flags> <id> -`; codex 0.155.1 rejects exec flags after `resume` ("unexpected argument '--sandbox'"), and because that error text contains "sandbox", `classifyRetryFailure` (daemon.go) marks the attempt non-retryable Blocked. Every Continue of a sandboxed codex run therefore fails. (2) Execute-lane codex_exec runs are launched with a 16 MiB completion-authoritative raw-log cap; `aggregated_output` in verbose runs reaches it and `boundedRawLogWriter.Write` terminates the process group, killing hours of work.

## Verified seams
- `codexExecResumeArgv` (runner_codex.go ~131) moves `argv[2:]` after `resume`. `codexExecResumeCommand` (runner_codex.go ~211) has the same bug for string commands. `CodexExecRunner.Resume` validates `resumedArgv[1]=="exec" && resumedArgv[2]=="resume"`, which must change with the argv shape.
- `TestRunSessionContinueCodexExecBindsExactSession` (run_session_continue_test.go ~29) locks the wrong order using only flags that `resume` happens to accept.
- Cap: `completionAuthoritativeRawLogMaxBytes = 16 << 20` (completion_worker_safety.go:13), applied in daemon.go dispatch (~4432/4497). `executeRunnerCommand` (runner_exec.go ~224) opens `openBoundedRawLog` and binds `bindTerminator` → `killContainedRunnerCommand`. `boundedRawLogWriter.Write` (runner_raw_log_limit.go ~106) sets overflow and fires terminate; `monitorBoundedRunnerCommand` publishes a Failed status with `completionAuthoritativeRawLogOverflowExitCode`.
- Readers of the raw log: `extractSessionRef` (runner_exec.go ~451, also daemon.go ~2704 reconcile) reads `thread.started`; `readFrozenReviewProposalLogWithOpen` (review_proposal.go) requires a single exclusive file ≤ cap for the REVIEW lane; `runActivityTail` (run_activity.go) reads the tail for display.
- `runner_codex_live.go` (codex app-server live runner) scans stdout/stderr with a 4 MiB `bufio.Scanner` limit (~461/477); one oversized JSON-RPC line ends the run with a scan error.

## Implementation contract
Locked:
- Resume argv is `<codex> exec <all exec flags from the start argv, without trailing -> resume <session_ref> -`. Apply to both `codexExecResumeArgv` and `codexExecResumeCommand` (template form ends `resume {{session_ref}} -`). Update the `Resume` shape check accordingly (still refuse non-codex argv).
- Do not edit daemon.go or `classifyRetryFailure` in this task (daemon.go is owned by hand-run-claims / run-liveness-stop; typed failure codes are wave B). Once argv is right the misclassification no longer triggers.
- Review lane keeps today's fail-closed kill on overflow: review proposals must come from one complete, exclusive log.
- Execute lane never kills the worker for log volume.
Proposed (worker may refine, keep the observable contract): on execute-lane overflow the writer rotates instead of terminating — keep the first segment frozen as `<raw>.head` (it holds `thread.started`, so `extractSessionRef` must also consult it), keep at most one previous segment `<raw>.prev`, reopen `<raw>` fresh with the same 0600/single-link checks, and append a `raw_log_rotated` diagnostic event with bytes dropped. Total retained bytes stay bounded (≤ 3× cap).
- `runner_codex_live.go`: an oversized line (> scanner limit) is skipped with a `stdout_line_oversized` diagnostic event carrying its byte length; the run continues. Use `bufio.Reader.ReadSlice`/discard or equivalent; do not raise the limit unboundedly.

## Failure and edge cases
- Start argv `codex exec --json --sandbox workspace-write -c model="x" --skip-git-repo-check -` → resume argv `codex exec --json --sandbox workspace-write -c model="x" --skip-git-repo-check resume S -`. Forbidden: any exec flag after `resume`; a duplicated `-`; the session id before `resume`.
- `--dangerously-bypass-approvals-and-sandbox` stays before `resume`.
- Argv not starting with `codex exec` → existing "direct codex exec command" refusal remains.
- Execute lane emits 40 MiB then exits 0 → attempt outcome follows exit/status, not overflow; process never receives SIGKILL from the writer; session ref is still extractable after rotation. Forbidden: exit code `completionAuthoritativeRawLogOverflowExitCode` on the execute lane.
- Review lane emits > cap → still terminated and Failed exactly as today.
- Resume mode (`allowExisting`) with an existing rotated set continues appending without deleting `.head`.
- App-server stdout line of 6 MiB followed by normal lines → later lines still observed; one diagnostic event recorded.
