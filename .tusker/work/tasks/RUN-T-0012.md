# RUN-T-0012 · Spend governor: layered token budgets with circuit-open

## Intent

Binding design: `docs/design/prior-art-playbook.md` §2 (budget rows) and §1 P5. Budgets are the defense against failure modes we have not met yet: they bound blast radius without knowing the mechanism. The 2026-07-06 incident burned 1.63B input tokens on one task; a per-task ceiling would have tripped it at ~15 attempts regardless of what caused the loop. The daemon already ingests runner usage events (`turn_usage_updated`) — enforcement is comparisons inside the RUN-T-0011 reconcile/eligibility path plus terminal transitions and UI surfacing. No surveyed system in this category has this (only OpenHands has a per-run ceiling); it is deliberately a Tusker differentiator.

Four independent layers, all config with the playbook defaults, each with a distinct loud outcome:

1. **Per-attempt budget** (default 50M input / 500k output tokens): breach ⇒ the daemon terminates the run, attempt recorded as `budget_exceeded` (counts toward the RUN-T-0010 continuation/retry caps).
2. **Per-task cumulative budget** (default 5× per-attempt, summed across all attempts): breach ⇒ task parked in `parked_budget`, redrive-only.
3. **Per-project concurrency** already exists (`max_active_runs_per_project`) — fold its enforcement into the shared eligibility function so all caps live in one place.
4. **Global daily ceiling** (default on, generous): breach ⇒ dispatcher circuit-opens — no new dispatches, running work drains, `daemon status` and the serve API report the open circuit with reset time; serve UI shows a red banner. Never silent.

Rules: budgets are read from config + optional per-task frontmatter override (`budget:` key, capped at 4× the default so a runaway contract can't self-exempt); spend is accumulated transactionally on the run/attempt records (survives restarts, feeds the existing tokens UI); `tusker redrive <TASK-ID>` (from RUN-T-0010/0011 parked semantics) is the only path back, and it resets the task budget window while recording who/why.

## Non-goals

- No USD pricing conversion (token-denominated only; pricing tables are a later concern).
- No per-model tiering or quota scanning (Gas Town-style role tiering is a separate decision).
- No mutating serve endpoints (the banner is read-only surfacing; redrive stays CLI).
