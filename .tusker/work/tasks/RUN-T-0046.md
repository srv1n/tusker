# RUN-T-0046 · Serialize broad validation and bound Go test process pressure

## Intent

Broad verification is being launched independently by runner attempts, and the
canonical commands have no machine-wide admission control. A single
`cmd/tusker` suite also fans out six copies of `tusker.test` in the event-log
contention fixture. The old orphan cleanup fix prevents permanent leaks, but it
does not prevent transient CPU/process storms. Keep coding concurrency, while
serializing broad validation across this repo's worktrees and bounding each Go
gate's CPU/package/helper fanout.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Broad validation uses one shared, cross-worktree lock; a second gate waits visibly, stale owners recover safely, and exit/signal cleanup releases the lock. | focused_test |
| A2 | Canonical runner/Makefile broad gates and raw `cmd/tusker` focused tests all join the same serialized lane, so bypassing Make cannot overlap shared-state suites; helper re-execs inherit the held lease without deadlocking. | focused_test |
| A3 | Go broad tests/build/vet run with conservative configurable CPU and package-parallelism defaults, and the event-log contention fixture proves the same behavior with no more than two helper processes. | focused_test |
| A4 | The broad Go suite passes through the bounded lane and leaves no `tusker.test` processes behind. | broad_test |

## Non-goals

- No reduction in production runner/task concurrency; only broad validation is serialized.
- No weakening of cross-process correctness assertions.
- No reopening of RUN-T-0041's already-fixed orphan lifecycle semantics.
