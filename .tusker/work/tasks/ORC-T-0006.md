# ORC-T-0006 · Lint shared namespaces for collision-prone names

## Intent

On 2026-07-19 two parallel branches both claimed migration number 0014
(rzn backend), forcing a manual renumber-and-rehash at integration. Sequential
names in shared namespaces collide silently whenever lanes work in parallel.
Add a vault-configurable lint for collision-prone name patterns (first target:
`migrations/NNNN_*.sql`-style sequential files) to `tusker validate` and the
skill doctor: detect duplicate numbers across the working tree, flag sequence
policy violations, and recommend timestamp naming where the project's runner
supports it.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A fixture with two files claiming the same sequence number fails validation, naming both paths and the pattern that matched. | Inline verification |
| A2 | The pattern set is configured per repo (tusker.yaml or vault config), with the sequential-migration pattern as a documented example, not a hardcoded rule. | Inline verification |
| A3 | A repo with no configured patterns validates exactly as before (zero behavior change). | Inline verification |

## Non-goals

- No auto-renumbering or auto-fixing; lint-only.
- No parsing of migration SQL content.
