# RUN-T-0035 · Codex attempt loop must drive multiple turns per attempt: one model turn is not one attempt

## Intent

Found in the first authorized daemon soak (2026-07-07, right after RUN-T-0017 closed). Every codex app-server attempt runs exactly ONE model turn and exits: `turn_started` → usage climbing (~70k input) → `turn_completed` → session end, ~60–90s total. Evidence: FBK-T-0003 attempt 3 events at `runs/tusker/FBK-T-0003/rev-00-execute-attempt-0003-01kwycgt7v9x4c7fsp06t4br9g.events.jsonl`. The turn classifies `early_exit` (RUN-T-0030 working as designed), continuation redispatches a FRESH session that re-reads all context, and after 3 one-turn attempts the run parks. Multi-turn tasks make zero code progress while burning ~70k input tokens per attempt; only tasks completable in a single turn ever finish (CLN-T-0006 did).

RUN-T-0030's audit established the shape: the codex app-server protocol has no native maxTurns — **Tusker owns the per-attempt turn loop** and logs `max_turns=30` at dispatch (`cmd/tusker/runner_codex_live.go`). But the loop ends the attempt after the first `turn_completed` instead of continuing the SAME session with a follow-up turn.

Semantics:

1. Within one attempt, after `turn_completed`, if the tracker state is still active (`ready`/`rework`) and turns-used < max_turns, the runner sends a continuation turn to the SAME codex thread (context intact, no re-read) — e.g. "continue executing the task contract; end only when the contract is satisfied or you are blocked".
2. The attempt ends when: the task leaves active state (completion), the runner reports blocked/needs-human, max_turns is reached, or the budget governor kills it. Only then does the attempt-level outcome record (early_exit only if turns remain unused and state is active — a max_turns exhaustion is its own outcome, e.g. `turn_cap_exhausted`).
3. Attempt-level continuation (fresh session, Ralph protocol) remains the OUTER loop for genuine attempt failures — it must not be the mechanism for ordinary turn-to-turn progress.
4. Per-attempt budget ceilings apply across all turns of the attempt (the governor already meters usage per attempt — verify it keeps doing so across multiple turns).
