# OPS-T-0004 · Ralph worker protocol: fresh context per attempt, durable plan, backpressure

## Intent

Binding design: `docs/design/prior-art-playbook.md` §5 decision 4 (donor: the Ralph loop — `docs/design/research/research-operating-models.md` §2). Two motivations, one of them expensive and already observed: **continuation attempts currently append to the same codex thread**, so per-attempt input grows linearly and total burn quadratically — the 2026-07-06 incident's 1.63B input tokens were mostly re-reads of one ever-growing thread. Ralph's core insight is that fresh context per unit of work is *better* as well as cheaper: the model works in its context-quality sweet spot, and durable state lives on disk where the next attempt (or a different runner) can pick it up.

Semantics:

1. **Fresh context per attempt:** every dispatched attempt starts a NEW runner session/thread (codex app-server: new conversation; claude: new session). No attempt ever appends to a predecessor's thread. The prompt carries: the task packet, the plan file (below), and the previous attempt's structured outcome (error/park reason) — never the raw predecessor transcript.
2. **Durable plan file per task:** `.tusker/scratch/<TASK-ID>/PLAN.md` — the attempt reads it first, maintains it (checklist of sub-steps with done/pending), and writes it before finishing or when the heartbeat stop-signal fires. It is disposable state, not evidence: never referenced from task markdown, cleaned when the task closes. The prompt template instructs: read plan → do the next undone item(s) → update plan → verify → finish.
3. **One-task-per-attempt discipline** stays absolute (already Tusker's shape); the prompt template's command budget gains the Ralph rules: search-before-implement (no duplicate implementations), no placeholder/stub code, serialized validation (one build/test invocation, not parallel storms).
4. **Backpressure formula from config:** the repo's gate formula (shared with OPS-T-0002's lane; `tusker.yaml`) is injected into the prompt as *the* verification commands, replacing free-text convention.
5. **Prompt-template "signs":** a per-repo `signs.md` (operator-maintained, injected into every attempt prompt) for accumulated corrective rules — the "tune it like a guitar" loop. Keep it capped (~60 lines) with a validation warning when it bloats.
