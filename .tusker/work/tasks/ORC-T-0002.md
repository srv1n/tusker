# ORC-T-0002 · Generate a live stream board from runs and leases

## Intent

On 2026-07-19/20 (rzn backend), two work streams could not see each other:
one committed to main while the other gated against it, and the collision was
discovered by audit the next morning. Tusker's runs, leases, and attempts
already know every live lane's task, workspace, and heartbeat. Generate the
missing shared view: a stream board at `.tusker/dashboards/streams.md` plus a
`--json` query, listing every live lane (lane/runner, task ids, worktree path,
branch, owned paths, last heartbeat, status) and lanes landed in the last 24h.
Hand-maintained boards are the failure mode; this one is a projection of live
state and regenerates on reconcile and on CLI mutations.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The board regenerates on reconcile and after mutating CLI commands, listing every live run and lanes landed within 24h with lane, task, worktree, branch, owned paths, heartbeat age, and status. | Inline verification |
| A2 | A JSON query (e.g. `tusker streams --json`) returns the same data with stable field names. | Inline verification |
| A3 | Lanes with expired heartbeats are flagged distinctly (stale), not shown as live. | Inline verification |

## Non-goals

- No web/UI surface beyond the markdown projection and JSON output.
- No cross-repo aggregation; one vault per board.
