# ORC-T-0005 · Record a gate ledger keyed to tree state

## Intent

"Do not repeat a passing gate on an unchanged tree" is prose doctrine, so
agents ignore it under pressure: on 2026-07-19 one lane ran eight full
workspace attempts (~69 minutes of remote command time) where at most half
were justified by actual code changes. In slow-compile ecosystems (Rust,
Xcode) redundant gates are the single largest waste. Record every gate
execution keyed to (tree state hash, command, feature profile) so the CLI can
answer "has this exact gate already passed on this exact tree?" — and let
proof rows cite a ledger hit as satisfied evidence instead of re-running.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A CLI query (naming per implementer, e.g. `tusker gate-ledger check --command <c>`) returns hit/miss keyed to the workspace's current tree state and the exact command + profile. | Inline verification |
| A2 | A passing gate execution is recorded with tree hash, command, profile, host, and duration; an unchanged tree with the same command + profile returns a hit; any tracked-file change flips it to miss. | Inline verification |
| A3 | A proof/verification row can cite a ledger hit (id or hash) as its satisfied result, and validation accepts that citation form. | Inline verification |

## Non-goals

- No distributed or cross-host cache; the ledger is repo-local.
- No attempt to model which specific tests a diff invalidates; tree-hash
  granularity only.
