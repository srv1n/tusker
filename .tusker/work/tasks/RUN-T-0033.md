# RUN-T-0033 · Review-flip under a live run must converge via the reconciler, not open the global circuit

## Intent

Observed in RUN-T-0017 trial runs 1, 2, and 3, step 3 — unchanged across all three because no prior task owned it. Flipping a live task to `review` (`tusker status FBK-T-0003 review` mid-attempt, run 3, 13:20:20Z) opened the invariant circuit on `held_lease_dispatch_eligible` within 3 seconds, blocking ALL dispatch until a manual `tusker daemon resume`. The lease then released honestly at 13:22:01Z (~101s), no re-dispatch, no loop, sibling run unaffected.

Nothing unsafe happened — but a routine operator action (pulling a task into review while its runner is mid-attempt) should not trip the alarm that exists for corruption and runaway loops. The sentinel's 3-second tick will always beat the reconciler's 30-second poll, so as built, every mid-run review-flip costs a manual resume.

Semantics:

1. A held lease on a task that left dispatch-eligible states is a *convergeable* condition: the reconciler releases the lease and stops the run. The sentinel should only open the circuit if the condition survives longer than a grace window (at least one full reconcile tick, e.g. 2× the tick interval) — meaning convergence failed.
2. Preferably, a status transition on a task with an active run event-wakes the reconciler for that project so convergence starts immediately instead of waiting for the next poll (level-triggered stays as the backstop, per playbook P4).
3. Halt latency target: lease released within one heartbeat TTL of the flip (observed 101s in run 3; expected ~15–60s).
4. No weakening of the sentinel for non-convergeable states: a held lease on a `done`/`cancelled` task, or one the reconciler repeatedly fails to release, must still open the circuit.
