## Intent
`openACPLogSink` opens the bounded log without rotation, so codex_acp and Devin execute-lane runs are killed at 16 MiB, which a 90-minute run reaches. The ACP client enqueues updates one-to-one into a 2048-slot queue; a burst larger than that while the consumer is busy poisons the session. The Devin MCP env list is built by ranging over a Go map, so start and resume differ in order. No driver emits the `permission_wait` event that run_state.go looks for, so "Waiting on you" never shows for ACP permission requests.

## Verified seams
- runner_acp.go `openACPLogSink` (~1133); consumer writes on every message/tool switch (~586); MCP env assembly (~348) from `projectWorkerMCP`.
- internal/acp/client.go `Limits.MaxUpdates = 2048` (~113), `enqueueUpdate` (~2053), thought-chunk drop (~1699), update enqueue (~1702); `session/request_permission` handling.
- run_state.go ~145 reads event kinds `permission_wait` / `permission_request` (owned by run-state-truth; do not edit).

## Implementation contract
Locked:
- ACP raw logs use the same newline-safe rotation as exec runs (behavior defined by exec-driver-reasons; call the shared writer rather than copying it). A run is never killed for log size.
- Queue overflow never poisons the session. Consecutive `agent_message_chunk` updates coalesce into one pending update. Consecutive `tool_call_update`s for the same toolCallId coalesce, keeping the latest status and concatenated content up to a bound. If the queue is still full, the client stops reading the agent's stdout until space frees (backpressure), and records one `acp_backpressure` diagnostic per episode. Ordering between different tool calls and messages is preserved.
- MCP env entries are emitted sorted by name, so start and resume are byte-identical.
- On `session/request_permission`, append event `permission_wait` (tool name, request id); on the response or cancellation, append `permission_resolved` with the same request id.
Proposed: coalescing bound values.

## Failure and edge cases
- Fake ACP agent emits 10,000 tool_call_update notifications for 3 tool calls while the consumer sleeps → session stays healthy; final state of each tool call is correct. Forbidden: session poisoned/closed or out-of-order tool completion.
- 20 MiB of agent output → run continues; rotated segments parse.
- Start and resume `session/new` / `session/load` both carry `mcpServers` with identical env order.
- Permission request then approve → `permission_wait` then `permission_resolved`.

## Ownership and coordination
Hard-depends on exec-driver-reasons for the shared newline-safe rotating writer. Does not edit run_state.go.
