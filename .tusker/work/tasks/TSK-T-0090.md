## Intent
Continue from the run Say box always fails, because `POST /runs/:id/continue` computes capability with an empty wave and `nativeContinuationPreflight` then reports "the existing wave execution window is not current". `POST /recover action=continue` skips the Blocked/Failed/Lost check that GET applies, so POST can accept what GET says is unavailable. Continue excludes Stopped, which the spec allows. Operator messages are marked accepted before the continuation child spawns, so a failed spawn loses them. Orphan classification can park a run as orphaned instead of foreign. Start fresh still matches on error text. Interrupt eligibility lives only in the UI.

## Implementation contract
Locked:
- One function computes each action's availability and is called by GET capabilities and by every POST that performs the action, with the same project, wave and run. POST refuses with the same reason GET shows.
- Continue is available for Blocked, Failed, Lost and Stopped.
- Continuation deliveries are marked accepted only after the child process start is recorded. If the spawn fails, they return to pending and are delivered by the next continue.
- Stop's post-interrupt writes are compare-and-set on the intent written before the interrupt.
- Orphaned requires the recorded wrapper pid gone and a live process in the recorded process group whose start time matches the recorded start identity. A PGID leader that fails the identity check is foreign (not ours; retry allowed). A failed `ps`/`sysctl` probe is unknown, never orphaned.
- Start fresh uses the typed intent/decision only; delete the text match.
- Capabilities include `interrupt` (available when Working or Quiet with a live owner).

## Failure and edge cases
- Failed run in a current wave: GET says Continue available; POST /runs/:id/continue and POST /recover continue both queue exactly one continuation. Two concurrent POSTs → one continuation; second returns the existing one.
- Succeeded run: GET unavailable; both POSTs refuse with the same reason. Forbidden: a POST that queues.
- Stopped run: Continue available and resumes the same native session.
- Spawn failure after a hard Say: the message returns to pending and is delivered by the next continue exactly once.
- PGID leader with a different start time → foreign, not orphaned.
