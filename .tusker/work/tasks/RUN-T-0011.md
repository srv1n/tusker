# RUN-T-0011 · Level-triggered reconciler with fenced TTL leases

## Intent

Binding design: `docs/design/prior-art-playbook.md` (§1 doctrine, §2 semantics table, §3 catalog items 1–5). This task replaces the daemon's edge-triggered dispatch/event-reaction logic with a **level-triggered reconcile loop** and upgrades run leases from set-once flags to **TTL leases with heartbeat renewal, generation fencing, and grace-window reclaim**. RUN-T-0010 patched the known holes; this task makes the whole class structurally impossible. RUN-T-0010's tests must keep passing unchanged — that is the proof the rewrite preserved behavior.

Core semantics (donors cited in the playbook; numbers are config defaults):

1. **Reconcile tick (every 30s and on any wake event):** derive the desired-run-set from the ledger via ONE shared eligibility function (tasks in ready/rework, unblocked, under caps ⇒ exactly one active run; every other task ⇒ zero). Read the actual-run-set (leases + verified processes). Converge idempotently: release/park what shouldn't exist, dispatch what's missing (through the same eligibility CAS), never act on remembered transitions. Events only wake the loop.
2. **Lease = `{owner, generation, expires_at, host, pid, start_time}`.** Claim is a CAS inside the store transaction (`WHERE task dispatchable AND unleased`); renewal every 15s pushes `expires_at` (TTL 60s) without changing generation; reclaim only when expired past a 2×TTL grace, and the reclaim predicate is re-checked inside the UPDATE so a racing heartbeat wins.
3. **Generation fencing:** every runner-originated ledger/store write carries the lease generation and is rejected loudly on mismatch — a superseded or adopted-away runner cannot corrupt state.
4. **Owner-scoped heartbeat as stop signal:** the heartbeat UPDATE is scoped to `owner = me AND task still dispatch-eligible`; zero rows updated ⇒ the runner-side ingester terminates the run cleanly. A task moved to review kills its own stale run from both ends within one heartbeat interval.
5. **Verified liveness:** "alive" requires recorded `{pid, start_time}` to match the live process (PID-reuse guard) — both before adopting AND before killing. Boot-time adoption keeps D3 semantics but only for verified-alive runners; anything else is swept to interrupted with a synthetic "interrupted by restart" event appended to the attempt log.
6. **Self-fencing daemon:** each tick re-verifies the instance guard; if superseded, stand down loudly (no ghost dispatch).
