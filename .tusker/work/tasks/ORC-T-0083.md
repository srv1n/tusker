# ORC-T-0083 · Define one typed readiness and blocker contract

## Intent

CLI and internal callers share a versioned readiness projection whose independent dimensions and structured blockers replace overloaded booleans and string-matched refusal codes.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The contract independently reports contract, import, interactive, automation, authorization, runtime, and optional-integration readiness with provenance and no derived all-purpose project-ready boolean. | See mapped verification. |
| A2 | Every blocker has a stable kind, authority domain, affected task, gate, wave, project, or integration IDs, bounded reason, and exact safe remedy; dependency and human-gate causes are never inferred from substrings. | See mapped verification. |
| A3 | Compatibility adapters preserve existing CLI and Serve fields during migration while new consumers use the typed contract as the source of truth. | See mapped verification. |
| A4 | Constructing and projecting readiness is read-only and cannot mutate registry, automation, authorization, runtime, provider, Git, release, or spending state. | See mapped verification. |
