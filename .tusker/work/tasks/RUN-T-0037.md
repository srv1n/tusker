# RUN-T-0037 · Plan gate reads worktree-local task state: divergent worktrees decline dispatch and churn as early_exit

## Intent

Found in the second soak (2026-07-07, ~16:56–17:00Z) on redriven rows AGX-T-0005 and FBK-T-0003. The canonical vault said both tasks were `ready`, so the operator redrive was legitimate. But each dispatched runner ran `tusker automation plan` inside its reused worktree, where the tracker carried flips from earlier completed-but-never-merged attempts (`status: review` / `status: done`), got `do_not_dispatch`, correctly declined, and exited clean in ~60–90s. The daemon classified the clean decline as `early_exit`, requeued, and the pair churned until the park guard contained them at attempt 2. Evidence: run rows + events under `runs/tusker/{AGX-T-0005,FBK-T-0003}/`, runner final messages quoting the worktree-side blockers (`status is review, readiness is waiting_on_review` / `status is done, readiness is done`).

Two defects, one seam:

1. **State authority.** Durable task state consulted at dispatch time — by the daemon's plan and by the runner's own routing gate inside the worktree — must come from the canonical vault (main/control branch), never from the worktree's stale tracker copy. Either the plan resolves the vault path explicitly, or the worktree tracker is refreshed from canonical state at attempt start; pick one authority and make both gates share it.
2. **Decline classification.** A runner that exits cleanly because its routing gate returned `do_not_dispatch` is not an `early_exit`: record a distinct outcome (e.g. `dispatch_declined`), release the lease without consuming a continuation attempt, and surface the blocker text on the run row. When the canonical state is terminal (`done`/cancelled), retire the row instead of requeueing. The park guard stays the containment of last resort.

Context worth keeping: the underlying work for both tasks sits finished in their worktrees awaiting review/merge (the merge lane, OPS-T-0002, is the consumer). Redispatch can never help that case; only landing the worktree output can.
