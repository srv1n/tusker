## Intent
Running the repository test suite must leave no process behind. Today daemon
tests start real detached agent wrappers using the test program itself. Those
wrappers outlive the suite and spin for hours. One suite run on 2026-10-18 left
about 54 of them.

Make the suite safe in two ways:
1. When the test program is started as an agent wrapper, it must behave as a
   wrapper and never run the whole test suite again. First confirm whether
   that recursion actually happens today and record what you observed.
2. The suite ends with a leak check. Any process the suite started that is still
   alive is stopped and named, and the suite fails.

## Failure and edge cases
- A test that deliberately starts a long sleeper must still pass if it cleans
  up its own process group.
- The leak check must not touch processes the suite did not start, such as the
  operator's resident daemon or a real agent run.
- The guard must work when the suite is killed partway, at least on the next
  suite start: leftovers from an earlier run of the same kind are reported.

## Implementation notes

Verified seams:
- The wrapper is spawned in cmd/tusker/runner_wrapper.go (startDetachedRunnerWrapper,
  exec of runnerWrapperExecutable() with "runner-wrapper --request <path>", Setsid).
  runnerWrapperExecutable returns TUSKER_WRAPPER_EXE or os.Executable(), which is
  the test binary under go test.
- TestMain in cmd/tusker/test_main_test.go:24 sets a temp TUSKER_STATE_ROOT and has
  no branch for runner-wrapper arguments. Suspected: the test binary then runs
  the full suite inside each wrapper. Confirm before relying on it.
- Tests that set TUSKER_WRAPPER_EXE (runner_wrapper_test.go, runner_claude_detached_test.go,
  runner_live_test.go, runner_acp_*_test.go) already clean up their own group.
Proposed approach (best guess):
- In TestMain, if os.Args[1] is "runner-wrapper", dispatch to the real CLI entry
  point and exit with its code; never call m.Run().
- Label the suite: TestMain sets an env marker unique to this run (for example
  TUSKER_TEST_SUITE_ID). Wrappers inherit os.Environ(). After m.Run, find
  processes with that marker (or with argv paths under the suite temp roots),
  SIGKILL their process groups, print them, and exit nonzero.
- Do not edit runner_wrapper.go; that file belongs to the inventory task.
