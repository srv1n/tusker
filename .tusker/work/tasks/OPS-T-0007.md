# OPS-T-0007 · tusker land: bind branchification source to the task (reject wrong-worktree/commit --from + substring auto-match)

## Intent

From the GPT-5.5 Pro Extended pre-push review (handoff `cgpt_mrc05ks3_5fcda4b9`), HIGH finding on the merge lane. `tusker land` branchification does not bind its source commit to the task being landed:

- `cmd/tusker/v7_land_cmd.go:269` — `land --from` accepts any resolvable ref/worktree commit and immediately creates the task branch from it, with no check that the ref actually belongs to this task.
- `cmd/tusker/v7_land_cmd.go:320` — the auto-discovery fallback matches any detached worktree whose absolute path merely *contains* the task id (`strings.Contains`), so `APP-T-0001` can match `APP-T-0001x`, a scratch path, or an unrelated worktree.

Consequence: a caller (or the daemon/UI land action) can branchify `APP-T-0001` from `APP-T-0002`'s worktree or an unrelated commit and then merge the **wrong diff** through the serialized integration lane — a silent, hard-to-detect wrong-work-landed failure.

Fix: validate the branchification source against task-owned provenance before creating the branch. Validate explicit `--from` and auto-discovered worktrees against the `.tusker/workspace.json` `record_id` (exact, delimited workspace-key match — not a substring), and for raw commit refs require task-local tracker metadata or an explicit trusted override. Remove or tighten the broad `strings.Contains` absolute-path match to an exact, delimited match only. A source that cannot be proven to belong to the task must be refused with an actionable error, never landed.

## Acceptance

| A2 | Auto-discovery no longer accepts a substring path match: only an exact, delimited workspace-key/`record_id` match selects a worktree; `APP-T-0001` never matches `APP-T-0001x` or an unrelated path. | focused_test |

## Non-goals

- No change to the serialized integration-branch / merge mechanics themselves (that is OPS-T-0006 / OPS-T-0008 territory); this task is strictly about *source selection/provenance*.
- No new trust model beyond binding source→task; the explicit-override escape hatch stays minimal and logged.
