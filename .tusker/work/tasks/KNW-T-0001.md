# KNW-T-0001 · Find and create commands route to one right doc

## Intent

- What this is: two small commands. One answers "where is the document about
  X?" by searching document headers and headings and returning a short
  ranked list — the official reference first, then design specs, then
  decision records. The other creates a new document, and refuses if a
  document about that subject already exists, pointing at the file to update
  instead.
- Why it matters: agents and humans must find the one right document in
  seconds, and it must be impossible to accidentally start a second copy of
  something that already exists. Search that routes wrong and duplicate
  copies are the two classic ways documentation dies.
- What "done" looks like: asking for a topic by any reasonable alias returns
  the right file at the top of the list; asking for a retired document lands
  on its replacement; trying to create a duplicate is refused with a helpful
  message naming the existing file.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The find command matches subject, keywords, and headings; results rank canonical doc, then spec, then decision log; each row shows path and one-line description. | Inline verification |
| A2 | A query matching a superseded document resolves to its successor, marked as such. | Inline verification |
| A3 | The create command scaffolds a new doc with the required header block, and refuses an existing subject with the existing file path in the message. | Inline verification |
| A4 | A no-match query says so and suggests the closest subjects rather than returning nothing silently. | Inline verification |

## Non-goals

- No semantic/embedding search; deterministic keyword matching only.
- No map generation (KNW-T-0002); no skill-text updates (KNW-T-0005 wires habits).

## Implementation notes

- File map (best guess): `cmd/tusker/docs_cmd.go` (+ `docs_cmd_test.go`)
  for `tusker docs find <query>` and `tusker docs new <subject>`; matching
  logic in `internal/docgraph/search.go` on the KNW-T-0007 model.
- Ranking: exact subject > keyword alias > heading substring; node-type
  order canonical > spec > decision log as tiebreak. Case-insensitive,
  multi-word queries AND across terms with fallback to best single term.
- `docs new` writes the scaffold with front-matter contract comments;
  target directory by node type flag (`--kind doc|spec`), default doc.
- Register the subcommands wherever the CLI wires commands (locate via
  `grep -rn "gate-run\|logbook" cmd/tusker/cli.go` for the pattern).
