# ORC-S-0001 - Enforce workspace cwd and containment for daemon runners

## Problem

Tusker currently creates per-record workspaces but the live Codex runner can still start with the registration repo root as cwd. That collapses the isolation claim: two daemon runs can operate in the same checkout, and a user reading the workflow will believe the safer workspace path is being enforced when it is not.

This is not polish. It is the first honesty fix. No later orchestration work should build on a runner that can silently ignore the workspace it just prepared.

## Scope and non-goals

In scope:

- Make daemon-launched Codex and detached runner commands execute with cwd equal to the prepared workspace path.
- Keep repo root available as metadata through env vars and prompt/template context.
- Validate workspace path containment before launch.
- Reject or fail attempts when workspace metadata does not match project_id and record_id.
- Add regression tests that prove the runner cannot start in repo root.

Out of scope:

- Implementing continuation turns.
- Changing workspace creation strategy semantics beyond what is needed for cwd correctness.
- Deleting existing workspaces automatically outside explicit cleanup rules.

Non-goals:

- Hide the repo root from the agent. The repo root may be passed as read-only context or env metadata.
- Replace worktree/clone/copy strategies.

## Acceptance criteria

- [x] Codex app-server starts with thread cwd equal to the prepared workspace path, never the registration repo root.
- [x] Detached runner commands execute in the prepared workspace path.
- [x] Launch fails before process start if the workspace path is outside the daemon workspaces root.
- [x] Launch fails before process start if workspace metadata does not match project_id and record_id.
- [x] TUSKER_REPO_ROOT or equivalent metadata remains available for commands that need original repo context.
- [x] A regression test proves runner execution uses the workspace cwd and leaves repo-root metadata separate.

## Plan

1. Add a single helper that resolves and validates runner cwd from WorkspacePath plus state-root containment.
2. Update Codex live and detached runner paths to use workspace cwd only.
3. Pass repo root separately through env/template context.
4. Add tests for cwd selection, path escape, metadata mismatch, and repo-root sentinel mutation.
5. Update docs if any command examples imply repo-root execution.

## Considered and rejected

- **Keep repo root as fallback cwd** - Rejected because fallback behavior is exactly how the isolation promise becomes false.
- **Only validate cwd in tests** - Rejected because runtime checks catch bad custom workflow and future adapter paths.

## Decision

Workspace cwd is mandatory for every daemon-run attempt. Repo root is metadata only. This makes some workflows slightly more explicit, but it makes isolation honest.

## Verification plan

- Unit test workspace containment helper with normal, escaped, empty, and symlink-like paths.
- Integration test daemon dispatch with fake runner that records cwd.
- Integration test live Codex command path using the existing app-server fake where practical.
- Manual test: dispatch one story and confirm pwd inside runner output is under the state-root workspaces directory.

## Kill list

- Remove any tests, docs, or defaults that still imply the old unsafe/unenforced behavior.

## Rollout

Ship behind normal daemon path with no compatibility flag. If a project relied on repo-root cwd, it was relying on a broken isolation model; the fix is to use workflow hooks or repo-root metadata explicitly.
