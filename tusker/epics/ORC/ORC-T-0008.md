## Problem

The live Codex path mostly appends raw app-server lines and handles only a few notifications. Raw logs are necessary, but they are not enough for operators. Tusker needs normalized events, latest-event timestamps, token/runtime usage, and tool-call visibility before long continuation sessions become the default.

## Scope and non-goals

In scope:

- Normalize key Codex app-server notifications and server requests to JSONL.
- Update run_turn latest_event_at on each meaningful event.
- Extract token usage and runtime where available.
- Preserve raw logs for deep debugging.
- Define mandatory event names for v2.

Out of scope:

- Full transcript storage in SQLite.
- A web dashboard.
- Claude Code parity beyond synthetic degraded events.

Non-goals:

- Depend on undocumented event payloads without defensive parsing.
- Drop raw logs after normalization.

## Acceptance criteria

- [ ] Live Codex path writes normalized JSONL events for turn start, turn complete, approval requests, file changes, command execution, errors, token usage, and tool calls when available.
- [x] Runtime store records latest_event_at per run/turn.
- [x] Token totals aggregate per turn when available. Attempt-level aggregation remains open.
- [ ] Event normalization tolerates unknown event shapes and preserves them as raw/unknown events.
- [x] Tests cover app-server fixture events.
