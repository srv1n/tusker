# ORC-S-0007 - Add attempt and turn runtime model

## Problem

Continuation turns require a different model than one process invocation equals one attempt. The clean model is one attempt as a worker session and one turn as one Codex interaction. Without that split, retry, telemetry, resume, and viewing semantics will become mud.

## Scope and non-goals

In scope:

- Add run_turns or equivalent SQLite table.
- Add active turn pointer and latest event/usage summaries where needed.
- Migrate old attempt-only runtime state safely.
- Update run inspection to show attempt versus turn shape.
- Keep existing raw artifact paths compatible.

Out of scope:

- Implementing multi-turn continuation behavior.
- Full event normalization beyond enough to populate turn records.
- Public socket API.

Non-goals:

- Treat every continuation turn as a separate attempt.
- Store transcripts in SQLite.

## Acceptance criteria

- [x] Runtime store can persist one attempt with multiple ordered turns.
- [ ] A run row can point at active attempt and active turn.
- [x] Existing attempts without turns can be represented or migrated without losing inspectability.
- [ ] Turn records include status, failure class, latest event time, usage summary, and timestamps.
- [x] Tests cover migration and invariants.

## Considered and rejected

- **One attempt per turn grouped by session ref** - Rejected because retry semantics become misleading.
- **Only JSONL events, no turn table** - Rejected because operator views and budget queries would require parsing logs.

## Decision

One attempt is one worker session. Turns are first-class runtime records inside that attempt.

## Verification plan

- Unit tests for Migrate adding turn table and columns.
- Unit tests for create/list/update turns.
- Integration test run inspect shows active turn and attempt history.
- Backward-compatibility test opening a DB from before the migration.
