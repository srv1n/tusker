## Problem

Tusker's review discipline is stronger than Symphony's, but the daemon does not yet produce a proof packet. A finished run should show what changed, what was verified, what failed, what remains risky, and where the reviewer should look.

## Scope and non-goals

In scope:

- Generate a baseline review packet from attempt/turn/event/runtime data.
- Include changed files, diff summary, commands/tests, artifacts, token/runtime totals, open risks, and follow-ups.
- Attach or append the packet under Evidence or a linked artifact path.
- Support screenshot/video references when UI artifacts exist.
- Make review packet generation happen before daemon review packet.

Out of scope:

- Automated code review quality judgment.
- Guaranteed video capture for all UI tasks.
- PR provider integration beyond linking available artifacts.

Non-goals:

- Replace human review.
- Let an empty packet satisfy evidence gates.

## Acceptance criteria

- [x] Successful attempts produce a review packet artifact.
- [x] Packet is referenced from the note evidence section.
- [ ] Packet includes attempt id, work revision, turns, changed files, verification commands, results, and open risks.
- [ ] UI-tagged or UI-surface work can include screenshot/video references when available.
- [x] Evidence gate treats packet as evidence only when it has substantive content.
