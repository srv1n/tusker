# ORC-S-0014 - Add workpad and follow-up runbooks to the skill

## Problem

Symphony's persistent workpad comment gives humans and agents one stable place to read progress. Tusker has Work log, Evidence, and Agent handoff sections, but no explicit live workpad convention. Agents also need a standard way to propose follow-up stories without activating them automatically.

## Scope and non-goals

In scope:

- Define a Workpad convention or decide which existing section carries live progress.
- Update skill docs so agents edit the workpad in place across continuation turns.
- Add PR feedback sweep guidance.
- Add rework reset guidance.
- Add agent-proposed follow-up story guidance with human activation gate.

Out of scope:

- Tool-host implementation for updating workpad.
- Automated PR review integration.
- Changing all old ticket templates unless required for validation.

Non-goals:

- Turn workpad into a second source of truth for status.
- Let agents auto-activate follow-up stories.

## Acceptance criteria

- [x] Skill docs explain the workpad purpose, format, and edit-in-place rule.
- [x] Workflow reference includes PR feedback sweep and rework reset routines.
- [x] Follow-up stories created by agents default to intake and cite discovered-from context.
- [x] Docs tell agents not to bury current state in append-only logs.
- [x] Templates or docs support the convention consistently.
