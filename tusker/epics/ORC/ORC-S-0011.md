# ORC-S-0011 - Implement same-thread continuation loop

## Problem

Tusker's current model is effectively one runner pass followed by review handoff. Symphony's core worker unlock is same-thread continuation: keep the Codex thread warm, re-check tracker state after each turn, and continue on the same thread when the note is still active.

## Scope and non-goals

In scope:

- Add max-turns workflow policy.
- Run multiple turns inside one attempt on the same Codex thread.
- Use full rendered prompt for first turn and continuation guidance for later turns.
- Re-check note state after each turn before deciding to continue or hand off.
- Implement 1-second continuation retry after clean worker exit if needed.

Out of scope:

- Tool host.
- Risk-tier routing beyond existing trust policy.
- Review packet generator beyond whatever minimal summary is needed.

Non-goals:

- Re-render full prompt every turn.
- Increment work_revision for continuation.
- Treat each continuation turn as a separate attempt.

## Acceptance criteria

- [x] One attempt can contain multiple turns on the same session/thread ref.
- [x] First turn prompt is full workflow-rendered prompt.
- [x] Continuation turns use short continuation guidance only.
- [x] Runner reloads note status between turns and stops if the note is no longer active.
- [x] Max-turn exhaustion is surfaced in the raw runtime log and does not loop inside the same process.
- [x] Clean exits with still-active tracker state queue a 1-second continuation retry instead of forcing review.

## Plan

1. Add max_turns to workflow and validation.
2. Create turn records around each Codex turn.
3. After turn completion, reload note and decide continue/stop/review.
4. Send continuation guidance on same thread when eligible.
5. Record terminal attempt outcome once, after final turn.

## Considered and rejected

- **New attempt for each continuation turn** - Rejected because it ruins retry and resume semantics.
- **Resume command for steady-state continuation** - Rejected because resume is recovery, not the normal loop.

## Decision

Continuation is the normal worker loop. Resume remains recovery after interruption or restart.

## Verification plan

- Fake app-server test with three completed turns and same thread id.
- Test note moves to blocked between turns and loop stops.
- Test max_turns exhaustion classification.
- Test review handoff after final successful turn.
- Manual run inspect shows one attempt with multiple turns.
