# ORC-S-0009 - Add sessions and run viewing commands

## Problem

Long-running orchestration is impossible to trust if operators cannot see what is alive, resumable, stalled, or abandoned. Tusker has runs inspect and logs today, but the view needs to understand attempts, turns, sessions, latest events, and resume availability.

## Scope and non-goals

In scope:

- Expand runs inspect to show attempts, turns, active turn, session ref, workspace, token totals, latest event, failure class, and resume status.
- Add runs events for structured event tails.
- Add sessions and sessions inspect commands or equivalent JSON output.
- Add Unix socket read operations for state, record, and refresh if low-cost.
- Keep Obsidian view requirements in docs.

Out of scope:

- Full web UI.
- Remote multi-user control plane.
- Tool host mutations.

Non-goals:

- Make raw logs the only operator surface.
- Expose unsafe write controls over the read API.

## Acceptance criteria

- [x] runs inspect presents attempt and turn summary in text and JSON. Active turn pointer remains open.
- [x] Operator can see latest session state/resumable data in inspect output. More state-specific fixtures remain open.
- [x] Structured event tail is available without reading raw logs manually.
- [x] JSON output includes turns, attempts, run, and latest session objects for CLI, Obsidian, and local read-view consumption.
- [ ] Tests cover inspect output for running, failed, abandoned, and completed attempts.
