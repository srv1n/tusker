# ORC-S-0006 - Interrupt or park runs when tracker state becomes ineligible

## Problem

The tracker is supposed to be the control plane. If a human marks a note blocked, done, or cancelled, a live agent should stop or park. Today the daemon focuses on active notes and can drop runtime rows for notes that disappear from active eligibility without first handling the process safely.

## Scope and non-goals

In scope:

- Reconcile running attempts against current note status before dispatch.
- Interrupt or park live runs when status leaves active states.
- Handle cancelled, done, blocked, in_review, and missing note cases distinctly.
- Record attempt outcome and operator-visible reason.
- Keep raw logs and workspace for inspection unless cleanup policy says otherwise.

Out of scope:

- Full continuation loop.
- Full failure-class taxonomy beyond state-change outcomes.

Non-goals:

- Let a human status change be ignored until process exit.
- Delete workspaces immediately on every status change.

## Acceptance criteria

- [ ] A running attempt is interrupted when its note moves to cancelled.
- [ ] A running attempt is parked or interrupted when its note moves to blocked, according to documented policy.
- [ ] A running attempt is released when its note moves to done or in_review externally.
- [x] Runtime state records cancelled, blocked, or released reason without writing runtime fields into markdown.
- [x] Tests cover state changes detected during reconcile.

## Plan

1. Load all relevant notes, not only active candidates, before reconciling running attempts.
2. Map current durable status to runtime action.
3. Call runner interrupt where needed and mark attempt outcome.
4. Avoid deleting runtime rows until terminal state is safely recorded.
5. Add tests for cancelled, blocked, done, missing note.

## Considered and rejected

- **Wait for the runner to notice note state** - Rejected because the tracker must be authoritative even when the agent is wedged.
- **Always kill on any non-active state** - Rejected because blocked may later support parked/resumable behavior.

## Decision

The daemon must reconcile live runtime state against tracker state before launching new work. Human tracker changes win.

- Check no runtime fields are added to note frontmatter.
- Manual test with tusker runs interrupt still works after reconciliation change.
