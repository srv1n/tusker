# ORC-T-0019 · Add policy-driven agent reviewer close lane

## Intent

Add a policy-controlled agent reviewer lane after tasks enter `review`, so low/medium work can be independently checked and auto-closed while high/critical work gets an agent advisory pass but still waits for a human gate.

## Scope

In:
- `WORKFLOW.md` reviewer policy with default reviewer actor, auto-close risks, human-required risks, and prompt text.
- Daemon dispatch from `review` into an independent reviewer run without adding another task status.
- Close/verify guardrails so the configured reviewer cannot close human-gated risk tiers.
- Close output/work log that states who reviewed the task.
- Runtime, CLI, and adoption docs that explain the lane.

Out:
- A web UI for review queues.
- Multi-reviewer quorum or scorecards.
- Letting reviewer runs silently edit implementation code.

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | Workflow policy exposes an enabled reviewer lane with low/medium auto-close and high/critical human gate defaults. | Workflow validation/default tests and rendered `WORKFLOW.md`. | `reference/runtime`, `reference/cli`, `spec/v5-adoption` |
| 2 | Review-state tasks dispatch a distinct reviewer run once per review handoff and do not create a new tracker status. | Daemon test showing review prompt, runtime lane, and no repeat dispatch loop. | `reference/runtime` |
| 3 | Configured reviewer can verify/close auto-close risks, but cannot verify/close human-gated risks. | CLI lifecycle tests. | `reference/cli` |
| 4 | Closed tasks make reviewer attribution visible. | Close command/work log test or inspection. | `reference/cli` |

## Constraints

- Keep markdown task lifecycle unchanged: `review` remains the handoff state and `done` remains terminal success.
- Runtime reviewer state belongs in SQLite/run artifacts, not task frontmatter.
- Reviewer runs must be independent from worker runs and should mark `rework` instead of editing implementation.
- High/critical close remains human-gated by default.

## Escalate if

- Review dispatch needs another task status.
- Auto-close requires weakening docs/evidence/verification gates.
- Existing dirty tracker files make it impossible to isolate this task's changes.

- Daemon review-lane dispatch/reconciliation.
