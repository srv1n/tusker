## Problem

Long-running orchestration cannot be a blind `while active: continue` loop. A ticket can need same-session resume, a fresh thread because the current context is bloated, a separate branch because the implementation path should be isolated, or a stop for human audit. Today those decisions are scattered across runner behavior, retry policy, and human intuition.

Tusker needs an explicit run supervisor policy: a daemon-owned decision layer that decides when to continue the same thread, resume a native session, fork a fresh thread, start a separate branch under the same ticket, create a new revision, or stop for audit.

## Scope and non-goals

In scope:

- Add a durable supervisor decision model.
- Define `continue_thread`, `resume_session`, `fork_thread`, `new_branch`, `new_revision`, and `stop_for_audit`.
- Support same-ticket resume semantics for Codex and Claude Code where native session continuity can be proven.
- Support separate branch/workspace lineage under one ticket when the work remains in scope.
- Surface supervisor decisions in `runs inspect`, `runs events`, review packets, and operator docs.
- Define token/context pressure thresholds that prefer `fork_thread` over burying more turns in a confused session.

Out of scope:

- Cloud dashboard.
- Multi-tenant control plane.
- Linear live adapter.
- Complex web UI.
- Making a parent model the scheduler.

Non-goals:

- Do not create a new task merely because a separate branch is useful.
- Do not resume an old session after `work_revision` changes.
- Do not pretend Claude Code has Codex app-server continuity if the adapter cannot prove it.
- Do not let a model auditor override deterministic daemon safety policy.

## Acceptance criteria

- [x] Runtime records can store supervisor decision kind, reason, parent attempt/session, target attempt/session, branch/workspace, validation delta, merge/discard rule, and token/context signals.
- [x] Codex same-ticket resume requires matching `record_id`, `work_revision`, runner, workspace metadata, and compatible thread/session ref.
- [x] Claude Code same-ticket resume either proves native continuity or starts a new supervised attempt with an explicit degraded/unsupported reason.
- [x] Context-window or token-pressure failure can produce `fork_thread` instead of blind retry.
- [x] A separate branch under the same ticket records parent attempt, parent session, branch name, workspace path, reason, expected validation difference, and merge/discard rule.
- [x] Human-requested changes create `new_revision`; old sessions are not resumed.
- [x] `runs inspect --json` and `runs events` expose supervisor decisions.
- [x] Review packets include supervisor decision hitask when more than one thread/branch exists.

## Considered and rejected

- **Always continue the same thread until max_turns** — Rejected because long sessions bury important state and make context-window failures worse.
- **Always start a new ticket for alternate branch work** — Rejected because branch isolation is often implementation strategy, not new product scope.
- **Always use a parent model to decide** — Rejected because it becomes an expensive second scheduler. Deterministic policy must stay authoritative.

## Decision

The daemon owns supervisor decisions. A model auditor is optional and policy-bound. Same-ticket resume and branch/thread forking are first-class runtime concepts, while durable scope changes remain `work_revision` changes.
