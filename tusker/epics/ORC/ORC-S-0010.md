# ORC-S-0010 - Add event-based stall detection and failure classification

## Problem

A process can be alive and still be dead work. Symphony detects stalls from event inactivity, not pid existence. Tusker also needs failure classes so retry policy can distinguish transient infrastructure from auth, sandbox, budget, and deterministic failures.

## Scope and non-goals

In scope:

- Add latest-event based stall timeout.
- Classify runner outcomes into retryable and non-retryable failure classes.
- Store failure class in SQLite attempt/turn state.
- Update retry policy to use failure class before attempt count.
- Expose failure class in run inspect output.

Out of scope:

- Risk-tier trust routing.
- Context-window prompt compaction implementation beyond classification.
- Full review packet generation.

Non-goals:

- Retry unknown failures by default.
- Write failure_class into note frontmatter.

## Acceptance criteria

- [x] If a running Codex run has no events after codex.stall_timeout_ms, it is interrupted and classified stalled.
- [x] Failure classification controls retry eligibility.
- [x] Auth, sandbox, approval/config/deterministic/budget/context-window failures do not auto-retry by default. Unknown remains retryable for now.
- [x] Stalled and uncategorized transient runner failures may retry within budget.
- [ ] Tests cover each failure class category.
