# ORC-S-0012 - Add dependency priority and risk-aware dispatch

## Problem

After the daemon is honest and observable, dispatch needs a brain. Active status alone is not enough. Tusker already has blockers, priority, due dates, risk, and workflow policy. The daemon should use them.

## Scope and non-goals

In scope:

- Block dispatch when blocked_by references unresolved work.
- Sort candidates by priority, due date, risk policy, retry due time, and age using documented precedence.
- Route by risk-tier trust profile.
- Expose dispatch-blocked reasons in inspect/status output.
- Keep tracker state canonical.

Out of scope:

- Machine learning prioritization.
- External tracker adapters.
- Remote worker pools.

Non-goals:

- Use risk to bypass human gates.
- Mutate note priority automatically.

## Acceptance criteria

- [x] Notes with unresolved blocked_by items are not dispatched.
- [x] Terminal or cancelled blockers resolve according to documented rules.
- [x] Dispatch order is stable and explainable.
- [x] Critical-risk work does not auto-dispatch without explicit workflow profile.
- [x] Runtime rows record the skip reason in last_error so runs JSON can explain why a note was skipped.
