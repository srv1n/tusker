# KNO-T-0005 - Freshness fingerprints

## Agent capsule

- Essence: make current truth difficult to rot by hashing declared source files and gating close on stale touched knowledge nodes.
- Next action: compute source fingerprints from `source_of_truth` and `stale_when`, then record fingerprints in resolution events.
- Read next: RFC section 20, close-gate section 16, existing docs freshness code.
- Avoid: timestamp-only freshness or vague "checked docs" state.

## Intent

Implement V6 freshness tracking so knowledge pages declare source authorities, Tusker detects stale nodes when those sources change, and knowledge close-gate commands record source fingerprints as proof.

## Read this when

Read this task when changing freshness status, source hashing, knowledge-resolution events, or close validation for stale knowledge nodes.

## Scope

In:
- Glob expansion for `source_of_truth` and `stale_when.paths`.
- Stable content hashing and missing-source handling.
- `freshness.index.json` with current/stale/missing/unknown/waived/historical states.
- Resolution events with source fingerprint.
- Close validation that blocks unresolved stale touched nodes.

Out:
- Git blame or semantic freshness.
- External source fetchers.
- Human review of every stale page by default.

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | Changing a declared source path marks affected knowledge nodes stale. | Fixture test that mutates source content and reindexes. | `spec/v6-rfc`, `tusker/docs-system` |
| 2 | Applying/nooping/waiving a node records status, reason, actor, timestamp, and fingerprint. | CLI tests over task frontmatter/body updates. | `reference/cli` |
| 3 | Closing a task that touches stale unresolved nodes fails. | Lifecycle validation test. | `reference/validator` |
| 4 | Historical/deprecated nodes are excluded from default stale checks unless referenced by active work. | Freshness index tests. | `tusker/docs-system` |
