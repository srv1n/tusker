# KNO-T-0004 - Backrefs and Obsidian graph

## Agent capsule

- Essence: generate proof backrefs, current-work blocks, wikilink resolution, and graph inspection for V6 vaults.
- Next action: wire indexed links and knowledge resolutions into managed blocks plus `graph.index.json`.
- Read next: RFC sections 17, 18, 19.4, 27.4 and current Obsidian docs.
- Avoid: treating loose links as proof; only knowledge-resolution entries prove docs impact.

## Intent

Make V6 vault navigation good in Obsidian and useful to agents without plugins: source files use wikilinks, generated backrefs point from knowledge pages to task proof, and `tusker graph` exposes domain/knowledge/task relationships.

## Read this when

Read this task when changing generated backrefs, current-work blocks, wikilink resolution, graph index output, or Obsidian-facing vault navigation.

## Scope

In:
- Managed backref blocks on knowledge pages.
- Managed current-work blocks in domain indexes.
- Wikilink resolver for domains, knowledge nodes, tasks, epics, and aliases.
- `graph.index.json` and `tusker graph <node-or-task-or-domain>`.
- Ambiguous/missing wikilink validation.

Out:
- Full web renderer route rewriting.
- Freshness fingerprinting.
- Publishing graph visualizations beyond index output.
