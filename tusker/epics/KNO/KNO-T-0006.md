# KNO-T-0006 - Publish split and LLM lanes

## Agent capsule

- Essence: separate source-truth commands from generated projections and make LLM surfaces filtered by default.
- Next action: move export/build/dev/llms/skill projection behavior under `tusker publish ...`.
- Read next: RFC section 23, current docs export/build code, skill bundle code.
- Avoid: publishing task records or internal/historical knowledge in the default LLM lane.

## Intent

Implement the V6 publication model: `tusker publish ...` generates site output, LLM surfaces, and project skill bundles from the knowledge graph while excluding internal, historical, deprecated, and task-proof material by default.

## Read this when

Read this task when changing generated docs/site output, `llms*.txt`, publication manifests, or packaged project-skill projections for V6.

## Scope

In:
- `tusker publish export/build/dev/llms/skill`.
- `publication.index.json`.
- `llms.txt`, `llms-full.txt`, `llms-internal.txt`, and `llms-historical.txt` lane filters.
- Wikilink route rewriting in rendered output.
- Default exclusion of task records from reader-facing docs.

Out:
- Source-truth knowledge commands.
- Markdown renderer rewrite beyond what projection requires.
- Public website redesign.

## Constraints

- Source truth remains in `tusker/domains/**`; site and LLM files are disposable projections.
- V6 docs and generated prompts must not teach `tusker docs ...`.
- Default LLM surfaces should be useful and conservative, not exhaustive dumps.
- Task evidence and work logs are proof records, not docs.

## Escalate if

- Existing site pipeline assumes docs-map is authored source.
- Publication filters require hand-maintained allowlists to be correct.
- Skill packaging cannot distinguish operator skill from project knowledge router.
