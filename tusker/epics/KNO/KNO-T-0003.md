# KNO-T-0003 - Domain and knowledge CLI

## Agent capsule

- Essence: expose the V6 source-truth command surface and stop teaching the overloaded `docs` namespace.
- Next action: implement `domain` and `knowledge` commands over the generated indexes and bounded capsules.
- Read next: RFC sections 7, 21, 22, 27; `cmd/tusker/cli.go`; current docs command implementations.
- Avoid: adding publication commands here except for compatibility stubs required by tests.

## Intent

Add the V6 CLI for source-truth inspection and close-gate resolution: `tusker domain ...` and `tusker knowledge ...`, including deterministic route lookup, capsule show output, and task knowledge-resolution commands.

## Read this when

Read this task when changing the public V6 command surface for domains, knowledge pages, capsules, routing, or knowledge close-gate commands.

## Scope

In:
- `tusker domain list/show/new/canon/graph`.
- `tusker knowledge map/list/show/route/freshness/check/apply/noop/waive`.
- Capsule output for domain and knowledge pages.
- Knowledge-resolution updates on task files.
- Compatibility stance for old `tusker docs ...` commands.

Out:
- Publish/export/build/LLM lane implementation.
- Freshness hashing internals beyond consuming the freshness index.
- Backref block generation beyond invoking indexed graph data.

## Constraints

- V6 docs and generated prompts must teach `knowledge` and `publish`, not `docs`.
- Route output must be deterministic and explain why a node matched.
- Capsule commands must read bounded indexed data before falling back to full Markdown.
- Resolution commands must preserve task proof and not write runtime-only state into frontmatter.

## Escalate if

- Compatibility aliases make it impossible to keep V6 help text clean.
- Route behavior needs embeddings to satisfy basic RFC examples.
- Knowledge-resolution writes conflict with existing V5 docs-resolution fields during migration.
