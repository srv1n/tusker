# KNO-T-0007 - Dogfood Tusker V6 vault

## Agent capsule

- Essence: migrate Tusker's own vault into the V6 domain knowledge graph and project router shape.
- Next action: create `tusker/SKILL.md`, `tusker/domains/**`, and initial canonical nodes from the RFC.
- Read next: RFC section 33, current `tusker/docs/**`, current operator `skill/SKILL.md`, and `AGENTS.md`.
- Avoid: perfectly migrating every historical page before the initial graph works.

## Intent

Use Tusker itself as the first V6 consumer repo: build the project knowledge router, create initial domain indexes/canons, move current truth from V5 docs into knowledge pages, and keep task history in epics.

## Read this when

Read this task when migrating this repo's vault, writing `tusker/SKILL.md`, creating domain pages, or updating `AGENTS.md` to point agents into the project knowledge graph.

## Scope

In:
- `tusker/SKILL.md` project knowledge router.
- Domains: `cli`, `runtime`, `workflow`, `schema`, `knowledge-system`, `skill`, `obsidian`, `adoption`, `codebase`.
- Initial canonical nodes named by RFC section 33.
- Minimal `AGENTS.md` update that points into `tusker/SKILL.md` and route commands.
- Obsidian-readable wikilinks/backrefs/current-work blocks after reindex.

Out:
- Perfect migration of every old docs page.
- Rewriting all historical tasks into V6 schema in one pass.
- Installing every domain as its own external skill.
