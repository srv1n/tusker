# KNO-T-0002 - Lightweight Markdown indexer

## Agent capsule

- Essence: build the small parser/indexer that turns V6 Markdown source into deterministic graph records.
- Next action: index frontmatter, headings, required sections, wikilinks, Markdown links, managed blocks, and Knowledge delta tables.
- Read next: RFC sections 19, 26, `cmd/tusker/frontmatter.go`, `cmd/tusker/notes.go`, and existing docs index code.
- Avoid: rendering Markdown or inventing a CMS.

## Intent

Implement the cheap Go indexer specified by the RFC so Tusker can generate `knowledge-map.json`, section capsules, graph edges, and validation facts without loading or rendering the full corpus.

## Read this when

Read this task when adding parser/index infrastructure for V6 source files or changing the validation data model that downstream commands consume.

## Scope

In:
- YAML frontmatter extraction.
- ATX heading and section-body extraction.
- Wikilink and Markdown `.md` link extraction.
- Managed block detection/replacement primitives.
- Markdown table parsing for `## Knowledge delta`.
- Generated `knowledge-map.json` records for domains, knowledge nodes, epics, and tasks.

Out:
- HTML rendering.
- Embeddings or semantic search.
- Full CommonMark compliance.
- Publication route rewriting beyond exposing link facts to later tasks.

## Constraints

- Parse only the structures named by the RFC.
- Preserve generated-file boundaries: generated indexes go under `_system/generated/**`.
- Keep indexing deterministic so route and validation tests do not depend on filesystem ordering.
- Do not promote task evidence or attachments into knowledge pages.

## Escalate if

- Existing note parsing cannot distinguish V5 docs from V6 knowledge without invasive rewrites.
- Managed block replacement risks overwriting authored prose outside marked regions.
- The parser starts needing full Markdown rendering to satisfy acceptance.

## Deliverables

- Indexed Markdown data model.
- V6 reindex path for `knowledge-map.json`.
- Tests for headings, sections, links, managed blocks, and Knowledge delta tables.
- Validation integration for required V6 sections.
