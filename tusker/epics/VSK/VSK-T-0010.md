# VSK-T-0010 · Harden V7 project skill publish output path deletion

## Agent capsule

- Essence: Harden V7 project skill publish output path deletion.
- Next action: define acceptance, do the smallest scoped change, and attach concise evidence.
- Read next: this note, then only the code/docs anchors named here.
- Avoid: raw logs, full transcripts, generated indexes, and attachments unless doing evidence forensics.

## Intent
Prevent `tusker publish skill --v7 --out <path>` from deleting unsafe paths. The command currently removes the output directory before writing the skill package, so it needs stronger guards than "not empty and not filesystem root".

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | V7 skill publish rejects `--out .`, repository root, vault root, home directory, and paths inside source-truth Tusker folders. | Unit tests using temp directories. | Update CLI help if rejected paths are documented. |
| 2 | V7 skill publish still permits normal generated package directories such as `dist/project-skill`. | Regression test. | None. |
| 3 | Existing output cleanup remains deterministic for safe output directories. | Export test. | None. |

## Symptom

- `publishV7SkillCmd` calls `os.RemoveAll(out)` after only rejecting empty output and filesystem root.

## Reproduction

1. Run `tusker publish skill --v7 --out .` or point `--out` at another important directory in a temp fixture.
2. Observe that the command reaches the recursive delete path.

Expected:
- The command refuses dangerous output locations before deletion.

Observed:
- The current guard does not reject `.`, repo root, vault root, home, or source-truth directories.

## Scope

In:
- Harden `publishV7SkillCmd` output path validation.
- Add tests for unsafe and safe output paths.

Out:
- Changing the V6 publish skill behavior unless it shares the same deletion risk.

## Deliverables

- Output path safety helper.
- Regression tests for unsafe output paths.
