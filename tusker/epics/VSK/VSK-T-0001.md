## Intent
Add a V7 setup path that initializes a repository with the skill-shaped knowledge structure described by the V7 spec. The result should not be "a tracker plus some docs"; it should be a repo-local agent context system with a project skill entrypoint and V7 domain canon.

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | `tusker init` or an explicit V7 init/profile can scaffold V7 work directories, `tusker/knowledge/domains/**`, and a project skill entrypoint without relying on V6 `tusker/domains/**`. | Focused init smoke test over a temp repo. | Update CLI and skill docs with the canonical setup command. |
| 2 | The initialized project skill names the operator skill as the Tusker mechanics layer and routes repository questions into V7 domain `INDEX.md` and `CANON.md`. | Snapshot/assertions against generated `SKILL.md`. | Clarify two-skill model in agent docs. |
| 3 | The setup path preserves existing V5/V6 init behavior unless the caller opts into V7 or V7 defaults are intentionally selected. | Regression tests for existing V6 init plus V7 init. | Note migration/compatibility boundary. |

## Scope

In:
- Add or refine V7 init/profile flags and defaults.
- Generate minimal V7 domain starter content suitable for agents.
- Ensure repo-local `AGENTS.md`/skill pointers tell agents where the project knowledge skill lives.
- Keep the output deterministic and easy to validate.

Out:
- Migrating all existing V6 domain files.
- Remote sync/state branch setup beyond existing V7 state support.
- Full public website rewrite.

## Deliverables

- CLI path for V7 skill-shaped repo initialization.
- Generated project skill entrypoint with routing table or routing instructions.
- Tests proving V7 init creates the expected files.
