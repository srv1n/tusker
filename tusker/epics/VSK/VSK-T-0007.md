# VSK-T-0007 · Refresh installed skill bundles during install and update

## Agent capsule

- Essence: Refresh installed skill bundles during install and update.
- Next action: define acceptance, do the smallest scoped change, and attach concise evidence.
- Read next: this note, then only the code/docs anchors named here.
- Avoid: raw logs, full transcripts, generated indexes, and attachments unless doing evidence forensics.

## Intent
Ensure installed Tusker skill bundles are refreshed whenever users run the normal install/update paths. Skill guidance changes often; stale `SKILL.md` and reference files create bad agent behavior even when the binary is current.

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | `make install` refreshes all already-installed Tusker skill locations, not only the destinations explicitly selected by the install target. | Make/install integration test or scripted smoke with fake home. | Update README/install docs. |
| 2 | `tusker install` refreshes existing user skill installs by default when a Tusker skill is already present, while still allowing explicit destination installs. | Unit test proving stale installed skill files are replaced without requiring `--refresh-existing-user-skills`. | Update install help text. |
| 3 | `tusker update` continues to refresh existing user skills and, when `--repo` is provided, repo-local `.agents/skills/tusker` and `.claude/skills/tusker`. | Existing update tests plus regression for repo-local refresh. | Clarify update behavior. |
| 4 | Refresh replaces removed/stale payload files, not just overwrites `SKILL.md`, so the installed skill exactly matches the embedded skill bundle. | Test with a stale extra file and modified reference content. | Note skill payload is authoritative. |

## Scope

In:
- Makefile install targets.
- `tusker install` and `tusker update` skill refresh behavior.
- User skill locations: `~/.agents/skills/tusker`, `~/.codex/skills/tusker`, and `~/.claude/skills/tusker` when present.
- Repo-local skill locations when `--repo` or install-repo paths are used.

Out:
- Auto-updating arbitrary third-party project knowledge skills.
- Network update checks.
- Changing where agent platforms discover skills.

## Deliverables

- Installer/update implementation changes.
- Tests with fake home/repo skill installs.
- Updated help and README text.

## Constraints

- Existing installs should become current without making users remember a special refresh flag.
- Refresh must be local and deterministic; do not fetch remote skill content.
- Keep `--repo-only` semantics intact for callers that intentionally skip user installs.

## Escalate if

- The installer should also refresh generated per-repository project knowledge skills automatically; that may require knowing the target repo and should be a separate explicit mode.
