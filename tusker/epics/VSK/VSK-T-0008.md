## Intent
Fix V7 project skill routing so `SKILL.md` stays synchronized with the V7 domain set. A V7 repository must not export domain canon files without also routing agents to those domains from the project skill entrypoint.

## Acceptance contract

| # | Outcome | Proof required | Docs impact |
|---|---|---|---|
| 1 | Adding a V7 domain after `init --profile v7` refreshes or regenerates `tusker/SKILL.md` so the new domain appears in the routing table. | Focused regression test. | No docs change unless command behavior changes. |
| 2 | `tusker publish skill --v7` writes an exported `SKILL.md` whose routing table includes every exported `knowledge/domains/<id>`. | Export smoke assertion for `providers`. | No docs change unless export mode changes. |
| 3 | Validation fails when V7 knowledge domains exist but the project skill routing omits one of them. | Validator fixture test. | Update validator reference if a new issue code is added. |

## Symptom

- `tusker domain new providers --v7` creates `knowledge/domains/providers/**`, but the existing `tusker/SKILL.md` remains unchanged.
- `tusker publish skill --v7` copies the stale `tusker/SKILL.md`, so the exported skill includes provider canon files but does not route agents to them.

## Reproduction

1. Build the CLI from the review branch.
2. In a temp repo, run `tusker init --profile v7 --vault ./tusker --yes --vault-only --no-mount`.
3. Run `tusker domain new providers --v7 --vault ./tusker --title Providers --summary "Provider integrations."`.
4. Run `tusker publish skill --v7 --vault ./tusker --out ./dist/project-skill`.
5. Search for `providers` in `tusker/SKILL.md` and `dist/project-skill/SKILL.md`.

Expected:
- Both skill files route to `knowledge/domains/providers/INDEX.md` and `knowledge/domains/providers/CANON.md`.

Observed:
- Neither skill file contains `providers`, even though `dist/project-skill/knowledge/domains/providers/{INDEX.md,CANON.md}` exists.
