# VSD-T-0026 · Add skill doctor route and pack commands

## Intent

Add a first-class CLI surface for docs-as-skill retrieval and validation.
Agents should not have to grep the repo to answer "what do I read next?" or
"is this skill package trustworthy?"

This task turns the architect feedback into command behavior:

- `tusker skill doctor` validates the skill package and project skill.
- `tusker skill route` returns the minimal files for an intent.
- `tusker skill pack` produces a bounded agent context bundle, or becomes a
  documented alias/wrapper over the existing V7 packet command.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `tusker skill doctor --strict --json` checks required skill files, embedded paths, publication sources, route collisions, missing V7 domain `INDEX.md`/`CANON.md`, stale generated manifests, forbidden source truth, local absolute paths, links, body budgets, and task-domain route coverage. | strict fixture tests |
| A2 | `tusker skill doctor --package <path> --strict --json` validates an exported project skill package without needing the source repo. | temp package test |
| A3 | `tusker skill route "<intent>" --json` returns ordered `read` paths and `do_not_read` path globs, using project skill/domain metadata before broad search. | route fixture test |
| A4 | `tusker skill pack <TASK-ID> --budget <n> --for agent` returns bounded context: task capsule, project skill routing, relevant domain summaries/canon excerpts, proof requirements, close policy, and forbidden paths. If implemented as an alias to `packet`, help must make that relationship explicit. | packet/pack budget test |
| A5 | CI has a strict doctor gate for both the repo and a generated V7 project skill package. | workflow or make target assertion |

## Non-goals

- Do not replace `tusker packet`; extend or wrap it cleanly.
- Do not include task bodies, evidence logs, attempts, events, generated indexes, or raw logs in skill source truth.
- Do not require an LLM or embedding service for routing.
