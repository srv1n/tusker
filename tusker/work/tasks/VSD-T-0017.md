# VSD-T-0017 · Harden V7 object creation and local writes

## Agent capsule

Make local markdown/runtime writes boring and crash-safe. Start with `cmd/tusker/commands_v7.go`, `cmd/tusker/v7_state_runtime.go`, event writing, and generated dashboard writes.

## Intent

Remove avoidable race and corruption paths from V7 object creation, leases, events, and generated projections. The review called out orphan task creation, sequence races, and non-atomic lease writes; this task turns those into tested behavior.

## Scope

In scope:
- Require V7 epic existence before creating tasks.
- Allocate pretty task IDs safely under concurrent creators.
- Use atomic write patterns for canonical notes, event JSON, local leases, and generated projection files where practical.
- Make local claim/lease writes resistant to duplicate claim and partial-file failure.

Out of scope:
- Cross-machine distributed locking.
- Replacing markdown with SQLite as canonical durable state.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `tusker new task --epic XXX` fails when the V7 epic note does not exist. | CLI regression test |
| A2 | Concurrent task creation for the same epic cannot produce duplicate IDs; allocation uses atomic create/CAS/retry or equivalent. | concurrency test |
| A3 | Task notes, events, lease JSON, and generated indexes are written via temp-file plus rename or a stronger local atomic primitive. | focused tests/code review |
| A4 | Lease claiming remains single-owner under concurrent claimers and leaves no valid-looking partial lease after interrupted writes. | lease test |

## Constraints

- Do not make generated dashboards authoritative.
- Do not serialize all local work through one broad global lock unless a narrower atomic primitive will do.
- Keep pretty IDs if possible; switch to opaque IDs only with a deliberate decision note.

## Escalate if

- Atomic writes behave differently enough on the target OSes to require a portability decision.
- Existing task IDs depend on the old race-prone sequence behavior.

## Deliverables

- Epic-existence validation for task creation.
- Atomic write helper or equivalent local pattern.
- Concurrent creation and claim regression tests.
