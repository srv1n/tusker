# VSD-T-0032 · Add opt-in agent improvement scans

## Intent

Build an opt-in Tusker workflow that reviews recent work history and proposes the smallest useful reusable asset: a skill/playbook, custom subagent, scheduled automation, extension to an existing asset, or an explicit skip.

The user-facing product should adapt the OpenAI-style prompt into Tusker's repo-local model instead of pasting a giant prompt into every agent run. Tusker should help users periodically ask: "What am I repeating, what already exists, and what narrow asset would save future work without speculative prompt bloat?"

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A command or documented workflow exists for an opt-in improvement scan over a bounded lookback window, defaulting to 30 days or all available Tusker history when shorter. | Focused CLI or docs regression |
| A2 | The scan gathers evidence in priority order from Tusker tasks/attempt summaries/feedback digests, installed project skills and agent docs, then optional external history adapters such as Codex sessions, Claude Code transcript metadata, Memories, Chronicle, or equivalent sources when configured. | Unit tests or adapter contract review |
| A3 | Output starts with a compact shortlist: repeated workflow, supporting evidence with dates, frequency/confidence, recommended form, and why it is or is not worth packaging. | Snapshot test |
| A4 | Asset creation is conservative: only high-confidence missing items may be created, existing skills/docs/automations are extended before duplicates are added, and ambiguous/sensitive/poorly evidenced candidates are skipped. | Focused regression covering create/extend/skip cases |
| A5 | Users can choose execution profile without making providers part of the durable record: at minimum dry-run versus apply; preferred runner/model/reasoning profile is an invocation option or workflow config, with cheap/default profiles encouraged for discovery and stronger models reserved for apply/review. | Help/config test |
| A6 | Codex and Claude Code integrations are source-aware: Codex can use session/task summaries where available; Claude Code can use transcript/session summaries where available; neither integration requires private Memories or Chronicle access unless explicitly enabled. | Contract test or documented manual proof |
| A7 | The workflow produces a clear finish summary: created or extended assets, deliberately skipped candidates, and candidates needing more evidence. | Snapshot test |

## Non-goals

- No always-on background mining by default.
- No automatic reading of raw full transcripts, private memory stores, or Chronicle data without explicit user opt-in.
- No speculative broad "productivity" mega-skill.
- No provider-specific schema baked into Tusker task files; provider options stay in workflow config, CLI flags, or runtime state.
- No automated domain registration, app installation, or external action as part of an improvement scan.
