# VSD-T-0028 · Reconcile docs publication manifests with V7 surfaces

## Intent

Reconcile the human docs publication outputs with the current V7 surface. The
local repo no longer has the archive-missing-file problem for `README.md`,
`go.mod`, `skill/SKILL.md`, or current `docs/publication.yaml` sources. Those
exist.

But validation still proves a real stale-docs problem:

- `site/public/canon-manifest.json` points at removed sources:
  `skill/references/BASES.md`, `OPTIONAL_PLUGINS.md`, and `PLUGIN_COMPAT.md`.
- The manifest is older than the current publication registry and skill
  references.
- `tusker validate --json` reports docs source missing/stale errors plus legacy
  V6 knowledge-node freshness errors.

Public docs are projections, not V7 canon, but stale projections still poison
agent trust when published as manifests or `llms.txt`.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `docs/publication.yaml` references only existing source files and has no stale deleted skill references. | registry source check |
| A2 | `site/public/canon-manifest.json`, `site/public/llms.txt`, and `site/public/llms-full.txt` are regenerated from the current registry and do not mention removed sources. | manifest assertions |
| A3 | `tusker validate --json` has no `DOCS_SOURCE_MISSING`, `DOCS_MANIFEST_STALE`, or route-removed publication errors after export. | validation output |
| A4 | Legacy V6 knowledge-node freshness errors are either resolved, waived with explicit reason, or fenced so V7 release validation is not blocked by legacy canon. | validation or legacy-fence test |
| A5 | CI has a docs/publication check that fails when a registry source is missing or a public manifest points to a missing source. | CI/test assertion |
| A6 | Documentation states that public docs/site outputs are human projections; V7 project truth remains `tusker/SKILL.md` plus `knowledge/domains/**`. | docs diff |

## Non-goals

- Do not revive removed legacy reference docs just to satisfy a stale manifest.
- Do not make `docs/publication.yaml` the canonical V7 knowledge source.
- Do not solve all V6 migration history unless needed to clear release validation.
