# VSD-T-0027 · Harden review archive and local-state hygiene

## Intent

Fix review/package hygiene so external archives do not leak local runtime state,
absolute paths, or duplicate skill debris.

The missing-Markdown finding from the architect is mostly a `make codebasezip`
artifact and is not the core bug here. The real bug is that the newer
`scripts/package-code-review.sh --list` currently includes things it should not:

- `tusker 2/**`, an accidental duplicate skill payload.
- `tusker/events/**`, `tusker/attempts/**`, `tusker/evidence/**`, dashboards,
  and generated bases.
- `tusker/_system/project.yaml`, which used to contain this checkout's local
  absolute repository path.

That makes the archive noisy and undermines the "project skill source truth"
boundary.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The review archive includes source, module files, README, operator skill, project skill, docs registry, and intentional text assets. | archive list fixture |
| A2 | The review archive excludes `tusker/events/**`, `tusker/evidence/**`, `tusker/attempts/**`, `tusker/_generated/**`, `tusker/dashboards/**`, `.tusker-*`, raw logs, local runtime state, and `tusker/_system/project.yaml`. | archive list negative assertions |
| A3 | `tusker 2/**` is removed or ignored, and duplicated skill mirrors are documented/generated from the canonical `skill/**` payload. | `rg --files` and package list assertion |
| A4 | No tracked/distributed file contains repo-local absolute paths as source truth. | `rg` guardrail |
| A5 | `make codebasezip` is either renamed/documented as code-only or replaced by the review archive path so future reviewers get the intended artifact. | Makefile/help test or docs diff |

## Non-goals

- Do not delete legitimate task records from the working vault.
- Do not solve public release tarball packaging unless it shares the same filter.
- Do not include binary/media artifacts just to make external review convenient.
