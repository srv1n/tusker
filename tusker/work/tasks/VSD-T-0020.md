# VSD-T-0020 · Replace permissive field coercion with typed validation

## Agent capsule

Stop silent coercion from deciding state transitions. Start with helpers, config merge/defaulting, frontmatter normalization, and duplicate project-ID parsing.

## Intent

Make malformed config/frontmatter fail where it affects behavior. Convenience coercion is fine for display, but scheduler logic and validation should not turn bad data into zero values or false defaults.

## Scope

In scope:
- Strict parse helpers for config/frontmatter fields that affect state transitions.
- Pointer/default-aware config booleans where explicit false matters.
- Frontmatter normalization that does not mutate caller-owned maps unexpectedly.
- One project-ID resolver and exact markdown-heading section extraction.

Out of scope:
- Full typed V7 domain model extraction; that belongs with [[VSD-T-0011]].
- Broad CLI framework replacement.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | State/config paths use strict parse helpers that return errors for malformed ints/bools instead of silent zero/false. | validation tests |
| A2 | Config merging distinguishes unset boolean from explicit `false` where defaults matter. | config tests |
| A3 | Frontmatter normalization/serialization does not mutate caller-owned maps unless the API says so. | unit test |
| A4 | Project ID and markdown section parsing use one resolver/exact heading behavior across V7 schema and CLI code. | unit tests |
| A5 | Hook timeout cancellation happens per hook iteration, not deferred until all hooks finish. | config hook test |
