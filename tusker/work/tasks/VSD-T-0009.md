# VSD-T-0009 · Reconcile task projections during control mutations

## Intent

Update affected task projections immediately when control operations change state. Human gate actions should not leave stale dashboards or require users to know they must run a separate reconcile command.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `gate satisfy`, `gate waive`, and `gate obsolete` eagerly update readiness, next owner, next action, dashboards, and affected generated indexes for directly blocked tasks. | gate transition tests |
| A2 | Task lifecycle control operations eagerly refresh projections for directly affected objects. | task transition tests |
| A3 | `tusker reconcile` remains available for repair, but normal control operations do not require a follow-up reconcile. | CLI smoke tests |
| A4 | Projection updates use CAS and emit events when state changes. | event and CAS tests |

## Non-goals

- Do not make implementation branches directly mutate protected fields.
- Do not rebuild every dashboard when a bounded projection update is sufficient.

## Verification

- Command: `go test ./cmd/tusker -run 'Test.*Gate.*Reconcile|Test.*Projection|Test.*Dashboard|Test.*CAS' -count=1`
- `tusker new gate --blocks <fixture-task> --kind auth --owner human:fixture`
