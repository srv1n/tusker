# VSD-T-0024 · Make show and search V7-kind aware

## Intent

Fix the main bounded-retrieval commands for V7 records. `commands_show.go` and
`commands_search.go` still key several behaviors off frontmatter `type`, but V7
uses `kind`.

Current repro:

- `tusker search "VSD-T-0010" --type task --json` returns `items: null`.
- `tusker show VSD-T-0010 --capsule` renders an incomplete header because
  `noteHeaderLine()` prints `type`, which is empty on V7 tasks.
- V7 tasks with no explicit `## Agent capsule` do not get task-specific capsule
  facts because `synthesizeCapsule()` switches on `type`.

For agent-first docs, `show --capsule` and `search --type task` are not nice-to-have.
They are the safe read path.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `show`, `search`, capsule synthesis, capsule frontmatter facts, and header rendering use effective kind: `kind` first, `type` fallback. | focused CLI tests |
| A2 | `tusker search <query> --type task` finds V7 tasks and still finds legacy task records where supported. | mixed-fixture search test |
| A3 | V7 task capsules include readiness, risk/proof mode/proof status, next owner/action, domains, project skill route, `tusker packet <id> --for agent`, and forbidden paths. | snapshot test |
| A4 | JSON search output keeps a stable `type` field for compatibility while exposing V7 `kind`; filtering behavior is documented. | JSON assertion and help/docs update |
| A5 | Existing V5/V6 show/search behavior does not regress. | legacy fixture test |

## Non-goals

- Do not rewrite the search engine or add semantic search.
- Do not dump full task bodies in capsules.
- Do not make agents read events, evidence, attempts, generated indexes, or raw logs by default.
