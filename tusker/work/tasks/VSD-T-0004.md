# VSD-T-0004 · Replace direct Obsidian status hooks with V7-safe commands

## Intent

Delete or replace bundled Obsidian snippets that directly mutate task frontmatter. V7 protected state must move through CLI control operations, not JavaScript that writes `status: active` or `status: blocked`.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `skill/assets/snippets/status-hooks.js`, `.agents/skills/tusker/assets/snippets/status-hooks.js`, and `.claude/skills/tusker/assets/snippets/status-hooks.js` no longer mutate protected YAML fields directly. | static guardrail test |
| A2 | Replacement helpers call or document V7-safe commands: `gate satisfy`, `gate waive`, `status review`, `status rework`, `evidence add`, `close`, or proposal equivalents. | snippet review and CLI smoke test |
| A3 | Bundled Obsidian assets do not mention durable `active` or `blocked` as V7 statuses. | `rg` guardrail |
| A4 | Validation catches future bundled JS that writes protected state fields. | automated lint test |

## Non-goals

- Do not build a full Obsidian plugin.
- Do not support V5 status mutation as a default workflow.

## Verification

- Command: `go test ./cmd/tusker -run 'Test.*Snippet|Test.*Hook|Test.*Protected' -count=1`
- `rg -n "status:\\s*(active|blocked)|frontmatter.*status|processFrontMatter" skill .agents .claude`
- `tusker validate --branch-policy --json`
