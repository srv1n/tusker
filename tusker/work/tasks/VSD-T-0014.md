# VSD-T-0014 · Fix V7 daemon dispatch semantics

## Agent capsule

Fix the orchestration blocker where V7 tasks can exist but the daemon does not reliably see them. Start with `cmd/tusker/daemon.go`, `cmd/tusker/workflow.go`, `cmd/tusker/commands_v7.go`, and `internal/v7schema/schema.go`.

## Intent

Make daemon dispatch speak V7, not legacy tracker semantics. A V7 task with `kind: task`, no `type`, `status: ready`, `readiness: ready`, and `next_owner: agent` must be pickable; `status: active` must not become a backdoor lifecycle state.

## Scope

In scope:
- Canonical object-kind resolution for workflow semantics.
- Daemon dispatch eligibility for V7 tasks.
- Focused tests for the review-reported `kind`/`type` and `ready`/`active` failures.

Out of scope:
- Large package refactors.
- Runtime SQLite migration work.
- Docs/site publication cleanup.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Daemon task discovery uses one canonical kind resolver that accepts `kind`, legacy `type`, and schema-derived V7 object kinds. | focused daemon/index tests |
| A2 | V7 dispatch eligibility is based on `status in {ready,rework}`, `readiness=ready`, agent ownership, and no live lease/run conflict. | focused daemon tests |
| A3 | `status=active` is rejected or ignored for V7 task dispatch; legacy active-state behavior is explicitly quarantined. | regression test |
| A4 | The review-reported case, `schema: tusker.task/v7` plus `kind: task` and no `type`, is claimed by the daemon/fake runner path. | automated test |
| A5 | Default operator drill-down, `tusker list --epic VSD --type task --open`, sees V7 `kind: task` notes with scalar `epic` fields. | list regression test |
