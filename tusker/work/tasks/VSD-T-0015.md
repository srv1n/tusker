# VSD-T-0015 · Unify V7 lifecycle, readiness, and runtime state

## Agent capsule

Define and enforce one production state model. Start from `internal/v7schema/schema.go`, `cmd/tusker/workflow.go`, `cmd/tusker/v7_validation.go`, and the runtime store.

## Intent

Stop letting durable lifecycle, readiness, workflow active states, and runtime execution state pretend to be the same thing. V7 should have one lifecycle model for tasks, one readiness model for blockers, and one runtime model for daemon execution.

## Scope

In scope:
- Canonical status/readiness/runtime-state definitions.
- Validation that prevents legacy lifecycle values from entering V7 tasks.
- Workflow config behavior that cannot silently override the V7 state machine.

Out of scope:
- Moving V7 code out of `cmd/tusker`; that is [[VSD-T-0011]].
- Replacing all runtime schema; keep the change as small as the state contract allows.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | V7 task lifecycle is documented and enforced as `idea`, `backlog`, `ready`, `review`, `rework`, `done`, `cancelled`, `superseded`. | validation tests |
| A2 | Readiness is documented and enforced separately from lifecycle; blockers do not require fake statuses. | validation and reconcile tests |
| A3 | Runtime execution state is represented separately from task status, either in SQLite/runtime records or a typed runtime projection. | runtime-store test or schema test |
| A4 | Workflow config cannot make V7 dispatch depend on legacy `active` states without validation failure or explicit legacy routing. | config/workflow validation test |

## Constraints

- Do not preserve both `active` and `ready` as equivalent V7 task lifecycle states.
- Do not bury runtime execution state in markdown task status.
- Keep generated dashboards as projections only.

## Escalate if

- Existing ORC daemon tasks still require legacy `active` semantics after [[VSD-T-0014]].
- A state transition cannot be represented without a schema decision.

## Deliverables

- V7 state contract in code and knowledge canon.
- Validation coverage for invalid lifecycle/readiness combinations.
- Workflow validation guard against accidental legacy-state dispatch.

## Non-goals

- Do not implement the full typed domain model in this task.
- Do not close or migrate old ORC tasks unless needed for validation.
