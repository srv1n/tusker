# VSD-T-0023 · Strengthen V7 project skill router generation

## Intent

Make generated V7 project skills strong enough to act as agent routing tools,
not just domain tables. `renderV7ProjectSkillBody()` currently gives a short
route list and boundary note. That is better than nothing, but it does not
teach first action, when to use the skill, when not to use it, update rules,
validation commands, or the stop/ask boundary.

The project skill should remain short, but it needs to be operationally complete.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Generated `tusker/SKILL.md` includes `Read This When`, `Do Not Read This When`, `First Action`, `Routing Algorithm`, `Domains`, `Updating Canon`, `Forbidden Source Truth`, and `Validation` sections. | golden-file or snapshot test |
| A2 | First action tells task agents to run `tusker packet <TASK-ID> --for agent`, then read only routed domains. | generated text assertion |
| A3 | Updating canon instructions require the narrowest domain `CANON.md`, a leaf node when needed, and validation; they forbid proof logs and task history in canon. | generated text assertion |
| A4 | Forbidden paths include work/task records, evidence, attempts, events, `_generated`, `_system`, dashboards, raw logs, packet caches, and local absolute paths. | generated text assertion |
| A5 | `tusker init --profile v7` and `tusker domain new --v7` write/refresh the richer project skill idempotently. | CLI fixture test |
| A6 | No V7 project skill template or generated body mentions Diataxis, docs-map, V5, or V6 except in explicit legacy/migration context. | guardrail test |

## Non-goals

- Do not turn `SKILL.md` into an encyclopedia.
- Do not duplicate the Tusker operator skill's lifecycle, proof, and closeout semantics.
- Do not make human/public docs canonical for V7 project knowledge.
