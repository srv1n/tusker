# VSD-T-0002 · Make V7 the default CLI and quarantine legacy surfaces

## Intent

Make V7 the default CLI behavior and quarantine or delete legacy paths. The current compatibility stack points agents at the wrong system; top-level commands must mean V7.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `tusker new task`, `tusker new gate`, `tusker next`, `tusker close`, `tusker reconcile`, and `tusker validate` operate on V7 objects without requiring `--v7`. | CLI smoke tests |
| A2 | V5 tracker, V6 knowledge graph, docs-map, docs publishing, and migration commands are removed from top-level help or moved behind explicit `tusker legacy ...` commands. | help snapshot tests and command routing tests |
| A3 | In a mixed repo, `tusker next` selects V7 work only and never starves V7 tasks behind stale V5 records. | mixed-fixture automated test |
| A4 | Skill assets, command references, and generated help stop teaching old default status/docs behavior. | `rg` guardrail plus docs/skill diff |

## Non-goals

- No V5/V6 compatibility promise.
- No broad migration project; legacy data may be archived or accessed through explicit legacy tools only.
