# VSD-T-0007 · Make evidence durable and acceptance-linked

## Intent

Make evidence records durable proof artifacts instead of pointers that can rot. Evidence must cover acceptance IDs, screenshots must require real review, and generated packets must summarize proof rather than count as proof.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `tusker evidence add --path <file>` copies local artifacts into `tusker/evidence/<task>/artifacts/` and records stable repo-relative paths by default. | automated test |
| A2 | `--link-only` and `--external-url` exist for intentional exceptions; `/tmp`, absolute local paths, and path escapes are rejected or marked non-durable. | negative tests |
| A3 | Evidence records require `covers` entries such as `TASK:A1`; `evidence_packet` is not accepted as an evidence kind required for close. | validation tests |
| A4 | Screenshot evidence starts pending review and accepted screenshots require explicit `checked_by`; creator self-check is allowed only by explicit low-risk policy. | screenshot policy tests |

## Non-goals

- Do not store secrets, customer data, or raw logs in evidence artifacts.
- Do not make generated packets an evidence kind.

## Verification

- Command: `go test ./cmd/tusker -run 'Test.*Evidence|Test.*Artifact|Test.*Screenshot|Test.*Packet' -count=1`
- `tusker evidence add VSD-T-0001 --kind automated_test --covers A1 --summary "fixture proof"`
- `tusker validate --json`
