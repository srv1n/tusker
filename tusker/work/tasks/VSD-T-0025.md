# VSD-T-0025 · Add V7 knowledge leaf-node creation

## Intent

Add a V7-native command for creating leaf knowledge nodes under an existing
domain. V7 validation already recognizes leaf kinds such as `runbook`,
`decision`, `invariant`, `interface`, `glossary`, and `source`, but the current
top-level `tusker knowledge new` still creates V6 notes under `tusker/domains/**`.

Without a V7 generator, agents will freestyle file names, frontmatter, and body
shape. That is how canon slowly turns into mystery meat.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `tusker knowledge new <domain>/<folder>/<slug> --v7 --kind <kind> --title "..."` creates V7 leaf nodes under `tusker/knowledge/domains/<domain>/**`. | CLI fixture test |
| A2 | Supported V7 kinds include `runbook`, `decision`, `invariant`, `interface`, `glossary`, and `source`, with folder/kind compatibility checks. | validation fixture |
| A3 | Generated templates include `Read This When`, `Do Not Read This When`, source truth, related links, and kind-specific content: procedure for runbooks, contract for interfaces, rule for invariants, decision/rationale for decisions, raw attribution for sources. | golden-file tests |
| A4 | Command rejects missing domains, invalid kind/path traversal, accidental overwrite, and legacy `references/` paths. | negative CLI tests |
| A5 | Help and skill docs explain when to use V7 leaf generation versus legacy V6 knowledge commands. | help snapshot and docs diff |

## Non-goals

- Do not migrate every existing V6 knowledge node in this task.
- Do not add semantic search or embeddings.
- Do not make leaf docs the default read path; domain `INDEX.md` and `CANON.md` still route first.
