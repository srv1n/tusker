# VSD-T-0018 · Version runtime SQLite and platform state paths

## Agent capsule

Give runtime SQLite real migrations and stop assuming macOS for daemon state. Start with `cmd/tusker/runtime_store.go` and `cmd/tusker/daemon.go`.

## Intent

Make runtime state upgrades boring. SQLite is the right runtime layer, but `CREATE TABLE IF NOT EXISTS` plus a macOS-only default state root is not a production migration story.

## Scope

In scope:
- `PRAGMA user_version` migration flow or an equivalent explicit schema-version mechanism.
- Idempotent transactional migrations for existing runtime tables.
- Platform-aware default state root for macOS, Linux/XDG, and Windows.

Out of scope:
- Changing canonical markdown state.
- Adding new scheduler features.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Runtime store initialization applies numbered/idempotent migrations inside transactions and records the current schema version. | runtime-store tests |
| A2 | Re-opening an existing store does not rewrite or drop data and leaves `user_version` at the expected value. | migration regression test |
| A3 | Default state root is platform-aware: macOS Application Support, Linux `$XDG_STATE_HOME`/`~/.local/state`, Windows local app data. | unit tests with env/GOOS seam |
| A4 | Daemon and runner code use the configured state root/store rather than reopening an implicit global default. | code review plus focused test |

## Constraints

- Preserve existing local runtime data when possible.
- Do not put transient scheduler state into task markdown to avoid SQLite migrations.
- Avoid a migration library unless the in-repo mechanism becomes more complex than the code it replaces.

## Escalate if

- Existing runtime stores in the wild need a one-time compatibility import.
- Windows path behavior cannot be tested cleanly without a small path resolver abstraction.

## Deliverables

- Numbered runtime migrations.
- Runtime schema-version tests.
- Platform-aware state-root resolver tests.

## Non-goals

- Do not redesign the whole runtime event model.
- Do not implement cross-machine runtime sync.
