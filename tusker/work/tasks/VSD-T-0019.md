# VSD-T-0019 · Clean runner trust boundaries and hidden runtime dependencies

## Agent capsule

Fix runner surprises: no hidden default runtime store, no Python dependency just to write status JSON, and clear trusted-shell boundaries. Start with live Codex and exec runners.

## Intent

Make runner behavior explicit enough to debug and safe enough to document honestly. Tusker executes configured commands, so the trust boundary must be stated, and runtime writes must go where the daemon was configured to write them.

## Scope

In scope:
- Pass configured runtime store/state root into live runners.
- Stop ignoring runtime store open errors in runner startup.
- Remove the `python3` dependency from exec-runner status writing.
- Document shell-command workflow config as trusted code.

Out of scope:
- Full sandboxing for untrusted repositories.
- Replacing every shell command config with argv arrays in one pass.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | `startLiveCodex` and related live-runner paths use the daemon/configured runtime store or state root, not `DefaultStateRoot()` from inside the runner. | focused test |
| A2 | Runtime-store open/write errors are surfaced to logs/events or returned; they are not silently ignored. | focused test/code review |
| A3 | Exec runner writes status JSON from Go or an internal wrapper without requiring `python3`. | runner test |
| A4 | Workflow hooks and shell command runner docs/validation clearly state trusted-local-repo assumptions. | docs/validation evidence |
