# VSD-T-0029 · Reduce agent token burn in V7 workflow

## Intent

Cut context/token waste in downstream Tusker repositories by making the agent-facing workflow smaller and more truthful by default.

The core design is:
- `AGENTS.md` stays a tiny bootstrap pointer.
- The installed Tusker operator skill owns tracker mechanics and can be updated centrally.
- `tusker/SKILL.md` owns repo-specific knowledge routing.
- Task, evidence, event, generated, and runtime files remain ledger/proof surfaces, not prompt material.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Repo install/update converges the managed `AGENTS.md` Tusker block to a tiny bootstrap instead of injecting verbose workflow prose. | Focused install tests cover create/update behavior and preservation of unrelated human content. |
| A2 | Repo update refreshes repo-local skill payloads and Tusker pointers in one command so downstream repos do not carry stale workflow instructions. | Focused update/install tests. |
| A3 | Agent task discovery distinguishes runnable work from merely open work by showing readiness/owner and exposing a runnable-only queue. | CLI tests for list/next output and filtering. |
| A4 | Human-wait closeout status tells agents to stop as soon as only human-owned gaps remain, even before a durable checkpoint exists. | Closeout status test. |
| A5 | Proof status defaults to concise output and keeps verbose acceptance/evidence cross-products behind an explicit flag. | Proof command output test. |
| A6 | Default proof requirements avoid screenshot/manual-smoke gates for ordinary backend/code tasks. | Proof default test plus task creation fixture. |

## Non-goals

- Perfectly redesign all V7 state internals.
- Migrating historical downstream task files.
- Rewriting the daemon runtime.
