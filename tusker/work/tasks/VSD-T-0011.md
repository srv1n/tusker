# VSD-T-0011 · Refactor V7 code into agent-legible packages

## Intent

Refactor the monolithic V7 implementation into packages with real ownership boundaries. The current `cmd/tusker` concentration is agent-hostile and will keep causing semantic drift.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Core V7 model, markdown parsing, store/CAS, git/project discovery, validation, workflow projections, evidence, events, and CLI wiring live in separate internal packages. | package structure review and tests |
| A2 | `cmd/tusker` contains command wiring and minimal adapter code, not core V7 business rules. | source-structure lint |
| A3 | Existing V7 behavior remains covered by public CLI/package tests while files are moved. | full automated test suite |
| A4 | Package boundaries allow future agents to own disjoint write sets without editing one multi-thousand-line file. | documented package map |

## Non-goals

- Do not combine this with new product behavior unless a move requires a tiny adapter fix.
- Do not preserve dead V5/V6 code in new packages.

## Verification

- Command: `go test ./...`
- `go vet ./...`
- source-structure lint for file size and forbidden V7 logic in `cmd/tusker`
